# Implementation roadmap

This is the proposed subsequent production phase. No schema, persistence format, runtime interface or host adapter below was changed by this review. Cost is relative engineering scope, not a time estimate.

| Order | Work package | Deliverable and acceptance gate | Cost / dependencies |
|---|---|---|---|

| 0b | Harden acceptance evidence | Reject unknown/empty assertions and false operation results; separate automated/human/cleanup gates; score all required live-fixture outputs and semantic self-test content. Negative controls R12 and intentionally failing runner checks must fail for the expected reason. | Small/medium; before using green tests as a release decision. |

## Explicit proposed contract changes

| Contract | Proposed change | Migration / compatibility policy |
|---|---|---|
| Story format | Distinguish required lorebooks from owned/granted assets; optional player-safe summary separate from author objective; specify generated outcome identity/tie/progress semantics. | Do not grant writes to existing requirements automatically. Additive fields may retain format 2 only if old readers safely ignore them; otherwise bump format with export/downlevel behavior. A player summary is an optional UX proposal, not a confirmed spoiler fix. |
| Persisted runtime | Session/input revision, replay base+journal, mutation provenance, per-effect before-image/status, derived-memory dependencies, ledger/retirement versions. | Version the metadata format. Old chats keep their current state but must be marked history-unavailable until rebuilt; never fabricate a rollback log. Bound retention with a visible recovery path. |
| Runtime task interface | Immutable owner/context plus abort signal and a typed result that can be applied only by the matching session. Commit returns applied/discarded/failed with reasons. | Introduce at coordinator boundaries and migrate all off-path jobs; do not leave one legacy callback capable of bypassing the checks. |
| Host adapters | Capability/version probe, stable identities where available, typed success/failure, supported backend preset variants, save completion status, ownership-aware inverse operations. | Preserve current adapters behind a narrow compatibility layer. Unsupported effects should be diagnosed before play; avoid silent fallback that claims success. |
| Extraction protocol | Enforced requested key/source set, source span/window revision, structured rejection diagnostics and bounded response size. | Keep current line syntax as an input adapter while strengthening validation. Fixtures must label evidence rather than accepting any non-empty quote. |
| Generation cache | Preserve all outcomes and record validation per path; distinguish draft/rejected/approved/inserted/stale without implicit promotion. | Invalidate/revalidate existing caches on contract upgrade; do not mutate a played graph invisibly. |
| Pinning | Retention, source validity and manual truth override are separate concepts. | Surface a conversion decision for legacy pins; do not silently discard deliberate user-authored facts. |
| Compatibility claim | Tested host version/hash, browser, model revision/template, bundle hash and required capabilities accompany each release. | Declare only the matrix actually exercised. No automatic “all SillyTavern versions” promise. |

## Fault and acceptance matrix for the production phase

Every stateful package should run with a delayed success, delayed error, malformed response, duplicate completion and backend unavailability. Inject failures before/after host writes and persistence, including partial multi-operation effects. Switch chats and stories between awaits. Verify queued owner IDs, resulting state, persisted blob, journal and actual generation payload; a UI toast alone is insufficient.

For mutations, cover swipe/edit/delete during streaming, after generation, after reload, after story update and beyond retained history. Compare a replay of corrected history with the rolled-back run, including removed-source knowledge and all derived summaries. For privacy, use deliberately distinct secrets for two roster members and inspect their final requests, not just extension prompt registries.

For live extraction, maintain separate datasets for quality deltas, memory facts, private knowledge and scene breaks. Report all attempts and first-attempt reliability, model settings, response latency, token usage and retry cost. Use at least three independently authored stories and alternate branches. Human checks must assess continuity, agency, terminology and authoring comprehension; agent assessments remain labeled as such.
