## How it works (new mechanisms)
- **Consolidation receipt** (`consolidationRecovery.js:84-110`, `consolidationReceiptPolicy.js:23-78`): per candidate, persist an intent `{id, sources:[{uid, hash, contentHash}], candidate, status:pending}` to settings with verified save (`:34-63`) BEFORE the book write; the write stamps `STMB_consolidationCommitId=id` on the new entry; resume = load book, find entries carrying the id: >1 → conflict, 1 → compare tier/content/member set → saved|conflict, 0 → re-hash sources, write only if unchanged, then re-read to confirm. Unconfirmable → `needsReview`, never auto-retried.
- **Narrator generation binding** (`narratorGenerationState.js:4-68`, wiring `index.js:13234`, `:13286`): capture `{lastIndex, lastMessage obj, swipe_id}` at `GENERATION_STARTED` (skip dryRun/quiet/impersonate); at `GENERATION_ENDED` bind the streaming target `{messageId, message obj, swipe_id, gen_started}` from `streamingProcessor` unless stopped/aborted; at `MESSAGE_RECEIVED` stamp only if identity matches. Fixes stamping the wrong message on swipe/regenerate/continue.
- **Child rollback unhide receipt** (`index.js:12992-13020`): ranges to `/unhide` are written into the book save itself, replayed after interruption (idempotent), cleared after.
- **Connection-profile route** (`connectionProfileRequest.js:5-41`, `stmemory.js:416-420`): `sendRequest(profileId, messages, max, {stream, signal, extractData:false, includePreset:true}, overrides)` with `model/temperature/max_*/json_schema` forced in the override payload; on failure throw `error.cause` (ST wraps it) and never retry via the direct path ("can compound a provider rate limit").
- **Combine clips** (`combineClipsPolicy.js:4-68`): snapshot sources `{uid,title,content,keywords,disabled}`, refuse commit if any changed (`areCombineSourcesCurrent`); prompt rule: on conflict prefer an explicit correction, else keep both claims, never invent a resolution.
- **Selection hash** (`chatSelection.js:3-32`): picked message indices + per-message hash, revalidated before use.

## Patterns for SO

### P1. Profile tool bridge reads the wrapper, not the cause — host-fact / bug · copilot routes · our state: present but misclassifies · value 3 · effort S
What: `ConnectionManagerRequestService.sendRequest` wraps every failure as `new Error('API request failed', {cause})` (ST `public/scripts/extensions/shared.js:489-490`); the provider text (`"Insufficient Balance"`, `"Got response status 429"`, `custom-request.js:474`, `:500`) is only on `cause`. STMB unwraps (`stmemory.js:416-420`). Ours: `openProfileToolBridge` sends through `sendRequest` (`src/services/stHost/connectionProfiles.ts:119-121`), but `profileToolBridge.ts:30-33,65-67` classifies `error.message` only, so auth/quota always read as `transport`. Fallback still fires (all four kinds in `HARNESS_FALLBACK_KINDS`, `copilot/agent/route.ts:65`), but the kind the owner sees (and `onFailure.kind`) is wrong: a DeepSeek out-of-quota looks like a network fault. `modelReply.ts:64-97` already unwraps for plain model calls. Test `profileToolBridge.test.ts:37-39` uses raw messages, not ST's wrapper shape. Fix: reuse the `cause` unwrap from `modelReply.ts` before `errorKind`; add a test with the wrapped shape.

### P2. Idempotency receipt on the written artifact — pattern · stagecraft/curator, effect ledger · our state: partial · value 3 · effort M
What: write-ahead intent + a commit id stamped INSIDE the host object, so resume can answer "did it land, once?" even when content compare is ambiguous (duplicate creates, someone edited after). Theirs: `consolidationReceiptPolicy.js:23-43`, `consolidationRecovery.js:94-104`. Ours: `effectLedger.ts:113-147` reconciles `pending` by value compare `before/after` (applied | dropped | externally-changed); curator creates carry a `{{// so:created <chat> | <group>}}` stamp (`stagecraft/createdStamp.ts`) but no per-op id. Gap: a crashed curator create re-proposed and applied again cannot be told apart from an author's twin entry; value compare of `after` for a create is content-equality, so two identical creates both read "applied". Fit: add op id to the existing created stamp (kept by rewrites already); reconcile counts entries carrying it (>1 = conflict row). No invariant conflict; stamp forgery already refused.

### P3. Bind per-generation state to the rendered message's identity — pattern / test-idea · turnBridge, talk, warden · our state: partial · value 3 · effort S
What: anything captured at generation start (drafted member, cast, injected warden note) is attached to a message only if `{messageId, message object, swipe_id, gen_started}` captured at `GENERATION_ENDED` from `streamingProcessor` matches at `MESSAGE_RECEIVED`, and dropped when the processor was stopped/aborted. Theirs: `narratorGenerationState.js:4-68`. Ours: `turnBridge.ts:134-158` keys turns by message id (+continue stamp), `GENERATION_STOPPED` → `flushPending` (`:82`); the warden note is "marked applied only when that generation renders a real reply" (architecture.md). Test idea: a user-stopped stream: ST's `stopGeneration` sets `isFinished=true` (`script.js:5607-5618`, `:3847-3850`) and finalize still emits `MESSAGE_RECEIVED`/`CHARACTER_MESSAGE_RENDERED` (`:3797-3801`), so a stopped partial reply commits a boundary and is extraction input. Decide deliberately (partial reply = turn?) and pin it in `so-turn-types-check.mts`; check whether the warden note counts a stopped partial as "real reply".

### P4. Hidden ≠ deleted on re-reads (carry-over idea 6) — enhancement · extraction · absent · value 2 · effort S
Unchanged since v2.4: `windowHygiene.ts:115`. STMB now hides AND unhides around rollbacks (`index.js:12992-13020`), so with STMB installed a consumed range can flip `is_system` repeatedly; fingerprints already ignore `is_system` (`fingerprints.ts:7`), re-reads do not. Policy question stays (user-hidden OOC).

### P5. Merge op for curator duplicates — feature · stagecraft · absent · value 2 · effort M
Curator ops are `disable|rewrite|patch|create` (`src/stagecraft/types.ts:27-32`); near-duplicate creates are flagged "patch X instead" (architecture.md, v2.8 11 A15) but two existing near-duplicate entries cannot be folded. Theirs: Combine Clips = new body + union keys + disable sources, refused if any source changed since snapshot (`combineClipsPolicy.js:59-68`). For SO it composes from existing ops (`rewrite` A + `disable` B) as one proposal card with a source snapshot re-checked at the write edge; protected/gated entries stay refused. Their conflict rule ("keep both claims, never invent a resolution", `:8-9`) is worth copying into any SO consolidation/merge prompt.

## Host facts
- `sendRequest` failures arrive as `Error('API request failed', {cause})` (`shared.js:489-490`); provider message only on `cause`. SO's profile tool bridge misses it (P1).
- `GENERATION_ENDED` is emitted from `hideStopButton()` with payload `chat.length` (`script.js:3532-3537`), i.e. a UI stop-button event; in streaming it fires inside `finalizeIntermediaryMessage` BEFORE `MESSAGE_RECEIVED` (`:3794-3801`), and `streamingProcessor` is nulled right after `onFinishStreaming` (`:5440-5441`). Bind streaming state at `GENERATION_ENDED`, not later.
- User stop: `stopGeneration` → `onStopStreaming` sets `isFinished = true` + aborts (`script.js:3847-3850`, `:5607-5618`). This contradicts `gotchas.md:53` ("a stopped stream leaves `isFinished === false` forever") at least for the stop-button path; re-check which path that gotcha measured.
- `onErrorStreaming` emits `MESSAGE_RECEIVED` + `CHARACTER_MESSAGE_RENDERED` for a failed stream except swipe/impersonate/continue (`script.js:3820-3829`): consistent with the known "backend down still commits a boundary".
- STMB claim (not verified here): ST's open-chat functions can create an empty chat for a missing file; they read the file first (`stmbProgress.js:209-216`). Relevant to any SO "reopen chat" affordance.

## Not worth taking
- Memory reminders (`memoryReminders.js`): SO extracts automatically; a nag toast also breaks "one surface, no toasts".
- Side-prompt versioning (`sidePromptHistory.js`): versioned tracker entries in WI; SO trackers are typed qualities with history in rings.
- Child-rollback `/unhide` receipt: SO never hides chat messages (prior review anti-pattern stands); the generic receipt shape is P2.
- Clip format templates (`clipFormatPolicy.js`): presentation wrapper for WI text, no SO analogue needed.
- Extract/Find selection hash (`chatSelection.js`): SO's `fingerprints.ts` already covers the staleness check.
