## What it is / what changed

Tracker extension for a single narrator card: a background reader (separate call, own Connection Profile) reads each
reply and writes absolute stat strings + collection add/remove/update for player and NPCs. Swappable "Systems" (fantasy,
dating sim, creature trainer) define stats, collections, XP/levels. Cardless speakers get a placeholder portrait; "Fill"
generates a profile + portrait from chat. Model is told to write `Name: "dialogue"`; the DOM is decorated with
per-speaker portrait and colour. Places tree, NPC memories, per-NPC TTS/expressions. Most interesting part is not the
product but the **measurement discipline**: frozen prompt bundles, holdout scene sets, bounded scoring, honest reports.

## How it works

- **The 96.4%**: 20 holdout scenes × 3 repeats = 60 replies, 609 checks, Gemma 4 E4B Q4, llama.cpp `response_format`
  json_schema (`docs/evaluations/gemma-e4b-qualitative-schema-20261020-report.md`). Read the denominators: 2 of the ~10
  checks per reply are near-free (`validJsonAndNotTruncated`, `preservedPoolMaxima`,
  `tests/fixtures/gemma-tracker-score.mjs:92-93`) = 120 of 609; many others are "unchanged" checks. The hard part,
  **inferred numeric changes, is 76/96 (79%)**; **replies passing every check 44/60 (73%)**. Unconstrained mixed/delta
  contract scored 588/609 — schema enforcement bought shape validity, not accuracy.
- **Scene fixtures** (`tests/fixtures/roleplay/**/*.json`): 2 prior exchanges + fresh user turn + reply, starting state
  immediately before the fresh turn, `checks` as `[method, ...args, critical]`. Replies generated by Gemma 31B through the
  real narrator card from an authored `generationBrief`, then hand-reviewed; raw output kept in `review.originalText`,
  generation params/model/narrator sha256 in `generation` (`tests/generate-roleplay-scenes.js:22`). Brief and checks never
  reach the reader (`tests/gemma-qualitative-evaluation.mjs:41`). Second set `holdout: true` (`:23`), declared "used" once
  evaluated.
- **Bounded scoring** for inferred magnitudes: `playerChangeBetween HP -4 -1`, `npcChangeBetween` (`gemma-tracker-score.mjs:74-81`),
  intervals including 0 for ambiguous effects, `BelowCapacity` for partial recovery, regex for condition text. Scene
  catalogue deliberately covers *reasonable non-changes* (ordinary pause, passing joke), attempted-not-achieved claims
  (player narrates a kiss/victory), costs paid on failure, absent characters mentioned in context.
- **Freeze/run split**: `eval-gemma-tracker.js --freeze <label>` hashes prompts, scenes, schema, settings; `--run` executes
  against an endpoint; reports separate retrospective rescoring (fixture corrections) from new inference.
- **JSON repair** (`src/core/utils-format.js`): strict parse first (`:177`); one adjacent transposed-closer swap (`:64`,
  string/escape aware); trailing-comma strip; close open strings/structures (`:98`); truncation recovery by cutting back to the
  last `,`/`{`/`[` up to 10 times (`:144`, silently drops trailing fields); bare-key quoting. Field-level "keep usable
  updates" = per-field sanitizer that refuses a bad reading, keeps the held value and logs a warning
  (`src/tracker/numeric-stat-bounds.js` `constrainNumericStat`, `status-stat-values.js:112`). `strictJsonValid` and
  `parseRecovered` are scored separately so repair never earns the validity check.
- **Fresh vs accounted history** in the reader prompt: `EARLIER MESSAGES (already reflected in state)` / `FRESH PLAYER TURN
  (not yet reflected in state)` / `LATEST ASSISTANT REPLY` (`src/prompts/prompt-texts-reader.js:119-127`). Measured 282→286/298
  on identical fixtures (modest, stated as such).
- **Per-speaker styling**: injected instruction `Name: "dialogue"` (`src/core/constants-prompts.js:21`,
  `src/prompts/dialogue-format.js`), label regex (`src/chat/dialogue-line.js:1`), DOM decoration of `.mes_text` with portrait +
  colour; revision key = chat, group, char, mesid, swipe_id, mes, display_text (`src/chat/dialogue-presentation.js:10-17`).
- **Phrase ban**: on demand, a model scans the last N assistant replies for phrases repeated ≥3 times (≤15) plus fake speaker
  labels; user ticks; approved list goes out as `{{banned "phrase"}}` macros (TC) or a "PHRASES TO AVOID" prompt block
  (`src/prompts/banlist.js:52-96,107`). Install-wide, not per character.

## For per-character polish

Castward has **no post-processing rewrite pass**. Relevant mechanisms are pre-generation only:
- Phrase ban (`banlist.js`): model-mined repeated phrases, user-approved, applied every loud generation (request-scoped
  macro, so swipes/regens get it too; nothing to undo). Cannot add facts or player actions (it only removes options). Cost:
  one reader call per manual scan. Config: one install-wide list — **no per-character config**.
- Narrator card PHI "Ensure each NPC feels distinct" (`examples/narrator.json`) — prompt only.
- `[[NPC_VOICE description=…]]` cue for TTS: model-written, stripped from display; audio only.

What SO can take for per-member polish:
- We already mine repetition in code (`src/stagecraft/repetition.ts:65`, N6; author readout `snapshotBuilder.ts:348`; judge
  warden note `repetitionCheck`, 13 §N6) but over **all** non-user replies mixed (`replyTexts`, `repetition.ts:80`). Per-member
  variant: group `replyTexts` by `name`, mine each member's window, feed that member's hot phrases into **that member's
  private block** only when drafted (`onMemberDrafted` path), as "avoid" lines. Deterministic, no model call, rides the
  existing per-member injection; rollback-neutral (derived from the chat at read time). Effort S–M.
- Authored per-member lexicon/avoid lists (roster field) are the static half of the owner's idea; mined phrases are the
  dynamic half. Both are prompt requests, not bans — see the host fact below for why a sampler ban is not available on
  our route.
- Safety vs Recast-style rewrite: an avoid list never edits a rendered reply, so no thought-leak/streaming/swipe
  interaction (69 K6/K8 rows stay relevant only for an actual rewrite pass).

## Host facts

- **`{{banned "phrase"}}` is a token ban, not a phrase ban, on our backend.** The macro handler strips the quotes
  (`public/scripts/macros/definitions/core-macros.js:438-446`); `getCustomTokenBans` treats an unquoted line as text to
  tokenize and bans every token of it (`public/scripts/textgen-settings.js:466-492`); for `LLAMACPP` the tokens become
  `logit_bias [id,false]` (`:1809-1816`), and `banned_strings` is not forwarded in the llama.cpp params at all. So banning
  "a shiver ran down" bans " a", " shiver", … individually. Castward's "The model cannot emit these" (`banlist.js:46`) is
  wrong and harmful on llama.cpp. SO does not use bans today (grep `banned` in `src/`: none) — keep it that way; any
  per-member avoid list must be prompt-side.
- Castward notes Gemini structured output rejects `additionalProperties` and returns `{}` silently
  (`status-extractor-schema.js` header comment). Not relevant to us (no json_schema route; V49 SKIP).
- `ConnectionManagerRequestService.sendRequest(..., {json_schema:{name,value,strict}})` and
  `generateRawData({jsonSchema})` return already-parsed objects (`status-extractor-request.js:25-27,85-90`). Unverified here;
  only matters if V49 is ever revisited.

## Not worth taking

- JSON repair: our read contract is line-based with per-line rejection reasons (`src/extraction/parse.ts:112-216`), which
  already "keeps usable fields"; truncation-by-comma would silently drop fields.
- Constrained decoding (json_schema): their own data shows +0 accuracy vs unconstrained (587 vs 588/609). Confirms 61 V49 SKIP.
- Absolute vs delta readings: their absolute contract lost numeric accuracy (73–76 vs 81/96); we already use absolute +
  `step_rule` (61 V52 SKIP stands).
- XP/levels/loot/level-up rewards: plan 18 rules out generic XP (`18-quests-and-game-layer.md:36,219`).
- Swappable genre Systems / generate-from-premise: our stories are authored; wizard covers premise → story.
- Places tree with reader-proposed containment: 65 owns the here-now card; authored locations suffice.
- Per-NPC TTS voices / designed voices: 61 R40 SKIP.
- Per-line expression sprites: present (`src/sprites/segment.ts`, `passageClick.ts`).
- NPC reuse across chats with carryover: 45 New Game+ covers it with a stricter projection.
- Risk-tiered "ask before applying" for reads: SO reads are evidence-gated and roll back by message; no player chore needed.
