## What it is

Per-message JSON trackers (scene: time, place, weather, present characters' outfit/state) generated by a side model through a connection
profile, rendered under the message, optionally embedded into later generations. "Modules" = several trackers per chat, each with its own
schema/prompt/connection; modules can chain earlier modules' history (Plot Log → Plot Steer suggests the next beat, injected). Structured
output modes: native schema, JSON, XML, TOON; optional grammar enforcement with a Test button.

## How it works (worth knowing)

- Dry-run World Info scan for the side pass (`world-info-scan.ts:165-205`): calls `getWorldInfoPrompt(chat, max, isDryRun=true)`, pads
  the window with empty strings to the real chat length so entry `delay` sees it (`:175`), restricts lore by emptying the host arrays in
  a `WORLDINFO_ENTRIES_LOADED` listener (`:104-111`), captures activated entries from `WORLDINFO_SCAN_DONE`, waits up to 5 s for an
  in-flight generation first (`:92-101`, `:181`). Readme admits: a dry scan clears entries other extensions force-activated.
- Per-part regeneration (`tracker-parts.ts:188-237`, `:263-320`): rebuild one top-level field, one array item (by `x-ztracker-idKey`,
  default `name`), or one field inside an item, merging the result into the stored tracker. Cleanup marks targets "pending" instead of
  holding a wrong value (`tracker-cleanup.ts:52-185`).
- Per-run message badge: module, phase (preparing / waiting for the model), part N/M, ticking `m:ss`, cancel x (CHANGELOG 2.22.0).
- "World Info used" record per tracker: which entries reached the side prompt and why, titles/keys only, never content (CHANGELOG 2.20.0).
- Schema dialect lint warns about wrappers that cost tokens without meaning (one-field objects, `maxItems: 1` arrays) (readme §schema).

## Host facts

- Dry `getWorldInfoPrompt(..., isDryRun=true)` still emits `WORLDINFO_ENTRIES_LOADED` and `WORLDINFO_SCAN_DONE`; only
  `WORLD_INFO_ACTIVATED` and timed-effect writes are skipped (verified: ST `world-info.js:4604`, `:5175`, `:683`, `:731`, `:748`, `:900`).
  Sticky/cooldown are not applied to a dry scan; `delay` is evaluated against the chat array length passed in (hence their padding).
- The `WORLDINFO_SCAN_DONE` payload carries `state.current` (1 initial, 2 recursion, 3 min-activations) and `new.successful`
  (`world-info-scan.ts:56-58`, `:130-140`); SO's `services/stHost/worldInfoScanDone.ts:13-16` documents the same shape.

## Not worth taking

- Pre-reply tracker hold (outgoing auto mode): adds a model call before every reply; SO reads off-path by design.
- Plot Steer (side model suggests the next beat, injected): SO living director + suggestions cover it with guards.
- TOON/XML structured modes, grammar Test button: SO reads use a line contract, no JSON schema sent (grep finds no `json_schema`/grammar).
- Schema lint for token-wasting wrappers: SO has no user schemas.
- Per-character auto-mode overrides: SO's cast is the story's roster.
