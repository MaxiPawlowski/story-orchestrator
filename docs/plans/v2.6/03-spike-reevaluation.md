**Status: APPROVED 2026-09-30; SP7, SP2, SP3, SP5, SP9 run 2026-10-01, SP5 C1–C5, SP8, SP3.b Phase B and SP4 run 2026-10-01/02 (gate records below); SP6, SP1, SP10 not yet.** SP7 goes first (W17). The spike legs are measurements and run in
plan 15 Part B on the €20 RunPod budget (W28); any rater leg is recorded for the user's review (overview rule 11).

v2.5 plan 09 ran all ten spikes on toy stories: two members, one room and a dozen lorebook entries. Several stalled
for lack of data, and several failed for reasons the data caused. `adolion-campaign/lab/` rebuilds each spike's
measurement data from Adolion in the plugin's own fixture formats. None of it has run live. This plan re-runs every
spike on that data and makes the worth review (include / defer / drop) that v2.5 never did.

## Rules

- v2.5 `09-research-spikes.md` rules apply unchanged. The exceptions are overview rules 3 and 4: toy-data verdicts
  are history, and conditions are restated before a re-run.
- **Step 0 per spike:** write `v2.6/03-spN-restated.md`. It gives the conditions, bars, data (a lab path at a campaign
  commit), arms and controls. Commit it before any run. A bar changes only with a stated reason, and never after a run.
- **Toy regression tier stays.** Each spike's jest legs keep running on toy data. Adolion adds the live legs and any
  offline leg the lab supports.
- **The worth review is written into the spike's report** as `## Worth review (v2.6)`. It gives the measured value,
  the cost (bundle bytes, coordinator lines, prompt tokens, latency), the player/author surface, and the call:
  include (`SPN.b` in v2.6 04), defer (a v2.7 seed with the reason), or drop (code removed in this plan).
- **Lab data is checked first.** Run `python scripts/check_lab.py` in the campaign at the pinned commit. A failing dir
  is regenerated by its named generator before its spike runs.

## Order

The order is set by cost, then by what unblocks others:
0. **SP7 first** (overview W17): Adolion's 7 rolls do nothing on a prod build until `SP7.b` lands.
1. **Cheap, deterministic or short:** SP2, SP5, SP3 (offline plus director answers), then SP9.
2. **Model-heavy:** SP8, then SP4.
3. **Long:** SP6. Its K3/K4 journey is the longest run in the plan. Batch it overnight on its own lane.
4. **SP1 and SP10 last:** SP1 waits on plan 10's sessions for S4, and SP10 waits on v2.6 02's data.

## Code

**The failed spike code stays behind its flag** until its Adolion verdict. This covers SP4, SP8 and SP9. v2.5's
"remove before freeze" is satisfied by the Adolion verdict landing before plan 10's freeze. The SP10 fold is restored behind its flag only for the Q3 re-run on D3 (W3), and it is removed again on FAIL.
