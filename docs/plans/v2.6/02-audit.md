Two facts shape the whole table. Each is cited, not assumed.

- **No Adolion row has ever run live.** In the lab, `lab/README.md:12` says "Nothing here has run on a live lane yet", and each lab README says the same for its own legs. For the campaign, `TESTING.md:10` says "Nothing has run in a live SillyTavern yet". The lab's `live-*.json` files are fixtures to run, not run records. No `records/` directory and no chat transcript from real play exist anywhere in the campaign. The only real-play trace is one quoted misread in `tests/commit-cases.json` (the 2026-09-29 playtest).
- **The campaign's routes are state recipes, not dialogue.** Each `tests/routes-*.json` step is `{set: {quality: value}, expect: <checkpoint>}`, occasionally `{activate}`. It carries no player line and no reply. That comes to 58 routes, and the saga's 4 are generated by `tests/make_saga_routes.py` (109, 111, 58 and 106 steps). A scripted-route player therefore needs a player line written for every step before D1 can run (see §D1 below).

Coverage key:
- **yes**: the data exists at the pin and fits the measurement as the plan states it.
- **partial**: data exists, but the plan or the lab README names a gap.
- **no**: nothing exists.

## D1: size and layout (the audit's sizing; nothing played)

**Scored set (scripted routes).**
- **Source:** one route per story, taken from `tests/routes-*.json`:
  - `adolion-adventurer`: 20-step route #2;
  - `adolion-academy`: all 6 routes, 44 gates;
  - the Saga: the 111-step route.
- **Player lines:** each step needs 2–4 player lines that make its `set` values true in play. That is about 3 × 175 steps, roughly **525 lines**. They are written per step and **labelled generated** when a model writes them (plan 02 §Rules).
- **Where the lines live:** in the campaign beside the routes, as `tests/lines-<story>.json` keyed by route name and step index, with a `check.py` that fails when a route step has no lines or a line names a checkpoint that is not reachable.
- **Turns:** at ~3 turns per step that is about 525 turns across the three stories, short of the ≥ 300 per story target for `adolion-academy` (44 steps ≈ 130 turns). Academy therefore runs its 6 routes twice, with different line picks.
- **Lane time:** at ~100 turns an hour (`02-data-gaps.md` §Rules), about 9–10 lane-hours with the ×2 academy pass. That matches the plan's estimate.

**LLM-player set.** One run per story. It is labelled and never pooled with the scored set (`02-data-gaps.md` §Resolved).

**Layout** (the resolved answer: text lives in the campaign repo):

```
adolion-campaign/corpora/<story>/<run-id>/
  run.json           run header (so-run-header capture): bundle sha, campaign commit, lane, profiles, judge uses
  chat.jsonl         the chat as ST saved it
  journal.jsonl      so-journal follow
  audits.jsonl       extraction audits (inside journal follow)
  payloads.jsonl     st-payload arm --persist
  inventory.json     adolion-fresh inventory the run started from
  MANIFEST.sha256    sha256 of every file above
```

**What the plugin repo holds.** Only fixtures derived from a run (D6 extractor triples, D7 pairs), each naming the `<story>/<run-id>` it came from.

**Starting a run.** Every run starts from `adolion-fresh seed <lane>` (overview rule 14).

**Which lines first.** The line lists are the first D1 task, and the cheapest. They need no lane.
