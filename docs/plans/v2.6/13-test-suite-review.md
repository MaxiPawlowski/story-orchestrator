## Method

### R1 Classify every asset (a table, `v2.6/13-inventory.md`, generated by a script, not by hand)

Columns:
- tier: pure unit / Storybook / harness / no-LLM scenario / LLM scenario / journey check / live suite / spike fixture /
  record;
- runtime, and whether it needs an LLM;
- what it guards: a named invariant (`architecture.md`), a named historical defect (gotchas or a fix commit), a feature
  contract, or nothing named;
- whether it has ever failed on master (a `git log` search of its file against fix commits);
- duplicates: the same assertion at a higher or lower tier;
- vacuity: an assertion that holds on an empty or unrelated input (checked by running it against a blank fixture).

### R2 Measure quality instead of counting

- **Mutation score on the pure modules** (`engine/`, `memory/`, `extraction/` non-host, `judge/` policy, `talk/`,
  `pacing/`), sampled with a mutation tool such as Stryker. The suite's worth is the share of mutants it kills, not how
  many tests there are. The baseline is recorded before pruning.
- **Defect replay:** re-introduce each historical defect that has a fix commit and a gotcha entry, for example:
  - the NaN rollback;
  - the unowned `ExpansionCoordinator.generate`;
  - the `LoreSelector` stale cache;
  - the save-binds-late race;
  - `Math.max(0, NaN)`;
  - the empty private block;
  - the patch spread erasing a write.

  Each becomes a mutant patch in `test/findings/defect-replay/`. The suite has to fail on every one. This is the gate
  that makes pruning safe.

### R3 Decide per asset

For each asset, one call:
- **keep:** guards something named, is not a duplicate, and fails on a mutant;
- **merge:** folded into a parameterised case or a single journey check;
- **demote:** an LLM check becomes a no-LLM or pure check when the behaviour is deterministic;
- **retire:** duplicate, vacuous, or guarding nothing named. It is deleted from `test/` and stays reachable in git
  history.

Rules:
- Nothing that guards a named invariant or defect is retired, unless another kept asset provably covers it (defect
  replay).
- A vacuous assertion is fixed or retired, never kept as coverage.
- LLM-tier checks are the most expensive, so each must justify itself by guarding something no cheaper tier can see
  (model behaviour, real generation timing).

### R4 Records

Keep only the records that a gate record or attestation cites (the release attestation test already reads citations).
Move the rest to `C:\dev\backups\story-orchestrator\records\` outside the repo, with a manifest. Target: `test/` under
10 MB.

### R5 The final LLM suite (the output plan 10 runs)

A named, fixed list:
- the journeys and checks that survive R3;
- the live scenarios that survive R3;
- the carry-over rows (01);
- the integration runs (09);
- the recommended-config rows (05, 11, 12);
- the kept spike rows (03).

Each item carries a lane-time estimate, and the list states its total. **Budget: the full suite ×2 fits in 2 nights of
lanes on the current pod.** When it does not fit, items are merged or demoted until it does, and the cut is stated.

## Budget rules every v2.6 plan follows (overview rule 17)

1. A new test names what it guards: an invariant, a defect, or a contract clause.
2. A new test at the LLM tier states why no cheaper tier can see the behaviour.
3. A new test is shown to fail once (a mutant or the pre-fix code) before it counts. The v2.3 "a guard test that passes
   with the guard removed proves nothing" rule, made general.
4. One-shot measurement fixtures (spike legs, calibrations) live under `test/measurements/<plan>/` and are not part of
   the regression suite, unless R3 keeps them.

## Gates

- **R1:** the inventory script's output is committed.
- **R2:** the mutation baseline is recorded, and every defect-replay mutant is killed **before** pruning.
- **R3:** after pruning, the mutation score is not lower than the baseline, beyond the change a stated retire explains.
  Every defect-replay mutant is still killed.
- **R4:** `test/` is under 10 MB and every cited record resolves (`test:release`).
- **R5:** the suite list is committed with its lane-time total.
- **Overall gates at the end** (overview rule 16).

## Unresolved questions

- The mutation tool, and how far to sample (the full pure tier may be slow on this box). Decided at R2 by a timing probe,
  not by the user.

### R2: the tool decision (the plan's unresolved question)

- **Custom runner, not Stryker.** Stryker is not installed, `node_modules` is one junction shared by every parallel agent,
  and the jest setup (ts-jest, `diagnostics: false`, path aliases, the findings reporter) would need a Stryker jest-runner
  config. `scripts/mutate.mjs` (2026-09-20) was the precedent: prove the mutant landed, then run the tests.
- **Timing probe:** one `--findRelatedTests` run costs 14–240 s (a pure file can pull 40–120 related suites). With six
  workers the effective rate was ~20 s per mutant, so the full population (4 469 mutants in 111 pure files) is ~25 h.
  **Sample: 200, stratified by module dir, seed 20260930.** `--bail` exits before jest writes its JSON, so a bailed run is
  read from its stderr summary (`classifyRun`).
- **Baseline: 71.9 %** (143 killed / 199 scored, 1 crash; engine 69.1 %, memory 76.2 %, extraction 75.6 %, judge 68.5 %,
  talk 2/3, pacing 3/4). The sample was drawn on the tree before plans 12 and 05 merged; the same `--seed --sample` re-run
  is the comparison point. The 56 survivors are listed in the JSON; most are `if (…) → if (false)` and `cond ? → true ?`
  in `engine/validate/*` diagnostics and `judge/*Calibration` measurement code.

### R2: what the defect replay found

- `empty-private-block-ledger` **survived every related suite**: the ledger half of the v2.3 plan 05 fix
  (`applyLedger` → `updateInjection()`) had no test. Added one to `memoryInjectionRefresh.review.test.ts`; killed.
- `expansion-generate-unowned`: removing the check after `generateReviewedBeats` survived, because the ownership tests
  reach only the throwing path. The spec replays the historical defect instead (a run that never lapses, as the review
  test's own negative control does); killed. The non-throwing path's check is still reached by no test (recorded, not fixed).
- Six first-draft specs named the wrong test file; `defect-replay.mjs --discover` (runs every related test under the
  mutant and names the files that failed) found the killers.

- Measurement fixtures were demoted in place, not moved to `test/measurements/<plan>/`: plan 03 re-runs them and the
  docs cite their paths. New measurements go to `test/measurements/` (plan 05 already does).
- The inventory counts differ from the draft's table (354 jest files / 4 723 tests; 15 journeys / 144 checks, at merge of master 44921b8c): the
