Add fixtures with only `roster[].polish`, no drive/motive/life, epistemic capability off, and no inner beat; verify per-speaker repetition refreshes between members in one group round. Remove the competing all-callers alternative from Unresolved questions.

## 03 — Per-character reply polish

- **P0 — Proposed auto polish degrades thought carry.** The Reasoning section explicitly hides polished replies' reasoning from carry and harvest while calling inner voice “untouched.” This is an actual functional reduction: `withoutStaleReasoning` removes reasoning after a text revision (`src/runtime/reasoningRevision.ts:22`), and both carry and harvest consume that filtered input (`src/runtime/innerBeatHost.ts:36`; `src/runtime/coordinators/extractionCoordinator.ts:471`). **Fix:** label the reduction P0 in Recommendation, S3 and Decisions. State: “S3 cannot land with this reduction without explicit owner approval. S0/shadow work may proceed; automatic writes require preserved carry with validated provenance or an approved exception.” Do not bypass stale-reasoning checks or relabel old thoughts as evidence for changed meaning.
- **P1 — The adversarial gate contradicts the guard design.** Guards require 100% refusal of semantic negatives, then explicitly allow those same negatives to pass for later rating. Equal polarity counts do not distinguish “knew” from “guessed”; the current writer supplies no semantic safeguard (`src/services/stHost/chatMessages.ts:18`). **Fix:** separate structural refusal fixtures from semantic challenge fixtures. Require 100% refusal for explicit structural violations; score guard-passing semantic changes independently and retain the existing zero-change acceptance floor. Delete the assertion that the entire semantic set is deterministically refused. Freeze both fixture sets before inference.
- **P1 — S2 cannot measure all declared acceptance properties.** Shadow never changes the transcript, so it cannot establish accepted-write latency, downstream consumer behavior, full-round latency or next-speaker use of revised text. **Fix:** split evidence into shadow faithfulness/preference and isolated-lane S3 integration measurements. Require the latter before merging S2+S3, retaining the 100-reply denominator, 50% group coverage and all latency floors. Replace “Each builds and gates alone” with the actual S0/S1 independent and S2+S3 joint merge contract.
- **P2 — Deferred work is presented as an implementation slice.** S4 includes LanguageTool, although triage V07 defers it pending observed grammatical damage. **Fix:** move LanguageTool into a “Deferred to v3.0” paragraph with that reopening condition. Keep optional C+ and dialogue work explicitly dependent on their own decisions, outside v1 acceptance.

## 04 — Reactive character cues

- **P1 — Topic raises are neither uniquely consumed nor reliably addressed.** “At most +1 per boundary” permits several replies to consume the same player line repeatedly, including the draft-time preview after a prior increment. `addressedAmong` is a mention heuristic, not proof of address (`src/talk/rules.ts:58`, `:95`). **Fix:** define a raise occurrence by chat, player message, revision, member and topic; persist its consumed marker with rollback coverage. Draft preview and boundary apply must use that same occurrence exactly once. Require a conservative direct-address rule; mere third-person mentions abstain. Test multi-member rounds, regenerations, continues, edits, OOC and quoted mentions. Slice F must produce addressed evidence rather than an unqualified extraction bool.
- **P1 — The landed latch lacks its required input.** Slice A requires an earlier offer, but the latch view contains no offer ledger (`src/engine/engine.ts:516`); passing the ledger to `deriveLife` in slice B does not supply it to latch writers. **Fix:** specify an injected, immutable offered-evidence input to the pure cue latch writer, including message/revision identity. Keep runtime access outside `engine/`, and pin whether an offer rendered during this boundary is eligible. Test never-offered, filtered-out, thought-only and invalidated offers. Do not read extras from an engine import.
- **P1 — Authored changes leave stale cue state.** No story-update semantics are specified for `cue_` latches, topic counters or offer rows. Existing roster edits are universally compatible (`src/engine/storyDiff.ts:315`), which would preserve old progress under changed gates or tiers. **Fix:** add a story-update slice: wording corrections retain state; changed eligibility/tier identity resets the affected keys and offer records; removal prunes them. Apply the same pruning to retained engine history, then test update → rollback → reopen.

## 05 — Evidenced story threads

- **P1 — The proposed base cannot satisfy retained-history replay.** Slice B explicitly clears partials when the engine can still restore a target before the pattern base. This contradicts P4. A boundary-only base also cannot locate truncation inside one boundary's refs: `appendRefs` slices by individual ref (`src/runtime/recapPort.ts:48`), while engine history retains boundary snapshots (`src/engine/engine.ts:301`). **Fix:** replace the empty-reset fallback with matcher snapshots/deltas retained through the engine rollback floor. Use an exact ref cursor, including index within boundary, and a documented inclusive/exclusive base convention. Test more than 600 refs within 200 boundaries, including a truncation inside one boundary. Never claim equality for an unreconstructable cut.
- **P1 — Recap availability is assumed.** Ordering after recap does not ensure refs were produced: its port returns when the lazy kit is absent (`src/runtime/recapPort.ts:67`). **Fix:** make matcher activation await the required kit before the first relevant commit, or consume the same finished-boundary derivation through an explicit ready reader contract. Add a cold-load fixture proving the first event is retained. Keep one ref derivation and no second event database.
- **P1 — Eviction can re-enable a once-only pattern.** `completed` is capped at 200, but no durable once-completed state is specified. **Fix:** keep compact once-completion tombstones after display/evidence eviction, with rollback metadata retained through the engine floor. Specify removed/re-added and edited-pattern identities. Test more than 200 completions and later occurrences of an evicted once-only pattern.
- **P2 — Matcher branching and ordering are underspecified.** “Advance each partial” can discard a valid later alternative; cancellation ordering can let a forbidden completion win. **Fix:** state that each ref advances at most one step per branch, preserves the waiting branch, and spawns distinct advanced branches before deterministic deduplication/capping. Define `unless` endpoint behavior and cancellation precedence. Add overlapping A–B–B–C, same-boundary and bound-variable negatives before implementing Slice B.

## 06 — Grounded next actions and stakes

Add a conditional-promise negative and a secret-bearing quote fixture. Do not infer public eligibility from “the player's own words.”

Test the same offer before and after its visibility/disclosure gates. Keep unavailable reasons authored and never derive offers from hidden routes.

## 07 — Delayed story echoes

- **P1 — Rescanning cannot guarantee recovery of every occurrence.** S2 claims lazy loading or retention never drops a schedule, but boundary logs retain only 200 entries and check records only 100 (`src/engine/engine.ts:292`; `src/runtime/storyCheckDraws.ts:11`). **Fix:** await the echo kit before commits in an echo-bearing story and schedule from each finished boundary plus that boundary's check records. Permit catch-up only over a verified contiguous retained range; report gaps explicitly. For catch-up, calculate due time from each source entry's recorded `after` values, never today's `story_time`.
- **P1 — Closed-event eviction loses once-only identity.** The cap permits closed events below the history floor to disappear, but “one open or landed event” neither remembers evicted landings nor defines whether cancelled/expired events may reschedule. **Fix:** retain compact settled identities after detail eviction and state the terminal-state policy. For the recommended once-per-chat mode, all terminal outcomes consume that echo until rollback reverses them. Test a looping source after eviction and cancellation before a later source occurrence.
- **P2 — Expiry and capacity precedence need an exact rule.** A jump can cross both due and expiry, and a valid echo can wait behind the two-landing cap. **Fix:** specify cancel → expiry → due/revalidate → bounded landing, with explicit inclusive endpoints. Capacity waiting must not reset due or expiry. Freeze these expectations in the 40-schedule corpus; retain the existing floors.

## 08 — Player observations

- **P1 — Writer order does not provide same-pass latch visibility.** Slice 1 promises that placing observations after codex lets them read new codex latches immediately. The engine instead creates one copied values view for all writers (`src/engine/engine.ts:516`; `src/engine/blackboard.ts:82`). The second pass runs only after a transition (`src/engine/engine.ts:273`). **Fix:** replace that promise with explicit frozen-pass semantics: observations use values at pass entry; a newly latched dependency is visible only on a subsequent pass. Add no-transition and transition fixtures to O1. If same-pass visibility is required, make changing the shared latch contract a separate prerequisite with existing-writer regression tests.
- **P1 — Whole-payload invariance contradicts discovery-scope additions.** Slice 1 adds previously unscoped gate qualities to extraction requests, while O3 and the privacy section require identical requests on/off. **Fix:** narrow the assertion to “no observation prose, private passive results or observation records enter model requests”; explicitly allow and declare budgeted discovery-scope hunks. Keep all original triage floors, including zero secrets and imposed mental states.
- **P2 — The passive resolver call does not match its type.** `resolveCheck` accepts `StoryCheck`, including required `id`, `quality` and `narrate` (`src/engine/storyChecks.ts:37`; `src/engine/gameSchema.ts:116`); the proposed passive object deliberately lacks those fields. **Fix:** extract a pure roll/modifier resolver used by both checks and observations, with existing check-result regression fixtures. Do not create fake writable qualities or cast the passive object to `StoryCheck`.

## 09 — Effective feature Help

Retain control-specific predicates and provenance for creation, accept modes and other subfeatures. Represent Story memory's reading and injection states separately rather than treating `reading` as its complete state. All predicates must read the existing resolved controls, not settings again.
- **P1 — Check association and viewer filtering are not available as described.** `CheckResult` contains a check id, not `feature` (`src/runtime/checks.ts:66`, `:169`), and `forViewer` is private (`src/runtime/repair.ts:100`). The “only 7 checks” claim also misses sprite, image and route checks (`src/runtime/checksSprites.ts:10`; `src/runtime/checksSetup.ts:173`). **Fix:** consume the existing viewer-safe `setupFindings`, join result ids to `CHECKS` for feature ownership, and remove the seven-check restriction. Export a shared viewer helper only if needed; add no readiness registry.
- **P2 — No-story routing and the 24 cases are incomplete.** The plan retains Story → Features links despite noting they are disabled without a story (`src/components/workspace/FeaturePages.tsx:103`). Folding no-story into install-default also fails to exercise both contexts. **Fix:** route mapped no-story Help links to Orchestrator → Defaults. Freeze 24 explicit cases containing distinct loaded-story/default and no-story cases, plus master-off, story/chat overrides, subordinate-off and route outage. Keep the 24-case and all-links floors unchanged; remove the proposed Cartesian construction if necessary.
