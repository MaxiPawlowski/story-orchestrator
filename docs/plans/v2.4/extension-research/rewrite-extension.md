# Rewrite Extension — v2.4 review

author: asd / SplitClover · repo: https://github.com/splitclover/rewrite-extension · commit `019f5f5` (2025-09-02, README: "no longer maintained") · 123 upvotes / 235 msgs · source available: **y** (`source/index.js` 1472 lines, `manifest.json` v1.3.0, settings html, css)

## What it is
Select text inside ONE rendered message → floating context menu (Rewrite / Shorten / Expand / Custom / Delete) → LLM rewrites only that span, streamed into the DOM, spliced into `chat[id].mes`, chat saved. In-memory 15-step undo per message. Macros `{{rewrite}}` (span), `{{targetmessage}}` (whole message), `{{rewritecount}}` (word count) are substituted into a chosen CC preset or a text-completion prompt template. A utility, not a narrative system — relevance to SO is indirect: it is a **third-party writer of chat text that SO cannot see**, and a few of its techniques map onto our passes.

## How it works
- **Trigger/UI**: `document` `selectionchange` → 50 ms → checks start+end share one `.mes_text` → fixed-position `ul.ctx-menu` appended to body (`source/index.js:282`, `:315-351`, `:461-491`). Repositions on `#chat` scroll (`:287`). Hijacks `#mes_stop` click for abort (`:289`, `:293-307`).
- **Span mapping**: DOM range offsets (TreeWalker over text nodes, `:681-695`) mapped back to raw markdown via a char-alignment of `messageFormatting(mes)` stripped to text (`:625-673`, `:698-717`), with a heuristic that widens the span over abutting `*`/`**` (`:719-743`). Result: `{fullMessage, selectedRawText, rawStartOffset, rawEndOffset}`.
- **LLM call, three routes** (`:784-800`):
  1. CC "full preset": fetch `/api/settings/get`, find preset by name in `openai_setting_names`, `JSON.parse(openai_settings[i])`, **`Object.assign(oai_settings, preset)`** globally (`:833-871`), then `getContext().generate('normal', {}, true)` (dry run) and awaits `CHAT_COMPLETION_PROMPT_READY` to harvest the fully assembled chat array (`:874-879`); appends custom instructions to the last user message (`:882-919`); substitutes macros in every message (`:921-939`); sends via `sendOpenAIRequest('normal', chat, signal)` (`:958`); restores `oai_settings` in `finally` (`:963-968`).
  2. CC "simplified": one system message from a template (`:1019-1088`).
  3. Text completion: `getTextGenGenerationData`/`getNovelGenerationData`/Horde (Horde non-custom also dry-runs `generate` and grabs `GENERATE_AFTER_DATA`, `:1220-1225`), streaming via `generateTextGenWithStreaming`, else `generateRaw` (`:1246-1263`).
- **Response budget**: `max_tokens = tokens(span) × mult` (defaults 1.05 / 0.8 / 1.5) or `+ add`, min 1 (`:1332-1383`, applied `:866-868`, `:1179-1196`).
- **Post-processing**: strip configured prefix/suffix (`"`), then optionally run the built-in regex engine `getRegexedString(text, regex_placement.AI_OUTPUT)` (`:1430-1451`).
- **Write**: splice at raw offsets `full.slice(0,start)+new+full.slice(end)` (`:1454-1457`), write `chat[id].mes` and `swipes[swipeId]`, `await context.saveChat()` (`:1462-1471`). Delete does the same with an empty span and re-renders via `messageFormatting` (`:430-453`).
- **Persistence**: settings in `extension_settings["rewrite-extension"]` (`:131-177`). Undo history is **in memory only** (`:77`, `:757-772`), cleared on `CHAT_CHANGED` (`:264-267`), pruned for a message on `MESSAGE_EDITED` (`:269-271`, `:551-557`).
- **Mutation handling**: it **emits no event** for its own writes — no `MESSAGE_EDITED`/`MESSAGE_UPDATED` (`:442-452`, `:1399-1420`, `:1462-1471`). Swipes: writes the current swipe only.
- **Generating state**: `deactivateSendButtons()` before the request, `activateSendButtons()` after (`:952`, `:967`, `:1122`, `:1329`).

## Overlap with Story Orchestrator
- Span-level text surgery with review: our WI curator `[patch]` op (`first || last` anchors) is the same idea done safer (anchored, reviewed, boundary-applied, revertible) — `src/stagecraft/proposal.ts:30` `applyCuratorPatch`. But our `[rewrite]` op is weaker than theirs (see idea 2).
- Side LLM calls: we route every pass through one Connection Manager profile, message-array + instruct (`src/services/stHost/connectionProfiles.ts:43`) and never touch global generation settings — strictly better than their `oai_settings` swap.
- Undo: our rollback is cross-store and persisted (`src/runtime/rollback.ts:35`), theirs is a volatile per-message stack. Nothing to take.
- Mutation awareness: we subscribe to `MESSAGE_SWIPED/EDITED/DELETED/UPDATED` (`src/runtime/turnBridge.ts:54-57`) — which is exactly what this extension bypasses. **We are worse here: blind to in-place edits by any extension written like this one.**
- Prompt preview: our next-turn preview lists our own blocks (`src/runtime/nextTurn.ts:76`); they harvest the whole assembled prompt via dry run. Our harness already does this (`test/scenarios/effects-author-note-role.json`, `GENERATE_AFTER_COMBINE_PROMPTS` + `generate('normal',{},true)`), the product does not.

**1. Silent-edit drift detection.** What: at each committed boundary (and on hydrate), compare a fingerprint of messages the run has consumed, or re-run `evidenceInWindow` on each live memory entry's stored `evidence` against `chat[provenance.messageId].mes`; a mismatch is routed to the SAME path as `MESSAGE_EDITED` (`runRollback(messageId)`), so memory goes `source-removed` and the blackboard rewinds. Theirs: in-place `chat[id].mes =` + `saveChat()` with no event (`source/index.js:1462-1471`, `:442-452`, `:1399-1420`) — any user of this (123-upvote) extension edits text SO already extracted from, and SO never learns. Ours: rollback is event-driven only (`src/runtime/turnBridge.ts:54-57`); `source-removed` is set only by `dropByMessageId` (`src/memory/stores.ts:109`, `:115`); `MemoryEntry.evidence` is already stored (`src/memory/types.ts:138`) and `BoundaryLogEntry` records no text hash (`src/engine/engine.ts:39-48`); grep `messageHash|textHash` = 0 hits. Fit: keeps inv. 11 (rollback ≡ replay) only if drift reuses `runRollback`, not a parallel path; fingerprint in boundary context = blob bump + migration (inv. 13); detection must live in runtime (engine purity, inv. 1). Also covers edits made while SO was disabled or to the chat file on disk.

**2. Curator `[rewrite]` from a truncated view.** What: the curator prompt shows each entry's content cut to 400 chars (`src/stagecraft/prompt.ts:13`) but offers `[rewrite] … <the full replacement text>` (`:32`), capped at 600 chars (`src/stagecraft/types.ts:5`), applied as a whole-content replacement (`src/stagecraft/proposal.ts:53-56`). On an entry >400 chars the model replaces text it never saw → silent content loss, stopped only by human review (and not at all in `acceptMode: auto`). Theirs: always hands the model both the span and the whole target (`{{rewrite}}` + `{{targetmessage}}`, `source/index.js:927-936`) and splices at exact offsets, never replacing unseen text (`:1454-1457`). Fix options: refuse `[rewrite]` in `previewCuratorOp` when `entry.content.length > shown length`; or show full content for the (few) allowlisted entries; keep `[patch]` as the only op for long entries. Fit: pure `src/stagecraft/`, no invariant touched (inv. 6 strengthened).

**3. Input-proportional response budget.** What: compute `maxTokens` from the input the pass must reproduce/summarise instead of the flat default. Theirs: `tokens(span) × {1.05, 0.8, 1.5}` (`source/index.js:1332-1383`). Ours: `callExtractionModel` defaults to 512 (`src/extraction/client.ts:14`); canon regen (`src/runtime/coordinators/memoryCoordinator.ts:342-345`), curator (`stagecraftCoordinator.ts:147-150`) and short-term compaction (`extractionCoordinator.ts:327-330`) pass none. A truncated reply with a reasoning block strips to `""` (gotchas: unterminated block); a truncated canon/summary is silently shorter. Token counting seam exists (`src/services/stHost/tokenizer.ts:3`). Fit: none violated; cheap.

**4. Regex-aware extraction window.** What: optionally run the chat window through ST's regex engine with `isPrompt: true` (+ per-message `depth`) so extraction/evidence see what the main model saw (status-block strippers, hidden HTML, prompt-only rewrites). Theirs: calls `getRegexedString(text, regex_placement.AI_OUTPUT)` from an extension (`source/index.js:20`, `:1449-1451`). Ours: `readMessage` uses raw `entry.mes` (`src/extraction/chatWindow.ts:10`); grep `regex|getRegexedString` in `extraction/` + `stHost/` = 0. Fit: new `stHost/regex.ts` via `importSTModule` (inv. 2); evidence must be checked against the same transformed text (inv. 4); default off / install-wide (inv. 13). Value capped at 3: most RP regex is display-only (`markdownOnly`), which must NOT be applied.

**5. Author "assembled prompt" preview.** What: an author-view button that dry-runs `generate('normal', {}, true)` and shows the prompt ST would send (our blocks in situ, WI, AN, history cut), next to the existing block list. Theirs: `generate(…, true)` + `CHAT_COMPLETION_PROMPT_READY` (`source/index.js:874-879`) or `GENERATE_AFTER_DATA` (`:1220-1225`). Ours: `buildNextTurnPreview` composes registry + held blocks only (`src/runtime/nextTurn.ts:76`); harness already dry-runs (`test/scenarios/effects-author-note-role.json`). Caveats from host source: a dry run fires `GENERATION_STARTED` with `dryRun=true` (`script.js:4299`) and skips generate interceptors (`script.js:4561-4564`), so talk-control speaker choice is NOT reflected; group dry run takes its own branch (`script.js:4350+`). Fit: author-only (inv. 9); must not capture into the payload ring (see 6).

**6. Dry-run hygiene in our `GENERATION_STARTED` handler.** What: skip `capturePayload()` and `talkController.onGenerationStarted` when `args[2] === true`. ST's own Prompt Manager dry-runs on every panel refresh (`public/scripts/openai.js:709` `tryGenerate`), and extensions like this one dry-run on every rewrite (`source/index.js:877`). Ours: `src/runtime/index.ts:189` captures unconditionally (lore and warden already skip dry runs, `index.ts:156`, `stagecraftCoordinator.ts:458`); the ring dedups identical blocks (`src/runtime/journal.ts:186`), so a dry run can pre-empt the real capture's timestamp/reason and a journal `payload` event appears with no request behind it. Fit: trivial.

**7. Testing: `silentHostEdit` fault shape.** What: add a 10th shape to `test/findings/faultMatrix.json` (current shapes: afterHostWrite, backendUnavailable, beforeHostWrite, delayedError, delayedSuccess, duplicateCompletion, malformedResponse, persistFailure, worldSwitched — no silent-edit) and a scenario verb that does what this extension does: `ctx.chat[id].mes = …; await ctx.saveChat()` with no event. Gates idea 1; red today by construction.

**8. Studio text-field assist.** What: select text in an objective/AN/WI-entry textarea → Rewrite/Shorten/Expand/Custom via the memory profile, shown as a diff the author accepts into the draft through `mutations.ts`. Theirs: whole UI (`source/index.js:461-491`, custom popup `:353-367`). Ours: no hit for `rewrite|shorten|rephrase` in `src/studio/`; the wizard covers whole-story generation, not line editing. Fit: author-only, proposes into the draft (never auto-writes). Low value: nice-to-have, not narrative control.

**9. Anti-pattern for the CC preset-adapter seed.** Their preset switch is `Object.assign(oai_settings, preset)` on the live global, then a restore in `finally` (`source/index.js:852-871`, `:963-968`); the abort path restores from a stashed copy on the signal (`:298-300`); the simplified/text paths never restore anything they touched. Any concurrent generation (ours off-path, a group round) runs with the swapped preset; a crash between assign and restore leaves the user's preset mutated. Our `presetBackend()` refusal (`src/services/stHost/presets.ts:36-41`) is the right default; if the seed is built, go through ST's preset manager/`/preset` (awaits the switch, per gotchas) plus the owned-effect ledger's compare-and-set restore (`src/runtime/effectLedger.ts:112`), never a raw global patch. Readable fact for the adapter: `/api/settings/get` returns index-aligned `openai_setting_names` / `openai_settings` (JSON strings) (`src/endpoints/settings.js:236`, `:275`).

## Patterns to copy / anti-patterns to avoid
Copy:
- Give the model the span AND the whole context, then splice at exact offsets (`source/index.js:927-936`, `:1454-1457`) — the principle behind idea 2.
- Output budget derived from input size (`:1332-1383`).
- Capture the selection range before any await (`:382-384`) — same discipline as our RunToken-before-write.
Avoid:
- Writing `chat[id].mes` + `saveChat()` without emitting `MESSAGE_EDITED` (`:1462-1471`): breaks every extension that tracks edits. If SO ever writes message text, emit the event.
- Global settings monkey-patching for a side call (`:871`).
- `activateSendButtons()` from a side call (`:967`): it sets `is_send_press = false` (`script.js:7075-7076`), so if run during a real generation it clears ST's generating flag.
- Hijacking host controls (`#mes_stop` handler, `:289`).
- Volatile undo (lost on reload/chat switch, `:264-267`).

## ST host facts learned
- `GENERATION_STARTED` is emitted for dry runs with `dryRun` as 3rd arg (`script.js:4299`); generate interceptors do NOT run on a dry run (`script.js:4561-4564`); `GENERATE_AFTER_DATA(generate_data, dryRun)` fires then the dry run returns (`script.js:5318-5322`); `CHAT_COMPLETION_PROMPT_READY` carries `{chat, dryRun}` (`public/scripts/openai.js:1618-1619`). Used by them at `source/index.js:874-879`, `:1220-1224`.
- ST's Prompt Manager itself dry-runs `Generate('normal', {}, true)` (`public/scripts/openai.js:709`) — dry runs are routine, not exotic.
- Writing `chat[id].mes` + `ctx.saveChat()` emits no message event; ST emits `MESSAGE_EDITED` only from its edit UI (`script.js:8405`) and `MESSAGE_UPDATED` at `script.js:8337`, `:8431`. `ctx.saveChat` is `saveChatConditional` (`public/scripts/st-context.js:155`). **Contradiction-adjacent to our design**: TurnBridge assumes every text mutation arrives as an event.
- `deactivateSendButtons()` sets `document.body.dataset.generating = 'true'` and swaps in the stop button WITHOUT setting `is_send_press` (`script.js:7085-7089`); `isGenerating()` = `is_send_press || is_group_generating` (`script.js:604`). So during a third-party side call, ST's own `isGenerating()` (our `isHostGenerating`, `src/services/stHost/generation.ts:4`) reads idle while `body.dataset.generating` and the `#send_but` swap read generating. **Nuance to our gotcha** that `dataset.generating` is "ST's own generating flag (sturdier than the `#send_but` swap)": any extension can set it; it is not evidence of a `Generate()` in flight, and the harness `getGenerationState` (button swap) will report "generating" during a rewrite.
- `getRegexedString(raw, placement, {isPrompt, isMarkdown, isEdit, depth, characterOverride})` is callable from extensions; `promptOnly` scripts apply only when `isPrompt`, `markdownOnly` only when `isMarkdown` (`public/scripts/extensions/regex/engine.js:334-360`); placements `USER_INPUT 1, AI_OUTPUT 2, SLASH_COMMAND 3, WORLD_INFO 5, REASONING 6` (`engine.js:281-292`). Chat `mes` never contains `promptOnly` results.
- `/api/settings/get` (POST) returns index-aligned `openai_setting_names` + `openai_settings` (raw JSON strings) (`src/endpoints/settings.js:236`, `:275`; used `source/index.js:181-189`, `:833-857`).
- `messageFormatting(mes, name, isSystem, isUser, id)` (`script.js:1800`) is the raw→HTML renderer; raw offsets ≠ DOM offsets (ellipsis `...`→`…`, markdown markers), hence their alignment map (`source/index.js:625-673`).

## Verdict
Relevance **low-medium**. As a feature it is outside SO's scope (player-side prose editing). Its value to v2.4 is as a **threat model and a mirror**: it is a popular extension that rewrites chat text silently, and SO's rollback/provenance chain is blind to that. The one thing worth taking: **idea 1, silent-edit drift detection routed through the existing edit rollback** (with idea 7 as its failing test). Cheap and sharp side find: **idea 2**, our curator `[rewrite]` op replaces entry text the model was only shown the first 400 chars of.
