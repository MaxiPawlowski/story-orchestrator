## What it is
Group-chat-only "per-character memory". Each message stores which members were *present* (unmuted) when it landed; when ST drafts a member, every message that member did not witness is hidden from the prompt. Narrator-style members get an "ignore presence" (sees everything) toggle; v3 adds a "universal" marker for messages everyone sees. Per-message avatar badges let the user edit presence by clicking. Solo chats: no-op. Author's pitch: knowledge isolation + big token savings (1000-msg chat, one member remembers 55).

## How it works
- **Stamp on arrival**: `MESSAGE_RECEIVED` (`makeFirst`) and `MESSAGE_SENT` (`makeLast`) → `onNewMessage` writes `chat[mesId].present = [avatar…]` = group members minus `disabled_members` (unless `includeMuted`) minus `chat_metadata.ignore_presence` (`index.js:47-65`, `:71-98`, `:372-389`). `seeLast`: a replying character is also added to the previous message's `present` (`index.js:82-93`). Identity = avatar filename, not name. Persisted **on the message object** (travels with the chat file), `saveChatDebounced`.
- **Hide on draft**: `GENERATION_AFTER_COMMANDS` registers a `once` `GROUP_MEMBER_DRAFTED` handler paired with a `once` `GENERATION_STOPPED` canceller (`index.js:178-194`). On draft: `hideChatMessageRange(0, len-1, false)` (hide all), then unhide each witnessed id one call at a time, then unhide the last message (`index.js:200-227`). Impersonate / ignore-presence members → unhide all. v3 chunks contiguous ids into ranges (`inst:index.js:253-276`), handles user-`continue` (`inst:index.js:241-245`), adds the `presence_universal_tracker` pseudo-member (`inst:index.js:76`, `:257`).
- **Restore**: `MESSAGE_RECEIVED` (first listener) and `GENERATION_STOPPED` (first) → unhide the **entire** chat (`index.js:372-398`).
- Mechanism is ST's own: `hideChatMessageRange` flips `message.is_system` + DOM attr, then **awaits `saveChatConditional()` every call** (`ST public/scripts/chats.js:147-169`); `Generate` builds `coreChat = chat.filter(x => !x.is_system …)` (`ST script.js:4496`), so hidden = out of prompt. It is NOT a `generate_interceptor`.
- **UI**: jQuery-injected badge row into `.mes_block > .ch_name > .flex1` or bottom of `.mes_block` per message, re-scanned on every `CHAT_CHANGED` / `*_MESSAGE_RENDERED` / "show more" click (`index.js:100-146`, `:160-176`, `:348-364`); eye-slash toggle cloned before `.group_member_icon` + `MutationObserver` on `#rm_group_members` (`index.js:470-488`); settings drawer `html/settings.html`.
- **Slash**: `/presenceForget`, `/presenceRememberAll`, `/presenceForceAllPresent`, `/presenceForceNonePresent` (`index.js:400-468`); v3 adds per-id/range `/presenceForget|Remember name= <id|a-b>`, `/presenceReplace`, `/presenceCopy` (`inst:src/js/slashCommands.js:292-612`, ranges via `stringToRange`).
- **Mutations**: none handled explicitly. Deleting a message deletes its `present`; swipes share one `present` per message (not per swipe); no rollback concept. Old per-chat data in `extension_settings` migrated into messages (`index.js:316-346`).
- **LLM calls**: none. Pure deterministic prompt shaping.

## Overlap with Story Orchestrator
- **We isolate knowledge additively, they subtractively.** SO injects each drafted member's private epistemic block (`src/runtime/coordinators/memoryCoordinator.ts:486` `onMemberDrafted`) and scopes facts to the active speaker (`src/memory/inject.ts:27`). But the **transcript is shared**: our interceptor ignores the chat array (`src/runtime/index.ts:186`, `_chat`), and gotchas J5.8 records that every member legitimately receives the full transcript. So a scene played while B was muted still reaches B verbatim, contradicting any `[unaware]`/`[hiding]` row we inject. Presence closes exactly that leak; we don't.
- **Presence source**: we already have a better one than "who is unmuted right now": checkpoint `cast_changes` replayed along the path + per-chat cast mirror (`src/runtime/effectsApplier.ts:238`, `:273`), boundary logs (`src/engine/engine.ts:39`), and the judge scene tracker's `present` (`src/judge/scene.ts:145`). Presence has none of that; it samples `disabled_members` at arrival.
- **Epistemic pass presence input is coarse**: `dropCommonKnowledge` and the epistemic pass take `enabledCharacterNames(story)` at *pass* time (`memoryCoordinator.ts:377`, `extractionCoordinator.ts:351`), not per message — a scene window spanning a cast change mis-attributes who was there.
- **Collision today**: our `getChatWindow` drops `is_system` (`src/extraction/chatWindow.ts:8`) and the scheduler has no generation/draft awareness (no `generating|wrapper` in `src/extraction/scheduler.ts`). In a group round, member 1's reply commits a boundary and may schedule a read while member 2 is drafted and Presence has hidden most of the chat → read sees one member's view (already a known gotcha, never fixed). Also Presence's global unhide un-hides messages the user hid on purpose — our window then includes them.
- Prior decision: `.claude/sillytavern-docs/community/prompting-memory-prior-art.md:452` says "message-level hiding (Presence) is deliberately not our approach". That decision was against **chat mutation**; idea 1 below is a non-mutating variant and should be re-decided on those terms.

## Ideas for v2.4

| # | idea | kind | our area | our state | value | effort |
|---|---|---|---|---|---|---|
| 1 | Witness-filtered transcript per drafted member, non-destructive via our existing `generate_interceptor` | new-feature | memory / talk / host | absent | 4 | L |
| 2 | Per-message witness sets as input to the epistemic pass + code filter dropping `[knows]` for absent members | enhancement | extraction / memory | partial | 3 | M |
| 3 | Draft-window guard for off-path reads (defer until `GROUP_WRAPPER_FINISHED`) + detect Presence in capabilities | host-integration | extraction / host | absent | 3 | S |
| 4 | Journey check: absent member's captured request carries no witnessed-only line (region-scoped, J5.8 style) | testing | judge/harness (journeys) | absent | 3 | S |

**1. Witness-filtered transcript.** What: story-level opt-in (e.g. `talk_control.witness: true` or roster `omniscient: true` for narrators) where, inside `talkControlInterceptor`, the spliced `coreChat` drops messages the drafted member did not witness. Witness set derived, not stored: cast along `engine.checkpointPath` + boundary `lastMessageId` ranges (same path-replay shape as WI gating, invariant 14) unioned with an author override map; `seeLast` rule (always see the message you reply to) and "omniscient" roster flag copied from Presence. Their evidence: `index.js:200-227`, `inst:index.js:236-280`, `index.js:82-93`. Ours: interceptor ignores `_chat` (`src/runtime/index.ts:186`). Host facts that shape it: interceptor gets a local copy array, items are `{...chatItem, mes, index}` where `index` is the *coreChat* position not the chat id (`ST script.js:4523-4527`) → map via `send_date`/shared `extra` reference, never `index`; interceptors are **skipped on dryRun** (`ST script.js:4561-4568`) → next-turn preview (`src/runtime/nextTurn.ts`) must apply the same filter itself. Fit: no chat mutation, no saves, no LLM on reply path (rule 5 ok — pure, sync). Strains: rule 13 if author overrides persist (blob bump), rule 11 (overrides message-keyed → drop on rollback), rule 9 (override editing author-only; player sees nothing), prior-art "deliberately not our approach" decision. Must no-op for impersonate/quiet (mirror `withholdPrivateKnowledge`).

**2. Witness sets into epistemic.** What: compute per-message witnesses (same derivation as #1) and (a) pass them into `buildEpistemicPassPrompt` per window line ("present: A, B") instead of the pass-time cast, (b) add a code filter beside `dropCommonKnowledge` that drops a `[knows]` whose evidence messages the subject never witnessed. Their evidence: presence stamped per message `index.js:76`. Ours: pass-time cast `memoryCoordinator.ts:377`, `extractionCoordinator.ts:351`. Fit: filter only removes model output (like `dropCommonKnowledge`), never writes state from code (rule 4 ok); pure function in `src/memory/epistemic.ts`. Useful even without #1.

**3. Draft-window guard.** What: scheduler holds reads while a group wrapper is running (we already subscribe `GROUP_WRAPPER_STARTED/FINISHED`, `src/runtime/index.ts:193-194`) or while `document.body.dataset.generating`; add a `presence` host-fact to the capabilities read-out (`extension_settings.Presence?.enabled`) with a Repair consequence line. Their evidence: whole-chat `is_system` flip during draft `index.js:212`, global unhide `index.js:375`. Ours: `chatWindow.ts:8` skips `is_system`; scheduler has no generation check. Fit: off-path only, delays a read (rule 5 ok). Cheap, fixes a documented gotcha regardless of #1.

**4. Journey check.** What: J5 variant — mute B via `cast_changes`, play two turns, unmute, draft B, assert B's captured `/api/backends/` request lacks the muted-window line inside the chat region while A's has it; control: witnessed line present. Only meaningful with #1; lives in `test/journeys/`, uses existing `st-payload arm` + region-scoped `payloadAbsent`. Ours: J5.8 (`test/journeys`) only proves block-level privacy.

## Patterns to copy / anti-patterns to avoid
Copy:
- **seeLast rule**: a replier always witnesses the message it answers (`index.js:82-93`) — cheap, right default.
- **Omniscient member flag** for narrators (`index.js:287-303`) and a "public" marker for messages everyone sees (`inst:index.js:76`) — both map cleanly to roster fields.
- Avatar filename as member identity (`index.js:125`), not display name (our gotchas: stored names can differ from requested).
- Range syntax for manual edits via ST's `stringToRange` (`inst:src/js/slashCommands.js:7`, `:13`).
Avoid:
- **Mutating `is_system` to shape a prompt**: persists through `saveChatConditional` on every call (`ST chats.js:168`) → N+2 chat saves per draft (v2) and a crash/reload mid-draft leaves the chat hidden on disk; `/hide`-state of the user clobbered by global unhide (`index.js:196-198`). Use the interceptor copy.
- Fire-and-forget async in event handlers (`index.js:187`, `:208-219` un-awaited) — ordering depends on sync prefix of `hideChatMessageRange`.
- Paired `once` listeners as a state machine (`index.js:181-192`): a draft that never comes (dryRun, aborted wrapper) leaves a stale `once` for the next generation.
- Full DOM re-scan + badge rebuild on every render event (`index.js:354-364`) — O(chat) per message.
- Irreversible bulk commands with no confirm (`/presenceForget`, post "COMPLETELY and IRREVERSIBLY"); `characters.find(...).avatar` throws on unknown name (`index.js:233`).
- `extensionSettings == {}` is always false (`index.js:33`).

## ST host facts learned
- `hideChatMessageRange(start,end,unhide)` sets `is_system` synchronously, updates `.mes[mesid]` attr, `refreshSwipeButtons()`, then **awaits `saveChatConditional()`** — every call is a chat save (`ST public/scripts/chats.js:147-169`).
- Prompt history = `chat.filter(!is_system || tool_invocations)` (`ST script.js:4496`); items are shallow copies `{...chatItem, mes, index}` with `index` = position in the filtered array (`ST script.js:4523-4527`).
- `runGenerationInterceptors(chat, contextSize, abort, type)`: sorted by `loading_order` then name, errors swallowed, **not run on dryRun** (`ST scripts/extensions.js:2024-2049`, `:49`; `ST script.js:4561-4568`). Our `loading_order: 1` runs before Presence (200 in clone, 400 installed).
- `GROUP_MEMBER_DRAFTED` is awaited per member immediately before `Generate` (`ST scripts/group-chats.js:1059-1062`); `eventSource.emit` awaits each listener in order and swallows errors (`ST lib/eventemitter.js:130-153`); `makeFirst/makeLast` reorder an existing listener (`ST lib/eventemitter.js:66-110`).
- `GENERATION_AFTER_COMMANDS(type, {automatic_trigger, force_name2, quiet_prompt, …, force_chid}, dryRun)` fires in `Generate` after slash processing (`ST script.js:4321`).
- Arbitrary top-level fields on a chat message (`mes.present`) persist with the chat file (their whole feature relies on it, `index.js:76`; solo save slices `chat` wholesale `ST script.js:7423-7425`, group path not checked).
- No contradiction with our gotchas; confirms the "Presence hides most of the chat while a member is drafted" line and the prior-art note that its global unhide reveals user-hidden messages.

## Verdict
Relevance **medium**. Tiny deterministic extension, but it targets the one leak our epistemic design leaves open (shared transcript). Worth taking: **the concept, not the mechanism** — a witness-filtered transcript applied inside our existing `talkControlInterceptor` on ST's prompt copy, with witnesses derived from checkpoint cast replay (idea 1), plus the cheap draft-window read guard (idea 3) which is worth doing regardless.
