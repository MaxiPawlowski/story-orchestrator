# ST Lorebook Ordering (STLO) — v2.4 review

meta: author Aiko Apples (aikohanasaki) · repo https://github.com/aikohanasaki/SillyTavern-LorebookOrdering · commit `9243b9c` 2025-12-23 (manifest v2.2.3) · 40 upvotes / 1569 msgs · source available: **y** (single `index.js`, 1859 lines, no tests)

## What it is
Book-level priority (1–5) + order adjustment (±10000) + per-book token budget for World Info, with per-character overrides in group chats and an "only when these characters speak" filter. No LLM calls. Settings UI = button next to WI search + `/stlo <book>` slash. Pitched as the companion to ST Memory Books: its guide (`guides/STMB and STLO - English.md:21-47`) tells users to **demote chat-bound memory books to priority 1 with aggressive budgets** — the same slot our memory mirror occupies.

## How it works
- **Reorder at `WORLDINFO_ENTRIES_LOADED`** (`index.js:237`, handler `:325`, `applyPriorityOrdering` `:1350`). ST emits it inside `getSortedEntries` before sorting (`world-info.js:4604`) with the four source arrays (global/character/chat/persona). STLO rewrites `entry.order = priority*10000 + adjustment + min(order,9999)` (`index.js:1425`), sorts, then **empties chatLore/characterLore/personaLore and dumps everything into globalLore** (`:1449-1453`) — deliberately defeating ST's "chat lore always goes first" (`world-info.js:4624`; CHANGELOG v2.0.0). Since everything is one array, the insertion strategy stops mattering.
- **Group scoping**: `GROUP_MEMBER_DRAFTED` (`index.js:256`, emitted `group-chats.js:1059`) stores the drafted member's avatar-stem as `currentSpeakingCharacter` (`:250`); cleared on `CHAT_CHANGED` (`:255`). At reorder time, a book with `onlyWhenSpeaking` is **removed from the scan** unless the drafted member has an override row (`:1396-1404`); overrides swap priority/adjustment/budget (`:1411-1417`, `:1692-1697`). Single chats: no drafted speaker, overrides ignored.
- **Per-book budget, new path** (`registerPerLoopBudgetTrimmer` `:1765`): on `WORLDINFO_SCAN_DONE` (`world-info.js:5175`, feature-detected `index.js:57`) group activated entries by book, resolve budget (`default|%WI budget|%context|fixed`, `calculateLorebookBudget` `:1684`; total WI budget = `getMaxContextSize()*world_info_budget%` capped, `:1662`), keep by order desc (or shuffled if `randomTrim`, `:1805`), then `entriesMap.delete(world.uid)` (`:1829`) and **substring-remove the entry's content from `args.activated.text`** (`:1834-1843`). Does not touch `args.budget.current` — trimmed tokens still count against ST's global budget ("accepts one-iteration lag", `:1846`).
- **Legacy path** (no SCAN_DONE): pre-scan `e.disable = true` over the global budget (`:1468-1496`), plus `WORLD_INFO_ACTIVATED` drop-set (`:1538`) applied at `CHAT_COMPLETION_PROMPT_READY` by removing entry text from system messages (`:1608-1647`) — chat-completion only.
- **Persistence**: settings live **inside the lorebook JSON** under top-level key `stlo` (`setLorebookSettings` `:367-414`: `loadWorldInfo` → mutate → `saveWorldInfo(name,data,true)` → `worldInfoCache.set` → emit `WORLDINFO_UPDATED`). Reads are cache-only and return defaults for an uncached book (`:345-360`). Nothing in `chat_metadata`/`extension_settings`.
- **Mutations**: none to handle — all effects are per-scan, recomputed each generation; state reset on `GENERATION_ENDED`/`CHAT_CHANGED` (`:1747-1752`).
- **UI**: `menu_button` injected before `#world_info_search` (`:269-319`, retried on `WORLDINFO_UPDATED`), `Popup` CONFIRM modal (`:751`), select2 for character pickers (`:1238`); i18n via `addLocaleData` + 11 locale JSONs (`:129-195`).
- Observability = `console.info('[STLO] Trimmed WI entry', …)` only (`:1827`; README FAQ).

## Overlap with Story Orchestrator
- **We never reorder or budget ST's WI scan.** Our WI levers: checkpoint `world_info` gated sets rebuilt from path (`src/runtime/worldInfoGates.ts:12`), judge lore-select forcing (`src/runtime/loreSelect.ts:33`, `src/services/stHost/worldInfoActivate.ts:20` `WORLDINFO_FORCE_ACTIVATE`), memory mirror (`src/runtime/memoryMirror.ts:50`, chat-bound → rides ST's chat-lore-first slot), curator edits. Our memory budget (`src/memory/budget.ts`) covers only our extension-prompt tiers, not WI.
- **Per-member scoping**: we do it better for knowledge — private epistemic block swapped per drafted member (`memoryCoordinator.ts:486` `onMemberDrafted`, wired `src/runtime/index.ts:188`), withheld for impersonate/quiet. STLO does it for **lore** (whole books per speaker); we have no member-scoped lore (`RosterMember` = `{id,name,role}`, `src/engine/schema.ts:177`).
- **Evidence**: we observe saves and injected blocks (`promptInspector.ts:18`, next-turn preview `runtime/nextTurn.ts`), but **nothing observes which WI entries actually fired** — no `WORLD_INFO_ACTIVATED`/`WORLDINFO_SCAN_DONE` subscriber in `src/` (grep 2026-09-23; `events.ts` declares only `WORLDINFO_ENTRIES_LOADED`/`UPDATED`/`SETTINGS_UPDATED`). STLO has the same blind spot (console log only).
- **Coexistence risk (real, not hypothetical)**: STLO + its recommended config would (a) demote our chat-bound mirror book below story lore, (b) budget-trim our judge-forced picks after ST activated them (forced entries enter `allActivatedEntries`, `world-info.js:4885`, `:5075`, which STLO deletes from), (c) silently drop a whole book from `getScannableEntries()` whenever its stale `currentSpeakingCharacter` has no override — our call to `getSortedEntries` fires their `ENTRIES_LOADED` listener too. `LoreSelector.forced` would still report `ok` (it checks the emit, not landing).

## Patterns to copy / anti-patterns to avoid
Copy:
- Feature-detect a host event rather than version-sniff (`index.js:57` `HAS_WORLDINFO_SCAN_DONE`) — same shape as our capability probes.
- Mutate only the per-scan copies ST hands out (`WORLDINFO_ENTRIES_LOADED` arrays are shallow copies of cached entries, `world-info.js:4535`) — scan-local, nothing to roll back.
- Per-asset config persisted in the asset itself (idea 3).

Avoid:
- **Substring surgery on assembled prompt text** (`index.js:1623-1641`, `:1834-1838`): removes every occurrence of an entry's content from system messages / activated text — collides with identical text from other sources, then reflows whitespace globally.
- **Mutating `entry.order` to mean "activation priority"** — ST re-sorts `allActivatedEntries` by the same `order` to place text (`world-info.js:5202`), so priority silently moves prompt position too.
- **Flattening chat/persona lore into global** (`index.js:1449`) — breaks other extensions' reliance on chat-lore-first (our mirror) with no signal.
- Trimming after ST's budget accounting without adjusting `args.budget.current` (`:1846`) — trimmed tokens still starve other books.
- Token cache keyed `uid:contentLength` (`:107`) — uid is per-book, so same-uid/same-length entries across books share a count.
- Cache-only settings read that returns defaults when the book is not cached (`:348-355`) — config silently ignored.
- `randomTrim` (`:1805`) — nondeterministic prompt; incompatible with our replay/rollback expectations.
- Global mutable "current speaker" (`:52`) consulted by every scan, including dry runs and other extensions' `getSortedEntries` calls.
- README advertises a strategy-warning popup that v2.0.0 removed (CHANGELOG `:24`; locale keys `stlo.warn.*` orphaned) — docs drift.

## ST host facts learned
- `WORLDINFO_ENTRIES_LOADED` is awaited inside `getSortedEntries` before strategy sorting, with `{globalLore, characterLore, chatLore, personaLore}`; listeners may reorder/remove entries in place (`world-info.js:4604`; STLO `index.js:1449-1453`). Entries are shallow copies `{uid, world, ...rest}` of cached data (`world-info.js:4535`), final result `structuredClone`d (`:4639`). It fires on **every** `getSortedEntries` call — including ours (`stHost/worldInfoActivate.ts:13`) and dry runs.
- Chat lore always precedes persona lore and the strategy-sorted global/character list (`world-info.js:4624`) — so our chat-bound mirror book gets WI budget first. Consistent with our `bindChatLorebook` design; not previously written down in gotchas.
- `WORLDINFO_SCAN_DONE` args (`world-info.js:5158-5175`): `activated.entries` is the live `Map` keyed `` `${world}.${uid}` `` (`:5075`) — deleting from it removes the entry; `activated.text`, `budget.current`, `budget.overflowed`, `state.next`, `recursionDelay.currentLevel` are read back after listeners (`:5179-5186`).
- `WORLD_INFO_ACTIVATED` is emitted only for non-dry runs with a non-empty set (`world-info.js:900-902`).
- Forced entries (`WORLDINFO_FORCE_ACTIVATE`, `:1020-1026`) are honoured only when the entry is visited in the scan loop over `sortedEntries` (`:4785`, `:4885`) — **a listener that removes the entry at `ENTRIES_LOADED` defeats a force**, and forced entries still pass through ST budget checks and SCAN_DONE listeners before landing. Extends our "force, never write" note: a `wrote` from the emit is not evidence of landing.
- `GROUP_MEMBER_DRAFTED` emits a numeric chId before each member's generation (`group-chats.js:1059`) — matches our `onMemberDrafted` (no contradiction).
- WI server save writes the whole posted object (`src/endpoints/worldinfo.js:154`), so custom top-level keys in a lorebook file persist.
- `loadWorldInfo` is cache-first (`world-info.js:2041`); STLO updates `worldInfoCache` itself after save (`index.js:386`). Consistent with our "evict worldInfoCache after API book writes" memory; no contradiction with our gotchas.

## Verdict
Relevance **medium**. Not a feature to adopt (we deliberately don't reorder/budget ST's scan), but a popular WI-mutating extension that can silently undercut our mirror and lore-select, and whose mechanics expose our blind spot. The one thing worth taking: **idea 1 — observe `WORLD_INFO_ACTIVATED` and verify our forced/gated/mirror entries actually landed**, surfaced author-side.
