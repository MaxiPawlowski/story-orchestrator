# Roadway — v2.4 review

## What it is
Per-message "what could {{user}} do next?" button. Sends the full ST context (card, WI, history up to that message) plus a brainstorm prompt to a chosen Connection Manager profile (cheap/local model), regex-parses a numbered list of 6 actions, and renders them as cards inside an `is_system` small-sys message inserted after the target. Each card: **Use** (paste into input, optional auto-send), **Impersonate** (draft the player's line focused on that option, via main API `/impersonate` or a second profile streamed into the textarea), **Edit**. Named, user-editable prompt presets. Optional auto-trigger after each reply.

## How it works
- **Entry / UI**: settings template appended to `#extensions_settings` (`src/index.ts:102-106`); button prepended to the message template `#message_template .mes_buttons .extraMesButtons` so every rendered message gets it (`:371-374`); delegated click handler (`:376`).
- **Prompt build**: `buildPrompt(api, {targetCharacterId, messageIndexesBetween:{end: targetMessageId}, presetName/contextName/instructName/syspromptName from the profile, maxContext: profile|sampler|custom, includeNames: !!selected_group})` from `sillytavern-utils-lib` (`:416-432`) — i.e. a full ST-style prompt assembled with the *profile's* templates, truncated at the clicked message. Brainstorm prompt appended as one message with configurable role (`:434-437`, `substituteParams` for `{{user}}`). Default prompt forces 6 options across 10 action domains, "avoid obvious/repetitive" (`:58-72`).
- **LLM call**: `ConnectionManagerRequestService.sendRequest(profileId, messages, maxResponseToken)` (`:438-442`). Per-target in-flight dedupe `pendingRequests: Set<number>` (`:375`, `:403-413`).
- **Parse**: `extractBulletPoints` regex `^(?:\d+\.(?:\s+|(?=\S))|-\s+)(.*)$` (`:562-567`); zero matches → toast + raw text shown (`:446-455`). Only unit test in the repo covers this regex (`src/test/bullet.test.ts`, which copy-pastes the function instead of importing it).
- **Persistence**: result stored in the chat as a message `{is_system:true, name: systemUserName, force_avatar: system_avatar, extra:{isSmallSys:true, roadway_target_chat:<id>, roadway_raw_content, roadway_options[]}}` (`:458-470`); re-generation finds it by `extra.roadway_target_chat` and rewrites `.mes_text` in place (`:457`, `:472-479`); new one `chat.push` + `addOneMessage(msg, {insertAfter: targetMessageId})` (`:481-482`); `saveChat()` (`:490`). Edits write back into `extra.roadway_options[i]` + `saveChat()` (`:754-765`). Settings via `ExtensionSettingsManager` with version migration + "reset?" popup on failure (`:99`, `:855-876`).
- **Rendering**: builds `<details><summary>Roadway</summary>…` HTML; first render uses bare class names (ST's sanitizer prefixes them `custom-`), in-place rewrite passes `'custom-'` itself (`:500-559`, `:478`). Handlers re-attached on `CHAT_CHANGED` only if the LAST message is a Roadway message (`:779-790`).
- **Impersonate**: selected option exposed as a per-call dynamic macro `substituteParams(preset.impersonate, {dynamicMacros:{roadwaySelected}})` (`:594-598`). Main-API path: `st_runCommandCallback('impersonate', undefined, prompt)` (`:706`). Profile path: `deactivateSendButtons()`, re-`buildPrompt` with no message bound, reads streaming/max tokens from the profile's CC/TC preset via `getPresetManager(api).getCompletionPresetByName` (`:636-654`), `Generator.generateRequest` streaming into `#send_textarea` (`:656-697`), and **manually emits `GENERATION_STARTED('impersonate', {signal})`** (`:672-674`) — no matching `GENERATION_ENDED`/`STOPPED` is ever emitted. `#mes_stop` click aborts it (`:823-827`).
- **Auto-trigger**: `eventSource.makeFirst(CHARACTER_MESSAGE_RENDERED)` → synthetic click on the new message's button, solo only (`:795-805`); groups via `makeFirst(GROUP_WRAPPER_FINISHED, {groupId,type})` for `normal|continue|swipe` on the last rendered id (`:807-821`).
- **Mutation handling**: none. Swipe/edit/delete of the target leaves the options message orphaned; `roadway_target_chat` is an index, so any earlier deletion silently re-points it.

## Overlap with Story Orchestrator
- **Suggestions**: ours is author-only Driver **Suggest** (2-3 story developments toward unmet gates, JSON, extraction profile) `src/copilot/prompts.ts:118`, `src/copilot/authoring.ts:63`, UI `src/components/drawer/DriverPanel.tsx:62,121-125` → "Nudge with this" (one-turn steering). Roadway's is the *player's* menu of *player* actions. We have no player-facing equivalent (player mode has no steering by inv. 9). Same gap and same design constraints already written up in `cyoa-extension.md` idea 2.
- **Profile routing for cheap side-calls**: same idea as our memory-model profile (`src/services/stHost/connectionProfiles.ts:43`). Ours is better: message-array + instruct template, reasoning stripped, strict parsers, typed audits. Theirs is better at one thing: the prompt is the real ST context (card+WI+history via the profile's templates); ours deliberately sends only a chat window + derived scope (privacy report: card text never read).
- **Foreign-message robustness**: Roadway's artifact is `is_system`, and our window drops `is_system` (`src/extraction/chatWindow.ts:8`), as do `scoreContext.ts:13` and the stagecraft reader (`stagecraftCoordinator.ts:61`). So unlike CYOA's `is_user` option messages, Roadway's list never reaches extraction evidence. Our boundary ids come from host events, so the extra index does not skew commits.
- **Impersonate privacy**: we already withhold private epistemic knowledge on `impersonate`/`quiet` starts (`src/runtime/runtimeManager.ts:633`, `memoryCoordinator.ts:482`) — but see idea 1: Roadway's event is unpaired.

**1. Unpaired GENERATION_STARTED.** What: Roadway's profile impersonation emits `GENERATION_STARTED('impersonate', {signal})` and never an END/STOPPED. Our handler (`src/runtime/index.ts:189`) then (a) `withholdPrivateKnowledge()` → `clearEpistemicInjection()` (`memoryCoordinator.ts:482-484`), which is only undone by `onGenerationEnded` → `clearPrivateInjection` → `updateInjection` (`runtimeManager.ts:634,637`) or an incidental extraction apply; (b) `capturePayload()` records a capture for a request ST never assembled; (c) talk/lore start hooks run. In a **solo** chat the next real reply therefore goes out without the speaker's resting epistemic block (groups are safe: `onMemberDrafted` re-stages per draft, `memoryCoordinator.ts:486-497`). Status: PLAUSIBLE by code read, not run live. Fix shape: on a start whose type is not withheld, restore the resting block first (idempotent `updateInjection`), so a withhold lasts one generation by construction, not by the host remembering to end it. Evidence theirs `src/index.ts:672-674`, only `onFinish` → `activateSendButtons` (`:683-695`). Fit: inv. 16 (write that changes injected state refreshes it) and inv. 15 (group resting block stays empty — restore through `updateInjection`, which already renders `""` for groups, `memoryCoordinator.ts:465`).

**2. Dangling profile.** What: Roadway binds its pickers with `ConnectionManagerRequestService.handleDropdown`, which subscribes to `CONNECTION_PROFILE_CREATED/UPDATED/DELETED` (ST `public/scripts/extensions/shared.js:634`, events at `:715,:730`). Ours lists profiles once per render (`src/index.tsx:164`, `connectionProfiles.ts:15`) and never listens, and neither `nextRepairStep` (`src/runtime/repair.ts:28` checks only `!settings.profileId`) nor `pipeline.ts:66` checks the id still **exists**. A deleted/renamed-away profile reads as configured while every read fails (→ extraction pauses install-wide, per memory notes). Take: subscribe to the three events through `stHost/events.ts` to refresh the snapshot, and add a "memory model profile no longer exists" branch to Repair (consequence first). React owns our `<select>`, so reuse the events, not `handleDropdown` itself. No invariant conflict (inv. 13: install-wide setting).

**3. Player "draft as me".** What: extends CYOA idea 2 (player options menu, player-safe context only, pre-fill don't send) with Roadway's second step: pick an option → `/impersonate` with a focus prompt so the model drafts the player's line in the player's voice, into the input box, for the player to edit. Their evidence: `src/index.ts:54-56` (focus prompt), `:594-598` (dynamic macro), `:706` (main-API path). Ours: no player menu; impersonate already respected (`runtimeManager.ts:633`; `stHost/generation.ts:8-9` treats impersonate as no-attach/no-textarea). Conflicts: inv. 9 — option generation may only see `narrative.ts`-level context, never gates/objectives/future checkpoints, or it becomes a spoiler oracle; agency (`src/engine/agency.ts:6`) — it is the player choosing, so it satisfies `never_narrate_player_action` only if it pre-fills and never auto-sends (Roadway's `autoSubmitUseAction` `:720-722` is exactly what we must not copy); inv. 5 — off-path call, never blocks. Render in drawer/HUD, never in `chat`. Install-wide opt-in, default off. Human-rubric item.

**4. Interop probe.** What: extend `scripts/debug/so-turn-types-check.mts` (covers `/sd` `extension` posts, `:178-198`) with Roadway's three shapes, no backend: (a) `chat.push` an `is_system`+`isSmallSys` message + `addOneMessage` with no event → expect no boundary, no window entry; (b) delete that message after later turns → exercises the middle-delete case, where ST emits `MESSAGE_DELETED(chat.length)` not the deleted id (see host facts; already flagged by `mcp-model-context-protocol.md:63`) — assert what our rollback does and decide policy; (c) emit `GENERATION_STARTED('impersonate', {signal})` with no END, then a real start → assert the epistemic block is back (idea 1). Merge with CYOA idea 3 into one foreign-traffic check.

## Patterns to copy / anti-patterns to avoid
- Copy: **a UI artifact that must live in chat goes in as `is_system` + `extra.isSmallSys`** — excluded from ST's prompt and from our window; if we ever post more than `/comment` notes, this is the shape (we already use `/comment`).
- Copy: **per-call dynamic macros** (`substituteParams(text, {dynamicMacros})`) to feed a value into a user-visible template without registering a global macro — cleaner than a global `{{story_*}}` for one-shot prompt values.
- Copy: **per-target in-flight set** (`pendingRequests`) — refuse a second request for the same message instead of racing two writes.
- Avoid: **emitting host lifecycle events by hand** (`GENERATION_STARTED` without END) — every listener (ours included) assumes pairs.
- Avoid: `chat.push` + `addOneMessage({insertAfter})` when the target is not last — `addOneMessage` renders at `mesid=insertAfter+1` while the array holds the message at the end (ST `public/script.js:2553-2562`, "Callers push … before calling"), so DOM id and array index disagree. And a numeric index as the link key (`roadway_target_chat`) with no mutation handling.
- Avoid: regex list extraction with raw-text fallback, and a test that copies the function under test (`bullet.test.ts:1-6`) — proves the copy, not the product.
- Avoid: **user-editable prompts replacing calibrated ones** (named prompt presets + "restore default"). Our prompts are measured against floors; an override would silently void the calibration. If ever offered, as author-only and journaled.
- Avoid: auto-send on "use" (`$('#send_but').trigger('click')`) — takes the choice away from the player and races the send-button state.

## ST host facts learned
- `ConnectionManagerRequestService.handleDropdown(selector, initialId, onChange, onCreate, onUpdate, onDelete)` keeps a `<select>` in sync via `CONNECTION_PROFILE_CREATED/UPDATED/DELETED`; throws if Connection Manager is disabled — ST `public/scripts/extensions/shared.js:634-645,715,730`; Roadway `src/index.ts:111-118,362-369`.
- `ConnectionManagerRequestService.sendRequest(profileId, prompt, maxTokens, custom, overridePayload)` — ST `shared.js:423`; Roadway passes a message array with 3 args (`src/index.ts:438-442`).
- `substituteParams(content, {dynamicMacros})` is supported by both macro engines — ST `public/script.js:2977,2998,3008`; Roadway `src/index.ts:594-598`.
- `addOneMessage(mes, {insertAfter})` sets `messageId = insertAfter + 1` and inserts the DOM after the target; caller must place the message in `chat` itself — ST `public/script.js:2551-2584`.
- `deactivateSendButtons()` sets `document.body.dataset.generating = 'true'` + shows stop; `activateSendButtons()` deletes it — ST `public/script.js:7075-7089`. So a foreign tool can make our harness's generating probe read "generating" with no ST generation (Roadway `src/index.ts:615,694,702`).
- `deleteMessage(id)` (edit-mode delete `script.js:11990`, `/cut` `power-user.js:2853`) splices the middle of `chat` and emits `MESSAGE_DELETED(chat.length)` — the NEW length, not the deleted id — ST `public/script.js:1678-1699`. **Contradicts the assumption in `turnBridge.ts:159-169`** (payload treated as the deleted id); not in `gotchas.md`. Corroborates `mcp-model-context-protocol.md:63`. Roadway makes middle deletes likely (its messages sit after old replies).
- `GROUP_WRAPPER_FINISHED` carries `{groupId, type}`; Roadway reads `type` (`src/index.ts:809-815`). `eventSource.makeFirst` exists (untyped, `@ts-ignore`, `:794,808`).
- `is_system` messages with `extra.isSmallSys` render compact (ST `script.js:2680`) — Roadway `src/index.ts:462-466`.

## Verdict
Relevance **medium-low**. A small, well-liked "player options" helper; its product idea is already on our list via CYOA (player-safe options, pre-fill). The one thing worth taking is defensive, not a feature: **make the epistemic withhold survive a foreign, unpaired `GENERATION_STARTED`** (idea 1), plus a Repair branch for a memory profile that no longer exists (idea 2). Both S-effort, both close real failure modes for players who run Roadway (or any tool that fakes host events) next to us.
