# Moonlit Echoes Theme — v2.4 review

Rivelle · github.com/RivelleDays/SillyTavern-MoonlitEchoesTheme · `5336f36` (2026-09-16, manifest v3.1.1) · 0 upvotes / 358 reactions / 3246 msgs (the most-discussed theme in the corpus) · source available: **y** (48 files; `style.css` 3849 + `extension.css` 921 lines of CSS, `index.js` 1123 + `src/**` ~3.3k lines of JS)

## What it is
A UI theme shipped as an extension: loads two global stylesheets on demand, writes ~100 user-tunable CSS variables to `:root`, adds five extra chat styles (Echo/Whisper/Hush/Ripple/Tide) on top of ST's Flat/Bubble/Document, a preset system synced into ST's own UI-theme select, a draggable settings pop-out, and per-extension compat CSS for popular third-party extensions. No LLM calls, no chat state, no prompt injection. It is relevant to SO only as a **host environment our UI has to survive**, plus a few host-integration techniques.

## How it works
- **Bootstrap**: `initExtension` (src/bootstrap/init-extension.js:12) seeds `extensionSettings.SillyTavernMoonlitEchoesTheme` from defaults, `saveSettingsDebounced`, then `toggleCss(enabled)` (index.js:416) appends/removes `<link id="MoonlitEchosTheme-style|extension">` for `style.css` + `extension.css`. Disable = remove the links; no teardown of the observers or `window.*` globals.
- **Theming**: `applyAllThemeSettings` (src/core/theme-applier.js:10) rebuilds one `<style id="dynamic-theme-styles">` with `:root { --<varId>: <value> !important }` from a declarative setting list (src/config/theme-settings.js, 1106 lines; each item `{varId, type, default, category}`); checkbox settings inject raw CSS blocks into `style[id^="css-block-"]` (index.js:467). Plus a free-text `rawCustomCss` (index.js:880).
- **Chat styles**: extra `<option>`s in ST's `#chat_display`; switching = swap body class (`echostyle`, `whisperstyle`, `hushstyle`, `ripplestyle`, `tidestyle`) + `localStorage.savedChatStyle` (src/services/slash-commands.js:19-47). Slash commands `/echostyle … /moonlit-document` via `SlashCommandParser.addCommandObject(SlashCommand.fromProps(...))` (slash-commands.js:51-105), registered only while enabled.
- **Observers** (src/core/observers.js): avatar injector — MutationObserver on `#chat` subtree, debounced 100 ms, writes `--mes-avatar-url` / `data-avatar*` on every `.mes` (observers.js:116-148); `#form_sheld` height monitor — ResizeObserver + MutationObserver (subtree, attributes, characterData) + body observer + textarea input + resize/orientation listeners + four staggered `setTimeout`s, publishing `--formSheldHeight` on `<html>` (observers.js:154-334). Floating UI (their own and other extensions' triggers) is positioned `bottom: calc(var(--formSheldHeight))` (extension.css:781, :802).
- **Host-variant robustness**: `whenElementsAvailable(ids, handler)` (src/bootstrap/lifecycle-hooks.js:56-76) — MutationObserver on `documentElement` until every id resolves, runs once, returns a disposer. Written because **TauriTavern detaches closed settings drawers from the document**, so `#chat_display` is unreachable until opened; they also cache the node reference once seen (src/services/chat-controls.js:1-31).
- **Pop-out**: `openPopout` (src/ui/popout.js:52-104) builds a `.draggable` div in `#movingDivs`, **detaches its own inline-drawer content node** into it, calls ST's `loadMovingUIState()` + `dragElement($popout)`, Escape closes, `closePopout` re-attaches the node to the drawer (popout.js:109-133). Entry points: wand-menu item in `#extensionsMenu` (index.js:133-157), a `#sidebar-buttons` button (src/ui/controls.js:38-49).
- **Presets**: named presets in extension settings, mirrored into ST's `#themes` select as `"<name> - by Rivelle"`; a `change` listener on `#themes` loads the matching preset (src/services/theme-selector.js:84-101); export envelope `{moonlitEchoesPreset: true, presetVersion, presetName, settings}` validated on import (index.js:1076-1110).
- **i18n**: manifest `i18n` map `{zh-tw: "i18n/zh-tw.json", …}` (manifest.json:13-19) + ST's `t\`…\`` tagged template everywhere.
- **Compat CSS for other extensions**: `.stwii--*` (WorldInfoInfo), `.stcs--*`, `.stih--*`, `#qr--bar`, `#extensionTopBar`, `.mfc--*`, `#notebookPanel` (extension.css:2-877).
- **Persistence**: install-wide extension settings + `localStorage` (`savedTheme`, `savedChatStyle`, section collapse state — index.js:702, :845-857). Nothing per-chat. No swipe/edit/delete handling (no chat semantics).
- **Public API**: `window.MoonlitEchoesTheme` (addSetting, presets CRUD/export/import), `window.updateAvatars`, `window.formSheldHeightController` (index.js:985-1118).

## Overlap with Story Orchestrator
- UI host integration only. SO mounts into ST chrome with ST's own class names — top-bar drawer `.drawer` / `.drawer-icon` / `#drawer-manager.drawer-content` (src/index.tsx:556-576), HUD as first child of `#form_sheld` (src/index.tsx:580-587), settings under `#extensions_settings` — so a theme that restyles ST chrome restyles ours for free. Moonlit's `.drawer-icon` sizing/colour (style.css:713-722) and mobile `.drawer-content { min-width: 100dvw; top: var(--topBarBlockSize) }` (style.css:750-763) will apply to `#drawer-manager`.
- SO does it **better** on containment: every SO rule is scoped to five mount roots (`src/styles.css`, gotchas "All our CSS is scoped"), no `:root !important`, no `window` API beyond debug handles, host modules only via `stHost/*` dynamic imports. SO colours map to `--SmartTheme*` with fallbacks (src/styles.css:6-14), which is exactly the variable family Moonlit re-tunes — SO panels should follow Moonlit presets without code.
- SO does it **worse** on host variance: `mount()` polls 50×100 ms then gives up (src/index.tsx:597-613); `openStorySettings`/`revealSetting` use `getElementById` against the live document (src/index.tsx:530-549). No i18n (only a stray `data-i18n` in `HelpTooltip.tsx:16`). No pop-out author surface.
- HUD vs `--formSheldHeight`: Moonlit measures `#form_sheld`'s full bounding box and observes its subtree, so our HUD's height is included and floating triggers sit above it — compatible by construction (observers.js:163-171, :224-229). Transition notes (`.mes.smallSysMes`) stay visible: Moonlit only hides the avatar wrapper and pseudo-elements (style.css:3771-3790), unlike the "ghost message" CSS in our gotchas.

## Ideas for v2.4

| 2 | Observer-based mount/reveal (`whenElementsAvailable`) instead of 5 s bounded polling; cache resolved host nodes | host-integration | host | partial | 2 | S |

**1. Theme pass target.** Plan 09 §"Theme, zoom and assistive technology" requires the drawer/HUD/settings/Studio checked "under ST's bundled dark and light themes and one community theme" and that row is unrun (docs/plans/v2.3/09-*.md:95-102, :240, :293). Moonlit is the obvious pick (largest thread) and it touches exactly our mount points: `.drawer-content` full-width mobile + border rules (style.css:750-800), `.drawer-icon` z-index 9000 (style.css:718), `#form_sheld *{box-sizing:border-box!important}` and `#form_sheld` repositioning at ≤1000 px (style.css:2408-2432), `#send_form` opacity 0.6 (style.css:2306-2311), five body-class chat styles. Add `--theme <name>` to `so-responsive.mts` (today no theme axis: grep `theme` in the script = only header prose) that selects the theme + each chat style via `#chat_display`, then runs the existing 24-viewport overflow sweep and `assert-player-clean`. No invariant conflict; harness only; restore the user's theme in `finally` (theme = install-wide ST setting, same rule as the run-header).

**2. Observer-based mounting.** Theirs: lifecycle-hooks.js:56-76 + chat-controls.js:1-31 (TauriTavern parks closed drawers outside the document). Ours: `mount(attempt)` stops at 50 attempts (src/index.tsx:609-613), so on a host that detaches `#extensions_settings` until the Extensions drawer opens the settings panel never mounts, and `revealSetting`/`openStorySettings` would miss a detached node. Replace with a disposable MutationObserver wait keyed on the three anchors (`#extensions_settings`, `#top-settings-holder`, `#form_sheld`) and keep node refs once resolved. Fits invariants (DOM-only, no host module import). Low value until a TauriTavern user appears — the host fact is only evidenced by their comment, not verified in TauriTavern source.

**3. Author pop-out.** Theirs: popout.js:52-104 — `#movingDivs` container, `.draggable` + `.panelControlBar` + `.drag-grabber` + `.dragClose`, ST `dragElement` persists position/size per element id in `power_user.movingUIState` (RossAscends-mods.js:477-499, :629), `loadMovingUIState` (power-user.js:1835). Ours: author tooling lives only in the top-bar drawer, which covers the chat (DrawerTabs.tsx:710); watching the next-turn preview or conflict queue while playing means toggling the drawer each turn. A pop-out React root portaled into `#movingDivs` (not the detach-ST-node trick — React owns our DOM) gives a live side panel. Conflicts to respect: new `stHost/movingUi.ts` for the `dragElement`/`loadMovingUIState` imports (invariant 2); add the root id to the CSS scope list + Storybook `mountRootFor` (invariant 19); author-only, player mode must not expose it (invariant 9, add selector to `assert-player-clean`); UI still reads the one snapshot (invariant 18). Position persists in ST's install-wide `movingUIState`, not our settings — acceptable, it is presentation.

**4. i18n.** Theirs: manifest.json:13-19 + `t` usage throughout; ST loads `manifest.i18n[currentLocale]` from `/scripts/extensions/<name>/<file>` at extension load (extensions.js:848-878), keys are the English source string with `${0}` placeholders (i18n.js:81-83). Ours: none. Player copy has one source (`narrative.ts`, `pipeline.ts`, `/story`), so translation can wrap that one composition; the model-written narrative (canon prose, recaps) stays in whatever language the model writes. Must go through a `stHost` seam (their static `import { t } from '../../../i18n.js'` would break out-of-tree typecheck/build). Effort L because every player string plus the away-recap popup and HUD; author surfaces could stay English. Only worth it if a non-English player is a v2.4 goal.

## Patterns to copy / anti-patterns to avoid
Copy:
- Wait-for-elements with a disposer, run-once, guarded handler (lifecycle-hooks.js:12-18, :56-76).
- Reuse ST chrome classes (`.drawer`, `.draggable`, `.panelControlBar`, `.drag-grabber`, `.menu_button`) so themes restyle you — we already do it for the drawer.
- Versioned export envelope with a type marker validated on import (index.js:1076-1110) — our Studio `io.ts` import could check a marker + format version the same way (minor; format-2 already carries `id`/`version`).

Avoid:
- Global unscoped CSS + `:root { … !important }` variable writes (theme-applier.js:25-31) — fine for a theme, the opposite of our scoped-root rule.
- Detaching an ST-owned node into another container (popout.js:74-76) — any host code holding a selector-based reference misses it while popped out; this is the same failure class they had to work around for TauriTavern.
- Silent catches (`// Error handled silently`, theme-selector.js:98, popout.js:83/90) — a failed load looks like "nothing happened"; our typed `WriteResult` + journal is the right shape.
- `localStorage` for state that shadows ST's own settings (`savedChatStyle` vs `power_user.chat_display`, index.js:845-857) — two sources of truth for one value.
- Static relative host imports (`../../../power-user.js`, index.js:11-13) and `window.*` public APIs with no teardown.
- Six staggered `setTimeout`s around one measurement (observers.js:264-299) — a ResizeObserver alone would do; timing ladders are what our "fixed timeout = hardware assumption" gotcha warns about.

## ST host facts learned
- `dragElement($el)` (scripts/RossAscends-mods.js:477) persists top/left/right/bottom/width/height per element **id** into `power_user.movingUIState[id]` (:491-499); drag handle is `#<id>header` (:487) or any `.drag-grabber` (:629). `loadMovingUIState` exported from power-user.js:1835. `#movingDivs` is the container (index.html:7737). Used by moonlit popout.js:78-91.
- Extension `manifest.json` `i18n` map `{locale: file}` is fetched from `/scripts/extensions/<name>/<file>` and merged via `addLocaleData` (scripts/extensions.js:848-878); `t` template keys use `${n}` placeholders (i18n.js:81-83). Evidenced by moonlit manifest.json:13-19.
- `#extensionsMenu` (wand menu) is rendered from the `wandMenu` template (extensions.js:690-692); ST hides `#extensionsMenuButton` when no visible child exists (extensions.js:230-238) — an item appended there makes the wand visible. Moonlit index.js:133-157.
- Chat display style is `#chat_display` (index.html:4966) backed by `power_user.chat_display` (power-user.js:142, :1043-1048); styles are body classes (`flatchat`, `bubblechat`, `documentstyle`); third parties add values ≥3 and their own classes (slash-commands.js:30-39).
- `SlashCommandParser` and `SlashCommand` are reachable from `getContext()` (slash-commands.js:17) — context-only registration, no host import needed.
- `#sidebar-buttons` (controls.js:44) does **not** exist in this ST checkout's index.html (0 matches) — that button is a no-op on mainline ST; presumably a fork/host-variant container. Unverified which.
- TauriTavern detaches closed settings drawers from the document (claimed in lifecycle-hooks.js:44-49, chat-controls.js:4-9); not verified against TauriTavern source. Does not contradict our gotchas, but it would break our "open by visibility" assumptions (`revealSetting`, `so-ui` settings driving) on that host.
- No contradiction with our gotchas found. Moonlit keeps `.mes.smallSysMes` visible (style.css:3771-3790), so our transition notes survive it.

## Verdict
Relevance **low**. Theme/UI extension with no chat, prompt or state semantics. The one thing worth taking: make Moonlit Echoes the "one community theme" for plan 09's still-unrun theme pass (idea 1) — it restyles exactly the ST chrome SO mounts into (`.drawer-content`, `#form_sheld`, `.drawer-icon`) and it is the theme a real player is most likely to run. The MovingUI pop-out (idea 3) is the only product idea with real author value.
