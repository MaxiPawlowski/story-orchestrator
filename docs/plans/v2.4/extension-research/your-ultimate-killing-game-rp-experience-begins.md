# Danganronpa SillyTavern (DRST) — v2.4 review

meta: authors Jojicus + LithiumWaves · repo LithiumWaves/danganronpa-sillytavern · commit `d565554` (2026-08-15) · 65 upvotes / 424 msgs · source available: **y** (paths below relative to `source/`; ~64k lines JS, `index.js` alone 14.1k)

## What it is
Total-conversion genre kit: Danganronpa "Monopad" UI (truth bullets, trust meters, map, inventory/gacha, chapter journal, settings), day/night/investigation phases, and ~12 DOM minigames (Non-Stop Debate, Mass Panic, Scrum, Rebuttal Showdown, Hangman's Gambit, voting...) that run over a group chat flagged as a "Class Trial". Needs Dynamic Audio + Prome. Game state is driven by **hidden markers the main model writes into its replies** (`V3C| TB: …`, `V3C| SOCIAL_UP: …`) which a DOM observer parses and then erases. Minigame lines are generated by side LLM calls; each outcome is injected back as a one-shot prompt for the next reply. Mostly presentation (CSS, cinematics, audio). The story logic is thin.

## How it works
- **Loading**: plain ES modules with static imports of ST internals (`index.js:1-9`: `extensions.js`, `script.js`, `power-user.js`, `group-chats.js`, `slash-commands/*`), `ConnectionManagerRequestService` from `../../shared.js` (`index.js:60`). Manifest has no `generate_interceptor` (`manifest.json`).
- **State from reply markers**: prompt snippets the user pastes into their preset tell the main model to emit `V3C|` lines (`v3c-marker-prompts/prompts.txt`). `startV3CObserver` (`index.js:5739`) puts a `MutationObserver` on `#chat` (subtree, rAF-throttled, `:5889-5902`) and re-scans **every** `.mes` `textContent` on every mutation (`:5745-5750`). Matches award trust/XP, add truth bullets, fire announcements, set trial context (`:5766-5874`). It then **rewrites the DOM text nodes** to strip the markers (`:5876-5886`); the markers stay in `chat[].mes`, so they are re-sent to the model on every later turn.
- **Dedupe instead of rollback**: in-memory signature sets (`processedTruthSignatures`, `trustHistory` keyed `UP||name||<full rawText>`, `:5791`), plus persisted marker stores keyed by `group:<id>`/`char:<id>` scope + mesId + 140-char text fingerprint in **`extension_settings`** (`index.js:1689-1729`, `getInvestigationScopeKey` prefers group/char over chat, `:1711-1729`). No `MESSAGE_SWIPED/EDITED/DELETED` listener anywhere (grep: 0). A swipe changes `rawText`, so it makes a new signature and **awards trust again**. Deleting or editing a message never takes anything back.
- **Persistence**: trust roster, truth bullets, inventory, time/day, trials all live **install-wide** in `extension_settings[extensionName]` (`index.js:7664-7676` `saveCharacters`, `truth/truthBullets.js:210-212`, `items/itemsPanel.js:695+`, `trial/trialManager.js:2000+` `trials[key]`). Only card-hygiene uses `chat_metadata` (`core/cardHygiene.js:150-162`).
- **Injection**: `setExtensionPrompt` with keys `dangan_time_context` (`index.js:475`), `dangan_mindmine_result`/`dangan_scrum_result` (`:7294`, `:7340`), `dangan_monokuma_rules`, `dangan_debate_history`, `dangan_rebuttal_judgment` (`trial/trialManager.js:1992`, `:2019`, `:6132`, `:6568`). One-shot pattern: set on a UI win, clear on the next `CHARACTER_MESSAGE_RENDERED` via a self-removing listener (`index.js:7321-7328`, `:7372-7379`). A stale prompt is cleared on `MESSAGE_SENT` if the phase moved on (`trialManager.js:6087-6099`). Role is passed as the **string `'system'`** everywhere.
- **LLM calls**: three transports picked **per feature** (`nsdLineSource`, `mpdLineSource`, `whiteNoiseLineSource`, … `core/openrouterSettings.js:4-60`):
  - `main`: `ctx.generateRaw({prompt, responseLength})` (`index.js:1461`, `:5047`).
  - `profile`: `ConnectionManagerRequestService.constructPrompt(messages, id)` then `sendRequest(id, constructed, maxTokens, undefined, {temperature, top_p, stop})` (`index.js:4985-5004`).
  - `openrouter`: a browser-direct `fetch("https://openrouter.ai/…")` with a Bearer key (`core/openrouterSettings.js:139-150`).
  - `default` (white noise only): a canned pool chosen by a hash of the statement (`trialManager.js:440-453`).
  - Prompts are user-overridable templates with `{{var}}` rendering and a shipped default (`trialManager.js:419-430`, `core/constants.js:175`).
  - Unparseable output is retried once with temperature +0.1 (`trialManager.js:6571-6584`).
- **Chapter journal**: gathers "marked" chats (other chats too, via `/api/chats/get` and group fetch, `index.js:884-909`), estimates tokens as `chars/4`, shows `N MESSAGES · M CHATS · ~T EST. TOKENS` and a response-token slider, and turns the button into **CONFIRM**. Only that second click spends the call (`index.js:1487-1533`, `:1413-1470`).
- **Card hygiene** (`core/cardHygiene.js`): on an empty chat whose participants have `first_mes`/greetings/`scenario`, a modal offers KEEP/CLEAN, with "remember for new chats". CLEAN is persisted as `chat_metadata.danganCardHygiene` + `tainted=true` (`:150-162`). It splices the leading greetings out of `chat` and saves (`:189-237`), and **blanks `char.scenario` on the in-memory card objects**, restoring them on the next chat switch (`:120-147`). It re-checks chat identity after the awaited popup and aborts if the chat changed (`:374-384`).
- **Preset toggle**: to switch on an "Investigation Time" prompt it BFS-walks `ctx`, `ctx.chatCompletionSettings`, `ctx.settings` to depth 8 and flips every boolean on any node whose label matches /investigation/+/time|mode|toggle/. Then it saves settings (`index.js:3509-3605`), or clicks a matching DOM checkbox as a fallback (`:3607-3640`).
- **Onboarding**: install-wide `welcomeSeen` + `onboardingCoachesSeen{tabId}` (`core/onboarding/onboardingState.js`). One diegetic line per tab is anchored to the tab's element with a dimmed highlight on first visit (`coachMarks.js:4-60`), plus per-minigame first-run guides and a replayable scripted "lesson" (`orientation.js`, `minigameGuides.js`), each toggleable.
- **Chat deletion**: `CHAT_DELETED`/`GROUP_CHAT_DELETED` run the trial UI teardown after 400 ms (`index.js:11533-11541`).
- **Slash**: ~30 commands via `SlashCommandParser.addCommandObject` (`index.js:12036+`). Every LLM minigame has a manual named-arg form (`/nonstopdebate s1-q=…`) for token-poor users.
- **Testing**: none. `.dbg/*.ndjson` debug logs only.

## Overlap with Story Orchestrator
- **Typed state from the story, not from reply markers**: SO reads off-path with a strict parser, evidence spans and boundary-applied deltas (`src/extraction/sharedRead.ts:87`, `src/extraction/evidence.ts:28`, `src/engine/applyQueue.ts:30`). DRST's main-model markers are the very design invariant 4 exists to forbid. SO is far ahead here.
- **Mutations**: SO rolls back across every store (`src/runtime/rollback.ts:35`, `src/runtime/turnBridge.ts:37`). DRST ignores swipes/edits/deletes and double-counts on swipe.
- **Scope**: SO keeps per-chat state in `chat_metadata` with chat stamps (`src/runtime/persistence.ts:60`). DRST keeps game state install-wide, so two playthroughs share one trust roster.
- **One-shot injection**: SO's warden note is set on `onGenerationStarted` and cleared on `onGenerationEnded` (registry `continuityNote`). DRST clears on `CHARACTER_MESSAGE_RENDERED`, so a stopped or failed generation leaks the prompt into a later turn. SO is better.
- **Injection seam**: ours passes numeric `IN_CHAT=1`/`ROLE_SYSTEM=0` constants (`src/services/stHost/extensionPrompts.ts:3-4,24`). DRST's string role silently drops its only IN_CHAT prompt (see host facts).
- **Model routing**: DRST routes per feature. SO sends every memory pass through one profile (`src/extraction/client.ts:13`), and only the judge is per-use (`src/judge/settings.ts:5`). DRST is ahead on flexibility; this was already raised by the polyceph review.
- **Ownership across awaits**: DRST's `stillHere` check (`cardHygiene.js:374`) is a manual RunToken. SO has it systematised (`src/runtime/runToken.ts:138`).
- **Card/opening conflict**: SO checks only that requirements are present (`src/runtime/requirements.ts:18-20`). Nothing inspects roster cards' `scenario`/`first_mes` against the authored story. DRST at least surfaces the conflict. **Gap.**
- **Onboarding**: SO has none (grep `onboard|coach|firstRun|welcome` in `src/` = 0; v2.1 J1.4 once asserted a `#so-first-run` nobody built). **Gap.**
- **Cost preview**: SO's "Memorize chat" fires immediately (`src/components/drawer/DrawerTabs.tsx:256`). It runs ⌈N/8⌉ window reads plus one whole-chat read (`src/runtime/coordinators/extractionCoordinator.ts:383-428`). DRST estimates and confirms first. **Gap.**

**1. Story-owned scenario.**
- What: ST already has a per-chat scenario override: `chat_metadata.scenario` replaces the card scenario in solo prompts (ST `script.js:3445`) and the combined group scenario (`group-chats.js:561`). The user edits it via the chat "override" popup (`script.js:9002-9054`, which also covers `mes_example` and `system_prompt`). An authored `scenario` on the story (and optionally as a checkpoint effect) could be written there, so the card's standing scenario — sent every turn — stops contradicting the checkpoint objective. The card itself is never touched.
- Their evidence: DRST needed this and did it the wrong way, by blanking `char.scenario` in memory and restoring on chat switch (`core/cardHygiene.js:120-147`).
- Our evidence: no `scenario` write anywhere in runtime (grep: only the wizard card field, `src/wizard/types.ts:19`). Effects today: `src/engine/schema.ts:87`.
- Fit:
  - The override is per-chat, so it avoids the cross-chat leak that forced invariants 14/21.
  - It still needs `EffectsApplier.withLedger` (`src/runtime/effectsApplier.ts:181`) with compare-and-set restore, because the user may have typed their own override. Record it as `externally-changed`; never clobber.
  - Path-replayed like WI (the last checkpoint on `checkpointPath` that sets it wins).
  - A save read back from evidence (inv 17).
  - A new `stHost/chatOverrides.ts` returning `WriteResult` (inv 2/16).
  - An empty override falls back to the card, so "clear" means restore-before, not blank.

**2. Repair step: cards compete with the opening.**
- What: when a story starts on an empty chat, list the roster members whose card carries `first_mes`/`alternate_greetings`/`group_only_greetings`/`scenario`. Offer the idea-1 override for the scenario, and say plainly that their greetings will appear before the story's first beat.
- Their evidence: `cardHygiene.js:94-117` (inspection), `:258-332` (KEEP/CLEAN + "remember").
- Our evidence: `src/runtime/requirements.ts:18-20` checks presence only. `src/runtime/repair.ts:25` has no such step.
- Fit: Repair diagnoses; it must not delete messages (a delete fires our rollback and is destructive) or edit cards (wizard create-only, inv 8).
- Host note: setting `chat_metadata.tainted = true` stops ST from re-inserting a solo greeting on reopen (`script.js:9910`) and marks a group chat non-fresh (`group-chats.js:269`). Worth knowing, but it is ST-owned state; do not write it without an explicit choice.

**3. Memorize preflight.**
- What: before "Memorize chat", show the number of reads (⌈len/8⌉+1), a `chars/4` or tokenizer estimate for the final whole-chat read, and the profile name. Continue only on Confirm, via `showChoicePopup`.
- Their evidence: `index.js:1487-1533` (collect → estimate → CONFIRM) and `:1413` (the second click spends).
- Our evidence: `DrawerTabs.tsx:256` fires `runMemorizeBacklog()` directly. The final read is `getChatWindow(0, chat.length-1)` (`extractionCoordinator.ts:428`), which is seed D's "no request-size bound".
- Fit: the UI half of seed D, cheap, no invariant touched. It does not replace the cap/chunk.

**4. Coach marks.**
- What: on the first open of each drawer tab, Studio tab and wizard step, show one line anchored to the control, dismissible. The seen-set lives install-wide in our settings store, with "Reset tips" in settings.
- Their evidence: `core/onboarding/onboardingState.js` (seen-set API) and `coachMarks.js:4-60` (target selector + text + highlight rect).
- Our evidence: none in `src/`.
- Fit:
  - Player-mode copy must pass `assert-player-clean` (inv 9): no checkpoint ids and no gate talk.
  - Render inside our mount roots or a native `<dialog>` (inv 19). The highlight must not be a body-level fixed overlay (see the `translateZ` gotcha).
  - This is install-wide config (inv 13).

**5. Per-pass routing.**
- What: optional profile per memory pass (shared read vs scene summary vs canon vs curator vs wizard), defaulting to the one extraction profile. DRST adds a `default` = no-LLM canned path per use.
- Their evidence: `core/openrouterSettings.js:4-60`, `trialManager.js:456-490`.
- Our evidence: `src/extraction/client.ts:13` and `copilotCoordinator.ts:32-33` both take the single `profileId`.
- Fit: install-wide settings. The self-test would need to run per assigned profile. Already raised in `polyceph-custom-multi-model-multi-prompt.md`; listed here only as corroboration.

**6. Campaign recap across chats.**
- What: "previously in this campaign" from other chats of the same story or group.
- Their evidence: marked-chat collection `index.js:884-941`.
- Our evidence: absent. `docs/plans/v2.3/privacy-report.md` states other chats are never read.
- Conflict: that privacy claim, plus per-chat pinning (inv 12). It would need an explicit author opt-in and the whole-request size cap from seed D first. Low priority.

## Patterns to copy / anti-patterns to avoid
Copy:
- Two-step spend: collect → estimate → CONFIRM, with the response budget exposed as a slider (`index.js:1487-1533`).
- Per-surface first-visit tip with a persisted seen-set and a global toggle and reset (`onboardingState.js`).
- A chat-identity re-check after any awaited popup before acting (`cardHygiene.js:374-384`); we already do this with RunToken.
- A self-removing one-shot listener pair: dismiss the UI on `MESSAGE_SENT`, clear the prompt after the reply. Ours is better (generation-ended). Copy only the "stale prompt cleared when the phase moved" check (`trialManager.js:6087-6099`).
- The `CHAT_DELETED`/`GROUP_CHAT_DELETED` subscription (`index.js:11540-11541`) corroborates the mirror-book reaper already proposed in `chat-top-info-bar.md` #1. Caveat from our side: `mirrorLorebookName` is fixed at adoption and survives a chat rename (`src/runtime/memoryMirror.ts:47-50`), so a suffix match misses renamed chats. Also reap by `wiBook` recorded in the rename handler.

Avoid:
- **Main model emits state markers, and a DOM observer parses and erases them** (`index.js:5739-5910`). The markers stay in `chat[].mes` and are re-fed to the model each turn. Every mutation re-scans the whole chat. The main reply is conditioned on bookkeeping. Invariant 4 forbids it.
- **Dedupe signatures instead of rollback**: the trust signature includes the full text, so a swipe re-awards (`index.js:5791`). The persisted marker store is keyed by group/character, not chat, and grows forever in `extension_settings` (`:1705-1729`).
- **Install-wide game state** (`index.js:7675`, `truthBullets.js:210`): parallel playthroughs corrupt each other.
- **Guessing host shapes**: a BFS over `ctx` flipping any boolean labelled like "investigation", then saving settings (`index.js:3509-3605`). The CC prompt-toggle idea is already in `nemopresetext-…md` #3 with the proper `PromptManager.getPromptOrderEntry` seam.
- **String `role` in `setExtensionPrompt`**: it becomes `NaN` and silently drops IN_CHAT prompts (see host facts). Several call sites also swap position/depth against their own comment (`trialManager.js:6131-6132`: the comment says "Depth 0, position 1", the code passes position 0, depth 1).
- **API key in `extension_settings`/memory with a browser-direct third-party fetch** (`core/openrouterSettings.js:139-150`). Our judge keeps its key server-side in ST secrets behind a plugin; keep it that way.
- **Mutating in-memory card objects** (`cardHygiene.js:135-147`) and splicing `chat` then `printMessages()` (`:189-237`). Both bypass ST's own event flow; for us that means no rollback signal.

## ST host facts learned
- `setExtensionPrompt(key, value, position, depth, scan, role)` coerces `role` with `Number()` (ST `script.js:8926-8934`). `getExtensionPrompt` filters `x.role === role` for IN_CHAT on both the textgen (`script.js:5628+`, roles 0/1/2) and CC (`openai.js:846-857`) paths. So a string role (`'system'`) becomes `NaN` and **an IN_CHAT prompt is silently never injected**. IN_PROMPT (position 0) is unaffected because it is read with `role === undefined` (`script.js:4701`). DRST hits this at `trial/trialManager.js:6568`. Consistent with our seam (`extensionPrompts.ts:3-4`); worth a gotcha line.
- ST has per-chat card overrides: `chat_metadata.scenario` (solo `script.js:3445`, group `group-chats.js:561`), `chat_metadata.mes_example` (`group-chats.js:562`), `chat_metadata.system_prompt` (`script.js:3415`), all set by the override popup (`script.js:9002-9054`). An empty value falls back to the card. DRST does not use them; noted because its card-mutation hack is the symptom.
- `chat_metadata.tainted` (written by DRST, `cardHygiene.js:157`) is ST's "not pristine" flag. It suppresses greeting regeneration on reopen for solo chats (`script.js:9905-9912`), makes a group chat non-fresh (`group-chats.js:269`), and changes swipe sync and overswipe for greetings (`script.js:6932`, `:9226`). It **qualifies** our gotcha "every open of a solo chat that still holds only its greeting re-emits `first_message`": that holds only while the chat is untainted.
- `ConnectionManagerRequestService.constructPrompt(messages, profileId)` returns an instruct-formatted string for textgen profiles and the array unchanged for CC (`extensions/shared.js:501-526`). DRST uses it before `sendRequest(..., custom=undefined, overridePayload)` (`index.js:4996-5003`). `sendRequest` defaults are `{stream:false, extractData:true, includePreset:true, includeInstruct:true}` and it accepts a `signal` (`shared.js:393-424`). This is equivalent to our message-array + `includeInstruct` path (`src/services/stHost/connectionProfiles.ts:43`), with no contradiction.
- `CHAT_DELETED` carries the chat name and `GROUP_CHAT_DELETED` the chat id (ST `script.js:1354`, `:1401`; `group-chats.js:2269`, `:2308`). DRST subscribes both (`index.js:11540-11541`). Our typing `CHAT_DELETED: []` / `GROUP_CHAT_DELETED: []` (`src/services/stHost/events.ts:11-12`) is wrong, as already recorded in `chat-top-info-bar.md`.

## Verdict
Relevance **low-medium**. It is a genre presentation kit whose state layer (reply markers, install-wide state, no rollback) is a catalogue of what SO's invariants forbid. **The one thing worth taking:** a story-owned scenario written through ST's per-chat `chat_metadata.scenario` override (idea 1, with Repair step 2), so a card's standing scenario stops fighting the checkpoint and no card is edited. Cheap runner-up: the Memorize-chat estimate + confirm (idea 3).
