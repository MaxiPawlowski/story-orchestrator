## What it is
Hands the **main chat model** a set of ST function tools (Search, Remember, Update, Forget, Summarize, Reorganize, MergeSplit, Notebook) over "TV-enabled" lorebooks, and **suppresses keyword activation** for those books so retrieval happens only by the model's tool calls. Entries are indexed by a per-book category tree (built from WI `group`/first key, or by LLM), which the model navigates. Plus: "[Tracker]" entries the model rewrites each turn, arcs as tree nodes for summaries, a private notebook injected every turn, `!command` shortcuts, interval auto-summary, activity feed, ~40 diagnostic checks. Requires a tool-calling API.

## How it works
- **Boot** (`index.js:35-93`): settings panel into `#extensions_settings2` (`:41`), then `registerTools()`; re-registers on `CHAT_CHANGED`, `WORLDINFO_UPDATED`, `WORLDINFO_SETTINGS_UPDATED`, `APP_READY` (`:72-77`, `:95-107`).
- **Keyword suppression** (`index.js:80-81`, `:115-144`): `WORLDINFO_ENTRIES_LOADED` handler splices every entry whose `world` is TV-enabled out of `globalLore/characterLore/chatLore/personaLore`, keeping `constant` entries if `passthroughConstant` (default on). Host: emitted inside `getSortedEntries` before sorting (`world-info.js:4604`); arrays hold shallow copies (`:4535`), final result is `structuredClone`d (`:4638`) → scan-local, nothing persisted.
- **Tool registration** (`tool-registry.js:378-435`): `ToolManager.unregisterFunctionTool` all, then `registerFunctionTool({name, description, parameters (JSON schema draft-04), action, formatMessage, shouldRegister, stealth})`. Descriptions are **rebuilt per registration** and embed live state: the tree overview (collapsed ≤6000 / traversal ≤4000 chars, `tools/search.js:422`), per-book descriptions for write routing (`tool-registry.js:267-298`), tracker titles (`:413-416`). User can disable tools, override descriptions (`:409-411`), or wrap mutating tools in a confirm popup whose denial string is returned to the model (`:347-371`).
- **Active books** (`tool-registry.js:97-132`): `selected_world_info` + character primary/`charLore.extraBooks` + `chat_metadata[METADATA_KEY]` + CarrotKernel `carrot_chat_books`, filtered by TV toggle. Single active book → the model's `lorebook` arg is ignored (`:245-248`).
- **Preflight** (`tool-registry.js:194-232`, called on every `GENERATION_STARTED` `index.js:153-159`): diffs expected vs registered vs `shouldRegister()`-eligible vs stealth tools, re-registers if drift, logs a one-line snapshot.
- **Prompt injections** (all `setExtensionPrompt(key, text, IN_PROMPT, 0)` on `GENERATION_STARTED`): mandatory "You MUST use at least one TunnelVision tool call this turn" (`index.js:162-170`); notebook contents from `chat_metadata.tunnelvision_notebook` (`index.js:186-188`, `tools/notebook.js:50-57`, cap 50 notes `:23`); auto-summary "You MUST call TunnelVision_Summarize" after N messages (`auto-summary.js:80-88`); `!command` → forced-tool instruction (`commands.js:126-168`).
- **Search** (`tools/search.js`): traversal (navigate node by node, recursion bounded by `ToolManager.RECURSE_LIMIT`, which TV **overwrites globally** 1-50, `index.js:200-209`) or collapsed (whole tree in the description, multi-id retrieve, `:231`); cross-book substring search, ≤10 hits, 200-char previews (`:666-760`). Returns `[Lorebook | UID | Title]\ncontent` blocks as the tool result.
- **Writes** (`entry-manager.js`): `loadWorldInfo` → `createWorldInfoEntry` → mutate the cached object → `saveWorldInfo(book, data, true)` (`:19-76`); update/forget(disable or **permanent delete**, `tools/forget.js:28`, `:48-50`)/merge/split same pattern (`:78-368`). Tree + tracker uids live install-wide in `extension_settings.tunnelvision.trees` (`tree-store.js:65-81`, `:544-565`); "[Tracker…]" title prefix auto-flags (`:12`, `:532-534`).
- **Dedup**: optional trigram Jaccard over `title+content` vs every enabled entry, warn-only, top 3 ≥ threshold (default 0.85, misnamed `enableVectorDedup`) (`tools/remember.js:26-91`, `:149-164`).
- **Summaries/arcs** (`tools/summarize.js`): entry filed under auto-created "Summaries" node or an arc child node (`:110-127`, `:207-233`); keys = participants + `summary:<significance>`; then `hideChatMessageRange(start, end)` over the covered span + watermark in `chat_metadata` (`:54-102`).
- **Side LLM calls** (tree build, node summaries, subdivision, `!ingest`): `generateRaw({prompt, systemPrompt})` with `<think>` regex strip (`tree-builder.js:29-35`), JSON extracted by greedy `\{[\s\S]*\}` (`:552`, `:620`), wrapped in `withConnectionProfile` that **switches the user's global profile via `/profile` callback and back** (`:45-75`). Chunking by chars named "tokens" with overfill (`:819-841`).
- **Activity feed** (`activity-feed.js`): `WORLD_INFO_ACTIVATED` (native activations from TV books) + `TOOL_CALLS_PERFORMED` + `TOOL_CALLS_RENDERED` (`:89-100`), persisted in `chat_metadata.tunnelvision_feed` (`:16`, `:127-133`); "stealth mode" hides pure-TV tool-invocation messages with a CSS class + `message.extra.tvHiddenToolCalls` and `saveChatConditional()` (`:458-481`, `:636-668`).
- **Mutations**: none handled. Entries written during a reply survive its swipe/edit/delete; notebook and watermark have no rollback; auto-summary counters are an in-memory `Map` counting `MESSAGE_SENT`+`MESSAGE_RECEIVED` (swipes included, lost on reload) (`auto-summary.js:16-32`, `:51-60`).
- **Diagnostics** (`diagnostics.js:38-1066`): ~40 checks incl. event availability, `ToolManager.isToolCallingSupported()` (`:119-130`), stale tree uids auto-removed (`:185-224`), settings self-heal.

## Overlap with Story Orchestrator
- **We do better**: all memory/lore writes are off-path, typed, provenance-tracked and rolled back with the chat (`src/memory/reverse.ts:23`, `src/runtime/rollback.ts:35`); curator writes are proposals, scoped to `stagecraft.lorebooks`, boundary-applied and revertible (`src/stagecraft/scope.ts:24`, `src/runtime/coordinators/stagecraftCoordinator.ts:74`); side calls go through `ConnectionManagerRequestService` without touching the user's profile (`src/services/stHost/connectionProfiles.ts:43`); reasoning stripping covers `<think>`/Gemma/Harmony and orphan closers (`src/extraction/parse.ts:51`); state lives in a typed blackboard + ledger, not free-text "[Tracker]" entries (`src/memory/ledger.ts:31`); arcs are extracted, not main-model-filed (`src/memory/arcs.ts:8`); per-member private knowledge (`src/memory/epistemic.ts:50`) vs TV's one shared notebook.
- **They do, we don't**: suppress/replace ST's keyword scan (we only add: `src/services/stHost/worldInfoActivate.ts:18` forces picks on top of keyword matches); observe what actually activated; per-book descriptions used for routing; trigram near-dup; hierarchical digest of a lorebook for prompts.
- **Philosophically opposite**: TV's thesis is "the main model manages its own memory mid-generation". SO's is "the reply path never writes; extraction reads off-path and applies at a boundary" (baseline invariants 3, 5, 6).

**1. Scan-time checkpoint WI gating.** Theirs: `index.js:115-144` edits the four per-scan arrays; nothing is written to any file. Host: arrays are shallow copies (`world-info.js:4535`), disabled entries skipped in the scan loop (`:4801`), result cloned (`:4638`), and the same `getSortedEntries` feeds the vectors extension's WI activation (`extensions/vectors/index.js:1629`) and our `LoreSelector.getEntries`. Ours: `applyWorldInfo` writes `disableWIEntry`/`enableWIEntry` per book into **global lorebook files** (`src/runtime/effectsApplier.ts:95-103`, called `:219`, release `:254`), plus `releaseGatedWorldInfo` on load/clear/swap (`src/runtime/runtimeManager.ts:231`, `:546`, `:607`) — the design that exists because the flags leak across chats (gotchas 2026-09-19). `WORLDINFO_ENTRIES_LOADED` is typed but unsubscribed (`src/services/stHost/events.ts:32`). Proposal: new `stHost/worldInfoScan.ts` seam; the handler takes the **pure** `worldInfoPlan(story, engine.checkpointPath)` (`src/runtime/worldInfoGates.ts:12`) for the chat that is scanning and sets `disable` on the copies (enable = `disable=false` on a copy of a file-disabled entry). Wins: zero lorebook writes, per-chat by construction, no release step, no leak when two chats/stories share a book, rollback/hydrate free, no ledger rows. Costs/traps: ST's WI editor keeps showing file state (the author view must show effective state); must be synchronous and cheap (emit is awaited); must no-op when requirements are not ready (invariant 14's "not-ready leaves WI alone"); capability-probe the event and keep the file path as fallback for one release; never mutate nested arrays (`key`) on the copies. Strengthens invariant 14 rather than straining it. Pair with activation evidence (st-lorebook-ordering #1 / probablytoomanytabs #1) to prove it live.

**2. Lore-select exclusive mode.** Theirs: TV's whole premise — reasoned retrieval *replaces* keyword matching for managed books, constants pass through (`index.js:119-128`). Ours: `LoreSelector` forces top-K via `WORLDINFO_FORCE_ACTIVATE` on top of ST's own keyword scan of the same books (`src/runtime/loreSelect.ts:30-33`, `src/services/stHost/worldInfoActivate.ts:18-26`), so the judge can add but never remove noise. Option: `lore_select.exclusive: true` → the #1 handler also drops non-picked, non-constant entries of the scoped books. Caveat from st-lorebook-ordering (`world-info.js:4785`, `:4885`): removing an entry at `ENTRIES_LOADED` defeats its force, so the filter must keep the picks. Invariant 7: its own opt-in, off by default, and it needs a **recall** floor declared before any run (the plan-10 spike measured ordering, not "did we drop something needed"); on judge timeout/unavailable it must fall back to the keyword scan, never an empty book.

## Patterns to copy / anti-patterns to avoid
Copy:
- **Scan-local, write-free WI control** via `WORLDINFO_ENTRIES_LOADED` (#1/#2). The one mechanism here that is strictly better than ours.
- **Preflight snapshot before every generation** (`tool-registry.js:194-232`): expected vs registered vs eligible, self-repair, one log line naming the failure. Shape fits our capability probes (`src/services/stHost/capabilities.ts:68`) for "our injections/macros/interceptor are still registered".
- **Per-book descriptions** fed into routing prompts (`tool-registry.js:267-298`) — if the curator ever writes to >1 allowlisted book, it needs the author's one-line purpose per book, not just names.
- **Denial is an answer**: a refused confirm returns a message to the caller rather than silence (`tool-registry.js:363-370`) — same rule as our `[data-so="decision-refused"]`.

Avoid:
- **Main-model tool writes mid-generation** (`tools/remember.js`, `tools/update.js`, `tools/forget.js:48-50` permanent delete, `entry-manager.js`): writes land before the reply is accepted, survive swipe/edit/delete, and a hallucinated `permanent: true` destroys authored lore. Violates invariants 3, 6, 11. The "You MUST call a tool every turn" depth-0 injection (`index.js:169`) spends reply-path tokens and latency on bookkeeping (invariant 5).
- **Hiding summarized chat** by `hideChatMessageRange` (`tools/summarize.js:94`) + persisting a hide flag via `saveChatConditional` (`activity-feed.js:667`): SO never mutates chat; also the model picks the span (`messages_back`) — an overestimate hides unsummarized turns.
- **Global host mutation**: `ToolManager.RECURSE_LIMIT = …` (`index.js:200-209`) changes every tool extension's limit; `/profile` swap around side calls (`tree-builder.js:45-75`) races the user's own generation and leaves the wrong profile on error paths mid-swap.
- **State without a chat scope or rollback**: in-memory counters (`auto-summary.js:16`), install-wide tree/tracker uids keyed by book name only (`tree-store.js:65-81`), notebook with no rollback (`tools/notebook.js:29-43`) shared by every group member.
- **Title-prefix conventions as schema** ("[Tracker]" regex, `tree-store.js:12`) — typed qualities/ledger fields are the right home.
- **Greedy JSON extraction** `/\{[\s\S]*\}/` (`tree-builder.js:552`, `:620`) — grabs from first `{` to last `}`; silent fallback to metadata tree on any parse failure.

## ST host facts learned
- `WORLDINFO_ENTRIES_LOADED` payload `{globalLore, characterLore, chatLore, personaLore}`, awaited inside `getSortedEntries` before strategy sort (`world-info.js:4604`); entries are per-call shallow copies (`:4535`) and the result is `structuredClone`d (`:4638`) → splicing or flipping `disable` is scan-local (theirs `index.js:115-144`). Also fired by the `CHAT_CHANGED` pre-cache (`:1013-1017`).
- The same `getSortedEntries` feeds vectors' WI activation (`extensions/vectors/index.js:1629`) → an `ENTRIES_LOADED` splice **also removes entries from vector matching**. **Contradicts the TV author's thread claim** ("we don't suppress matching done by the vector extension", post.md follow-up 05:29) — their code does.
- Tool-call turn shape: intermediary reply emits `MESSAGE_RECEIVED`+`CHARACTER_MESSAGE_RENDERED` (`script.js:3799-3800`); empty placeholder → `deleteLastMessage` (`:5414`, event `:1611`); invocations saved as an `is_system`, `isSmallSys` message with `extra.tool_invocations` between `TOOL_CALLS_PERFORMED` and `TOOL_CALLS_RENDERED` (`tool-calling.js:899-921`); recursion `Generate('normal', {depth+1})` (`script.js:5434-5435`, `:5557-5558`) bounded by `ToolManager.RECURSE_LIMIT` (`tool-calling.js:255`, checked `script.js:4495`), a **mutable static** any extension can overwrite (theirs `index.js:204-208`).
- `stealth` tool: result not shown, no follow-up generation (`tool-calling.js:43`, `script.js:5421`, `:5546`). `shouldRegister` is evaluated per generation (`tool-calling.js:404`). `registerFunctionTool` takes `{name, displayName, description, parameters, action, formatMessage, shouldRegister, stealth}` (`tool-calling.js:269-287`).
- `GENERATION_STARTED` (`script.js:4299`) fires **before** ST reads `#send_textarea` (`:4311`, `:4401-4402`), so a listener can rewrite or clear the user's input for that generation (theirs `commands.js:126-168`).
- `WORLD_INFO_ACTIVATED` carries the activated entries, only for non-dry scans with ≥1 activation (`world-info.js:900-903`; theirs `activity-feed.js:370-402`) — consistent with the other reports.
- `loadWorldInfo` returns the server's answer for any name and caches it (`world-info.js:2036-2058`); TV's "not found" guards (`entry-manager.js:27-30`) assume `null` for a missing book — per our gotcha the server answers a dummy `{entries:{}}`, so those guards are dead. Consistent with our gotchas, not a contradiction.

## Verdict
Relevance **medium**. Its product thesis (main model edits its own lorebook through tools, mid-reply, no rollback) is the opposite of SO's invariants and should not be copied. The one thing worth taking: **move checkpoint `world_info` gating from lorebook-file writes to a scan-time `WORLDINFO_ENTRIES_LOADED` filter** (#1) — write-free, per-chat by construction, nothing to release or roll back, and it would retire the cross-chat leak class that path replay was built to contain. Secondary: treat TV as the reference co-installed extension for the tool-call-turn TurnBridge decision (#3) and a Repair check when it suppresses a story book (#4).
