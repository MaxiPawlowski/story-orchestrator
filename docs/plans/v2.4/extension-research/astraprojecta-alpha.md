# AstraProjecta (Alpha) — v2.4 review

Author Rivelle (RivelleDays) · repo https://github.com/RivelleDays/SillyTavern-AstraProjecta · commit `e7ab01f` (2026-07-12) · 72 upvotes / 78 msgs · source available: **y** (`source/`, TS/React + shadcn, ~516 non-dist files, 153 vitest files, 57 nested `AGENTS.md`; `dist/` and `locales/` skipped)

## What it is
Mobile-first **frontend replacement** for ST (activates at `screen and (max-width: 1000px)`, `src/packages/core/layout-mode/index.ts:3`). Wraps `#sheld`/`#form_sheld` in its own shells, hides ST's top bar, and re-hosts ST's native drawers/pages as mobile panels. Astra-owned features: message revision history (regenerate/continue tree per message), Revert/Regenerate/Continue on the last message, in-chat find & replace with undo, context-usage meter with per-source token breakdown, chat categories/favorites. No LLM calls of its own, no prompt injection, no story/memory logic. Relevance to SO is **not** as a feature donor; it matters because (a) it is a UI that a player of ours may run, and it emits/omits host events in ways our `TurnBridge` reads as story mutations, and (b) it exercises two host seams (context budget, context cutoff) we do not.

## How it works
- Entry `src/index.js:1-18`: disposes any previous runtime at `globalThis.__astraProjectaRuntime` then `bootstrapMobileApp()` (hot-reload safe).
- **DOM takeover**: `#sheld` reparented into `#astra-chat-session-shell` with a top bar, restored on dispose (`src/app/mobile/top-bar/createMobileChatTopBarFeature.tsx:409-475`); `#form_sheld` reparented into `#astra-chat-composer-shell` (`src/app/mobile/styles/chat-send-form.css:164-176`); `body.astra-projecta-mobile-layout #top-bar, #top-settings-holder { display:none !important }` (`src/app/mobile/top-bar/mobile-chat-top-bar.css:1-5`); `#send_form #nonQRFormItems { display:none !important }` (`chat-send-form.css:58-59`). Native drawers ported by snapshotting parent/nextSibling/class/style and restoring (`src/packages/core/st/native-drawers/createNativeDrawerBridge.ts:1-80`). `#extensionsMenu` (wand) is treated as the single source of truth and reparented live only while open (`src/packages/features/chat-session/send-form/extensions-menu/AGENTS.md`). Full recovery path `restoreMobileNativeUi` (`src/app/mobile/runtime/nativeUiRecovery.ts:31-80`).
- **Host access**: `getStContext()` + typed "Like" shapes everywhere; private module imports isolated in `unstable-st-internals.ts` (`src/packages/core/st/chat-catalog/unstable-st-internals.ts:70-86`, dynamic `import(/* webpackIgnore */ "/script.js")`, `/scripts/group-chats.js`), each capability resolved by name, `ok:false reason:"api-unavailable"` result types, warn **once per capability** with `CLIENT_VERSION` (`:88-112`). Same shape as our `stHost/*` + `WriteResult` + capability probes.
- **Events**: `eventSource.on` over `APP_READY, CHAT_CHANGED/LOADED/RENAMED/DELETED, GROUP_*`, `MESSAGE_SENT/RECEIVED/EDITED/DELETED/SWIPED/UPDATED/SWIPE_DELETED`, `GENERATION_STARTED/STOPPED/ENDED/AFTER_COMMANDS`, `CHAT_COMPLETION_PROMPT_READY`, `SETTINGS_UPDATED`, `MAIN_API_CHANGED` (`chat-catalog/index.ts:1180-1191`, `chatContextUsage.ts:1609-1671`, `chatMessageRevision.ts:90-101`).
- **Revision history** (`src/packages/core/st/chatMessageRevision.ts`): tree `{kind: origin|regenerate|continue|edit, parent[], swipes[], active path, fullText}` per native swipe root, stored on the chat message under a namespaced key `message.astra_projecta` (`chatMessageRevisionData.ts:75-84`) and saved with `saveChatConditional` (`chatMessageRevision.ts:589-593`). Captured by listening to `GENERATION_STARTED(type)` for `continue|normal|swipe`, ignoring dry runs (`:971-999`), then diffing on render. **Switching revisions rewrites `message.mes`/`swipe_id`, patches the DOM directly, saves, and emits `MESSAGE_SWIPED` + `MESSAGE_EDITED` itself** (`:720-728` root; `:750-760` child path emits `MESSAGE_EDITED` only) — no generation, no render event. "Revert one step" = apply parent path (`:911-948`). Swipe deletion rebases roots (`:1430-1469`, `chat-message-revisions/rootRebase.ts`).
- **Find & replace / message edit** (`src/packages/core/st/chatMessageEdit.ts`): `batchSaveChatMessageTextEdits` writes all texts, saves once, rolls back in-memory on save failure, then emits `MESSAGE_EDITED` → `updateMessageBlock` → `MESSAGE_UPDATED` **per touched message**, best-effort (`:591-672`); replace-all groups matches per `messageId:swipeId` (`message-search/store.ts:398-440`). `copyChatMessageFromDraft` splices a clone at `id+1` (`:675-712`) and `moveChatMessage` swaps adjacent entries (`:714-745`) — both `redrawChat` + save with **no mutation event**.
- **Context usage** (`src/packages/core/st/chatContextUsage.ts`): budget = `openai_max_context - reserve` (`:227-248`); on `CHAT_COMPLETION_PROMPT_READY` (non-dry-run) reads `promptManager.tokenUsage` + `tokenHandler.getCounts()` from `/scripts/openai.js` and buckets `charDescription+charPersonality+scenario`, `chatHistory`, `personaDescription`, `worldInfoBefore+After`, "other" = remainder (`:403-455`); DOM fallback parses `#completion_prompt_manager_list [data-pm-identifier]` (`:465-550`); last fallback POSTs messages to `/api/tokenizers/openai/count?model=` minus a 3-token assistant primer, cached by `model:JSON(message)` (`:608-650`), plus tool-schema reserve via `ToolManager.registerFunctionToolsOpenAI` (`:685-754`). Ignores `quiet`/`impersonate` (`:134`, `:1540-1548`). Chat Completion only for the breakdown.
- **Context cutoff marker**: reads ST's `.mes.lastInContext` and inserts a boundary divider (`message-layout/createMessageHeaderLayoutFeature.ts:1506-1530`).
- Persistence: `extension_settings.astra_projecta.*` per module (`chat-categories/index.ts:533-546`) + revision tree inside chat messages. No `chat_metadata` writes. No migrations ("structural changes may reset this state", README).
- Dev process: nested `AGENTS.md` per folder injected into the agent **on edit** by a PreToolUse hook walking up to the nearest one (`.claude/hooks/inject-nearest-agents.cjs:1-60`); `documentationContract.test.ts` asserts README/AGENTS.md strings match code constants (`src/packages/core/layout-mode/documentationContract.test.ts:10-35`).

## Overlap with Story Orchestrator
- Host seam discipline: their `unstable-st-internals.ts` ≈ our `src/services/stHost/*` + `capabilities.ts` + `WriteResult`; ours is build-enforced (`stHost/typedResults.test.ts`), theirs convention. Nothing to take beyond "warn once per missing capability, include `CLIENT_VERSION`" — our capability read-out already covers it.
- Mutation handling: we subscribe the same `MESSAGE_SWIPED/EDITED/DELETED/UPDATED` (`src/runtime/turnBridge.ts:53-56`) and **rollback on any id, unconditionally** (`turnBridge.ts:168-178` → `runRollback`, `src/runtime/rollback.ts:35`). Even the engine-`noop` path still quarantines memory, drops audits/judge calls and reverts curator writes (`rollback.ts:40-45`, `:61-71`). Astra's synthetic events (and ST's own unconditional `MESSAGE_EDITED`) hit that path with **unchanged** text; its (and ST's) message move/copy hit **no** path.
- Next-turn preview: ours lists SO's injected blocks with `characters` (`src/runtime/nextTurn.ts:25`), no tokens and no share of the context budget; `countTokens` exists (`src/services/stHost/tokenizer.ts:3`) but only `runtime/entryTokens.ts` uses it.
- Memory scoring: `temporalProximity` rewards entries whose source is **close** to the newest message (`src/memory/score.ts:64-67`) — i.e. entries whose source text is most likely still verbatim in the prompt. No read of ST's context cutoff anywhere (`grep lastInContext src` → 0).
- UI mount: drawer in `#top-settings-holder` (`src/index.tsx:572-574`), HUD as first child of `#form_sheld` (`src/index.tsx:580-587`). Under Astra mobile: HUD survives (form_sheld is reparented, not hidden), **drawer is hidden**; no `#extensionsMenu` entry exists (`grep extensionsMenu src` → 0), so the player loses every drawer surface (Overview, Memory, Restart).
- Generation state: product uses `scriptModule.isGenerating()` (`src/services/stHost/generation.ts:4`) — unaffected. Our debug harness keys on `#send_but` visibility; Astra hides `#nonQRFormItems` → harness would misread (harness-only; not a product concern).

**1. Consumed-message fingerprints.** What: at each committed boundary record `{messageId → hash(mes)}` for the messages that boundary (and its extraction window) consumed; on `MESSAGE_EDITED/UPDATED/SWIPED` compare the message's current text hash — equal → no rollback (no quarantine, no curator revert); different → today's path. At the next boundary and on hydrate, re-hash the recorded ids; a mismatch with no event (move/copy/third-party write) → `rollbackFromMessage(earliestMismatch)` + journal "chat changed without a host event". Swiping *back* to the swipe that was consumed also becomes a no-op. Their evidence: revision switch emits `MESSAGE_SWIPED`+`MESSAGE_EDITED` with no generation (`chatMessageRevision.ts:726-728`); replace-all emits `MESSAGE_EDITED`+`MESSAGE_UPDATED` per message (`chatMessageEdit.ts:651-667`); move/copy emit nothing (`chatMessageEdit.ts:675-745`). ST itself: `messageEditDone` emits `MESSAGE_EDITED` even when nothing changed (`script.js:8398-8405`), native `messageEditMove` swaps entries + saves with no event (`script.js:8352-8395`). Our evidence: `turnBridge.ts:168-178`, `rollback.ts:40-45,61-71`; `grep messageHash|mesHash|textHash src` → 0. Today a replace-all fixing a typo in message 3 rewinds the story to before message 3 and quarantines every memory row sourced after it; "edit → Done" without changes on the last reply undoes its transition until the next reply. Fit: strengthens inv 11 (rollback ≡ replay *of a changed input*; an unchanged input has nothing to replay); hashing lives in runtime, engine untouched (inv 1); boundary logs already record `{lastMessageId, chatLength}`, this extends the record (blob bump + migration, inv 13 — absent hashes = today's behaviour). Keep the rewind conservative when the hash is missing. Swipe text lives in `swipes[swipe_id]`, hash `mes` after ST syncs it.

**2. Wand-menu entry.** What: add a `.list-group-item` to `#extensionsMenu` ("Story" + fa-route) that opens the drawer (or, when `#top-settings-holder` is not rendered, the Overview in a `<dialog>`). Their evidence: Astra hides `#top-settings-holder` at ≤1000 px (`mobile-chat-top-bar.css:1-5`) but bridges `#extensionsMenu` live and preserves `.extension_container`/`*_wand_container` ids (`extensions-menu/AGENTS.md`). Our evidence: drawer mount only in the top bar (`src/index.tsx:572-574`); `grep extensionsMenu src` → 0. The wand menu is the one ST surface both native ST and alternative frontends keep. Fit: pure UI; player-safe if it opens player mode (inv 9); new DOM seam belongs in `stHost/drawers.ts` (inv 2); CSS stays scoped (inv 19). Cheap insurance for mobile players and for any skin that hides the top bar.

**3. Token budget in the preview.** What: `NextTurnContributor.tokens` via `countTokensBatch`, plus a header "SO blocks: N tok of M available (max context − response reserve)"; for Chat Completion also show ST's own buckets (history/WI/character) from `promptManager.tokenHandler.getCounts()` so the author sees what SO displaces. HUD stays untouched (player). Their evidence: `chatContextUsage.ts:227-248` (budget), `:403-455` (prompt-manager counts), `:608-650` (tokenizer endpoint, 3-token primer). Our evidence: `nextTurn.ts:25` characters only; memory budgeting estimates tokens itself (`src/memory/budget.ts:9`). Fit: author-only (inv 9); reads through a new `stHost` module (`promptManager` is a private `openai.js` export, `openai.js:535`, CC-only — textgen gets tokens but no breakdown, say so rather than guess); off-path, cached (inv 5). Also a diagnostic for "memory tiers are eating the history".

**4. Context-horizon-aware scoring.** What: pass ST's `chat_metadata.lastInContextMessageId` into `ScoreContext`; demote entries whose `messageId` ≥ cutoff (their source is still verbatim in the prompt — injecting it again costs tokens for nothing) and boost/protect entries whose source just fell out. Their evidence: they read the cutoff via `.mes.lastInContext` (`chatContextUsage.ts:224`, `createMessageHeaderLayoutFeature.ts:1515`); ST writes both the class and `chat_metadata.lastInContextMessageId` in `setInContextMessages` (`script.js:6083-6100`) on every textgen and CC generation (`script.js:4954`, `:5312`). Our evidence: `score.ts:64-67` rewards proximity, no cutoff input (`grep lastInContext src` → 0). Fit: `score.ts` stays pure (the value is a plain number in the context); the read is a new `stHost` getter (inv 2). The value is one generation stale and not saved by ST on its own ("hopefully saved via another call") — treat absent/NaN as "unknown → today's scoring" (`hostMessageId`-style parse, gotcha V4). Measure against the live suite before changing weights; do not retune floors (inv 7 spirit).

**5. ## Patterns to copy / anti-patterns to avoid
- Copy: **reparent-with-origin-snapshot** (parent, nextSibling, class, style, restore on dispose) whenever we must move ST DOM (`createNativeDrawerBridge.ts:51-80`); **dispose-previous-runtime on bootstrap** via a global key (`src/index.js:4-10`) — check ours survives an extension hot re-run; **dry-run + quiet/impersonate filter** on generation listeners (`chatContextUsage.ts:134`, `:1540`) — we already do the same for private epistemic staging.
- Copy: batch edits save once and roll back the in-memory copy on a failed save before emitting anything (`chatMessageEdit.ts:625-648`) — same "put it back" rule as our `commitDecision`, but note their save-failure detection relies on an exception, which `saveChatConditional` never throws (our gotcha, `script.js:9412`).
- Avoid: **emitting host mutation events synthetically** from a UI (`MESSAGE_SWIPED` with no swipe, `MESSAGE_EDITED` for a revision switch) — every listener reads them as user mutations. SO must never emit host events; and SO must not trust that an event implies a content change (idea 1).
- Avoid: **silent structural writes** (splice/swap + save, no event) — if SO ever writes chat messages (NPC replies go through `/sendas`, fine), use host paths that emit.
- Avoid: `display:none !important` on shared ST chrome (`#top-settings-holder`) — hides every third-party entry point. Our CSS scoping rule already forbids the equivalent.
- Avoid: "structural changes may reset this state without migration" — contrast with our blob version + migration rule.

## ST host facts learned
- ST's own `messageEditDone` emits `MESSAGE_EDITED` unconditionally, before comparing text (`script.js:8398-8405`); Astra mirrors this and adds `MESSAGE_UPDATED` after (`chatMessageEdit.ts:547-576`). **Extends our gotchas:** an `EDITED` event is not evidence of changed text.
- ST's native **message move** (`messageEditMove`, `script.js:8352-8395`) swaps adjacent `chat[]` entries, swaps itemized prompts and saves with **no mutation event**; Astra's move/copy do the same (`chatMessageEdit.ts:675-745`). **Gap vs our rules:** `TurnBridge` assumes swipe/edit/delete are the only mutations; reorder/insert is invisible.
- Astra revision switch: `MESSAGE_SWIPED` then `MESSAGE_EDITED` on the same id with no `GENERATION_*` and no render event; DOM patched directly (`chatMessageRevision.ts:715-728`).
- `chat_metadata.lastInContextMessageId` = first message still in the prompt, set by `setInContextMessages` on every generation, deliberately **not** saved there (`script.js:6083-6100`; callers `:4954` textgen, `:5312` CC); the DOM mirror is `.mes.lastInContext` (Astra `chatContextUsage.ts:224`). For `swipe|regenerate|continue` ST counts one extra message (`script.js:6086-6088`).
- Chat Completion breakdown: `openai.js` exports `promptManager` (`openai.js:535`, instantiated `:682`); `promptManager.tokenUsage` + `tokenHandler.getCounts()` keys `charDescription, charPersonality, scenario, chatHistory, personaDescription, worldInfoBefore, worldInfoAfter` (Astra `chatContextUsage.ts:420-440`; ST `PromptManager.js:1584-1589`). Nothing equivalent for textgen.
- `CHAT_COMPLETION_PROMPT_READY` payload `{chat, dryRun}` (`openai.js:1618-1619`); Astra skips `dryRun === true` (`chatContextUsage.ts:1500`).
- `/api/tokenizers/openai/count?model=` counts an array of messages; Astra subtracts a 3-token assistant primer except for listed tokenizers (`chatContextUsage.ts:130`, `:635-645`; ST `src/endpoints/tokenizers.js:916`).
- Astra's own claim (not verified here): ST can emit `GENERATION_STOPPED` before the message render (`chat-message-revisions/AGENTS.md`, `generationTransaction.ts`). Our `TurnBridge` flushes on both and keys on render, so no conflict.
- Private `/script.js` exports Astra relies on: `renameGroupOrCharacterChat`, `deleteCharacterChatByName`, `updateRemoteChatName`, `CLIENT_VERSION`; `/scripts/group-chats.js` `deleteGroupChatByName` (`unstable-st-internals.ts:3-12`).
- Under Astra mobile layout: `#top-bar`, `#top-settings-holder` hidden (`mobile-chat-top-bar.css:1-5`); `#form_sheld` kept but reparented (`chat-send-form.css:164`); `#nonQRFormItems` hidden (`chat-send-form.css:58`) so `#send_but` is never visible — **contradicts the harness gotcha** that `#send_but` visibility tracks generation/connection (harness-only; product uses `isGenerating()`).

## Verdict
Relevance **medium** — not for its features (a UI skin; nothing to adopt for narrative), but because reading its event handling exposed a real SO correctness gap that exists in plain ST too. The one thing worth taking: **idea 1, consumed-message fingerprints** — stop treating every `MESSAGE_EDITED/UPDATED/SWIPED` as a content change (ST's own no-op edit already triggers a rewind + memory quarantine) and detect the event-less reorder/insert ST and Astra both perform. Idea 2 (wand-menu entry) is the cheap compatibility fix for mobile players.
