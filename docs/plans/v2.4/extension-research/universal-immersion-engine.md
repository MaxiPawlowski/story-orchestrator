## What it is
Giant jQuery overlay (~3 MB JS/HTML, ~45 modules) turning ST into an RPG/life-sim: phone with apps + generated "internet", inventory/equipment/crafting, party + War Room combat helper, social/relationships, calendar, map, journal/diary, databank memory, sprites, image gen. One LLM "Unified State Scan" reads the recent chat after each reply and returns a big JSON patch that updates all of it; a second "Turbo API" (direct OpenAI-compatible fetch) is recommended for these side calls. State is summarised back into the prompt as one large system block. No tests ("No formal test suite", README.md).

## How it works
- **Boot**: `index.js` dynamic-imports modules with `?v=Date.now()` cache-busting, records per-module load errors in `window.UIE_moduleErrors`, exposes `window.UIE_debugStatus()` (bound flags, last trigger/run/error times) (`index.js:24-98`, `:100-151`).
- **Auto scan (the extraction analogue)**: `initAutoScanning` binds `MESSAGE_RECEIVED` + `GENERATION_ENDED` → 800 ms debounce → `scanEverything({sourceMesId})` (`src/modules/stateTracker.js:2381-2461`), with an in-flight gate + min interval (default 8 s) and a `count|tail-fingerprint` dedupe (`:1196-1233`). Window = last ≥50/80 messages capped to 18 000 chars from the tail (`:1236-1237`, `chatLog.js:171-180`), with `<style>/<script>`/CSS blocks stripped (`chatLog.js:3-33`, `:131-138`) but every speaker relabelled `You`/`Story` (`chatLog.js:174`).
  - Phase 1 **regex writes state**: "found 30 gold" → currency += 30 directly (`stateTracker.js:1266-1300`, regex at `:1269`).
  - Phase 2 one JSON prompt listing current state + "Existing …" names + **"Deleted Social Names"** + a 15-key schema with `evidence` fields and "STRICT EVIDENCE MODE" (`:1341-1417`); applied in code with a second guard (deleted names filtered again at apply, `:1826`; weak ownership regex `hasExplicitOwnershipEvidence` `:647-670` whose first clause accepts any acquisition verb anywhere).
- **Per-message undo**: before a scan, snapshot the touched keys; after, diff into ops (`set`/`array_add|remove|set` keyed by an inferred id field) stored by message index and by a content fingerprint (`stateTracker.js:164-276`, `:299-312`, `:2336-2352`). Re-scan of the same index (swipe/regenerate) first reverts that index's ops (`:1246-1256`). **Delete**: `MESSAGE_DELETED` carries no deleted id, so it diffs the previous vs current per-message fingerprint list, and if exactly one fingerprint vanished, reverts that message's ops (`:2463-2495`). Undo store lives in `window.UIE_scanUndo` only — lost on reload, keyed by bare index (not chat) (`:278-288`).
- **Prompt injection**: `setExtensionPrompt('universal_immersion_engine_prompt', …, IN_PROMPT, 0, scan=true, 'system')` refreshed on `MESSAGE_RECEIVED`, `GENERATION_ENDED` and **every 60 s** (`prompt_injection.js:34-66`, `:96`). Content = `rootProtocolBlock`: "[SYSTEM OVERRIDE … CRITICAL PRIORITY: HIGHEST]" + a re-copy of the last 20 messages + inventory/stats/quests/social + keyword-matched databank memories (`apiClient.js:375-440`, `:247-269`). UI actions (use item, equip…) go into an in-memory "hidden event" buffer injected as `[RECENT_ACTIVITY_LOG]` and flushed on any `GENERATION_ENDED` (`features/rp_log.js:10-50`, `prompt_injection.js:38`).
- **LLM calls**: `generateContent(prompt,type)` → Turbo (raw `fetch` to user URL with API key from settings) else `generateRaw({prompt: system+prompt})` (`apiClient.js:1049-1340`); per-type prompt prefixes (`:1140-1156`); optional per-call confirm modal with model + prompt preview (`:442-480`, `:1164-1180`); JSON repair = one "[CORRECTION]" retry (`:1350-1362`); some types forced to Main API (`turboBlockTypes`, `:1056`). On a CORS failure it re-sends the request (headers incl. key) to ~20 guessed proxy paths on the ST server (`apiClient.js:695-780`).
- **Persistence**: settings bucket is `window.extension_settings[EXT_ID]` (`core.js:404-437`); per-chat state copied in/out of `settings.chats[chatId]` by **polling `ctx.chatId` every 1 s** (`core.js:709-840`); mirrored to localStorage + IndexedDB with a "settings look empty → restore" watchdog every 1.5 s (`core.js:6-9`, `:221-270`, `:578-612`); separate IDB auto-backups (`backup.js`).
- **Groups**: anti-"multibot" system prompt at depth 0 on `GENERATE_BEFORE_COMBINE_PROMPTS`, plus post-hoc rewriting of the rendered reply to strip other speakers' lines (`orchestration.js:210-250`, `:429-460`).

## Overlap with Story Orchestrator
- Extraction: SO's shared read is scoped, line-strict, evidence-span checked and boundary-applied (`src/extraction/sharedRead.ts:87`, `src/extraction/evidence.ts:28`, `src/engine/applyQueue.ts:30`); UIE's is an unscoped JSON dump applied immediately, with regex writes. SO strictly better on correctness.
- Rollback: SO's cross-store rollback (`src/runtime/rollback.ts:35`) is persisted and chat-owned; UIE's per-message diff-undo is in-memory and index-keyed. **But UIE handles one case SO does not: a mid-chat single-message delete** (see idea 1).
- Ownership: UIE's scan awaits the LLM (`stateTracker.js:1420`) then writes into the same settings object the 1 s poller swaps on chat change (`core.js:765-777`) — the cross-chat bleed SO closed with `RunToken` (`src/runtime/runToken.ts:138`).
- Persistence: SO uses `chat_metadata.story_orchestrator` + rename restamp (`src/runtime/persistence.ts:60`, `:97`); UIE bloats install settings with every chat and depends on browser storage.
- Multi-model: SO has one Connection Manager profile for every pass (`src/runtime/coordinators/stagecraftCoordinator.ts:148` reuses `extraction.profileId`; `src/runtime/coordinators/copilotCoordinator.ts:33`); UIE routes by call type (idea 4), with a worse transport.
- Injection: SO's registry of small depth-pinned blocks (`src/constants/injectionRegistry.ts:12`, `scan=false` `src/services/stHost/extensionPrompts.ts:24`) vs UIE's one huge scan-enabled block that re-copies chat.
- Group speaking-for-others: SO does talk control + agency steering and never rewrites messages; UIE's rewrite path is dead code (below).

## Ideas for v2.4

| # | idea | kind | our area | our state | value | effort |
|---|---|---|---|---|---|---|
| 1 | Detect mid-chat single-message delete by per-index fingerprint diff | host-integration | host / turnBridge / rollback | absent | 4 | M |
| 2 | Negative memory: author-removed facts fed to the read + paraphrase-level suppression at apply | enhancement | extraction / memory | partial | 3 | S–M |
| 3 | Sanitize extraction windows (strip `<style>/<script>`/CSS/HTML markup) once, in `getChatWindow` | enhancement | extraction | absent | 3 | S |
| 4 | Per-pass Connection Manager profile routing (cheap read vs. strong canon/wizard/curator) | enhancement | extraction / host | partial | 3 | M |
| 5 | Test: one-turn blocks (author nudge) spent by a third-party quiet generation | testing | runtime / copilot | partial | 2 | S |
| 6 | Author-only "about to send" preview + confirm for large manual passes (memorize backlog, wizard) | ux | player-ui / extraction | partial | 2 | S–M |
| 7 | Anti-pattern: unowned async writes + chat-blind caches + guessed host globals | anti-pattern | engine / host | present | 2 | S |

**1. Mid-chat delete detection.** ST emits `MESSAGE_DELETED` with the **post-deletion `chat.length`**, never the deleted index — including `deleteMessage(id)`, which `splice`s a message out of the middle (`script.js:1677-1699`), reached from the message edit panel's Delete (`script.js:11984-11991`) and `/cut` (`scripts/power-user.js:2853`). Theirs: fingerprint list diff → which message vanished (`stateTracker.js:2463-2495`, fingerprint = is_user|name|send_date|len|head|tail `:299-312`). Ours: `TurnBridge` treats the payload as the first deleted id and calls `rollbackFromMessage(chat.length)` (`src/runtime/turnBridge.ts:56`, `:159-170`), which rewinds nothing when a middle message is deleted, while every later message index shifts down by one — memory/epistemic/ledger rows keyed by `messageId` then point at the wrong message and the deleted message's facts survive (`src/memory/stores.ts:109-115` only acts on `messageId >= cut`). Fit: keep a per-chat fingerprint list at each committed boundary; on delete, first mismatching index = real cut → existing `runRollback` path. Strengthens invariant 11 (rollback ≡ replay); keep fingerprints out of the persisted blob (recompute on hydrate) or bump blob version (inv 13). Needs a live probe (delete a mid-chat message after a fired transition) before it is claimed a defect — static reading only here.

**2. Negative memory.** Theirs: names the player deleted are listed in the prompt as "Deleted Social Names" (`stateTracker.js:1353`) **and** filtered again at apply (`:1826`) — prompt asks, code enforces. Ours: exclusion is an exact text-hash filter (`src/memory/stores.ts:28-30`, `:146`); a paraphrase of an excluded fact returns on the next read, and the store keeps only hashes so nothing can be shown to the model or matched by similarity. Fit: keep excluded text (author content, never epistemic → inv 15 fine), run it through the existing dedup bands (`src/runtime/consolidationMatches.ts:8`, dup ≥0.82) at `addMemoryEntries`, optionally list recent exclusions in the read prompt as "do not re-report". Shape change to `extras.memory` → migration; exclusion reversal must still honour `derived.ts` rule 3.

**3. Window sanitizer.** Theirs: `stripCssBlocks` + DOM clone removing `style, script, noscript, template, button, input, textarea` before any scan (`chatLog.js:3-33`, `:131-157`). Ours: `readMessage` passes raw `mes` (`src/extraction/chatWindow.ts:7-14`) — community cards and tracker extensions embed HTML/CSS status panels in replies, which cost read tokens, can be quoted as "evidence", and can trip the parser. Fit: sanitize inside `getChatWindow` so the prompt, the evidence-span check (`src/extraction/evidence.ts:28`) and the stored `evidence` all see the same text (inv 4). Do **not** copy their `You`/`Story` relabelling — speaker names matter for epistemic/ledger.

**4. Per-pass model routing.** Theirs: route by call type, block some types from the fast model (`apiClient.js:1049-1058`), warn and fall back to main when the side model is unready (`:1183-1191`, `:1320`). Transport is the anti-pattern (key in plaintext settings, CORS spray `apiClient.js:695-780`). Ours: every pass uses one profile (`src/runtime/coordinators/stagecraftCoordinator.ts:148`, `copilotCoordinator.ts:33`, `src/extraction/client.ts:11`). Fit: optional install-wide `profiles.{sharedRead, scenePasses, canon, curator, wizard}` falling back to `extraction.profileId`; still Connection Manager only (inv 2, 13); self-test per assigned profile (`src/runtime/selfTest.ts:156`). Cost/latency win is exactly the v2.3 finding that the reply-path budget is tight.

**5. Quiet-generation test.** Theirs: the hidden-event buffer is flushed on any `GENERATION_ENDED` (`prompt_injection.js:38`) and ST emits that for quiet generations too (`finishGenerating` always calls `showStopButton`, `script.js:5336`; `GENERATION_ENDED` from `hideStopButton`, `:3536`) — so a third-party quiet call eats the player's events. Ours: the warden note skips quiet/impersonate at start (`src/runtime/coordinators/stagecraftCoordinator.ts:457`), but `onGenerationEnded` clears the author nudge unconditionally (`src/runtime/runtimeManager.ts:636`, `copilotCoordinator.ts:196-208`), and the nudge sits in the prompt during that quiet call. Add a scenario: set nudge → `/genraw`-style quiet generation from another source → assert nudge still pending for the next loud turn. Cheap; possibly a real defect.

**6. Pre-send preview.** Theirs: optional confirm modal naming the model and showing the first 900 chars before any AI call, mandatory for HTML generation (`apiClient.js:442-480`, `:1164-1180`). Ours: we record prompt+raw after the fact (audits, `lastPass`) and the privacy report flags `runMemorizeBacklog` sending the whole chat; no pre-send look. Fit: author-only, manual passes only (never the reply path or scheduler, inv 5), shows profile + char count + head. Low priority.

**7. Anti-pattern bundle (confirms our rules).** (a) async scan writes after an await into a chat-swappable object with no ownership (`stateTracker.js:1420` vs `core.js:765-777`) — our inv 10; (b) undo cache keyed by bare message index in `window` (`stateTracker.js:278-297`) — the same class as our v2.1 talk-decision cache bug (now `chatId:checkpointId:lastMessageId`); (c) host shapes guessed via `ctx?.world_info || ctx?.lorebook || …` (`apiClient.js:52-66`, `:155-175`) — `getContext()` has none of these (no hit in `scripts/st-context.js`), so both WI blocks are always empty; (d) `window.eventSource`/`window.setExtensionPrompt`/`window.chat` guards make `orchestration.js`, `group_harmony.js:361-383` and `sprites.js:1294-1320` bind nothing on stock ST, and the rewrite selector `[data-mes-id]` (`orchestration.js:440`) does not exist (ST uses `mesid`, `script.js:1654`). Nothing to build; cite in onboarding docs as why `stHost/*` + verified shapes exist.

## Patterns to copy / anti-patterns to avoid
Copy:
- Prompt-asks + code-enforces pairs for anything the author removed (`stateTracker.js:1353` + `:1826`).
- Content fingerprint per message as a mutation detector independent of ST's event payloads (`stateTracker.js:299-312`).
- A one-call self-report of what is bound and when it last fired (`index.js:24-98`) — our capability read-out already covers presence; "last trigger / last run / last error" timestamps per subscription are a cheap addition to "Copy for a bug report".
- Hard char cap on every read window (`chatLog.js:180`) — supports our open seed "no request-size bound on extraction path" (baseline §3D). Cap by whole messages, not a tail char slice (theirs can cut mid-message).

Avoid:
- Regex that writes state (`stateTracker.js:1266-1300`, regex at `:1269`) — violates inv 4.
- One giant scan-enabled system block that re-copies the chat and is refreshed on a 60 s timer (`prompt_injection.js:58-60`, `:96`; `apiClient.js:392-440`) — tokens, WI false triggers via `scan=true`, "SYSTEM OVERRIDE" shouting.
- Per-chat state in install settings + 1 s `chatId` polling + localStorage/IDB mirrors + "looks empty → restore" watchdog (`core.js:6-270`, `:578-612`, `:835-840`) — symptom of writing to a bucket ST never persists (host facts).
- Sending an API key to guessed proxy endpoints (`apiClient.js:695-780`).
- Rewriting rendered message DOM/text after the fact (`orchestration.js:436-460`) — SO never touches `mes_text`.
- `?v=Date.now()` on every module and stylesheet import (`index.js:100`, `:143-151`): defeats caching entirely; our stale-ETag trap is solved by the reload tool, not by never caching.

## ST host facts learned
- `MESSAGE_DELETED` payload is post-deletion `chat.length` on every path, including mid-chat `deleteMessage` splice (`script.js:1611`, `:1682-1699`, `:4411`, `:11734`); reached from the edit-panel Delete (`script.js:11990`) and `/cut` (`scripts/power-user.js:2853`). UIE consumes it by fingerprint diff (`stateTracker.js:2463`). **Contradicts an implicit assumption in `src/runtime/turnBridge.ts:159-170`** (payload used as the first deleted id); not in our gotchas.
- `GENERATION_ENDED` payload is `chat.length` (not a message id) and fires for quiet generations too (`script.js:3536`, `:5336`); UIE treats it as a message id (`stateTracker.js:290-297`, `:2461`) → off-by-one undo key.
- `setExtensionPrompt` coerces role with `Number(role)` (`script.js:8932`); UIE passes the string `'system'` (`prompt_injection.js:96`) → `NaN` role. Our seam passes numeric `0` (`src/services/stHost/extensionPrompts.ts:24`) — consistent.
- `generateRaw` takes an options object `{prompt, api, instructOverride, quietToLoud, systemPrompt, responseLength, trimNames, prefill, jsonSchema}` (`script.js:4122`); UIE's `skip_w_info` (`apiClient.js:1322`) is silently ignored and it concatenates the system prompt into `prompt` instead of `systemPrompt`.
- ST does not put `extension_settings`, `eventSource`, `event_types`, `chat` or `setExtensionPrompt` on `window` (only `globalThis.SillyTavern`, `script.js:293`; no assignment found in `script.js`/`lib.js`/`scripts/*.js`). UIE's `window.extension_settings[...]` bucket (`core.js:416-419`) is therefore its own object that `saveSettingsDebounced` never writes — which is why it needs localStorage/IDB mirrors. Their working modules import from `/script.js` instead (`prompt_injection.js:2`, `stateTracker.js:29`). Consistent with our "context from `globalThis.SillyTavern`" rule.
- `getContext()` exposes no `world_info`/`lorebook` field (`scripts/st-context.js`, no match); UIE's lore blocks read it anyway (`apiClient.js:52-66`, `:155-175`).
- Chat messages carry `send_date` usable in a stable per-message fingerprint (`stateTracker.js:303`); rendered messages are `.mes[mesid="N"]` (`script.js:1654`), not `data-mes-id`.

## Verdict
Relevance **medium-low**. A different product (RPG overlay), mostly built on patterns SO deliberately rejected. The one thing worth taking: **ST's `MESSAGE_DELETED` never names the deleted message, and UIE's fingerprint diff is the fix** — verify live that a mid-chat delete leaves SO's rollback and message-keyed memory stale, then add boundary-time fingerprints to `TurnBridge` (idea 1). Negative-memory suppression (2) and window sanitizing (3) are cheap follow-ons.
