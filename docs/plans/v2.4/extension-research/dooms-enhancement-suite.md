# Doom's Enhancement Suite — v2.4 review

Author: Doom (DangerDaza) · repo https://github.com/DangerDaza/Dooms-Enhancement-Suite · commit `f920222` (2026-09-06, "Release 2.5.0 — House Rules") · 38 upvotes / 962 msgs · source available: yes (`source/`, ~41k lines JS, vanilla ES modules + jQuery, no build). Fork of SpicyMarinara's RPG Companion, "vibe-coded with Claude Code" (post.md).

## What it is
Single-card "narrator runs a cast" RPG overlay: an LLM-filled tracker (scene info, present characters + thoughts/relationship, quests) rendered as portrait bar, scene headers, chat bubbles, weather, thought bubbles; a Lore Library that replaces ST's WI UI; a **Doom Counter** (tension-streak → countdown → plot-twist cards) with per-character authored **Knives**; Character Workshop (aliases, inject/eject a character into the scene, sprites, portraits); a Context Inspector. Mostly presentation; the parts relevant to SO are the generation-lifecycle handling, the twist/knife pacing loop, aliases and the inspector.

## How it works
- **Tracker generation, 3 modes** (`generationMode`): `together` = main model appends a JSON tracker block to its reply, parsed on `MESSAGE_RECEIVED` (`src/systems/integration/sillytavern.js:153-236`), block hidden by a regex script they register; `separate` = `generateRaw` side call 500 ms after the reply (`sillytavern.js:283-300` → `src/systems/generation/apiClient.js:244-420`), optionally after switching the **user's** Connection Manager profile + preset via `/profile` `/preset` slash commands and restoring them in `finally` (`apiClient.js:281-300`); `external` = direct OpenAI-compatible fetch, key in `localStorage` (`apiClient.js:47-49`).
- **Injection**: all through a wrapper `desSetExtensionPrompt` (`src/systems/generation/inspector.js:377-390`) — slots `dooms-tracker-inject|example|html|dialogue-coloring|context` IN_CHAT, `dooms-tracker-new-fields` IN_PROMPT (`src/systems/generation/injector.js:650-960`). Slots are cleared on disabled/suppressed generations and re-evaluated on `GENERATION_AFTER_COMMANDS` (`injector.js:977-997`, registered `:1031`). History persistence splices per-message "Context for that moment:" snapshots into the assembled prompt by **string-matching message content** in `GENERATE_BEFORE_COMBINE_PROMPTS` / `GENERATE_AFTER_COMBINE_PROMPTS` / `CHAT_COMPLETION_PROMPT_READY` (`injector.js:180-455, 524-640`).
- **Suppression** (`src/systems/generation/suppression.js:48-144`): per generation, decides to drop tracker instructions for `type==='impersonate'`, a `quiet_prompt`, or any GuidedGenerations guide present in `chat_metadata.script_injects.{instruct,thinking,state,…}` (+ regex over the inject text for impersonation phrasing).
- **Doom Counter** (`src/systems/generation/doomCounter.js`): model reports `doomTension` 1–10 inside the tracker JSON (`:882`); `onResponseReceived` (`:92-180`) counts a low-tension streak (≤ ceiling 4) → after threshold 5 a visible countdown ticks down faster at lower tension (`:78` 1→3, 2→2, else 1) → trigger opens inline twist cards generated by `generateRaw` over last 15 msgs + tracker scene (`:387-540`, JSON repaired, fallback twists on failure). Chosen twist → one-shot injection at `twistInjectionDepth` on next `GENERATION_STARTED`, then cleared (`injector.js:712-737`). Trap mode = silent auto-pick (`doomCounter.js:568`). State in `chat_metadata.dooms_tracker.doomCounterState` (`src/core/persistence.js:919-940`).
- **Knives**: pre-written beats per NPC/persona, stored install-wide (`extensionSettings.characterKnives`), `used` flag, candidate = random present character with armed knives (`doomCounter.js:224-300`); LLM "Generate Knives" by theme chips (`src/systems/ui/characterWorkshop.js:122-131`, `doomCounter.js:303`).
- **Workshop inject/eject/ban** (`characterWorkshop.js:63-100, 2388-2480, 2742-2807`): one-shot IN_PROMPT "[SCENE DIRECTION — INJECT CHARACTER]" template with `{?var}…{/var}` conditional blocks, optional lorebook activation, vision attach of portrait on next `MESSAGE_SENT`; lifecycle guarded so quiet/dryRun generations neither consume nor clear it (`inRealGeneration`, `injectStartsToSkip`).
- **Persistence**: per-chat blob `chat_metadata.dooms_tracker` rebuilt whole on each save (`persistence.js:552-586`, immediate `saveChatConditional` at commit points, debounced otherwise); **per-swipe** tracker payload on `message.extra.dooms_tracker_swipes[swipe_id]` with fallback to `swipe_info[swipe_id].extra` (`sillytavern.js:210-222`, `injector.js:217-224`). Many settings install-wide (`lockedItems`, knives, aliases).
- **Mutation handling**: swipe → load that swipe's stored payload for display (`sillytavern.js:435-480`); delete → re-derive from new tail message's payload (`:506-558`); edit → decorations only (tracker data of an edited message stays). Doom Counter state is never rolled back.
- **Locks**: `applyLocks` adds `"locked": true` to JSON sent to the model; `removeLocks` strips the flag from the reply and **accepts whatever value the model wrote** (`src/systems/generation/lockManager.js:16-35, 220-250`). Prompt-only.
- **Aliases**: `extensionSettings.characterAliases[canonical] = [...]`; parsed tracker names canonicalized before anything downstream sees them, prose untouched (`src/systems/features/characterAliases.js:47, 549`); structural variants + `namesAreSimilar` (normalize/NFD, capped Levenshtein ≤1–2, token-subset, space-prefix) queue a one-at-a-time "same character?" dialog (`src/utils/nameSimilarity.js`, `characterAliases.js:178-548`).
- **Context Inspector** (`inspector.js:1-130`): slot registry with labels, `currentSlots` (live), per-generation record (slot writes with `previousContent`, in-flight event mutations with before/after, the separate-mode prompt), ring 25, `window.DES_INSPECTOR`.
- **Events**: all via `registerAllEvents`/`unregisterAllEvents` teardown map (`src/core/events.js:44-80`, map at `index.js:3407-3428`). No `generate_interceptor`, no slash commands, no macros, no tool calling, no vectors.

## Overlap with Story Orchestrator
- Tension: theirs = raw 1–10 model self-report + streak counter; ours = extracted level → EMA vs dramatic-shape expectation → steering hint (`src/pacing/steering.ts:47`). Ours is better-founded; theirs has the thing ours lacks — a **concrete payload** when pacing stalls (twist/knife), where ours emits generic "force a confrontation, a reveal…" text (`steering.ts:24-45`).
- Locks: ours is truth (`Lock as canon`, `src/runtime/memoryQueue.ts:144`, quarantine excluded from injection); theirs is prompt-only and install-wide. Ours strictly better.
- Swipe/delete: ours rolls back every store (`src/runtime/rollback.ts:35`); theirs keeps per-swipe payloads so swiping back is free, but never rolls back the counter. Different trade-off (see idea 6).
- Side LLM calls: ours via `ConnectionManagerRequestService` without touching the user's active profile (`src/services/stHost/connectionProfiles.ts:43`); theirs flips the user's profile/preset. Ours better.
- Inspector: our next-turn preview (`src/runtime/nextTurn.ts:76`) + payload ring (`src/runtime/journal.ts:146`) + audit prompts cover "what goes out next"; theirs adds a per-generation diff of who wrote which slot.
- Suppression: we withhold only the private epistemic block for impersonate/quiet (`src/runtime/runtimeManager.ts:633`) and the warden note on start (`src/runtime/coordinators/stagecraftCoordinator.ts:458`); theirs has a fuller per-generation-kind policy incl. GuidedGenerations.
- Present cast/portraits, bubbles, weather, lore library, sheets: out of SO scope (baseline §4) except a small "who's here" read-out.

| 2 | One-turn injections cleared only by the END of the generation they were for | host-integration | stagecraft/engine | partial | 4 | S |

**1. Fetch watcher self-heal.** DES's `safeGenerateRaw` replaces `window.fetch` around every `generateRaw` and restores the reference it captured in `finally` (`src/utils/responseExtractor.js:75-109`). Our save watcher wraps `globalThis.fetch` once and sets `installed = true` (`src/services/stHost/persistence.ts:57-73`). If our first install lands while a DES separate-mode call is in flight (it fires ~500 ms after every reply, `sillytavern.js:283`), DES restores the native fetch over ours, `installed` stays true, every later `observeNextSave` times out as "no save request went out", `saveHealth` reads unsaved and `withLedger` refuses effects (`PENDING_NOT_SAVED`). Fix: keep a reference to our wrapper, re-check `globalThis.fetch === wrapper` in `observeNextSave`, re-wrap if displaced, journal "watcher displaced" as `unconfirmed` (not `unsaved`). PLAUSIBLE, not live-reproduced — needs a two-extension live check. Strengthens invariant 17; no conflict.

**2. One-turn lifecycle keyed to the real generation.** DES found that quiet generations from other extensions (GuidedGenerations autotriggers) fire `GENERATION_STARTED`/`ENDED` around the user's reply, and an unguarded `ENDED` wipes a one-shot prompt before the real reply is built; fix = remember the real START, ignore quiet/dryRun/image STARTs, clear only on the matching ENDED (`characterWorkshop.js:2771-2807`). ST emits `GENERATION_ENDED` from `hideStopButton` with only `chat.length` (`script.js:3536`) and `finishGenerating` shows the stop button for every type incl. quiet (`script.js:5336`), so the event carries no type. Ours: start side filters quiet/impersonate (`stagecraftCoordinator.ts:458`, `runtimeManager.ts:633`) but `onGenerationEnded` unconditionally clears the author nudge, the warden note and the private epistemic block (`runtimeManager.ts:634`, wired `src/runtime/index.ts:191-192`). A foreign quiet generation can therefore consume an author Nudge or a warden note it was never shown. Fix: a small `GenerationLifecycle` in runtime tracking the loud generation id; ENDED clears only when it closes the loud one. Fits invariants (host facts via stHost/events). Needs a live check with a quiet-gen extension (Stepped Thinking is installed here).

**3. Generation-kind carry policy.** DES suppresses its blocks for impersonate / quiet / GuidedGenerations `chat_metadata.script_injects` guides and re-checks on `GENERATION_AFTER_COMMANDS` because `/inject` lands asynchronously (`suppression.js:48-144`, `injector.js:33-40, 977-997`). Ours: `INJECTION_REGISTRY` (`src/constants/injectionRegistry.ts:12`) has no per-kind policy, so the pacing hint ("…Do not narrate the player's own words") rides into an **impersonation**, which is precisely a request to write the player's words, and every block rides into other extensions' quiet generations (image prompts, thinking). ST's `setExtensionPrompt` already takes an async `filter` (`script.js:8926`, evaluated `:3241/:3270/:3304`) — declare `carries: {normal, impersonate, quiet}` per registry entry and pass a filter reading the generation kind captured at START, instead of DES-style clear/re-set. Unused by us today (grep `filter` in `stHost/extensionPrompts.ts`: 0). Keeps invariant 16 (the write still refreshes; the filter only gates inclusion); next-turn preview should show the policy.

**4. Aliases + canonicalization.** DES canonicalizes names at the parse chokepoint and asks the user once when a new name is similar to a known one (`characterAliases.js:47, 549`; `nameSimilarity.js` Levenshtein-capped + token-subset + prefix). Ours keys ledger rows by `trim().toLowerCase()` (`src/memory/ledger.ts:23`) and epistemic subjects the same way (`src/memory/epistemic.ts:12, 99`); `RosterMember` is `{id,name,role}` (`src/engine/schema.ts:177`), no aliases anywhere (grep `alias` in memory/extraction: 0). Consequence: "Sarah Greenfield" and "Sarah" become two ledger entities and two epistemic subjects, and the per-member private block (selected by normalized subject name) never carries rows filed under the alias. Proposal: authored `roster[].aliases`, canonicalize extracted entity/subject/hiddenFrom names in the pure parse path, and let an unknown-but-similar name raise an author-only conflict-queue card ("same as Sarah?" → record alias in the pinned story via the Studio mutation path). Invariant 4 holds (normalization of a parsed signal, not text writing state); 12 holds (alias is authored story content, new version); 9 holds (author-only card). Talk mention matching (`src/talk/rules.ts`) benefits too.

**5. Complication pool.** DES's loop (`doomCounter.js:92-180`, knives `:224-300`, one-shot inject `injector.js:712-733`) turns "too calm for too long" into a specific authored beat tied to a present character, spent once. Ours has the better detector (EMA vs expected, `src/pacing/tension.ts:21`, `shapes.ts:33`) but only generic hint text; grep `complication|twist|streak` in src: 0. Proposal: story-authored `complications[]` (per roster member and/or checkpoint: text, requires-present, once), drawn when the pacing coordinator has held `escalate` for N consecutive boundaries, delivered as a one-turn steering block (same lifecycle as nudge, idea 2). "Spent" must be DERIVED from the boundary log like `src/runtime/agencyRecovery.ts:25`, never a mutable flag, so rollback reverses it (invariant 11; DES's `used` flag is not rolled back). Player-choice cards conflict with invariant 9 (player cannot steer, and cards spoil) — use DES's Trap mode shape (automatic, silent) for players; author view gets "draw now". Injection-only, no blackboard write (invariant 3); agency policy phrasing applies (`src/engine/agency.ts:6`). Wizard/Studio can suggest themed complications (DES's `KNIFE_THEMES`, `characterWorkshop.js:122`, with its explicit "not every knife a betrayal" guidance) — a copilot stage, create-only content in the draft.

**6. Swipe-keyed boundary cache.** Navigating to an EXISTING swipe emits only `MESSAGE_SWIPED` (`script.js:10315`; generation only when `run_generate`), and ST clones `message.extra` into `swipe_info[swipe_id].extra` (`script.js:6939`). DES exploits that: each swipe keeps its own payload and swipe navigation just reloads it (`sillytavern.js:435-480`). Ours: swipe → `rollbackFromMessage` (`src/runtime/turnBridge.ts:54, 159`), nothing re-commits until the next rendered reply, which then re-extracts that message — extra LLM cost, possibly a different verdict than the one the player saw, and (one transition per boundary) a transition fired on that swipe is delayed a boundary. Proposal: record the boundary result + accepted deltas keyed `(messageId, hash(swipe text))` in our blob; on `MESSAGE_SWIPED` to a known key, replay the recorded boundary instead of leaving the story rolled back. Rollback ≡ replay (invariant 11) is preserved because the cache IS the recorded replay of the same input; must be journaled and capped. L because it touches TurnBridge, engine replay and every store's reversal.

**7. Prompt fingerprint golden.** DES pins its default tracker prompt byte-identical in a node golden (`tools/tracker-prompt-test.mjs:1-20`) because a wording drift silently changes every user's model input. Our goldens are responses (`test/goldens/*.response.txt`), no prompt snapshots (grep `toMatchSnapshot`: 0 in src). Every judge floor and the live-suite baseline were calibrated against specific prompt text; a hash per prompt builder (shared read, epistemic, canon, curator, director, judge questions) in a golden, with the failure message "re-run calibration for <use>", makes invariant 7 enforceable against drift. Could ride `dist/manifest.json` as a `prompts` section.

**8. Injection write log.** DES wraps every `setExtensionPrompt` and records per-generation slot writes with the previous content, plus event-time mutations (`inspector.js:104-130, 377-390`). Ours shows the next turn and a 5-capture ring, not *which writer changed a block between two generations*. Cheap author-view addition: record `{key, writer, before, after, generationId}` in `setStoryExtensionPrompt` (`src/services/stHost/extensionPrompts.ts:19`); useful for exactly the "block went empty" class in gotchas (J5.8, `applyEpistemic` refresh). Low value because the payload capture already catches most.

**9. Who's here.** DES's whole identity is the present-cast bar; SO's player overview names where you are but not who is present (grep `present` in `runtime/narrative.ts`, `HudStrip.tsx`, `PlayerOverview.tsx`: 0) although the scene read has a present list (`src/runtime/coordinators/sceneCoordinator.ts:33`). A names-only chip is spoiler-free (invariant 9). Nice-to-have.

## Patterns to copy / anti-patterns to avoid
Copy:
- Lifecycle guard for one-shot prompts vs foreign quiet/dryRun generations (idea 2).
- `registerAllEvents`/`unregisterAllEvents` teardown map (`src/core/events.js:44-80`) — we should confirm our event seam can unsubscribe everything (useful for the hot-reload stale-bundle trap).
- Isolated renderers so one throwing panel cannot skip the persistence after it (CHANGELOG 2.4.1; `safeRender` in `sillytavern.js:227-236`) — same shape as our try/caught boundary work.
- Chat-switch render token with chatId re-check (`sillytavern.js:363, 409-414`) — their RunToken.
- Immediate save at commit points, debounced only for keystrokes (`persistence.js:548-586`).
- A parity checklist doc (`docs/parity-checklist.md`) and "measure, verify, then delete; never trust labels" (`docs/rebuild-philosophy.md`) — matches our findings-ledger culture.
- `{?var}…{/var}` conditional template blocks for authored injection templates (`characterWorkshop.js:2718-2734`).

Avoid:
- Prompt-only locks: `"locked": true` sent, AI value accepted anyway (`lockManager.js:220-250`), and locks stored install-wide so they leak across chats.
- Monkey-patching global `window.fetch` per call (`responseExtractor.js:77-108`) and `toastr` (`src/systems/ui/notificationLog.js:66-71`) — non-reentrant, clobbers other wrappers (idea 1).
- Switching the user's connection profile/preset for a side call (`apiClient.js:281-300`) — races the user's next send, mutates install state.
- API key in `localStorage` (`apiClient.js:49`).
- Writing to `chat[chat.length-1]` after an await with no chat ownership check (`apiClient.js:370-390`).
- Counter state advanced by every fresh generation, incl. swipes/regens, never rolled back on delete/edit (`sillytavern.js:283-300`, `persistence.js:919-940`).
- Silently rewriting another extension's settings (TTS regex, `index.js:3080-3086`).
- Rebuilding the whole metadata blob on each save, dropping any field not copied (`persistence.js:556-577`, their own comment).
- Splicing context into the assembled prompt by string-matching message content (`injector.js:312-455`) — breaks with any formatting/regex change.
- User-editable prompt stored verbatim freezing the dynamic prompt (CHANGELOG 2.5.0 "Saving the Prompts Editor could silently freeze the tracker prompt") — if SO ever exposes prompt editing, store an explicit override flag, compare before writing.
- `.catch` on `saveChatConditional()` (`persistence.js:583`) — unreachable, it never rejects (corroborates our gotcha).

## ST host facts learned
- GuidedGenerations writes its guides via `/inject id=<guide>` into `chat_metadata.script_injects.<id>`; ids `instruct, thinking, state, clothes, rules, situational, custom, customAuto, tracker, fun` (`suppression.js:18-29`); ST side `slash-commands.js:3814-3822`.
- `/inject` writes can land after `GENERATION_STARTED`; `GENERATION_AFTER_COMMANDS` fires once the slash queue drains, before prompt build (`injector.js:33-40, 977`; ST `script.js:4321`). Consistent with our gotchas; new to us.
- Quiet generations from other extensions fire `GENERATION_STARTED`/`ENDED` around the user's reply and their ENDED can clear one-shot prompts (`characterWorkshop.js:2771-2807`). **Contradicts our implicit assumption** in `runtimeManager.ts:634` (ENDED = end of the loud generation).
- `GENERATION_STARTED(type, data, dryRun)`: `dryRun` true for page reload / prompt-manager preview; `data.quietImage` for image generation (`injector.js:650-660`). Consistent (`script.js:4299`).
- Per-swipe extras live on `message.extra` in-session and in `swipe_info[swipe_id].extra` after load (`injector.js:217-224`, `persistence.js:739-743`); ST clones `extra` into `swipe_info` (`script.js:6939`).
- Activating a global lorebook by pushing into `selected_world_info` + `updateWorldInfoList()` also needs `$('#world_info').trigger('change')` or `world_info.globalSelect` reverts on reload (`src/systems/lorebook/lorebookAPI.js:92-101`). Consistent with our globalSelect-mirror gotcha (we use `/world state=on`).
- `message.extra.display_text` is used for rendering as well as TTS; setting it hides formatting on reload (`index.js:3011-3025`).
- `generateRaw` throws "No message generated" when the backend returns reasoning only (extended thinking) (`responseExtractor.js:96`). Consistent with our `stripReasoningBlocks` unterminated-block rule.
- `event_types.MORE_MESSAGES_LOADED` is absent on older ST builds (`index.js:3423-3427`).
- A debounced chat save can be dropped by a fast chat switch (`persistence.js:548-551`). Consistent.
- Claim, UNVERIFIED: `getContext().chatMetadata` did not reliably expose `script_injects`, the `script.js` live export did (`suppression.js:52-66`). Likely a stale-context-object effect (chat_metadata is reassigned per chat); we call `getContext()` per read, so not a contradiction, but re-verify before reading `script_injects` for idea 3.

## Verdict
Relevance **medium**. Mostly a presentation suite outside SO's scope, and several of its state practices are ones SO already rejected (prompt-only locks, profile flipping, no rollback). Worth taking: the **generation-lifecycle lessons** — (1) our save watcher can be silently displaced by DES's per-call `fetch` swap, and (2) our `onGenerationEnded` clears one-turn blocks on any generation's end, including foreign quiet ones — both S-effort, both need a two-extension live check. The one feature worth taking is the **authored complication pool** (knives) as a concrete payload for our already-better tension detector, with spent-state derived from the boundary log.
