## What it is
Presentation layer over ST's own Visual Novel mode (`waifuMode`) + expressions extension. Pure DOM/CSS: speaker focus/defocus/shake on sprites, card-image "sprite emulation" for cards without sprite packs, a phantom user sprite, auto-hide to N most-recent talkers, CSS-filter world/character tint (time-of-day look over one background), letterbox bars, hide-chat-box, "only last message" traditional VN mode, a chat-history popup. No LLM calls, no prompt injection, no chat_metadata. All settings install-wide.

## How it works
- **Entry** `index.js:290` jQuery ready: appends `html/settings.html` to `#extensions_settings` (`:301`), wand-menu button into `#extensionsMenu` (`:312`), letterbox divs onto `body` (`:291-297`), registers slash commands, calls `loadSettings()`.
- **Settings** `extension_settings["Prome-VN-Extension"]`, defaults merged key-by-key for new keys (`index.js:105-110`, defaults `constants.js:~91`). Everything global, `saveSettingsDebounced`. Seeds `enableVN_UI` from `power_user.waifuMode` and then *hijacks* it: `onVNUI_Click` writes `power_user.waifuMode`, toggles `body.waifuMode`, syncs ST's `#waifuMode` checkbox (`index.js:258-268`, `:217-219`).
- **Events** (`index.js:348-399`): `MESSAGE_SWIPED`→shake; `CHARACTER_MESSAGE_RENDERED`→stopShake; `CHAT_CHANGED`/`MESSAGE_DELETED`/`GROUP_UPDATED`→re-apply focus/defocus/scale/emulation/auto-hide + `visualNovelUpdateLayers`; `GENERATION_AFTER_COMMANDS` removes phantom `prome-user` from `group.members`, `GENERATE_AFTER_COMBINE_PROMPTS` pushes it back (`:376-399`) so the fake member never gets drafted.
- **DOM driving**: a `MutationObserver` on `#chat` and (after a 100 ms poll for it) `#visual-novel-wrapper` re-runs everything on every added/removed `.mes` / `.expression-holder` (`index.js:418-477`). `waitForElement` polls 50×100 ms (`listeners.js:81`).
- **Speaker focus** `listeners.js:102` `applyZoom` / `:155` `applyDefocus`: last message from `getLastChatMessage()` = chat reversed, filtered `!is_system && !extra?.image` (`utils.js:8-13`); user message → focus user sprite; group → `#visual-novel-wrapper [id='expression-<original_avatar>']`; disabled member (`group.disabled_members`) → defocus all.
- **Shake**: only when `textgen_settings.streaming` and `streamingProcessor && !isStopped` (`listeners.js:66-72`); stop polls `isFinished && !isStopped` every 100 ms with a 10 s hard cleanup (`listeners.js:361-417`).
- **Sprite emulation**: `GET /api/sprites/get?name=<char>` (`utils.js:94`); empty list → set the sprite `<img>` src to `/characters/<avatar>` (`listeners.js:208-248`).
- **User sprite**: pushes `{name:"prome-user", path}` into `extension_settings.expressionOverrides` (`index.js:119-127`), pushes a fake character `{avatar:"prome-user"}` into `context.characters` and into `group.members` (`modules/user.js:75-92`), drives it with expressions' `sendExpressionCall` (`user.js:152`); `/express` swaps the img src directly (`modules/slash-commands.js:536-543`).
- **Auto-hide** `modules/auto-hide.js:66`: keep the N most recent distinct non-user, non-system speakers who are still members (`utils.js:20`), `displayNone` the rest.
- **Tint** `modules/tint.js:47` `addTint`: builds a CSS `filter` chain (blur/brightness/contrast/grayscale/hue/invert/saturate/sepia) into `--prome-background-tint-filter` / `--prome-character-tint-filter` on `documentElement`; body classes gate it; CSS applies to `#bg1` and sprite holders (`style.css:315-331`). Named presets saved in settings.
- **Traditional VN mode** `modules/sheld.js:22-59`: `#chat .mes:not(.last_mes)` → `displayNone`, hides `#show_more_messages`; re-run on every chat mutation.
- **Chat history** `modules/chat-history.js:45`: renders `context.chat` through ST's `messageFormatting` + `appendMediaToMessage` + `addCopyToCodeBlocks` into a `callGenericPopup` (wide/large).
- **Slash** 14 toggles via `SlashCommandParser.addCommandObject(SlashCommand.fromProps…)` with `enumList` autocomplete, each returns the new state (`slash-commands.js:29-437`).
- Mutation handling: none semantic — swipe/delete just re-apply visuals. LLM calls: none. Persistence: install-wide settings only.

## Overlap with Story Orchestrator
- **Backgrounds**: we switch the background per checkpoint (`src/services/stHost/backgrounds.ts:50` `applyBackground`, effect `src/engine/schema.ts:87`). Prome cannot change *what* is shown per story beat, only a global look. We have no look/tint/VN layer at all (grep `sprite|visual-novel|waifuMode|tint|letterbox` in `src/`: only theme vars in `styles.css`).
- **Cast**: our `cast_changes` writes `group.disabled_members`; Prome reads it for defocus/auto-hide (`listeners.js:54`, `utils.js:132`), so our cast effects already propagate into VN mode for free.
- **Speaker identity**: our `activeSpeakerId` (`src/runtime/roster.ts:30`) scans for the last non-user message but does **not** skip `is_system`/`extra.image`; Prome's `getLastChatMessage` does. See idea 1 — this is the sharpest finding.
- **Transition notes**: we post `/comment compact=true` at the boundary (`src/runtime/effectsApplier.ts:173`). ST's `/comment` is `is_system: true` (`slash-commands.js:6118`) and becomes `.last_mes` (`script.js:2595-2596`) — under Prome's "only last message" mode the note is the only visible message and **hides the character's reply**. See idea 2.
- Settings hygiene: they merge new default keys; we sanitize (`src/runtime/settingsStore.ts`), stronger.

**1. Active speaker skips non-turn messages.** What: `activeSpeakerId` returns on the *first* non-user message from the end; if that is our own transition `/comment` (name `Note`, `is_system: true`), a `/sys`/narrator line, or a hidden message, the name matches no roster member and it returns `null` (`src/runtime/roster.ts:34-41`). `null` then filters every character-scoped fact out of the facts block (`src/memory/inject.ts:27` `entry.characterId === activeSpeakerId`) and makes `getEpistemicBlock` fall back to all enabled names (`memoryCoordinator.ts:405-406`), via `updateInjection` (`memoryCoordinator.ts:448`). Their evidence: `utils.js:8-13` filters `!mes.is_system && !mes.extra?.image`, `utils.js:20` also `!is_user`. Our evidence: roster.ts:36-40 has only the `is_user` skip. Status: PLAUSIBLE, not reproduced live — needs a solo-chat probe: fire a transition with `announceTransitions` on, then read `getMemoryInjectionBlocks().facts` for a character-scoped fact. Fit: pure change in a runtime helper; matches `TurnBridge`'s non-turn denylist idea (`turnBridge.ts:9`); refresh-own-injection invariant 16 unaffected.

**2. Announcement channel.** What: when ST's chat shows only `.last_mes` (Prome traditional VN mode) or "ghost message" CSS collapses `.smallSysMes` (already noted in gotchas), our boundary `/comment` is either the only visible message or invisible. Offer `display.announceTransitions: "comment" | "hud" | "off"` (HUD pulse / toast instead of a chat message), or insert the note *before* the reply (`/comment at=-1`, `slash-commands.js:6131` depth handling). Their evidence: `modules/sheld.js:55-57`. Ours: `effectsApplier.ts:171-173`, `settingsStore.ts:15` boolean only. Fit: install-wide setting (invariant 13 ok); the HUD already carries checkpoint name (`HudStrip.tsx:18`). Also removes ideas-1-style side effects of a chat message we author.

**3. `effects.look`.** What: authored per-checkpoint filter preset (`{world: {brightness, sepia, hue, …}, characters?: …}`, or named `night|dusk|storm`) so one background serves several beats. Their evidence: `modules/tint.js:47-59` builds the filter chain into a CSS var; `style.css:315` applies to `#bg1` (`index.html:53`). Ours: `CheckpointEffects` has `background` only (`schema.ts:87-98`). Fit/conflict: must be a new `stHost/look.ts` seam (invariant 2), applied through `EffectsApplier.withLedger` with compare-and-set restore on leave and rollback (invariants 11, 16) and a capability probe (`capabilities.ts`). Strains invariant 19 (CSS scoped to our roots) — a rule on `#bg1` is deliberately outside them; keep it an inline `style.filter` owned by the ledger rather than a global stylesheet rule. Collides with Prome's own `#bg1` filter if both run — the probe should detect `body.worldTint` and refuse with a reason. Candidate for the stagecraft "deterministic first" track, not an agent.

**4. Source-message popup.** What: the warden card, conflict queue and Memory rows cite a `messageId`; render that message (ST-formatted) in a popup instead of only naming it. Their evidence: `modules/chat-history.js:73-85` `messageFormatting(text, name, isSystem, isUser, index)` + `appendMediaToMessage` inside `callGenericPopup(..., {wide, large, allowVerticalScrolling})` (`:100-105`). Fit: author-only (invariant 9), host formatter via a new `stHost` export (invariant 2); popup text must stay DOM-text-safe per `stHost/popup.ts:13` — `messageFormatting` returns HTML, so this needs its sanitizer or a plain-text fallback.

## Patterns to copy / anti-patterns to avoid
- Copy: the "last meaningful message" filter `!is_system && !extra?.image` (`utils.js:8-13`) as the one definition of "who spoke last".
- Copy: slash commands that **return the resulting state** and carry `enumList` autocomplete (`slash-commands.js:53`, `:61-77`) — scriptable from STscript pipes. Check our `/story`/`/cp` return values against this.
- Copy (cautiously): shake-stop logic treats a stream as done only when `isFinished && !isStopped`, with a hard 10 s cleanup (`listeners.js:390-416`) — independent confirmation of our gotcha that a stopped stream never reaches `isFinished`.
- Avoid: **mutating `group.members` around generation** and pushing a fake character into `context.characters` (`user.js:75-92`, `index.js:376-399`) — any extension enumerating members/characters sees a phantom; and the removal is undone by an unrelated event ordering, not a lease.
- Avoid: **hijacking a host setting** (`power_user.waifuMode` written from the extension, `index.js:261`) — two sources of truth for one toggle.
- Avoid: install-wide storage for what is really per-scene presentation (tint, letterbox): it leaks across chats — exactly why our effects are per-chat + owned-effect ledger.
- Avoid: MutationObserver on `#chat` re-running all features per node + `setInterval` element polling (`index.js:418-477`, `listeners.js:81-99`) — O(messages) work on every render and races with ST's own re-layout.
- Avoid: `x === (null || undefined)` (`sheld.js:8`, `tint.js:7`, …) — always compares to `undefined`; a trivially wrong guard that reads as defensive.

## ST host facts learned
- `expressions/index.js` exports `visualNovelUpdateLayers(container)` (`index.js:93`; ST `extensions/expressions/index.js:299`) and `sendExpressionCall(spriteFolderName, expression, {force, vnMode, overrideSpriteFile})` (`user.js:12,152`; ST `:667`).
- `GET /api/sprites/get?name=<folder>` returns the sprite list JSON; empty = no pack (`utils.js:94-104`).
- `extension_settings.expressionOverrides` = `[{name, path}]` redirects a character's sprite folder (`index.js:119-127`, `user.js:15-31`).
- VN mode = `power_user.waifuMode` + `body.waifuMode` + `#waifuMode` checkbox (`index.js:99, 217, 264-266`). Group sprites live at `#visual-novel-wrapper [id='expression-<avatar>']`, solo at `#expression-holder` (`listeners.js:139, 148`). Background element `#bg1` (`style.css:315`; ST `index.html:53`).
- Messages carry `original_avatar` (group speaker's card file), `is_system`, `extra.image` (`utils.js:12, 29-30`).
- `.last_mes` is on the last `.mes` element whatever its type (`sheld.js:56`; ST `script.js:2595-2596`) — so a `/comment` (`is_system: true`, ST `slash-commands.js:6118`) becomes the last message. Not in our gotchas.
- Event ordering usable as a generation bracket: `GENERATION_AFTER_COMMANDS` … `GENERATE_AFTER_COMBINE_PROMPTS` (`index.js:376, 388`).
- `context.streamingProcessor.{isStopped,isFinished}` readable from context (`listeners.js:66-72`) — consistent with (not contradicting) our "stopped stream leaves `isFinished` false" gotcha.
- script.js exports `messageFormatting`, `appendMediaToMessage`, `addCopyToCodeBlocks`, `getThumbnailUrl`, `system_avatar`, `default_avatar`; `timestampToMoment` in utils.js; `getUserAvatar`/`user_avatar` in personas.js (`chat-history.js:1-16`).
- `renderExtensionTemplateAsync("third-party/<name>/html", "<tpl>")` renders extension HTML templates (`index.js:271`); `#extensionsMenu` is the wand menu (`index.js:312`); `loadMovingUIState` + `dragElement` make a panel draggable (`user.js:10-11, 109-110`).
- No contradictions with our gotchas found.

## Verdict
Relevance **low** for features (a cosmetic VN layer; we deliberately do no sprites/expressions), but reading it surfaced one sharp correctness lead for us: **idea 1 — our `activeSpeakerId` does not skip system/comment messages, so our own transition note can blank character-scoped facts for the next turn** (PLAUSIBLE, needs a probe). Worth taking: that filter, plus idea 2's announcement channel; `effects.look` is a reasonable later stagecraft effect if authors ask for time-of-day beats.
