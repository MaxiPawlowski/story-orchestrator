# Improved memory and summarization (qvink_memory) — v2.4 review

Author Qvink · repo https://github.com/qvink/qvink_memory · commit `81b3326` (2026-05-25, ext v1.3.29, needs ST ≥1.14.0) · 187 thumbsup / 4870 msgs · source available: **y** (`source/index.js` 4980 lines, no build step; read: settings defaults, storage, SummaryQueue, injection/threshold, interceptor, event handler, message/group buttons, prompt editor core, slash list)

## What it is
Replacement for ST's built-in Summarize. Thesis (README.md:28,34): summarizing the whole chat and letting the LLM *update* the previous summary degrades over time and one bad generation ruins it; instead summarize **each message individually**, store the summary **on the message**, and never let an LLM touch old summaries. Two injected tiers: **short-term** (newest summaries, rotated out by a token budget, default 10% of context) and **long-term** (only messages the user manually "remembers" via a brain button, separate budget). Optionally hides the summarized raw messages from the prompt (context saving). Pure summarization, no embeddings. Mature, very popular (4.8k msgs).

## How it works
- **Storage = the message itself**: `set_data` writes `message.extra.qvink_memory[key]` (`memory`, `hash`, `error`, `edited`, `prefill`, `reasoning`, `remember`, `exclude`, `include`, `lagging`) and **mirrors it into `message.swipe_info[swipe_id].extra`**, then `saveChatDebounced()` (`index.js:3492-3515`). ST restores `extra` from `swipe_info` on every swipe change (ST `public/script.js:7018` `targetMessage.extra = structuredClone(targetSwipeInfo?.extra)`), so each swipe carries its own summary for free. Per-chat state (`enabled`, locked profile) in `chat_metadata.qvink_memory` + `saveMetadataDebounced` (`index.js:663-670`). Settings + named config profiles in `extension_settings.qvink_memory`, profiles lockable to character/group/chat (`index.js:162-170`, `:1325-1398`).
- **LLM call**: `ctx.ConnectionManagerRequestService.sendRequest(profile, messages)` on a separate Connection Manager profile without switching the main one (`index.js:3437-3462`); warns (does not refuse) when the prompt exceeds the summary profile's context (`:3446-3452`). Prompt is chat-array built from a user-editable template: default "single, very short and concise statement of fact… past tense… no more than {{words}} words" (`index.js:79-93`); macros `{{message}}`, `{{history}}` (range of previous msgs/summaries, `compute_range_macro` `:2987`), `{{words}}` (preset max tokens via slash), `{{lorebook}}` (the WI that was active when that message was generated, `/qm-get-message-world-info` → `itemizedPrompts[mesId].worldInfoString`, `:95`, `:4672-4680`), custom STscript macros (`evaluate_script` `:2926`), `{{#if}}` via `Handlebars.compile` (`:3094`), per-section role + prefill (`evaluate_prompt` `:3125`). Reasoning split post-hoc with the **profile's own reasoning template**: `profile["reasoning-template"]` → `ctx.getReasoningTemplateByName` → `ctx.parseReasoningFromString` (`parse_reasoning` `:3464-3489`).
- **Queue**: `SummaryQueue` (`:3177`) — dedupe by index, N parallel workers, per-call time delay (cloud rate limits), progress bar, `stop()` (`:3328`) calls `ctx.stopGeneration()` (their own comment doubts it hits CM requests). `block_chat` → `ctx.deactivateSendButtons()` while summarizing (`:3289`).
- **When**: `CHARACTER_MESSAGE_RENDERED` via `eventSource.makeLast` (`:4958`), `USER_MESSAGE_RENDERED`, `MESSAGE_DELETED/EDITED/SWIPED`, `CHAT_CHANGED`, `MORE_MESSAGES_LOADED`, `GENERATION_STARTED` (optional "summarize before generation", **awaited → blocks the reply**, `:4124-4142`), `GENERATION_STOPPED` (skip next), `PRESET_CHANGED`/`CONNECTION_PROFILE_*` refresh (`:4958-4974`). Auto-summarize walks back ≤`message_limit` eligible msgs with `lag` and batch size (`collect_messages_to_auto_summarize` `:4029`). Swipe vs continue vs new detected by remembering last swiped/last rendered index (`:4169-4199`). 1 s "just opened" guard stops summarizing greetings on chat open (`:4108-4112`).
- **Mutations**: swipe → new swipe clears memory (`swipe_id === swipes.length`, `:4211-4226`), re-summarize if previous swipe had one; edit → re-summarize only if `auto_summarize_on_edit` (default **false**, `:124`, `:4201-4208`) — the stored `hash` of `mes` (`:3413`) is **never compared**, so an edited message silently keeps its old summary by default; delete → nothing to do (summary dies with the message); hide/unhide → refresh (`:4389-4396`).
- **Injection**: `refresh_memory` recomputes inclusion flags over the whole chat newest→oldest (`update_message_inclusion_flags` `:3799-3895`): eligibility (`check_message_exclusion` `:3744`: remember bypasses all, exclude, user/system/narrator/thought toggles, per-group-member disable, min token length), then short-term budget, overflow of `remember`ed ones into long-term budget, rest dropped. Budgets are % of `getMaxContextSize()` or tokens (`:235-255`), real tokenizer (`ctx.getTokenCount`), separator cost measured empirically (`calculate_injection_separator_size` `:3923`). Two `ctx.setExtensionPrompt` blocks with **configurable position/depth/role/scan** per tier (`:4022-4023`, defaults `:143-160`) + macros `{{qm-long-term-memory}}`/`{{qm-short-term-memory}}` (`MacrosParser.registerMacro` `:4977-4978`).
- **Context trimming**: manifest `generate_interceptor: memory_intercept_messages`; for every message older than the "injection threshold" it `structuredClone`s the entry and sets `extra[ctx.symbols.ignore] = true` (`:3978-3998`), which ST's `formatMessageHistoryItem` renders as `''` (ST `script.js:5841`) — hides the raw message for this generation only, keeps `keep_last_user_message`, skips the last msg on `continue`.
- **Prompt-cache stability**: threshold can be **frozen** and only jump forward when N new messages / N new summaries / last prompt ≥ X% of context (`get_injection_threshold` `:3663-3738`; prompt size read from `itemizedPrompts[..].rawPrompt`, `get_last_prompt_size` `:222`) — explicitly to avoid invalidating the backend's prompt cache every turn (README.md:92).
- **UI**: summary text rendered under each `.mes_text`, colour-coded by status (short / long / remembered-but-out-of-budget / excluded / lagging), click to edit inline (`update_message_visuals` `:1445-1512`); four buttons prepended to `#message_template .mes_buttons .extraMesButtons` with delegated `#chat` clicks (`:4351-4388`); brain toggle per group member in `#group_member_template .group_member_icon` (`:4400-4424`); bulk "Edit Memory" table with filters/regex/pagination (`MemoryEditInterface` `:1665`); injection preview modal (`:1569`); ~20 `/qm-*` slash commands (`:4467-4820`).

## Overlap with Story Orchestrator
- **Tiered memory + budgets**: ours is richer (4 tiers, scoring, diversity floor, pin=retention, provenance, quarantine, consolidation) `src/memory/budget.ts:32`, `src/memory/stores.ts:172-184`. Theirs is simpler but uses the **real tokenizer and context-relative budgets**; ours uses chars/4 (`budget.ts:3`) and fixed 800/600/300/500 tokens (`stores.ts:179`).
- **Rolling summary**: our `short_term` tier is exactly the pattern Qvink argues against — `buildShortTermSummaryPrompt` feeds the EXISTING SUMMARY back and asks the model to "update… drop what… irrelevant" (`src/memory/contract.ts:169-181`), and `runShortTermCompaction` REPLACES the entry (`src/runtime/coordinators/extractionCoordinator.ts:314-338`). Our `scene_history` is already append-only per scene.
- **Mutations**: ours is stronger — swipe/edit/delete roll back engine + memory by message id with quarantine and `rollback ≡ replay` (`src/runtime/rollback.ts:35`, `src/memory/reverse.ts:23`); theirs keeps stale summaries on edit by default. Theirs is cheaper on **swipe-back** (per-swipe summary restored by ST); ours drops and must re-read.
- **Off-path LLM**: both use a CM profile without switching (`src/services/stHost/connectionProfiles.ts:43`); ours never blocks the reply (inv. 5), theirs blocks by default (`block_chat`, before-generation await).
- **Reasoning**: ours strips a hard-coded list of forms (`src/extraction/parse.ts:21-51`); theirs uses the profile's configured template via ST's parser.
- **Injection**: ours is fixed in-chat/system/`scan:false` for every block (`src/services/stHost/extensionPrompts.ts:3-4,24`); theirs lets position/depth/role/scan vary. We have no context trimming (no `symbols.ignore` / `IGNORE` in `src/`, grep) and never touch `message.extra` (grep).
- **Curation UI**: our Memory tab has find/tier filter/pin/exclude/edit and an aggregate `pinnedOverflow` line (`src/components/drawer/DrawerTabs.tsx:224-317`) but no per-row "in next prompt / trimmed by budget" state; no per-message anchor in chat; no bulk edit.
- **Stop**: we have no abort for in-flight memory-model calls and no cancel for `runMemorizeBacklog` (`extractionCoordinator.ts:383`); `sendConnectionProfileRequest` passes no `signal` (`connectionProfiles.ts:43-50`).

**1. Append-only short_term.** What: replace the rolling rewrite with one short entry per compaction window (or per reply), prompt sees only the new window (optionally ≤N previous summaries as read-only context, like their `{{history}}` with `bot_summaries`), rotation by budget drops the oldest. Theirs: README.md:28-40, per-message prompt `index.js:79-93`, `summarize_message` never reads previous summaries by default `:3369-3435`. Ours: `contract.ts:169-181` + `extractionCoordinator.ts:333` `replaceShortTerm`. Fit: improves inv. 11 — each entry is keyed to its own window, so rollback is `dropByMessageId` instead of a derived-record reversal of a replaced entry; the plan-04 `derived.ts` "replace" case shrinks. Needs a live-suite fixture (drift over 60+ messages: rolling vs append), budget interplay with `short_term: 300` tokens, and a blob migration of the existing single entry (inv. 13).

**2. Context trimming.** What: optional install-wide setting; in `talkControlInterceptor`'s slot (we own one `generate_interceptor`, `manifest.json:12`) mark messages older than a threshold AND fully consumed by extraction (≤ engine `lastMessageId`, all tiers written) with `extra[symbols.ignore]` on a cloned entry; keep the last user msg; skip last on `continue`. Threshold **steps** (every N messages / at X% of context) instead of sliding, so the prompt prefix stays cacheable — matters on the 33 tok/s RunPod backend. Theirs: `index.js:3978-3998`, `:3663-3738`, README.md:92. Ours: `src/runtime/index.ts:186` (interceptor only routes speakers). Conflicts: inv. 5 ok (synchronous, no LLM); new host access → `stHost/` seam for `symbols.ignore` (inv. 2); must refuse while extraction lags or a message is quarantined, else the model loses facts no tier holds; composes with other interceptors (their README.md:295 notes WTracker breakage) — order/`loading_order` matter; next-turn preview must show trimmed ranges; checkpoint `world_info` scanning also reads chat (verify WI scan buffer vs ignored msgs before shipping).

**3. Per-tier scan.** What: pass `scan: true` for `memoryFacts`/`memorySceneHistory` so a remembered name/place keeps activating its lorebook entry after the raw message scrolled out of scan depth. Theirs: `short_term_scan`/`long_term_scan` `index.js:147,155`, forwarded `:4022-4023`; ST adds scanned extension prompts to the WI buffer (`public/scripts/world-info.js:4720`). **12. Anti-patterns (we already avoid; keep it that way).** Awaiting summaries in `GENERATION_STARTED` and `deactivateSendButtons` (`index.js:4142`, `:3289`) put memory work on the reply path (inv. 5). ## Patterns to copy / anti-patterns to avoid
- Copy: **one artifact per source unit, never an LLM rewrite of a previous artifact** — errors stay local, rollback is a key drop.
- Copy: **stepped (frozen) injection/trim boundaries** when anything moves the start of the prompt — backend prompt caches survive most turns.
- Copy: measure formatting overhead with the real tokenizer (`t(a+sep+a) − 2·t(a)`, `index.js:3923`) instead of a guessed constant.
- Copy: an explicit Stop that drains the queue and resolves pending promises (`index.js:3328-3346`) — but abort the request itself (`signal`).
- Copy (host): "summarize user messages / system / narrator / Stepped-Thinking thoughts" as explicit eligibility toggles (`check_message_exclusion` `:3744-3797`) — our `chatWindow.ts` filters only `is_system`; `is_thoughts` and narrator `extra.type` are worth a look for extraction hygiene.
- Avoid: blocking Send / awaiting in `GENERATION_STARTED` for background work; `delete chat[i].extra.ignore_formatting` on the ORIGINAL message before cloning in the interceptor (`index.js:3991`) mutates persisted chat; module-level `INJECTION_THRESHOLD_INDEX` not chat-scoped beyond a `CHAT_CHANGED` reset (`:3660`, `:4117`); `wait_for_event` removes listener for an undefined `event` on timeout (`:412`); uncaught `getReasoningTemplateByName` throw (`:3478`).

## ST host facts learned
- `generate_interceptor` receives `coreChat` (a filtered array copy of `chat`, ST `script.js:4496`) before prompt build, awaited in manifest order (`extensions.js:2024-2046`); replacing `chat[i]` with a clone + `extra[ctx.symbols.ignore]=true` drops the message from the prompt without touching the saved chat (`st-context.js:302`, `constants.js:25` `Symbol.for('ignore')`, `script.js:5841`). Only runs when `!dryRun` (`script.js:4562`).
- `setExtensionPrompt(key, value, position, depth, scan, role, filter)` (`script.js:8926`); `scan:true` puts the block into the WI scan buffer (`world-info.js:4720`). Not contradicting our gotchas — we simply always pass `false`.
- ST restores `message.extra` from `swipe_info[swipe_id].extra` on swipe (`script.js:7018`), so per-swipe data can live on the message.
- `itemizedPrompts` (`itemized-prompts.js:16`) holds per generated message `rawPrompt`, `allAnchors` (all extension prompts), `worldInfoString`, `mesId` (`script.js:5337-5351`); stored in browser localforage per chat (`itemized-prompts.js:14,46`) — browser-local, lost in another browser (their README.md:297).
- `ConnectionManagerRequestService.sendRequest` accepts `signal` in its custom params (`extensions/shared.js:424`).
- Connection profile carries `"reasoning-template"` (`extensions/connection-manager/index.js:48`); `ctx.getReasoningTemplateByName` throws on unknown names (`reasoning.js:1444-1447`); `ctx.parseReasoningFromString(str, {strict}, template)` returns null when the template lacks prefix/suffix (`reasoning.js:1461-1467`). Consistent with our gotcha that CM requests never apply the reasoning template themselves.
- Message action slot: `#message_template .mes_buttons .extraMesButtons` (ST `index.html:7391,7414`); group member row template `#group_member_template .group_member_icon` (`index.html:7543,7557`).
- Group generation fires `GENERATION_STARTED` twice, the first with undefined type (their comment + guard `index.js:4133-4137`) — author claim, not re-verified in ST source here; consistent with our "decision key pinned per wrapper pass".
- `eventSource.makeLast` exists for ordering a listener after others (`index.js:4958`).

## Verdict
Relevance **high** (same subsystem, battle-tested with a large user base). The one thing worth taking: **make `short_term` append-only per window** — our rolling rewrite is the exact degradation mode this extension was built to escape, and switching also simplifies rollback. Runners-up: opt-in context trimming with a stepped threshold (big win for long chats on slow backends, needs careful gating on extraction lag) and abortable memory-model calls.
