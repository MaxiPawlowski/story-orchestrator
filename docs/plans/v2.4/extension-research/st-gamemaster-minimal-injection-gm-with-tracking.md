## What it is
Game-mechanics layer over a running chat: party sheets (resources/attributes/skills/inventory), shared resources (money, food), warnings, skill trees, dice rolls, opposed combat, transactions. Two cheap side-LLM passes: a **pre-pass router** that judges each player action *before* generation (roll? transaction? warning? rewrite?) and a **post-pass tracker** that reads the finished exchange and emits XML "tool tags" that mutate state. Injects nothing itself: it exposes two macros the user places in the preset (`{{gamemaster-low-priority}}` persistent, `{{gamemaster-high-priority}}` one-shot). Wizard bootstraps sheets from card/persona/lore. Not a narrative engine — no plot structure, no checkpoints.

## How it works

Plain JS modules importing ST internals by relative path (`extensions.js`, `script.js`, `world-info.js`, `macros/macro-system.js`) — no seam layer.
- **Pre-turn (reply-blocking)** `source/inject/preTurn.js:541-555` — awaited `GENERATION_AFTER_COMMANDS` handler (types normal/swipe/regenerate/continue, skips dryRun) → `handlePreTurn` `source/core/triggerWatcher.js:195-431`. Player text read from `#send_textarea` first (`:106-112`, `:222-224`) because GAC fires before the user message is pushed; `MESSAGE_SENT` capture as fallback, timestamped 60 s (`:84-99`).
  - Router call `source/core/prePass.js:406-457`: system = long rule prompt (`:40-99`, tag vocabulary `roll/combat/transaction/warning/relevant/skill/note/rewrite/nothing`, worked examples) + optional deep context; user = compact XML state snapshot + last 6 messages wrapped in `<scene_context>` with a "PAST, already tracked, never act on it" note (`source/util/chatStore.js:55-62`). Tolerant regex XML parse, sanitized against live state (`prePass.js:186-369`). Raw reply persisted on the **user message object** as `gm_prepass` (`:475`, `chatStore.js:101-120`).
  - Specialists run only what the plan names (`triggerWatcher.js:308-417`): combat engine (ally AI + enemy AI + clash + dice), dice (`source/core/diceRoller.js:178-289`: LLM streams 4 tiers with % chances, code picks with `Math.random` weighted roll `:151-160`, result persisted as `gm_roll` on the message `:276`), transactions (fair-use value check, dice notation evaluated in code), warnings, one-shot "relevant" readouts, notes, skill suggestion, **action rewrite** (`prePass.js:79`: "the player controls the ATTEMPT, never the result").
  - Status bubble above the input while the reply waits (`triggerWatcher.js:271`).
- **Injection** `source/core/injection.js` — two in-memory buffers. `consumeHigh()` **drains on macro evaluation** (`:158-164`); `buildLowPriority()` renders warnings + always-inject resources + KO/dead states + enemies + one-shot lines, also draining one-shots (`:174-221`). Swipes: `stashHigh(mesId)` before prompt assembly, `replayHigh` re-queues on swipe/regenerate (`:73-104`); if stash lost (reload), `recoverSwipePlan` rebuilds from persisted `gm_prepass`/`gm_roll`/`gm_combat` with **zero LLM calls and no re-roll** (`triggerWatcher.js:142-191`). Post-pass is given exactly what the macros injected this turn (`injection.js:253-259`).
- **Macros** `source/inject/macro.js:343-367` — `macros.registry.registerMacro` (new macro engine only).
- **Post-pass** `source/inject/postTurn.js:441-461` on `MESSAGE_RECEIVED`: skip chats <2 msgs (greeting guard), skip replies <100 chars (`:407`), then `runAgentPass` (`source/core/agentRunner.js`): state XML + last 4 msgs, only the last 2 are "current exchange" (`:31-33`), tool tags parsed tolerantly (`source/docs/TOOL_TAGS.md`, `core/toolParser.js`), snapshot before apply + per-swipe post-state record (`agentRunner.js:370-379`). New characters → review chip queue, never auto-created (`source/core/characterSpawner.js:42-69`).
- **Persistence** — game state in `chatMetadata.game_manager.data` via `saveMetadata()` (`source/core/stateManager.js:2,61,229`); per-message baselines `chatMetadata.game_manager.snapshots`, last 5 messages, 10 swipe versions each (`source/core/snapshots.js:160-163`); per-turn records as ad-hoc top-level keys on chat messages (`gm_prepass`, `gm_roll`, `gm_combat`, `gm_rewrite`) with a 250 ms/20 s retry until the message lands (`chatStore.js:75-93`).
- **Mutations** — swipe/regenerate: `restoreSnapshot` inside the awaited GAC (`triggerWatcher.js:246-252`); delete: `MESSAGE_DELETED` → restore newest baseline ≥ `chat.length` (`snapshots.js:326-329`); swipe navigation: `restoreSwipeState` on `event_types.SWIPED` (`postTurn.js:468`) — **dead: that event does not exist** (see host facts). Edits: not handled.
- **LLM routing** `source/util/connectionService.js:106-139` — `ConnectionManagerRequestService.sendRequest(profileId, messages, undefined, {stream})`; streaming consumes the generator's cumulative `chunk.text`. Per-feature profile chain: wizard → pre-master → agentic → selected (`:53-100`). Legacy mode swaps the live profile via `/profile` callback + 1.5 s sleep (`source/util/profileSwapper.js:183-226`).
- **Deep context** `source/util/loreContext.js:36-134` (off by default) — card description/scenario, persona, AN, and **activated WI via `getWorldInfoPrompt(chatReversed, 100000, true)`** (dry run) incl. `outletEntries` with white/blacklist; called by 10 engines (prePass, dice, transactions, ally/enemy AI, clash, wizard, skill tree…).
- **UI** — floating body-level window + bubble/hotbar; DOM chips on messages restored by an idempotent pass on ST events + a `MutationObserver` over all of `#chat` (`source/util/messageDom.js:220-240`); message text never edited.

## Overlap with Story Orchestrator
- **State tracking**: they track numeric game state (HP, money, items) with relative deltas; we track typed story qualities with absolute DELTA values + evidence (`src/extraction/contract.ts:37-41`). Our writes are boundary-drained, evidence-checked, closed-vocabulary, rollback ≡ replay (`src/runtime/rollback.ts:35`); theirs apply immediately, 5-message snapshot horizon, delete handled by an index heuristic. We are far stronger on correctness; they have game mechanics we deliberately do not (baseline §4: no stat/HP/inventory UI).
- **Swipe consistency**: their "swipe never re-judges/re-rolls, replay the persisted decision" ≈ our talk decision cache keyed `chatId:checkpointId:lastMessageId` (`src/runtime/talkControl.ts:78`) and lore cache (`src/runtime/loreSelect.ts:51`). But our one-shot blocks do **not** replay on swipe (idea 2).
- **Injection**: we inject via `setExtensionPrompt` at registered depths (`src/constants/injectionRegistry.ts:12`) **and** expose `{{story_*}}` macros (`src/runtime/macros.ts:39`, dual-engine seam `src/services/stHost/context.ts:49`). Their macro-only, user-placed model is simpler but side-effecting.
- **Wizard**: both bootstrap from existing assets; ours provisions create-only with per-op review (`src/wizard/provisioning.ts:25`); theirs builds sheets, never cards/lore. Their in-play "new character → review chip" has no equivalent in ours.
- **Agency**: we stop the model narrating the player (`src/engine/agency.ts:20-36`); nothing in ours addresses the reverse — the player declaring outcomes — which is their rewrite rule.
- **Side-LLM routing**: they route per feature; we use one extraction profile for extraction, director, copilot and wizard (`src/runtime/runtimeManager.ts:174` `getProfileId: () => this.getExtractionSettings().profileId`).
- **Reply path**: they block every fresh send on ≥1 LLM call (combat: 3+). We keep extra compute off-path except budgeted judge/director uses (baseline inv. 5).

## Ideas for v2.4

| # | idea | kind | our area | our state | value | effort |
|---|---|---|---|---|---|---|
| 1 | Speaker-aware evidence: a player line proves an attempt/choice, not a world outcome | enhancement | extraction | absent | 4 | M |
| 2 | Replay one-generation blocks (nudge, continuity note) on swipe/regenerate of the reply they rode | enhancement | stagecraft / copilot | absent | 3 | S |
| 3 | Forced-lore landed check + foreign dry-scan hazard | host-integration | host / judge lore | absent | 3 | S |
| 4 | Agency clause "the player writes attempts; the world decides outcomes" | enhancement | pacing / engine agency | absent | 3 | S |
| 5 | Per-pass connection profile routing with fallback chain | enhancement | extraction / wizard | absent | 3 | S |
| 6 | In-play newcomer → author review card to add roster member (create-only) | new-feature | wizard / studio | absent | 2 | M |
| 7 | Code-rolled chance outcomes (LLM gives odds, code picks, recorded) | new-feature | engine | absent | 2 | L |

**1 — Speaker-aware evidence.** What: evidence quoted from an `is_user` message may satisfy only `read_as: choice|stated` qualities (player intent); an outcome quality (artifact secured, guard convinced) needs evidence from a non-player message. Deterministic, in `evidence.ts`, no prompt trust. Theirs: `source/core/prePass.js:79` ("the player controls the ATTEMPT, never the result"), `source/core/injection.js:112`. Ours: window entries carry only a speaker name (`src/extraction/chatWindow.ts:12`), the prompt has no speaker rule (`src/extraction/contract.ts:37-41`), `evidence.ts:28` checks presence in window only; zero `is_user` handling in `src/extraction/` besides the name fallback. Today "I grab the Sun Idol" from the player is valid evidence for a gate. Fit: strengthens inv. 4 (text never writes state beyond evidence). Needs a per-quality override (`evidence_from: any|world`) for stories where the player narrates legitimately, a Studio diagnostic, live-suite fixtures (player-claims-outcome rows), and a blob-free change (story schema only). Watch `/sendas` (`command` type, not user) and group-chat persona messages.

**2 — Replay one-shot blocks on swipe.** What: when the reply that carried the author nudge or an applied continuity note is swiped/regenerated, re-apply the same block for the regenerated reply instead of dropping it. Theirs: `source/core/injection.js:73-104` (stash keyed by target message, replay on swipe), `source/core/triggerWatcher.js:284-297`. Ours: `src/runtime/runtimeManager.ts:634` clears nudge + note on every `GENERATION_ENDED`; `src/runtime/coordinators/stagecraftCoordinator.ts:321` withdraws notes on rollback as `reverted`; `copilotCoordinator.ts:204-208` nudge is in-memory only. Result: a swipe silently regenerates without the author's nudge / the warden's correction whose cause still stands. Fit: key by `chatId + replyMessageId` under a `RunToken` (inv. 10); rollback of a message *before* the reply must still withdraw (inv. 11); journal the replay. Warden note needs its own rule: replay only if the contradiction's source message is still present.

**3 — Forced-lore landed check.** What: `forceActivateEntries` queues entries in `WorldInfoBuffer.externalActivations`, which **any** `checkWorldInfo`, dry runs included, clears (`world-info.js:5275`, our own note `src/services/stHost/worldInfoActivate.ts:16-17`). This extension calls dry-run `getWorldInfoPrompt` from ten engines (`source/util/loreContext.js:41`) inside GAC. We force at `MESSAGE_SENT` for fresh sends (after GAC — safe) but at `GENERATION_STARTED` for swipes/regenerates (`src/runtime/index.ts:154-158`, ST `script.js:4299` < GAC `script.js:4321`), so with GM's deep context on, a swipe's forced lore is consumed by GM's dry scan and the prompt silently carries plain keyword WI. Add: (a) verify on `WORLD_INFO_ACTIVATED` (non-dry only, `world-info.js:900`) that forced uids activated, else journal `lore-force-lost` + judge ring entry; (b) consider forcing on the last awaited event (`GENERATION_AFTER_COMMANDS` is after `GENERATION_STARTED`) for non-send types. Ours: zero `WORLD_INFO_ACTIVATED` subscriptions in `src/`. Fit: new `stHost` event use only; read-only (inv. 7 judge never writes — this is a runtime check). Also a harness scenario: foreign dry scan between force and scan.

**4 — Attempt-not-result agency clause.** What: optional `AgencyPolicy.player_attempts_only`: steering tells the story model "the player's message states an attempt; decide its outcome from the world, it may fail". Static text, no LLM, zero latency — the cheap half of their rewrite pass. Theirs: `prePass.js:79`, `injection.js:112`. Ours: `src/engine/agency.ts:20-36` covers only model→player. Fit: C4 says absent = defaults; adding a new default is a behaviour change → ship default `false` (or decide explicitly and record it). Pairs with idea 1 (prompt side + evidence side).

**5 — Per-pass profile routing.** What: optional profile per pass family (extraction, director, copilot/wizard, scene/epistemic P2, curator) falling back to the extraction profile. Theirs: `source/util/connectionService.js:53-100`. Ours: one `profileId` feeds copilot/wizard (`runtimeManager.ts:174`, `copilotCoordinator.ts:33`) and director (`src/runtime/index.ts:175-179`); baseline §4 lists "memory LLM = one CM profile". Fit: install-wide settings home (inv. 13); self-test (`src/runtime/selfTest.ts:156`) and Repair (`src/runtime/repair.ts:25`) must check every configured profile (gotcha: first-profile fallback after config clear). Don't copy their `""` = "current" fallback — it throws (host facts).

**6 — Newcomer review card.** What: when reads see a named character not in the roster/group, author view offers one card: "add X to the roster" (roster op) and optionally "create card for X" (existing create-only provisioning op). Theirs: `source/core/characterSpawner.js:42-69` (queue briefs, never auto-create, one at a time). Ours: provisioning exists (`src/wizard/provisioning.ts:25`) but only from the wizard; no in-play detection (no hits for newcomer/unrostered). Fit: inv. 8 (create-only, per-op, never bulk), inv. 9 (author-only — a newcomer name can spoil), inv. 12 (roster edit = story edit → goes through the author's save/update path, not a silent mutation).

**7 — Code-rolled chance outcomes.** What: an authored risk point (transition or beat) where the model supplies tiered odds and code picks with a recorded seed; the outcome is written as a `source: code` quality at the boundary and injected as ground truth. Addresses "stories never feel risky". Theirs: `source/core/diceRoller.js:151-160,244-276` (streamed tiers, weighted `Math.random`, result persisted, swipe replays). Ours: no randomness in `src/engine/` or `src/generation/` (only `npc_replies.probability`, `src/engine/schema.ts:109`). Strains inv. 1 (needs an RNG seam like the clock), inv. 11 (roll must be recorded in the boundary log so rollback ≡ replay), inv. 3 (applied at boundary), inv. 9 (odds are spoilers). Low value for a narrative engine; keep as a seed only.

## Patterns to copy / anti-patterns to avoid
Copy:
- **"Nothing" fast path** — router answers `<nothing/>` → zero specialists, zero injected tokens (`prePass.js:80`). Same spirit as our `NO_DELTA`/`SCENE_NONE`; worth applying to the P2 passes' prompts.
- **Tell the side model what the story model was told** — post-pass receives the exact injected payload of the turn (`injection.js:253-259`). Our reads see only the transcript; when a read is judging whether a nudge/note/steering was obeyed (warden, stall reconcile), give it the applied blocks (`readInjectedPromptBlocks`, `src/services/stHost/promptInspector.ts:18`).
- **Past-context fencing** in side prompts: a labelled `<scene_context>` "already tracked, never act on it" vs the one thing being judged (`chatStore.js:55-62`, `agentRunner.js:31-33`). Matters less for us (absolute DELTAs) but relevant to fact extraction re-proposing old facts.
- **Stable vs volatile blocks for prompt caching** — they document "low-priority changes = cache miss" and push volatile one-shots next to top instructions. We never reason about cache stability of registry depths; cheap to measure (count per-turn block changes in `st-payload` captures).
- **Output reminder as the last system line** for small models (`diceRoller.js:215`).
- Guard the greeting and trivially short replies before paying for a pass (`postTurn.js:446-456`) — we already drop `first_message` (`src/runtime/turnBridge.ts:9`); a min-length skip for cadence reads is not in ours.

Avoid:
- **Side-effecting macros**: `{{gamemaster-high-priority}}` drains its buffer when evaluated (`injection.js:158-164`), so any extra evaluation (prompt itemization, token counting, a second placement, another extension's `substituteParams`) eats the result. Our macros must stay pure reads.
- **Blocking every send on LLM calls** in an awaited `GENERATION_AFTER_COMMANDS` listener (combat = ally + enemy + clash + dice calls) — every other extension's generation waits too. Our inv. 5 is right.
- **Locating the action message by text equality** (`chatStore.js:27-37`) and deleted-message restore by "newest snapshot ≥ chat.length" (`snapshots.js:326`) — both guess; middle deletes restore the wrong baseline.
- Module-global `_running` / pending-action flags with no chat scoping (`triggerWatcher.js:76-99`) — the class our RunToken exists for.
- Ad-hoc top-level keys on chat message objects (`m.gm_roll`) instead of `message.extra`; retry timers that write into whatever chat is open 20 s later (`chatStore.js:75-93`, no chat check).
- `MutationObserver` over the whole `#chat` subtree for decorations (`messageDom.js:236-238`) — cost on long chats.
- A listener on a non-existent event name that silently never fires (`postTurn.js:468`). **Ours has the same hole**: `resolveEventName` falls back to the raw string (`src/services/stHost/events.ts:48-50`, `eventTypes[eventName] ?? eventName`), so a mistyped constant key subscribes to a name ST never emits, silently. Cheap fix: warn/refuse when a key is absent from `eventTypes` (the capability probe can report it).

## ST host facts learned
- `GENERATION_AFTER_COMMANDS` is emitted awaited (`public/lib/eventemitter.js:146` awaits each listener) at `script.js:4321`, **before** `sendMessageAsUser` pushes the player's message (`script.js:4453`, `MESSAGE_SENT` at `script.js:5917`); at that point the player's text is only in `#send_textarea`. Their `triggerWatcher.js:225-229` comment claims the stock flow already has it in `chat` — wrong; their textarea-first read is what makes it work. Consistent with our lore seam (`src/runtime/index.ts:149-150`). GAC is skipped entirely when a slash command in the textarea interrupts generation (`script.js:4314-4318`).
- `GENERATION_STARTED` (`script.js:4299`) precedes GAC (`script.js:4321`) — relevant to where a forced WI activation can be clobbered (idea 3).
- `getWorldInfoPrompt(chatNewestFirst, maxContext, isDryRun)` (`world-info.js:892`) with `isDryRun=true` emits no `WORLD_INFO_ACTIVATED` (`:900`) and skips timed-effect writes (`:683`, `:731`), but still ends with `buffer.resetExternalEffects()` (`:5275`) — i.e. clears every pending `WORLDINFO_FORCE_ACTIVATE` entry — and still rewrites the AN extension prompt when `shouldWIAddPrompt` (`:5268-5271`, not dry-run gated). Returns `outletEntries` (`:913`). Their usage `source/util/loreContext.js:41`. Agrees with our note in `worldInfoActivate.ts:16-17`; the AN side effect is new to us.
- There is no `event_types.SWIPED`; the event is `MESSAGE_SWIPED` (`public/scripts/events.js:7`). `st.eventSource.on(undefined, …)` at `source/inject/postTurn.js:468` registers a dead listener — their per-swipe-version restore never runs.
- `MESSAGE_DELETED` carries `chat.length` after removal, not the deleted index (`script.js:1611`, `:1699`, `:11734`) — matches their heuristic's premise.
- `ConnectionManagerRequestService.sendRequest(profileId, prompt, maxTokens, custom)` (`public/scripts/extensions/shared.js:423`): `custom` is merged over defaults, so passing `{stream}` alone keeps `includeInstruct/includePreset/extractData` true (`:424`); `stream:true` returns a generator factory whose chunks carry cumulative `text` (used `source/util/connectionService.js:121-130`). `getProfile("")` throws `Profile not found` (`shared.js:546-549`) — their "same as current connection" fallback (`connectionService.js:36-51` returning `""`) cannot work.
- `macros.registry.registerMacro` (their `source/inject/macro.js:351`) registers in the new engine only; the legacy parser iterates `MacrosParser.#macros` when `experimental_macro_engine` is off (`public/scripts/macros.js:140-150`), so their macros resolve empty on legacy installs. Current default is ON (`power-user.js:302`). Confirms our choice of the dual-engine `MacrosParser.registerMacro` seam (gotchas: macros bullet); no contradiction.
- Arbitrary keys on chat message objects persist with the chat file (their `gm_*` records survive reload, `chatStore.js:101-144`) — observed behaviour, not verified against a save schema.

## Verdict
Relevance **medium**. Different product (game mechanics vs narrative checkpoints) and weaker engineering (no tests, text-matched messages, draining macros, a dead swipe listener), but its core design claim — *the player owns the attempt, never the result* — exposes a real gap in ours: our extractor accepts a player's declared outcome as gate evidence. The one thing worth taking: **speaker-aware evidence (idea 1)**, paired with the zero-cost agency clause (idea 4). Second: the forced-lore landed check (idea 3), since this very extension would silently defeat our judge lore selection on swipes.
