## What it is
Player-side "what do I do next" menu. `/cyoa` asks the main model (quiet generation) for N one-line options for the user's next beat, renders them as buttons inside a fake chat message, and a click runs `/impersonate` with a direction prompt so the model drafts the user's reply into the input box. Manual-only (no auto trigger, author confirms in thread). No state, no memory, no story model. Tiny, plus several latent bugs.

## How it works
- **Trigger**: slash `/cyoa` only — `SlashCommandParser.addCommandObject(SlashCommand.fromProps({name:'cyoa'…}))` `source/index.js:288-295`. Macro `{{suggestionNumber}}` via `MacrosParser.registerMacro` `index.js:297`.
- **LLM call**: `generateQuietPrompt(prompt, false, !useWIAN, null, "Suggestion List", responseLength)` `index.js:116` — main API, main context, positional args (current ST takes an object and only tolerates positional with a `console.trace`, ST `public/script.js:3084-3087`). `skipWIAN` toggle = "Apply WI/AN" setting. No Connection Manager profile, no separate model.
- **Prompt shape** (default `index.js:23-35`): "Stop the roleplay now…" + N single-sentence suggestions from `{{user}}` perspective, each slot bound to a pacing archetype — (1) ease tension/improve, (2) raise tension/worsen, (3) believable wild twist, (4) slow advance within scene, (5) push forward/possibly end scene — output in `<suggestion>` tags.
- **Parse**: tolerant regex over 4 shapes `<suggestion>…</suggestion>` | `Suggestion N: …` | `Suggestion_N: …` | `^N. …` `index.js:51`. Zero matches → toast error, nothing rendered `index.js:118-122`.
- **Render**: builds HTML buttons with suggestion text interpolated unescaped `index.js:65-67`, pushes a synthetic message `{name:"CYOA Suggestions", is_user:true, is_system:false, extra:{api:'manual', model:'cyoa'}}` into `context.chat` and calls `addOneMessage` `index.js:154-169`. No save call, no event emitted (MESSAGE_SENT emit commented out `index.js:168`). Click handlers bind to `button.custom-suggestion` / `custom-edit-suggestion` `index.js:300-301` — relies on ST's DOMPurify hook prefixing every class with `custom-` (ST `public/scripts/chats.js:1921-1929`).
- **Choose**: removes the suggestion message by `setEditedMessageId` + synthetic click on `.mes_edit_delete` `index.js:142-143`, then writes `/impersonate await=true <impersonate prompt w/ {{suggestionText}}>` into `#send_textarea` and clicks `#send_but` `index.js:193-208` — DOM-driven slash exec; the model's impersonation lands in the input box for the player to send. Edit button (pencil) is supposed to stop before send (`index.js:199-201`) but still fills the textarea with the `/impersonate` command, not the raw suggestion.
- **Persistence**: `extension_settings.cyoa_responses` only (prompts, count 1-10, response length, WI/AN toggle) `index.js:233-278`. Nothing per chat.
- **Mutation handling**: none. Only the *last* message is removed and only if it is a CYOA one `index.js:131-135`; if the player types instead of clicking, the list stays in `chat` forever and is saved on the next ST save.
- **Bugs seen**: `waitUntilCondition` used but never imported `index.js:74,77` (ReferenceError swallowed by the catch, logged as "Timeout"; second call not awaited anyway); `loadSettings` copies saved into defaults instead of defaults into saved `index.js:238`, so on a fresh install `extension_settings.cyoa_responses.llm_prompt_impersonate` is undefined and `String(undefined)` → impersonate prompt `"undefined"` `index.js:194`; `apply_wi_an || default` can never read false once defaults were mutated. Post-reported: group + "Force Names" breaks impersonation (author follow-up, not code-evidenced).

## Overlap with Story Orchestrator
- **Suggestions**: our Driver *Suggest* is author-only — 2-3 story developments from objective + unmet gates + blackboard, applied as a one-turn Nudge (`src/copilot/prompts.ts:118`, `src/copilot/authoring.ts:63`, `src/components/drawer/DriverPanel.tsx:101,125`). Different audience and direction: ours steers the WORLD, CYOA offers the PLAYER's next action. We have no player-facing choice menu.
- **LLM routing**: we run passes off-path on a Connection Manager profile with instruct templating (`src/services/stHost/connectionProfiles.ts:43`); CYOA borrows the main API synchronously via quiet prompt. Ours better for the reply path; theirs gets the full chat context + our injected blocks for free.
- **UI placement**: we never put UI in the chat array (HUD `src/components/drawer/HudStrip.tsx:18`, drawer). CYOA's in-chat fake message is the pattern we deliberately avoid.
- **Parsing**: our parsers are stricter and tested (`src/copilot/parse.ts:512` `parseSuggestions`, `src/extraction/parse.ts:93`); CYOA's 4-shape tolerance is ad-hoc.
- **Interop exposure (gap)**: `src/extraction/chatWindow.ts:8` drops only `is_system` messages and does no markup stripping (no HTML strip in `src/extraction/*` / `src/memory/*`, grep). A left-behind CYOA list (`is_user:true`, HTML buttons of hypothetical player actions) enters our shared-read window and — since the quote is literally in the window — passes the evidence check `src/extraction/evidence.ts:28`. Hypotheticals could be read as things the player did.
- **Impersonate/quiet**: already handled — `onGenerationStarted` withholds private epistemic for `impersonate`/`quiet` (`src/runtime/runtimeManager.ts:633`), talk control never intercepts quiet, impersonate emits no render event so no boundary.

## Ideas for v2.4

| # | idea | kind | our area | our state | value | effort |
|---|------|------|----------|-----------|-------|--------|
| 1 | Extraction window hygiene: drop foreign UI-only messages + strip markup | host-integration | extraction | absent | 4 | S |
| 2 | Player "what could I do?" choice menu (opt-in, off-path, pacing-slotted, pre-fills input) | new-feature | player-ui / pacing | partial | 3 | M |
| 3 | Foreign-message interop probe in the turn-types check | testing | engine / host | partial | 3 | S |

**1. Extraction window hygiene.** What: in `readMessage` skip messages that are UI-only artifacts of other extensions (heuristic: `extra.api==='manual'` with no `gen_started`, `extra.model` not a real model like `cyoa`, or body that is only markup/buttons) and strip HTML tags from `mes` before it reaches any pass prompt or evidence check. Their evidence: `index.js:154-165` (is_user synthetic message, `extra.model:'cyoa'`), `index.js:65-67` (HTML body of hypothetical actions), left in chat when the player types instead `index.js:131-135`. Ours: `src/extraction/chatWindow.ts:6-14` (only `is_system` + in-flight filtered). Fit: strengthens inv. 4 (evidence must be real story text); pure change in a non-host module + one fixture. Needs an allow/deny list documented in gotchas, since `extra.api` values vary by ST version — verify in ST source before relying on any key. Also applies to other HTML-widget extensions (stat bars, trackers) in the corpus.

**2. Player choice menu.** What: a player-mode "Options" control (HUD chip or drawer) that asks the memory profile off-path for N one-line player actions, rendered in OUR UI (never in chat); clicking fills `#send_textarea` (optionally via `/impersonate` through our `stHost/slashCommands.ts` seam) so the player still edits and sends — authorship stays the player's. Borrow their pacing-slotted prompt (ease / raise / twist / slow / push) and map slots to our steering direction (`src/pacing/steering.ts:47` `getSteeringHint`) so the menu leans where the arc wants without forcing it. Their evidence: `index.js:23-35`, `index.js:193-208`. Ours: author-only Driver Suggest `src/copilot/prompts.ts:118` — its inputs (unmet gates, upcoming anchors, blackboard) are exactly what a player prompt must NOT see. Conflicts to design around: inv. 9 (player surface shows no gates/future checkpoints — the player prompt may only consume `narrative.ts`-level player-safe context, and options must not be steered to satisfy gates, or the menu is a spoiler oracle); agency policy (`src/engine/agency.ts:7`) — options are offers, never narration; inv. 5 (off-path profile call, never blocks the reply); config home = install-wide opt-in, off by default, story may disable. Also an optional hook into agency recovery: after `REFUSAL_PLAYER_TEXT` (`src/runtime/agencyRecovery.ts:14`) offer the menu instead of a bare line. Human-rubric item, not provable by machine gates.

**3. Foreign-message interop probe.** What: extend `scripts/debug/so-turn-types-check.mts` (covers `/sd` `extension` posts, `:178-197`) with the CYOA shape: push an `is_user` HTML message + `addOneMessage` with no event (expect: no boundary), then `deleteLastMessage` which emits `MESSAGE_DELETED(chat.length)` (ST `public/script.js:1607-1612`) (expect: rollback no-op when the message was never consumed), then a real turn (expect: no delta sourced from the options text — pairs with idea 1). Ours: `src/runtime/turnBridge.ts:57` MESSAGE_DELETED → `onMutation`. No backend needed for the first two legs.

**4. Anti-patterns (already avoided — keep it that way).** UI in the chat array pollutes the main prompt (is_user text is sent to the model), other extensions' windows and the saved chat; removal by synthetic click on `.mes_edit_delete`; slash exec by typing into `#send_textarea` and clicking `#send_but` (races the send button state, which our gotchas show is hidden while generating/offline); unescaped model text into HTML (relies on DOMPurify). Ours: HUD/drawer only, `executeSlashCommandsWithOptions` seam `src/services/stHost/slashCommands.ts:11-24`, popups built from DOM text nodes.

## Patterns to copy / anti-patterns to avoid
- Copy: **slot-per-archetype option prompt** — each option bound to a named pacing move gives spread without a diversity pass; natural fit for our tension shapes.
- Copy: **pre-fill, don't send** — offering the choice as editable input text preserves player authorship (matches `never_narrate_player_action`).
- Avoid: synthetic chat messages as UI; DOM-click deletion; textarea+send-button slash execution; positional `generateQuietPrompt`; settings loader that mutates the defaults object; unimported helpers hidden by a blanket catch (every failure logged as "Timeout").

## ST host facts learned
- `generateQuietPrompt` now takes an options object `{quietPrompt, quietToLoud, skipWIAN, quietImage, quietName, responseLength, forceChId, jsonSchema, removeReasoning, trimToSentence}`; positional calls still work with a `console.trace` — ST `public/script.js:3084-3087` (CYOA's call `index.js:116`). `skipWIAN` skips WI+AN only; extension prompts (ours) still land in quiet prompts.
- DOMPurify message hook prefixes every class with `custom-` except `fa-*`, `note-*`, `monospace` (and `menu_button` BUTTON/DIV when `MESSAGE_ALLOW_SYSTEM_UI`) — ST `public/scripts/chats.js:1910-1929`. Anything matching classes inside rendered message HTML must use `custom-<name>` (`index.js:300-301`).
- `addOneMessage` renders only; caller must push into `chat` first and it emits no message event — ST `public/script.js:2551-2552`; CYOA relies on that (`index.js:167-169`). So a foreign message can enter `chat` without any event our TurnBridge sees.
- `deleteLastMessage` emits `MESSAGE_DELETED` with the NEW `chat.length` (= the removed message's former index) — ST `public/script.js:1607-1612`. Consistent with our `hostMessageId` handling; no contradiction with gotchas.
- `is_group_generating` / `is_send_press` are exported live bindings — ST `public/scripts/group-chats.js:96,110`, `public/script.js:603`.
- No fact here contradicts our gotchas.

## Verdict
Relevance **medium-low**. A small, buggy, archived utility; nothing to take in code. The one thing worth taking: **harden our extraction window against foreign UI messages** (idea 1) — CYOA-style option lists sitting in `chat` as `is_user` text are hypothetical player actions that our evidence check would currently accept. Secondary, product-level: a player-safe, pacing-slotted choice menu is a plausible v2.4 player feature, but only if it is fed player-safe context, never gates.
