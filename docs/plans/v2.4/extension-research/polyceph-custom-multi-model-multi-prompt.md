# Polyceph (Custom Multi-Model, Multi-Prompt Response Pipelines) — v2.4 review

nialyn · https://github.com/nialyn-mid/polyceph · `0fff515` (2026-05-13), manifest v0.10.1.1 · 26 upvotes / 514 msgs · source available: **y** (`source/`, ~12.2k lines JS+CSS; entry `index.js` 295 lines, engine in `js/engine/**`, compat layer `js/compat-*.js`)

## What it is
Replaces ST's reply generation with a user-authored **pipeline**: steps run sequentially, the tasks inside a step run in parallel, each task = a prompt template + a Connection Profile + optional preset. Task outputs feed later templates through `{{label}}`/`{{s1}}` macros; any task can post to chat as the character, as a hidden "Background" message, or as a reasoning block. Adds tool-call recursion (ST `ToolManager` + an MCP service), streaming loop detection, a per-task progress indicator with Stop, and an in-chat pipeline selector. No story model, no state, no memory: it is a prompt-routing engine.

## How it works
- **Entry / takeover**: capture-phase listeners on `#rightSendForm` click/mousedown/submit and `#send_textarea` keydown swallow ST's send when a pipeline is active (`index.js:208-247`); the user message is posted by the extension itself (`index.js:144-156`), not by ST's `sendMessageAsUser`. A `MutationObserver` re-injects the selector if ST re-renders the form (`index.js:235-240`).
- **Swipes**: capture-phase click on `.swipe_right` of a message with `extra.polyceph_source` reruns the whole batch (`index.js:168-205`); new text is **pushed into `msg.swipes` directly** for every message of the batch (character, background, reasoning) — `js/engine/message-manager.js:179-212,248-271,292-309`; `orchestrator.js:433-447`. ST's `MESSAGE_SWIPED` is never emitted.
- **Run shape** (`js/engine.js:161-279`): fake `GENERATION_STARTED('normal', {automatic_trigger, force_chid, signal})` → release mutex → `GENERATION_AFTER_COMMANDS` → `saveChat` → recapture mutex → `executePipelineSteps` → finally: remove indicator, restore profile/preset, teardown "event storm".
- **Steps/tasks** (`js/engine/orchestrator.js:293-724`): tasks grouped by profile, groups run sequentially, **global `/profile` switch per group + fixed 1000 ms sleep** (`:384-390`), tasks in a group staggered by `delayMs` then `Promise.all` (`:397-403`). Results written to a `contextVault` under several keys (`:598-612`), step output = tasks joined with `---` (`:702-705`). A failed task stops the pipeline unless `continueOnFailure` (`:580-584`). Custom events `polyceph-step-started|task-finished|step-finished` are **awaited** so other extensions can hook between tasks (`:313-323,528-542,707-717`).
- **LLM calls** (`js/engine/generator/generator.js:166-363`, `api-client.js:373-484`): template → `parsePromptToMessages` role-tag state machine (`[[system]]`, `[[user?]]` permissive, `[[assistant:Name]]`, `[[/]]`; `js/engine/parser.js:153-267`) → token-budget check that **throws** when prompt > context − response (`generator/token-budget.js:7-19`) → own streaming/non-streaming request with retries (`maxToolRetries`, `retryDelayMs`), `Promise.race` against a timeout and the `AbortSignal` (`api-client.js:387-481`). Tool calls from the response are executed in parallel (`js/engine/tool-handler.js:111-119`) and fed back, up to `tool_call_recurse_limit` from the CC preset (`generator.js:196-203`).
- **Loop detector** (`js/engine/loop-detector.js:32-168`): on every streamed chunk, checks the buffer tail for a period p (1..500 chars) repeated `threshold × ceil(5/p)` times; on hit throws `Loop detected` (`api-client.js:396-402`); `getCleanText()` truncates to one instance of the pattern.
- **Output tags** (`js/engine/parser.js:8-150`): `<think>` → UI only, dropped from downstream; `<ramble>` → UI + downstream, not persisted; `<background>` → persisted as a **non-system** chat message named `Background` with `extra.polyceph_hidden` (`message-manager.js:216-223`; `compat-shared.js:456-491` sets `is_system: false`), hidden only by CSS/attribute (`js/ui/chat/thoughts/thoughts-renderer.js:41-42`).
- **Context macros**: `{{wi}}` runs `ctx.getWorldInfoPrompt(reversedChatStrings, maxContext, isDryRun, globalScanData)` **per task** (`compat-shared.js:533-601`, `js/macros/macros.js:29-41`); `{{chat_history}}`/`{{cc_all_prompts}}` re-weave `ctx.extensionPrompts` into history by position/depth/role (`js/macros/history.js:9-64`, `js/macros/chat-completion.js:60-130`) — i.e. it re-implements ST's prompt assembly; the per-prompt `filter`/`scan` fields are ignored.
- **Persistence**: settings + all pipelines in `extensionSettings.polyceph` (`js/state.js:323-327`); per-message `extra.polyceph_{source,batch,task_id,pipeline,thoughts,hidden}`. No `chat_metadata`. Profile/preset snapshot is module-level and restored after the run by `/profile` + waiting on `connection_profile_loaded` with a 3 s fallback (`js/engine/state-manager.js:18-51`, `js/state.js:14-91`); presets via `ctx.getPresetManager(api)` exact-name match (`js/compat-presets.js:29-60,147-184`).
- **Teardown** (`js/engine/teardown.js:80-148`): emits `MESSAGE_RECEIVED` + `CHARACTER_MESSAGE_RENDERED` for the last index (no `type`), `GENERATION_STOPPED`, and `eventTypes.GENERATION_AFTER_DATA` / `CHARACTER_GENERATION_STOPPED` — neither key exists in ST's `events.js`, so those two emits go to `undefined`. `postMessageToChat` also emits `MESSAGE_RECEIVED` for **user** messages (`compat-shared.js:495-498`).
- **Cooperation**: the community `GENERATION_MUTEX_CAPTURED/RELEASED` convention (`js/constants.js:59-62`; tracked `js/engine.js:90-122`) shared with Stepped Thinking and Tracker (`st-extensions-research/stepped-thinking/source/interconnection.js:5-45`, `tracker/source/lib/interconnection.js:7-47`); the indicator shows "Waiting for Extensions (<holder>)…".
- **UI**: in-chat typing indicator listing every queued/generating/executing-tools/waiting task with its profile and a Stop (`orchestrator.js:351-378`, `js/ui/chat/thoughts/renderers/typing.js`); settings prompt preview that expands each task's template with placeholders for upstream outputs and a token count vs budget (`js/ui/settings/prompt-preview.js:10-60`).

## Overlap with Story Orchestrator
- **Different layer**. Polyceph replaces the reply path; SO keeps ST's reply path and does its LLM work off-path (baseline invariant 5). There is no feature overlap in "what the reply is"; the overlap is in *how an extension talks to models*.
- **Model calls**: SO already uses the better seam — per-request `ConnectionManagerRequestService.sendRequest(profileId, …)` (`src/services/stHost/connectionProfiles.ts:43-50`) instead of flipping the install's active profile. Polyceph's global `/profile` switch + sleeps is exactly what SO must not do.
- **But SO routes every pass to ONE profile**: `extraction.profileId` (`src/runtime/settingsStore.ts:30`) feeds shared read, memory passes (`src/runtime/coordinators/memoryCoordinator.ts:239,343`), the curator (`stagecraftCoordinator.ts:148`) and the copilot/wizard (`copilotCoordinator.ts:33`). Polyceph's whole premise — cheap model for reads, strong model for synthesis — is absent in SO.
- **Cancellation/timeout**: Polyceph aborts in-flight requests on Stop and races a timeout. SO's memory-model calls have neither: no signal, no timeout (`src/extraction/client.ts:11-19`; grep `timeout` in `src/extraction` → only retry backoff `scheduler.ts:220`). `src/runtime/runOwner.ts:60-62` states CM `sendRequest` "takes no signal (shared.js:423)" — **false for this ST**: `custom.signal` is declared and forwarded (`public/scripts/extensions/shared.js:395,415,424,463,483` → `custom-request.js:283,329`).
- **Degenerate output**: SO strips reasoning and parses strictly (`src/extraction/parse.ts:51,93`) but has no repetition/loop check; the v2 acceptance's Gemma token loops were fixed only by templating.
- **Request size**: Polyceph refuses over-budget prompts and fails closed when the limit is unknown (`compat-shared.js:269-279`); SO has no bound on memory-model requests (baseline §3.D seed).
- **Prompt visibility**: SO's next-turn preview covers the main prompt (`src/runtime/nextTurn.ts:76`); the memory-model prompts are only a tooltip on "Last audit" (`src/components/drawer/DrawerTabs.tsx:261`). Polyceph previews every task prompt with tokens.
- **Interop hazard (SO + Polyceph together)**: with a pipeline active there is no real `Generate()`, so `talkControlInterceptor` never runs; the fake `GENERATION_STARTED` makes SO force lore (`src/runtime/index.ts:153-158,189`) that the next `{{wi}}` dry-run scan then consumes (forced set is cleared by any `checkWorldInfo`, dry runs included — our own note `src/services/stHost/worldInfoActivate.ts:16-17`); SO injections reach the model only if the pipeline template includes `{{chat_history}}`/`{{cc_all_prompts}}`; `MESSAGE_RECEIVED` on the user message and the teardown emits each commit an SO boundary (`src/runtime/turnBridge.ts:52-53,79-101` — no `is_user` check, untyped = turn); Polyceph swipes never emit `MESSAGE_SWIPED`, so SO never rolls back the swiped reply's reads (same silent-rewrite class the MFC review found). `Background` messages are `is_system:false` and enter SO's extraction windows (`src/extraction/chatWindow.ts:8`).

**1. Abortable, time-bounded memory-model calls.** What: pass `custom.signal = AbortSignal.any([runOwner.signal(), AbortSignal.timeout(n)])` from every coordinator pass into `sendConnectionProfileRequest`; a lapsed epoch (chat switch, restart) or a hung backend frees the slot instead of occupying a single-slot llama.cpp while the player's next reply waits; timeout → scheduler's existing retry/pause. Theirs: `api-client.js:416-429` (race timeout + abort), `engine.js:128-150` (Stop aborts). Ours: `runOwner.ts:56-78` already mints a per-epoch `AbortController` but documents it as judge-only on a wrong premise (`:60-62`); `connectionProfiles.ts:43-50` passes no signal; ST accepts one (`shared.js:415,424,463,483`). Verify the declared older host (ST 1.18.0) has the same parameter before relying on it; verify ST's server propagates client abort upstream on both backends. Fit: strengthens invariant 10 (token check stays the write-edge defence); no conflict.

**2. Per-pass profile routing.** What: optional install-wide `profiles: {read, synthesis, authoring}` falling back to `extraction.profileId` — shared read/scene/epistemic on a small fast model, canon/arc/expansion/critic on a stronger one, wizard/copilot on the author's best. Each role gets its own self-test row and Repair step. Theirs: task-level `profile` (`constants.js:39`, `orchestrator.js:327-390`) — the concept, not the mechanism (they switch the install's profile globally; we would keep per-request CM). Ours: single `profileId` everywhere (`settingsStore.ts:30`, `memoryCoordinator.ts:239,343`, `stagecraftCoordinator.ts:148`, `copilotCoordinator.ts:33`); baseline §4 lists "memory LLM = one Connection Manager profile" as current scope. Fit: install-wide home (inv. 13), no blob change; live-suite must be re-run per role before recommending a split (inv. 20). Cost: more profiles that must all be live (gotcha "every LLM profile has to be live").

**3. Honor the generation mutex.** What: subscribe to `GENERATION_MUTEX_CAPTURED/RELEASED` (string event names on ST's eventSource); while another extension holds it, treat the host as generating in `TurnBridge.flushPending` and defer (not drop) off-path reads; author pipeline detail "waiting for <holder>". Never capture it ourselves (our work is off-path). Cap the wait like `FLUSH_POLL_MAX_MS` because a crashed holder never releases. Theirs: `constants.js:59-62`, `engine.js:90-122,205-206,240`; same convention in Stepped Thinking/Tracker/Recast. Ours: 0 hits for `MUTEX` in `src/`; `turnBridge.ts:104-113` only checks `isHostGenerating()`. Fit: inv. 5 (reply path still never waits on us); new event subscription goes through `stHost/events.ts` (inv. 2) — needs a string-name subscription since it is not an `eventTypes` key.

**4. TurnBridge hardening vs synthetic emitters.** What: (a) ignore `MESSAGE_RECEIVED`/`CHARACTER_MESSAGE_RENDERED` whose target is `is_user` — core ST never emits them for a user message (only `script.js:3799,3828,6691-6781,7705,9916`, `slash-commands.js:6006,6011`, `group-chats.js:300`, `stable-diffusion/index.js:4997`, all character/command/greeting/extension); (b) record a text fingerprint of each consumed reply at commit and, on the next render of the same id, treat a changed fingerprint as a mutation → rollback (covers Polyceph swipes that bypass `MESSAGE_SWIPED` and MFC's silent regenerate). Theirs: `compat-shared.js:495-498`, `teardown.js:110-124`, `index.js:168-205`, `message-manager.js:248-271`. Ours: `turnBridge.ts:79-101` (no `is_user` guard; untyped = turn by design), boundaries record only `{lastMessageId, chatLength}`. Fit: inv. 11 (rollback ≡ replay) is what (b) protects; keep the denylist philosophy — (a) filters by target role, not by type. Testing: add synthetic-emitter cases to `so-turn-types-check.mts`. Shares (b) with the MFC review's text-aware rollback idea — build once.

**5. Degenerate-output detector.** What: pure `extraction/degenerate.ts` using their period/reps rule over the (non-streamed) reply tail; a hit marks the audit `degenerate`, truncates to the clean prefix for the evidence check, and retries once (or pauses per scheduler policy) instead of parsing a loop. Theirs: `loop-detector.js:49-142`. Ours: no repetition check (`parse.ts`), and Gemma loops were a v2 ship-blocker. Fit: pure module, no invariant touched; cheap (≤500 × reps char compares on the tail).

**6. Pre-send token budget, fail closed.** What: count the assembled pass prompt with `countTokens` (`src/services/stHost/tokenizer.ts:3`) against the profile's context minus `maxTokens`; over budget → shrink the window/chunk (memorize backlog, canon) or refuse with a named reason; unknown limit → refuse, not guess. Theirs: `generator/token-budget.js:7-19`, `compat-shared.js:188-279` (fail closed at `:276`). Ours: baseline §3.D "No request-size bound on extraction path"; only the judge caps (chars). Fit: none violated; the "unknown limit" read needs a new stHost seam (profile → preset → context) verified in source.

**7. Author pass inspector.** What: author-view panel listing the last N memory-model calls per pass (prompt, raw reply, tokens in/out, latency, profile, outcome), from the existing audit/lastPass rings; "Copy" for bug reports. Theirs: `prompt-preview.js:10-60` (per-task expanded prompt with upstream placeholders and budget). Ours: `DrawerTabs.tsx:261` tooltip; `extras.stagecraft.lastPass` keeps prompt+raw; `so-journal follow` is harness-only. Fit: inv. 9 (author-only, adds), inv. 18 (read from snapshot).

**8. Detect generation-replacing extensions.** What: capability probe reads `extensionSettings.polyceph.activePipelineId !== 'none'` (and similar known replacers) and surfaces "another extension writes the replies; speaker direction, lore forcing, private blocks and swipe rollback are not guaranteed" in `#so-capabilities`/Repair. Theirs: `constants.js:13`, `state.js:323-327`. Ours: `src/services/stHost/capabilities.ts:68` has no such probe. Fit: "blocked, not failed" philosophy of plan 06. Low value: small overlap of users.

**9. Role-split pass prompts.** What: send `[{role:'system', contract}, {role:'user', window}]` instead of one user message; may reduce chat-text-as-instruction leakage and suit instruct templates. Theirs: `parser.js:153-267`. Ours: `connectionProfiles.ts:45` single user message; the acceptance showed message shape matters. Only ship if `so-live-suite` per-tier scores do not drop (inv. 20; floors not retuned).

**10. Chat-completion preset effect.** What: for seed A (OpenAI/CC preset adapter), their `getPresetManager(CONNECT_API_MAP[api].selected)` + case-insensitive exact name + `findPreset`/`selectPreset` avoids `/preset`'s fuzzy match. Theirs: `compat-presets.js:29-60,147-184`. Ours: textgen-only by decision (`src/services/stHost/presets.ts:36-41`, inv. 21). Only relevant if the seed-A decision goes "build"; still must go through `withLedger` with compare-and-set restore.

## Patterns to copy / anti-patterns to avoid
Copy:
- Loop rule `reps = threshold × ceil(5/period)` — scales false-positive protection by pattern length (`loop-detector.js:49-52`).
- Fail closed on an unknown context limit (`compat-shared.js:274-279`) — matches our "blocked, not failed".
- Stamp every artifact of one run with a batch id (`extra.polyceph_batch`) so a rerun can find and replace them (`context.js:20,33-38`) — our provenance envelope is the richer version; keep it.
- Awaited per-step custom events so other extensions can act between steps (`orchestrator.js:707-717`) — if SO ever exposes hooks, await them rather than fire-and-forget.
- Status that names who it is waiting on ("Waiting for Extensions (Tracker)").

Avoid:
- Switching the install's active profile/preset per task with fixed sleeps and a 3 s fallback restore (`state.js:14-60`, `orchestrator.js:384-390`, `state-manager.js:31-39`) — races every other extension and the user; per-request CM is the right seam.
- Synthesizing core events with wrong shapes: `MESSAGE_RECEIVED` for user messages, untyped `CHARACTER_MESSAGE_RENDERED`, `GENERATION_STARTED` without a real `Generate`, emits on non-existent keys (`teardown.js:110-124`, `compat-shared.js:495-501`, `engine.js:191-226`).
- Mutating `msg.swipes` directly and eating the swipe click, so `MESSAGE_SWIPED` never fires (`index.js:168-205`).
- Persisting hidden content as `is_system:false` messages hidden by CSS (`message-manager.js:216-223`) — every other extension reads it as dialogue.
- Forcing `window.isChatSaving = false` when "stuck" (`compat-shared.js:438-441`) and treating `await saveChat()` as server confirmation (`:444-446`); our gotcha: `saveChatConditional` swallows errors (`script.js:9412`).
- Re-implementing ST's prompt assembly (`history.js:9-64`) — drops `filter`/`scan` and drifts with ST; we read ST's own assembled blocks (`readInjectedPromptBlocks`).
- A `checkWorldInfo` dry run between another extension's force-activate and the real generation consumes the forced set — never dry-run WI scans on the reply path.
- Letting models call tools that write state — SO's non-goal (inv. 4) stands.

## ST host facts learned
- `ctx.getWorldInfoPrompt(chat, maxContext, isDryRun, globalScanData)` takes the chat as **reversed `"name: mes"` strings** and returns `{worldInfoBefore, worldInfoAfter, worldInfoString}` — `compat-shared.js:573-601`; host `world-info.js:892`.
- `ctx.getPresetManager(apiId)` + `ctx.CONNECT_API_MAP[api].selected` maps derivative APIs to the canonical preset manager; manager exposes `getAllPresets/findPreset/selectPreset/getSelectedPresetName/getCompletionPresetByName` — `compat-presets.js:29-60,88-133,147-184`; host `st-context.js:285,288`.
- `/profile` completion is observable as `connection_profile_loaded` — `state-manager.js:31-39`; host `events.js:81`.
- `ctx.swipe` = `{left, right, to, show, hide, refresh, isAllowed, state}`; `swipe.refresh(true)` redraws swipe arrows after a direct `swipes` push — `message-manager.js:212,270`; host `st-context.js:248-256`.
- `ctx.chatCompletionSettings.tool_call_recurse_limit` and `.tool_reasoning_mode` drive tool recursion — `generator.js:196-203`.
- Community generation mutex: string events `GENERATION_MUTEX_CAPTURED {extension_name}` / `GENERATION_MUTEX_RELEASED` on ST's `eventSource`; not in `events.js` — `constants.js:59-62`, `engine.js:90-102`.
- `eventTypes.GENERATION_AFTER_DATA` and `CHARACTER_GENERATION_STOPPED` do **not** exist (the key is `GENERATE_AFTER_DATA`, host `events.js:58`); `eventTypes.GENERATION_AFTER_COMMANDS` does (`events.js:22`) — their `teardown.js:121-124` emits undefined.
- `ctx.abortGeneration` is not on the context (their guard `engine.js:136`); the exposed one is `stopGeneration` (host `st-context.js:146`).
- With Polyceph active: `MESSAGE_RECEIVED` fires for user messages and swipes emit no `MESSAGE_SWIPED` — contradicts TurnBridge's implicit assumptions (see idea 4), not a written gotcha.
- **Contradicts our code comment** (found while checking their abort pattern; evidence is ST source, not theirs): `ConnectionManagerRequestService.sendRequest` DOES accept `custom.signal` and forwards it to `ChatCompletionService/TextCompletionService.processRequest` (`shared.js:395,415,424,463,483`; `custom-request.js:283,329,544,564`), vs `src/runtime/runOwner.ts:60-62` "takes no signal (shared.js:423)".
- Their claim, unverified: `window.isChatSaving` can stay stuck `true` (`compat-shared.js:431-441`).

## Verdict
Relevance **medium**. Nothing to take from the pipeline product itself — it lives on the reply path SO deliberately leaves to ST, and several of its host techniques are on our avoid list. What it sharpens is SO's own model-call hygiene. The one thing worth taking: **make memory-model calls abortable and time-bounded (idea 1)** — our "no signal" premise is wrong for this ST, and the fix is small. Per-pass profile routing (idea 2) is the bigger feature idea; idea 4 is the interop fix to fold into the MFC text-aware rollback work.
