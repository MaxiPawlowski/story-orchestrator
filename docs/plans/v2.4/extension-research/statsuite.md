## What it is
Per-message character physical-state tracker (pose, location, outfit, exposure, accessories, bodyState, mood) aimed at "teleporting character" continuity bugs. Runs a **dedicated fine-tuned 2B model** (StatSuite_G2B, OpenAI-compatible `/v1/completions`, separate port) instead of the main model, so creative samplers and the main context cache are untouched. Every stat of every tracked character is read after every message, stored on the message per swipe, shown as an editable table under the message, and the latest block is injected at depth 1 via a Handlebars template. Alpha, small scope; custom stats "probably won't work well" (README).

## How it works
- **Entry / hooks.** `manifest.json:11` `generate_interceptor: "injectStats"` → `source/index.ts:14` (skips `regenerate|quiet|impersonate|continue`, `:15`), exposed as `globalThis.injectStats` (`:30`). Events `source/events.ts:138-161`: `CHAT_CHANGED` (rehydrate registries, redraw all tables), `CHARACTER_MESSAGE_RENDERED` (process, or defer to `GENERATION_ENDED` while a global `generating` flag is set, `:139-158`), `GENERATION_STARTED/ENDED`, `MESSAGE_SWIPED` (`onSwipeChanged`, `:103`). **No `MESSAGE_EDITED` / `MESSAGE_DELETED` handler anywhere** (grep: 0 hits).
- **LLM call.** Raw browser `$.ajax` POST to `<modelUrl>/v1/completions` (`source/api.ts:122-133`), `temperature: greedy?0:1` (`:130`; Alt-click = non-greedy re-read). **One call per (character × stat)** (`source/stats/stats-logic.ts:215-263`). Prompt = completion prefill, no instruct: previous message + previous stats block + new message, ending mid-attribute `<stats character="X" pose="…" location="` (`source/prompts.ts:1-4`); output cut at the first unescaped quote (`api.ts:138-142`). Already-generated fields of the same character are fed in as dependencies (`location`←`pose`, `exposure/accessories`←`outfit`, `stats-registry.ts:10-14`, `api.ts:94-102`), so fields are ordered by `order`. Model may answer `!!no_change!!` → previous value copied (`api.ts:85,144-146`).
- **Health/circuit breaker.** Automatic runs first probe `GET /v1/models` with a 500 ms timeout (`api.ts:17-44`, called `stats-logic.ts:164-171`; manual runs skip the probe). A network/timeout failure sets `connectionFailureDetected` (`api.ts:157-159`); `shouldSkipApiCalls()` (`api.ts:51-64`) bails every call for `CONNECTION_CHECK_INTERVAL = 10000` ms (`:15`) and then **auto-retries**; loops break mid-character/stat (`stats-logic.ts:216,229,264`). Nothing persisted, no settings flipped.
- **First-appearance seeding.** A character with no prior stats gets `<character name description>` appended, filled from `substituteParams('{{persona}}')` for the player or `{{description}}` for the card (`source/export.ts:122-156`).
- **Persistence.** Stats live **on the chat message**, indexed by swipe: `message.stats[swipe_id] = ChatStatEntry{Characters, Scenes}` (`source/chat/chat-manager.ts:167-186`), saved with `saveChatConditional` (`:182`); lazy migration of old flat/object shapes (`:101-142`). Per-chat `chat_metadata.StatSuite = {selectedPreset, trackedCharacters}` (`chat-manager.ts:273-283`, `chat-metadata.ts`). Install-wide `extension_settings.StatSuite` created **at module import** with `??=` (`source/settings.ts:36`).
- **Mutation handling.** Swipe: a new swipe fires `MESSAGE_SWIPED` with `swipe_id >= swipes.length` → shows "..." placeholder (`events.ts:110-113`); swiping back to an existing swipe re-displays that swipe's stored stats **without a model call** (`:116-118`), else reads it. Edits/deletes: none — an edited message keeps stale stats until manually regenerated.
- **Injection.** Interceptor clears `ctx.setExtensionPrompt("StatSuite","",IN_CHAT,0)`, reads the last eligible message's stats (generating them **inside the interceptor, awaited**, if missing), renders each enabled Handlebars template, writes it to `ctx.variables.local` and optionally `setExtensionPrompt("StatSuite.<tpl>", text, IN_CHAT, depth)` (`stats-logic.ts:284-326`). Default template = XML `<metadata><stats character=… />` at depth 1 (`templates-registry.ts:5-16`); README: depth 0 too strong, deeper confuses recency; only the latest block is sent. `{$var}` pre-substitutes ST macros before Handlebars compiles (`templates/template.ts:88-97`).
- **UI.** `<details>` table inserted after `.mes_text` (`ui/stats-table.ts:402`), edit mode with `sanitizeStatInput` (strips articles/double spaces, `:10-21`, applied `:345`), per-cell/row/column regen, modifier keys = range (Shift all later, Ctrl next 5, right-click copy-from-previous, `:36-49`, `:165`), delete via `confirm()`. Per-message `.extraMesButtons` paste/request buttons (`ui/message-buttons.ts:9-24`). Stat presets per chat, lockable per character (`stats/presets-registry.ts:51-66`). Bracket-only messages `[…]` are ineligible (`chat-manager.ts:253`).
- **Training loop.** "Copy message export" button emits the exact training format (prev msg + prev stats + msg + new stats) with optional name anonymization `CharacterN` (`export.ts:71-107`, `:90-98`); full-chat export `export.ts:11-69`. Author asks users to send mis-reads for training.

## Overlap with Story Orchestrator
- **Physical state**: our state ledger already tracks `location, injuries, outfit_disguise, mood, active_goal, carried_items` per character (`src/memory/contract.ts:139`), injected at depth 3 (`src/constants/injectionRegistry.ts:19`), rendered as latest-value only (`src/memory/ledger.ts:164-177`). Ours is broader (objects/places/factions, blackboard-bound single writer, provenance, rollback) but coarser in time (full pass at scene breaks; per-read lines only with the capability profile) and author-only in the UI; no `pose`. Scene tracker covers location/present cast at depth 1 (`injectionRegistry.ts:22`).
- **Cost model**: they pay chars×stats calls per message on a tiny local model; we pay one shared read per cadence on a CM profile (`src/extraction/sharedRead.ts:87`). We are far cheaper per turn; they are more reliable per field on a 2B model. "No change" is native to us (DELTA lines only on change) — their `!!no_change!!` token is catching up to that.
- **Mutations**: we roll back every store on swipe/edit/delete (`src/runtime/turnBridge.ts:159-170`, `src/runtime/rollback.ts:35`); they handle swipes only and ignore edits/deletes — we are strictly better on correctness, they are better on **swipe-back reuse** (no re-read).
- **Reply path**: our interceptor is bounded (`src/runtime/talkControl.ts:70-75,253` `DIRECTOR_TIMEOUT_MS`); theirs awaits an unbounded chain of 60 s calls.
- **Backend failure**: theirs self-heals after 10 s; ours retries 3× at 250/500 ms (`src/extraction/scheduler.ts:213-224`) then **pauses install-wide by persisting `extraction.enabled=false`** (`scheduler.ts:174-181` → `src/runtime/runtimeManager.ts:430-436`), which only a user re-enables (grep: no auto re-enable path besides the one-time legacy lift `settingsStore.ts:152`). Theirs is better here.
- **Output to user scripts**: they write `ctx.variables.local`; we expose lazily computed `{{story_*}}` macros (`src/runtime/macros.ts:39`) — ours is fresher and needs no stale copies.
- **Editing**: they edit any stat inline; we edit memory rows (`src/runtime/coordinators/memoryCoordinator.ts:168`) but ledger rows only pin/remove (`memoryCoordinator.ts:420-422`; grep `editLedger`: 0 hits).

## Ideas for v2.4

| # | idea | kind | our area | our state | value | effort |
|---|------|------|----------|-----------|-------|--------|
| 1 | Transport-aware extraction backoff: probe + timed circuit breaker + auto-resume, persistent pause only for content failures | enhancement | extraction / pipeline | partial | 4 | M |
| 2 | "This read is wrong" → export flagged audit as an extractor fixture triple (anonymized) | testing | extraction / harness | absent | 3 | M |
| 3 | Author edit of a ledger row (override w/ provenance, bound fields refused) | enhancement | memory | partial | 3 | S |
| 4 | Deterministic OOC-message exclusion from read windows (consumer for dead `sceneOoc`) | enhancement | extraction | absent | 2 | S |
| 5 | Swipe-back reuse: restore the accepted read of a previously seen swipe instead of re-reading | enhancement | extraction / rollback | absent | 2 | L |
| 6 | First-appearance ledger seeding from card/persona text | enhancement | memory | absent | 2 | M |

**1. Transport-aware backoff.** What: split read failures into *transport* (network error, timeout, CM "API request failed", 5xx) vs *content* (parse/validation). Transport → no settings write; circuit-open for N s with exponential cap, a cheap CM-profile probe (the PONG `sendRequest` from our debug rules — `ctx.onlineStatus` is a cached label, gotcha) before the next automatic job, pipeline reads `stalled-rechecking` with "memory model unreachable, retrying", and resumes by itself; manual reads (`/cp extract`, re-read) bypass the probe as theirs do. Content failures keep today's pause. Theirs: `api.ts:15,17-64,157-159`, `stats-logic.ts:142-171`. Ours: `scheduler.ts:174-181,213-224`, `runtimeManager.ts:430-436`; `src/runtime/pipeline.ts:47` already has the state. Why it matters: the pause is install-wide and persisted, so one pod outage (a recurring event in our own gate records) silently disables extraction for every chat until someone notices — the same failure our S11 harness fix guards against, but caused by the product. Fit: no invariant conflict; the pause lives in the install-wide home (13); a resumed read still applies only at a boundary (3) and needs a `RunToken` check (10); the pending-queue invariant ("reload drops, reconciliation recovers") covers reads missed while open.

**2. Flagged read → fixture.** What: from the author-view extraction audit (or a ⚑ flag), "Copy as fixture" emits `*.story.json|transcript.json|expected.json` for the audited window with the author's corrected deltas/facts, names optionally replaced by `CharacterN`. Theirs: `export.ts:71-107` (single-message export in the exact training format), `:90-98` (anonymize), button `ui/stats-table.ts:154-161`. Ours: `so-journal.mts export` carries flags but not triples; the live-suite corpus is 22 hand-authored fixtures and its facts/rejected floors are explicitly uncalibrated (baseline §3C). Fit: author-only surface (9); clipboard/local only (privacy report); pairs with the existing `stateExport.ts` clipboard-or-console promise. Anonymization must also rewrite roster ids in the story slice, not only prose (their regex replace would also hit substrings — do it on word boundaries).

**3. Ledger row edit.** What: `editLedgerEntry(id, field, value)` mirroring `editMemoryEntry`: provenance `source: author` + `override`, refreshes its own injection (16), reversible by rollback (11). Rows bound through `ledger_binding` refuse and point at `/cp set` (single-writer rule). Theirs: inline edit + sanitize `ui/stats-table.ts:10-21,335-353`; README tells players to seed/fix state by editing. Ours: pin/remove only `memoryCoordinator.ts:420-422`; memory edit `:168`. Coordinator is at 615/620 lines — may need the helper in `memory/ledger.ts` (pure) with a one-line delegate.

**4. OOC exclusion.** What: `readMessage` in `src/extraction/chatWindow.ts:6-14` drops `is_system` and in-flight messages only; add an opt-in deterministic filter for whole-message OOC (`[…]`, `(OOC: …)`, `//…`) so an OOC aside is never evidence for a delta. Theirs: `chat-manager.ts:253` (`/^\[.*\]$/`). Ours: judge use `sceneOoc` has no consumer (`src/judge/settings.ts:11,114`, `src/judge/readiness.ts:38`, baseline seed "wire or remove"). A deterministic floor lets the judge use be removed or become a refinement. Fit: regex here filters *input*, never writes state (4 intact). Default **off**: README-style "seed with an OOC note" is legitimate player intent and hiding it from the reader would change today's behaviour.

**5. Swipe-back reuse.** What: key accepted audits by (message id, swipe text hash, scope hash, story id+version); on `MESSAGE_SWIPED` to an existing swipe whose key matches, re-enqueue the recorded deltas instead of waiting for the next reply's read. Host fact that makes it matter: swiping to an existing swipe calls `addOneMessage(…, {type:'swipe'})` and emits only `MESSAGE_SWIPED` (ST `public/script.js:10288-10315`; `addOneMessage` `script.js:2551` emits no render event), so we roll back and commit no boundary until the next reply. Theirs: `events.ts:103-127`, per-swipe storage `chat-manager.ts:144-186`. Ours: `turnBridge.ts:159-170` always rolls back. Low value (state catches up one turn later) and costly: the rollback≡replay property (11) must hold with a cache hit treated as "same input → recorded output", and the cache must not survive a story edit. Only worth it if players report swipe-induced state lag.

**6. First-appearance seeding.** What: when an entity first enters the ledger, include its card description (or persona for the player) in that one pass so outfit/carried items start from the card instead of "unknown". Theirs: `export.ts:122-156`. Ours: ledger entity list is names+types only (`memory/contract.ts:130-133`). Conflict: `docs/plans/v2.3/privacy-report.md` states persona and card text are **never read** — this would add a new crossing to the memory profile; needs an explicit opt-in and a privacy-report row. Value low given our target is authored stories whose roster already describes the cast.

## Patterns to copy / anti-patterns to avoid
Copy:
- Circuit breaker with a cheap pre-flight probe on automatic work only, manual work unthrottled (`api.ts:51-64`, `stats-logic.ts:164`) — idea 1.
- Inject only the *latest* state block, near the end (depth 1), not a history (README; default template). Our ledger at depth 3 sharing depth with session details is a tuning question worth one A/B, not a change.
- Dependent-field conditioning (generate `pose` before `location`, feed it in, `stats-registry.ts:10-14`) — relevant only if we ever do narrow per-quality re-reads (stall reconciliation, `src/extraction/reconcile.ts:58`).
- Export in the exact training/fixture format from the place the error is seen — idea 2.
Avoid:
- **Blocking, unbounded work in `generate_interceptor`**: ST awaits interceptors sequentially (`public/scripts/extensions.js:2033-2037`), and they run up to chars×stats×60 s there (`stats-logic.ts:296-297`). Our invariant 5 + director timeout already forbid this.
- Ignoring edits/deletes while caching per message (0 handlers) → stale state; per-swipe caches without invalidation.
- A single global `generating` flag + one `latestMessageIndex` (`events.ts:130,139-158`): in a group round, all but the last rendered member message are skipped until the interceptor lazily fills the last one.
- Writing extension settings at module import (`settings.ts:36` `extension_settings[name] ??= new …`) — the exact F2 trap our `settingsReady()` gate exists for.
- Browser-side `$.ajax` to a user URL (`api.ts:122`): CORS-dependent, no ST proxy/secrets; we route through CM profiles.
- Raw string completion prompt: fine for their purpose-trained model, but our acceptance run showed an untemplated string prompt drives Gemma into token loops — keep message-array + instruct.
- Power actions hidden in modifier keys + tooltips (`stats-table.ts:36-49`), native `confirm()`, jQuery modal with inline `position:fixed` (breaks under ST's transformed `<html>` — our `<dialog>` rule).

## ST host facts learned
- `generate_interceptor` receives `(chat, contextSize, abort, type)`; `type` includes `regenerate|quiet|impersonate|continue` (their `index.ts:14-15`); ST awaits interceptors **sequentially**, ordered by manifest `loading_order` (ST `extensions.js:2024-2037`; theirs `loading_order: 9`, ours `1`). Consistent with our use.
- `MESSAGE_SWIPED` fires **before** `Generate('swipe')` for a new swipe, with `swipe_id >= swipes.length` at that moment (their `events.ts:110`; ST `script.js:10278-10318`). Swiping to an **existing** swipe emits `MESSAGE_SWIPED` and **no** `CHARACTER_MESSAGE_RENDERED` (ST `script.js:10288-10293`, `addOneMessage` `:2551`). Not a contradiction of our gotchas, but a refinement: the "`swipe` render type commits a boundary" row covers only generated swipes.
- Arbitrary top-level fields on a chat message (`message.stats`) are persisted by `saveChatConditional` (their `chat-manager.ts:176-182`) — evidenced by their code only; not verified in ST here.
- `ctx.variables.local.set/get` exists on the context (ST `st-context.js:258`; their `templates-registry.ts:114`, `stats-logic.ts:313`).
- `setExtensionPrompt(key, "", IN_CHAT, 0)` is their clear (`stats-logic.ts:287-292`); we use a dedicated clear seam.
- `substituteParams('{{persona}}')` / `('{{description}}')` read persona and card text from an extension (`export.ts:126,132`).
- Per-message UI mounts: `.extraMesButtons` (`message-buttons.ts:9`) and after `.mes_text` (`stats-table.ts:402`).

## Verdict
Relevance **medium**: same problem space as our ledger (per-character physical continuity), but a much narrower product built around a purpose-trained model, so most of its surface (tables under messages, Handlebars templates, stat presets) is not for us. **The one thing worth taking: the self-healing circuit breaker** (idea 1). A transient backend failure should back off and resume. Today it persists `extraction.enabled=false` install-wide. Second: the "export the bad read in fixture format" loop (idea 2), which feeds the uncalibrated live-suite floors.
