## What it is
Chat-Completion "prompt workstation". Mostly UI over ST's PromptManager: collapsible divider sections + search (`features/prompts/prompt-manager.js`, `category-tray.js`, 7.6k lines), preset/character navigators, prompt archive/snapshots. Three pieces with behaviour: (1) **prompt directives** — `{{// @requires x}}`-style metadata inside prompt comments driving dependency/exclusion validation and **message-count triggers** that toggle prompts; (2) **improved reasoning capture** — post-processes assistant messages that ST's native parser missed, moving leading think-blocks into `message.extra.reasoning`; (3) **bundled preset installer** with a setup checklist. No LLM calls, no chat_metadata writes of its own, no injection.

## How it works
- **Boot**: `content.js:115` waits for `#left-nav-panel`, `publishPublicApi()` first (frozen `window.NemoPresetExt` + `nemo:preset-ext-capabilities` CustomEvent, `content.js:39-54`), then feature inits gated by `extension_settings.NemoPresetExt` flags; one `cleanupExtension()` owns every runtime's teardown (`content.js:56`), asserted by `tests/global-cleanup-wiring.test.js`.
- **Directive parsing**: regex over `{{// … }}` blocks (ST comment macro → never sent to the model), one `@key value` per line, ~60 keys (`features/directives/prompt-directives.js:88-120`, key table `:123-210`). Cached by exact content, TTL 60 s, cap 2000 (`:13-15`, `:78`).
- **Activation validation**: capture-phase document click listener on `.prompt-manager-toggle-action` (`prompt-directive-hooks.js:65-120`) cancels ST's toggle, runs `validatePromptActivation` (`prompt-directives.js:485`: exclusive-with + reverse check, requires, max-one-per-category, mutual-exclusive-group, soft conflicts, deprecated; dedup of mirror conflicts `:640-690`), then auto-resolves (`@auto-disable`, `@auto-enable-dependencies`, `prompt-directive-hooks.js:188-261`) or shows a conflict toast. Toggle = `promptManager.getPromptOrderEntry(activeCharacter,id).enabled = x; render(); saveServiceSettings()` (`prompt-directive-hooks.js:266-308`).
- **Message triggers**: `@enable-at-message N`, `@disable-at-message`, `@message-range a-b`, `@enable/disable-after-message` evaluated against `getContext().chat.length` (`prompt-directives.js:971-1095`) on `MESSAGE_SENT`/`MESSAGE_RECEIVED` (+100 ms timeout), `CHAT_CHANGED` (+200 ms), `GENERATION_STARTED` (`prompt-directive-hooks.js:339-357`). Dedup via module-level `lastProcessedMessageCount` (`:311`, reset on CHAT_CHANGED `:327`). Writes go into the **global preset's** prompt order and are saved — not chat-scoped, never reverted on swipe/delete/chat switch.
- **Reasoning capture**: pure core `reasoning/reasoning-capture-core.js` (14 known delimiter pairs `:19-34`, tagless hints `:36-43`, strategy/confidence gate `isUsableReasoningResult` `:287`: explicit ≥90, structured ≥85 + min lengths, both halves non-empty, content must change) + thin adapter `reasoning/nemonet-reasoning-config.js`. Listens `MESSAGE_RECEIVED/UPDATED/SWIPED`, `CHARACTER_MESSAGE_RENDERED`, `GENERATION_ENDED/STOPPED`, `CHAT_CHANGED` (`:99-107`). On capture: mutates `chat[id].mes` + `extra.reasoning`, `syncMesToSwipe(id)`, `saveChatDebounced()`, `updateMessageBlock()` if rendered (`:46-72`). Skips pristine greeting (`id 0 && chat.length === 1`, `:52`), skips messages with native `extra.reasoning`, tags must start the message, fenced code excluded (`core:88-120`), fails closed (README "Safety rules"). Native first: delegates to ST `parseReasoningFromString` when a closing delimiter exists; `getReasoningCandidates` guarded by `typeof` (`:95-98`).
- **Preset installer**: fetches bundled `assets/nemo-engine-latest.json`, validates shape (`features/preset-installer/runtime.js:50-76`), emits `OAI_PRESET_IMPORT_READY`, POSTs `/api/presets/save {apiId:'openai'}`, upserts `openai_settings`/`openai_setting_names`, selects via `#settings_preset_openai` change (`:100-190`). `getNemoEngineSetupReport` (`:270-330`) = ok/warning/error checklist incl. "installed preset references every `{{getglobalvar::Nemo*}}` slot" the sibling extensions (NemoLore, NemoGuides) write — a cross-extension contract carried by ST global variables (`:15-21`, `:258-262`).
- **Compat**: DOM/global sniffing for Chat Completion Tabs + Moonlit Echoes, adapts ownership instead of calling their APIs (`features/prompts/compat/capability-detector.js:1-60`); `getCompatibilityState()` debug handle.
- **Persistence**: `extension_settings.NemoPresetExt` only; one-time copy from legacy `NemoPromptTools` namespace + localStorage, **source kept for downgrade** (`core/storage-migration.js`, README §Migration).
- **Tests**: node:test source-regex boundary tests (`tests/core-source-boundary.test.js`), reasoning regression suite.

## Overlap with Story Orchestrator
- Preset control: they own Chat Completion presets (prompt toggles, install, select); SO preset effect is **textgen-only by design** and refuses on CC (`SO: src/services/stHost/presets.ts:41` `PRESET_UNSUPPORTED_REASON`). Their toggles are exactly the in-place global mutation SO forbids for WI (`SO invariant 14`, `src/runtime/worldInfoGates.ts:12`).
- Reasoning: SO strips leading reasoning only from **memory-model output** (`SO: src/extraction/client.ts:12-14`, `src/extraction/parse.ts:51` — 4 forms: `<think>`, `<thinking>`, Gemma channel, Harmony). The **chat window fed to extraction reads raw `mes`** (`SO: src/extraction/chatWindow.ts:6-13`), no reasoning strip, `extra.reasoning` ignored. Their capture is more careful (native-first, fenced-code aware, fail-closed, wider delimiter set).
- Setup checklist: SO's Repair (one worst-first step, `SO: src/runtime/repair.ts:25`) + capability read-out (`SO: src/services/stHost/capabilities.ts:68`) are stronger (consequence-first, derived), theirs is a flat checklist with a "Run setup" fixer.
- Lifecycle/tests: SO has `stopRuntime` (`SO: src/runtime/index.ts:214`) and far stronger architecture guards (`SO: src/runtime/architecture.test.ts`); nothing to take.
- Message-count triggers vs SO gates: SO's typed gates at rendered boundaries with rollback strictly dominate `chat.length` thresholds.

## Ideas for v2.4

| # | idea | kind | our area | our state | value | effort |
|---|---|---|---|---|---|---|
| 1 | Reasoning-safe extraction window | enhancement | extraction | absent | 4 | S |
| 2 | Third-party interference probes | host-integration | host / player-ui | absent | 3 | S |
| 3 | Chat-Completion prompt-toggle effect (path-replayed) | new-feature | stagecraft | absent | 3 | L |
| 4 | Story `requirements.api` (backend) → Repair step | enhancement | wizard / player-ui | absent | 2 | S |

**1. Reasoning-safe extraction window.** What: `readMessage` in the chat window should (a) drop a leading reasoning block from assistant `mes` using a fail-closed variant of `stripReasoningBlocks` (never the "unterminated → empty" rule, which is right for model output but would erase a chat message), (b) skip fenced code, (c) widen forms (`<thought>`, `<reasoning>`, `<reflection>`, `<analysis>`, `<cot>`, `[THINK]`, `◁think▷`, `<|begin_of_thought|>`). Why: on TC backends without auto-parse the character's private planning lands in the window; the extractor can then quote it and pass the evidence check (`SO: src/extraction/evidence.ts:28` only checks the quote is in the window), so unsaid intent becomes a fact/delta. Second reason: Nemo (and ST's own `auto_parse`, `ST: scripts/reasoning.js:1617`) rewrite `mes` **after** `MESSAGE_RECEIVED` via `updateMessageBlock`, which emits **no** `MESSAGE_UPDATED` (`ST: script.js:2033`) — so the same message reads differently depending on read timing; normalising in the window makes reads deterministic. Their evidence: `reasoning/reasoning-capture-core.js:19-34,88-120,287`, `nemonet-reasoning-config.js:46-72`. Ours: `SO: src/extraction/chatWindow.ts:10` reads `entry.mes` raw; `grep extra.reasoning src` → 0 hits. Fit: strengthens invariant 4 (evidence must be in the *visible* window); pure change in `extraction/`, gates tier = pure + a live-suite fixture with an inline `<think>`.

**2. Third-party interference probes.** What: extend capability probes / Copy-for-bug-report with "known interfering extensions present" (Nemo reasoning capture silently mutating `mes`; Presence hiding chat during drafts; Stepped Thinking Separated mode posting thoughts as messages — both already in our gotchas). Detection the way Nemo does it: globals/DOM markers + `extensionNames` (`ST: scripts/extensions.js:21`, exported) + their public handles (`window.NemoPresetExt.capabilities`, `content.js:39-54`). Report as `present` with the consequence, never block. Their evidence: `features/prompts/compat/capability-detector.js:1-60`. Ours: `SO: src/services/stHost/capabilities.ts:68` probes only host features (`macros, slashCommands, backgrounds, vectors, judge`). Fit: new `stHost/` read; no invariant strain.

**3. Chat-Completion prompt-toggle effect.** What: answers the open seed "OpenAI/CC preset adapter" (`SO: docs/plans/v2.3/v2.4-seeds.md:16`) differently — instead of a sampler adapter, a checkpoint effect that enables/disables named prompts of the active CC preset (the use case Nemo's `@message-range` serves crudely). Host seam learned from them: `promptManager` (`ST: scripts/openai.js:535`), `getPromptOrderEntry(activeCharacter,id).enabled` (`ST: scripts/PromptManager.js:1248`), `isPromptDisabledForActiveCharacter` (`:949`), `render()` + `saveServiceSettings()`; `OAI_PRESET_CHANGED_AFTER` (`ST: scripts/events.js:38`) to detect a user preset switch. Their evidence: `features/directives/prompt-directive-hooks.js:266-308`. Conflict: this is global, install-wide preset state — the same leak class that forced WI to "rebuilt from path, never toggled in place" (invariant 14) and preset textgen-only (21). Only acceptable as a gated set replayed from `checkpointPath`, through `EffectsApplier.withLedger` with compare-and-set restore on leave/chat switch (`SO: src/runtime/effectLedger.ts:112`), refused when `mainApi !== 'openai'`. L because of the restore semantics and live gate on a CC backend; decide the contract question first.

**4. Story `requirements.api`.** What: let a story declare the backend family it was authored for (e.g. `textgenerationwebui`) so Repair/requirements report it before play instead of the preset effect failing at a boundary. Inspired by `@incompatible-apis`, `@recommended-api`, `@model-incompatible` (`prompt-directives.js:30-50`, validation `:485`). Ours: `StoryRequirements` = personas/members/lorebooks only (`SO: src/engine/schema.ts:221`); `repair.ts` has no backend step. Fit: story-record field (invariant 13 home), needs `validate.ts` normalisation + Studio Story tab + diagnostic consequence (`DIAGNOSTIC_CONSEQUENCES`). Low value unless #3 or the CC adapter ships.

**5. Anti-pattern (already avoided).** Their message triggers key off `chat.length` (counts system/greeting messages, shifts on delete), dedup with a module-level counter only reset on CHAT_CHANGED, and write into the global preset — so a toggle made in chat A persists into chat B, and a swipe/delete never reverts it (`prompt-directives.js:1088`, `prompt-directive-hooks.js:311-421`). SO's boundary counters ≠ message indexes, rollback, and path replay are the correct answer; keep it that way in any #3 implementation. Ours: `SO: src/runtime/turnBridge.ts:54-57`, `src/runtime/worldInfoGates.ts:12`.

## Patterns to copy / anti-patterns to avoid
- Copy: **native-first, fail-closed post-processing** — defer to ST's parser when a closing delimiter exists, only then fall back; require both halves non-empty and "content actually changed"; leave bytes untouched on any doubt (`reasoning-capture-core.js:287`).
- Copy: **pristine-greeting guard** (`id 0 && chat.length === 1`) — ST keeps greeting swipe text unresolved for macro replay (`nemonet-reasoning-config.js:50-52`); matches our NON_TURN handling of `first_message`.
- Copy (minor): public frozen API + a capabilities CustomEvent published before async init, so other extensions can detect SO without racing (`content.js:39-54,111`). SO exposes debug globals, not a stable API.
- Avoid: capture-phase document click interception that cancels ST's own toggle and re-implements it (`prompt-directive-hooks.js:65-120`) — brittle to ST DOM changes, and on error it "allows the toggle" by re-running it itself.
- Avoid: global preset mutation driven by chat events (idea 5).
- Avoid: silently rewriting `chat[i].mes` without emitting `MESSAGE_UPDATED` — invisible to every other listener (including our TurnBridge).

## ST host facts learned
- `updateMessageBlock(id, msg)` re-renders only; emits no event (`ST: script.js:2033`). A third party can change `chat[i].mes` after `MESSAGE_RECEIVED` without SO's `MESSAGE_UPDATED` handler (`SO: src/runtime/turnBridge.ts:57`) ever seeing it — used by Nemo `nemonet-reasoning-config.js:62-70` and ST's own auto-parse (`ST: scripts/reasoning.js:1605-1618`). Extends our gotchas; no contradiction.
- `parseReasoningFromString(str, {strict}, template)` exported (`ST: scripts/reasoning.js:1461`); `getReasoningCandidates` referenced by Nemo (`nemonet-reasoning-config.js:96`) is **not** exported in this ST checkout (1.19.0) — Nemo guards with `typeof`. Version skew, verify before relying.
- `promptManager` is a module-level `export let` in `openai.js:535`, assigned at `:682` (null before CC setup); per-character prompt order: `getPromptOrderEntry(character, id)` (`ST: scripts/PromptManager.js:1248`), `isPromptDisabledForActiveCharacter` (`:949`); `saveServiceSettings` may be a no-op stub before configuration (`:377`).
- CC preset save path: `OAI_PRESET_IMPORT_READY` emitted before `POST /api/presets/save {apiId:'openai', name, preset}` (`ST: scripts/openai.js:4813-4820`); `OAI_PRESET_CHANGED_AFTER` after a switch (`:5078`). Nemo mirrors it (`features/preset-installer/runtime.js:168-185`).
- `{{// … }}` comment macro content is never sent to the model — Nemo stores structured metadata there (`prompt-directives.js:88`); usable carrier for author metadata inside ST-owned text fields.
- Global variables live in `extension_settings.variables.global`, chat variables in `chat_metadata.variables` (`features/prompts/category-tray.js:2703-2706`).
- `extensionNames` is exported from `ST: scripts/extensions.js:21`; `activeExtensions` is private (`:40`).

## Verdict
Relevance **low-medium**. Mostly a preset-UI workstation with no LLM, memory or narrative logic. The one thing worth taking: **make the extraction window reasoning-safe** (idea 1) — our window reads raw `mes`, so inline thinking can become "evidenced" facts, and reasoning post-processors (Nemo, ST auto-parse) rewrite `mes` without any event. Idea 3 is the only feature-level contribution and only if v2.4 answers the CC-preset contract question with "build it, path-replayed".
