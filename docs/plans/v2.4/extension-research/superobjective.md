## What it is
Fork + expansion of ST's built-in **Objective** extension. User types an objective; main model (quiet prompt) turns it into a numbered task list; tasks form a tree (branch any task into sub-tasks). The "current task" (first incomplete leaf, depth-first) is injected every turn; every N replies a quiet prompt asks the main model "is this task done? true/false". Adds: append-more-tasks, progress bar, per-task min-message "duration", recently-completed + upcoming tasks in the prompt, per-injection role, injection frequency, templates/prompt-set import-export, per-chat + global stats, pop-out panel, `/taskcheck`.

## How it works
- **Injection** — `setCurrentTask` (`index.js:396-495`) builds `"Your current task is [{{task}}]. Balance existing roleplay with completing this task."` (`:38`) + optional `Recently completed tasks: …` / `Upcoming tasks: …` (`:437-461`), then `context.setExtensionPrompt('SuperObjective', text, IN_CHAT, depth, true /*WI scan*/, role)` (`:467-474`). Role system/user/assistant per chat (`:464`, `:2880-2903`). Upcoming = remaining siblings, then any incomplete task in tree order (`:3060-3111`). Injection frequency N: on non-inject turns the prompt is **cleared** (`:478`), so the task is present 1 turn in N.
- **Completion check** — `MESSAGE_RECEIVED` handler (`:2959-3010`): increments `elapsedMessages` unconditionally (`:2968`), decrements `checkCounter` unless last gen type ∈ `continue|quiet|impersonate` (read via `substituteParams('{{lastGenerationType}}')`, `:2984-2985`) or it was a swipe and "count swipes" is off (`:2988-2989`). At 0 → `checkTaskCompleted` (`:254-342`): waits `is_group_generating===false` (10 s) and `is_send_press===false` (30 s) via `waitUntilCondition` (`:267`, `:270`), then `generateQuietPrompt(prompt,false,false)` on the **main model with full character context**, prompt begins "Ignore previous instructions… respond only true or false" (`:37`); parsed with `taskResponse.includes('true')` (`:326`). Duration gate: if `elapsedMessages < duration` it **still spends the call** only to toast "would be completed but duration not met" (`:285-307`).
- **Tree logic** — `ObjectiveTask` (`:515+`); parent auto-completes when all children done (`checkParentComplete`, `:583-602`); next task = first incomplete leaf depth-first (`:344-375`).
- **Persistence** — whole state in `chat_metadata.objective` via `saveMetadataDebounced` (`saveState`, `:1393-1421`) — settings values read **from the DOM** (`$('#objective-check-frequency').val()` etc.). Templates, custom prompt sets, global stats in `extension_settings.objective` (`:1078`, `:1995`, `:2223`). Migrates legacy flat `objective/tasks` and old per-chatId settings on load (`:1713-1745`).
- **Mutation handling** — none beyond a swipe flag (`:2956-2958`). No `MESSAGE_DELETED/EDITED` listener; a completion or elapsed count earned by a reply that is later swiped/deleted stays.
- **UI** — inline drawer in Extensions panel (`settings.html:2-10`); wand items "Manual Task Check" / "Complete Current Task" appended to `#objective_wand_container ?? #extensionsMenu` (`:1862-1877`); pop-out clones the drawer HTML into a `#zoomed_avatar_template` shell in `#movingDivs`, made draggable with `dragElement` + `loadMovingUIState` (`:1879-1922`); popups via `callGenericPopup`/`Popup.show.confirm`; drag-reorder via sortable (`:1502`).
- **Slash** — `/taskcheck` returns `"true"|"false"` for STscript (`:3013-3018`).

## Overlap with Story Orchestrator
- Goal graph: theirs = flat/tree task list with a boolean LLM judge; ours = typed checkpoint graph, typed gates over extracted qualities, one transition per boundary (`src/engine/transitions.ts:5`). We are strictly stronger on determinism, auditability, rollback (`src/runtime/rollback.ts:35`), provenance.
- Completion check: theirs = main-model quiet prompt + substring bool; ours = separate Connection Manager profile, strict parser, evidence span in window (`src/extraction/parse.ts:93`, `src/extraction/evidence.ts:28`), scheduler off-path (`src/extraction/scheduler.ts:54`).
- Task duration ≈ our `messages_in_checkpoint` code quality (`src/engine/engine.ts:345`) used in a gate — present.
- Hide tasks ≈ our player/author split (`src/components/drawer/DrawerTabs.tsx:710`) — ours better (spoiler checklist, `assert-player-clean`).
- Recently completed ≈ `{{story_past_checkpoints}}` macro (`src/runtime/macros.ts:43`); upcoming ≈ scene lookahead `reachableFrom` (`src/runtime/coordinators/sceneCoordinator.ts:167`) but that only feeds the judge scene read, not the main prompt.
- Templates / import-export ≈ story library + Studio `io.ts` (`src/studio/io.ts:6`); generate/append tasks ≈ wizard + expansion.
- **Where they are ahead:** the current objective reaches the main model **by default**. Ours reaches it only through an authored `author_note` effect or a macro the author places: no `INJECTION_REGISTRY` key carries the objective (`src/constants/injectionRegistry.ts:13-24`); `effects.author_note` is applied only when defined (`src/runtime/effectsApplier.ts:222`), so a checkpoint without one **inherits the previous checkpoint's AN**; generated beats are merged with `objective` + `guidance` and no effects (`src/generation/merge.ts:24-31`), and `Checkpoint.guidance` (`src/engine/schema.ts:156`) is never read by any runtime injection path (grep: only `copilot/parse.ts`, `engine/validate.ts`, `studio/components/CheckpointEditor.tsx:173`, expansion request). Sun-ruins hand-writes 9 `author_note`s to cover this.

**6. Anti-pattern: substring bool over main-model quiet prompt.** `includes('true')` (`index.js:297`, `:326`) accepts "not true", "true or false"; the prompt runs on the roleplay model with full card/WI context and an "Ignore previous instructions" preamble (`:37`); it blocks the main backend and burns a call even when the answer cannot change state (duration unmet, `:285-307`). Ours already: strict parse + separate profile + evidence + off-path. Keep as a reviewer checklist line for any new judge/curator parser (cf. V14 evidence word-span fix).

**7. Anti-pattern: reserved namespace + shared default.** ST ships `extension_settings.objective: {}` as a core default (`public/scripts/extensions.js:194`) and a reserved `#objective_wand_container` (`public/scripts/templates/wandMenu.html:15`); SuperObjective reuses both plus `chat_metadata.objective`, so it and the built-in Objective read/write the same state — the likely cause of the author's "uninstall Objective first, not sure why" (post.md). It also relies on the core key existing (`Object.keys(extension_settings.objective)` at `index.js:1695` would throw otherwise). Ours: unique `story-orchestrator` / `story_orchestrator` keys, blob versioned + chat-stamped (`src/runtime/persistence.ts:60`).

## Patterns to copy / anti-patterns to avoid
Copy:
- Re-render the directive on **every** goal change, and clear it when there is no goal (`index.js:489-493`) — the property our AN carry-over lacks (#1/#2).
- Wait for `is_group_generating`/`is_send_press` before an extra call (`:267-270`) — we already avoid needing it by running off-path on a separate profile; note for any future main-model call.
- Pop-out floating panel via `#movingDivs` + `dragElement` + `loadMovingUIState` (`:1879-1922`) — possible later for the HUD/Overview; would need a new mount root in the CSS scope list + `mountRootFor` (inv. 19) and a React portal, **not** their `.html()` clone (clone only works because every handler is `$(document).on`, `:2930+`).

Avoid:
- Substring bool parsing; main-model quiet checks (#6).
- No rollback: swipes only toggle a counter flag (`:2957`), `elapsedMessages` counts every received message incl. regenerations (`:2968`); no delete/edit handling.
- Settings read back from the DOM at save time (`saveState`, `:1400-1415`) — same trap as our "drive the store, never `box.checked`" gotcha.
- LLM/user text interpolated raw into HTML (`contenteditable` span `:652`, history popups `:2850`, `:3205`) — injection risk; ours uses DOM text nodes (`src/services/stHost/popup.ts:13`).
- Hard-coded install folder in `renderExtensionTemplateAsync('third-party/ST-SuperObjective', …)` (`:2916`) — breaks if cloned under another name.
- User-editable core prompts + prompt-set import/export (`:944-1330`): fine for a toy judge, wrong for us — calibrated floors/goldens assume fixed prompts (inv. 7, 20).
- Global/per-chat statistics (`:2211-2360`): no story value; journal covers auditing.
- Spending an LLM call whose answer cannot change state (`:285-307`).

## ST host facts learned
- `extension_settings.objective` is a **core default key** (`public/scripts/extensions.js:194`) and `#objective_wand_container` is reserved in `public/scripts/templates/wandMenu.html:15`; third-party extensions without a reserved container append to `#extensionsMenu` (their `index.js:1863`).
- `generateQuietPrompt` takes an options object now (`script.js:3084`); positional calls still work via a compat shim that `console.trace`s a deprecation (`script.js:3085-3088`). Their positional call (`index.js:132`) relies on it.
- `setExtensionPrompt(key, value, position, depth, scan=false, role=SYSTEM, filter=null)` — `script.js:8926`; `scan` lets injected text trigger WI (their `index.js:472`).
- `{{lastGenerationType}}` is set on `GENERATION_STARTED` (dry runs skipped) and reset on `CHAT_CHANGED` (`public/scripts/macros/definitions/state-macros.js:15-21`; legacy registration `macros.js:723`). Reading it inside `MESSAGE_RECEIVED` (their `index.js:2985`) is racy when any other quiet generation starts in between; `MESSAGE_RECEIVED` itself carries `(messageId, type)` (`script.js:3799`, `:6691`) — the reliable source, which is what TurnBridge uses. Their `quiet`/`impersonate` skip (`:2984`) is consistent with our gotcha that those never emit `MESSAGE_RECEIVED` (dead branch, not a contradiction). They also skip `continue`, which we deliberately commit.
- `is_group_generating` (`public/scripts/group-chats.js:110`), `is_send_press` (`script.js:603`), `waitUntilCondition(cond, timeout, interval)` (`public/scripts/utils.js:1934`) — usable "host busy" waits.
- Floating panels: `dragElement($el)` (`public/scripts/RossAscends-mods.js:477`), `loadMovingUIState()` (`public/scripts/power-user.js:1835`), shell `#zoomed_avatar_template` (`public/index.html:6423`), container `#movingDivs` (`public/index.html:7737`).
- No fact here contradicts `.claude/rules/gotchas.md`.

## Verdict
Relevance **medium-low** as a feature source (we supersede it on every axis of state and rollback), but it surfaced one real gap by contrast: **the checkpoint objective is not injected by default** — it depends on hand-authored `author_note`, a missing one silently inherits the previous checkpoint's note, and generated beats' `objective`/`guidance` never reach the model. The one thing worth taking: SuperObjective's "always re-render the current goal into the prompt, clear it when none" — as #1 (agency-aware objective block, no upcoming-task lookahead) or at minimum #2 (diagnostic).
