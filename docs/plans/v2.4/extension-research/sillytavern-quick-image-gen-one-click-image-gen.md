## What it is
One-click image generation from chat context into the chat, over 18 image backends (Pollinations, NovelAI, OpenAI, Gemini, A1111/ComfyUI, custom JSON APIs…). The Text AI (main API, or a separate Connection Manager profile) turns the chat scene into an image prompt, optionally in two passes. Also: auto-generate every N replies, an "AI-tagged" inject mode where the RP model emits image tags in replies, batch/gallery, style presets, per-character references, and chat-background setting. Domain overlap with SO is small. The value is in its **host-persistence and ownership plumbing**. Its `lib/` is a careful, heavily tested (and codex-audited, `docs/bug-sweep-report-*.md`) take on the same host traps SO has hit.

## How it works
- **Bootstrap**: `jQuery(async …)` imports ST modules by relative path. Each optional module (`world-info.js`, `openai.js`, `utils.js`, `popup.js`, `RossAscends-mods.js`) sits in its own try/catch, so one missing host export only degrades a feature (`index.js:22625-22680`). A failed init is shown in `#extensions_settings` plus a sticky toast (`index.js:22736-22760`), not left as a console line.
- **Events** (`index.js:22609-22621`, via `lib/lifecycle.js:30-37` disposable scope): `MESSAGE_RECEIVED` → auto-gen cadence + delay (`index.js:22536-22592`); `CHAT_COMPLETION_PROMPT_READY` → **mutates the prompt array** to insert the inject-mode instruction (after the system block, before the last user turn, or at a depth; `index.js:21998-22051`), and skips its own internal calls through a global counter; `CHAT_CHANGED` → cancel run, reset cadence, clear dedupe (`index.js:22594-22607`). No `generate_interceptor`, no `setExtensionPrompt`, no macros.
- **LLM calls**: the main API goes through `generateRaw` / `generateRawData` / `generateQuietPrompt({quietPrompt, skipWIAN, quietToLoud:false, signal})`, and a direct `/api/backends/chat-completions/generate` built with `createRawPrompt` + `createGenerationParameters` (`index.js:1872-2010`). All of it runs through one abortable serialized queue (`lib/client-orchestration.js:30-70`, `index.js:1636`). A failed request is **never retried** (`index.js:1889-1891`, to avoid "double billing"). The override route is `ConnectionManagerRequestService.sendRequest(profileId, messages, maxTokens, {extractData, includePreset, includeInstruct, stream:false, **signal**})` (`lib/client-orchestration.js:188-228`). A preset override clones the profile and re-implements CMRS's per-API switch (`:106-160`).
- **Two-step prompt**: pass 1 = a plain visual description of the selected message range, pass 2 = conversion to a style (README "Chat-scene generation"; `lib/prompt-pipeline.js`). Optional WI context comes from `checkWorldInfo(reversedChat, maxContext, isDryRun=true, globalScanData)` (`lib/world-info-context.js:165-177`), flattened across every slot (`:16-66`).
- **Chat writes**: image messages are pushed as assistant messages (`mes:"Generated image"`, `extra.media[{source:'generated'}]`, `inline_image:true`) with `chat.push` + `addOneMessage` + `saveChat`. **No event is emitted** (`index.js:10480-10507`). Inject cleanup strips the tags from `mes`/swipes/`display_text` **in place**, saves, then `reloadCurrentChat()` (`index.js:21830-21875`).
- **Mutation handling / ownership**: each async job carries
  - a `createMessageTargetSnapshot`: chat array identity, index, persistent id, and a hash of `mes`/`display_text`/swipe/reasoning (`index.js:2066-2129`);
  - a `createChatIdentitySnapshot` (chat, chatId, chatMetadata object identity, `:2092-2106`);
  - a conversation checkpoint: the chat length plus the messages the job itself inserted (`lib/client-orchestration.js:229-257`).

  The job is re-asserted before every write. Undo only removes the **last** message and refuses otherwise (`index.js:10513-10517`).
- **Persistence evidence** (`lib/host-persistence.js`): chat saves are read back via `/api/chats/get` / `/api/chats/group/get` and compared as whole JSON (`:50-85`). Settings saves are confirmed by `SETTINGS_UPDATED` plus a read-back of `/api/settings/get`, matching a written `_syncCacheId` (`:32-48`, `:87-137`). Each write is wrapped in `runDurableTransaction` (mutate → persist → validate, else rollback + persist the rollback, `AggregateError`; `lib/chat-transaction.js:49-77`) with field-level compare-and-set restore (`restorePropertyIfUnchanged`, `lib/client-orchestration.js:72-77`).
- **Other persistence**: settings in `extension_settings.<name>`, synced through the ST server user. The gallery lives in IndexedDB namespaced by account (`createAccountStorageScope`, `lib/client-orchestration.js:367-379`). The locked background goes in `chatMetadata.custom_background` + `chat_backgrounds` (`lib/chat-transaction.js:87-150`). Logs go to a bounded, redacted ring (`lib/privacy-log.js`).
- **Slash commands**: `/qig [mode=] [quiet=true]` (quiet returns the saved image path), `/qig-auto state= every= delay=`, `/qig-cancel` (`index.js:22430-22500`).
- **Tests**: `node --test` + jsdom + fake-indexeddb. `tests/helpers/qig-harness.js:1-140` writes **fake ST host modules at ST's real relative paths** in a temp tree, so the real `index.js` entrypoint boots unmodified (`tests/index-entrypoint.test.js`).

## Overlap with Story Orchestrator
- **Save evidence**: SO already observes the chat-save request and reads back the server's copy (`src/services/stHost/persistence.ts:52-133`, `src/runtime/saveEvidence.ts:44`). SO's check is narrower and sturdier (it compares our boundary only, not the whole-JSON equality that any concurrent metadata write breaks). SO has **nothing** for install-wide settings saves (story library, wizard sessions, settings store: `src/runtime/storyLibrary.ts:69,110,119`, `src/runtime/settingsStore.ts:135,161`, `src/runtime/wizardSessions.ts:44,49` all fire `saveSettingsDebounced()` and trust it). QIG does this better.
- **Ownership**: SO's `RunToken` (`src/runtime/runToken.ts`) is richer on story/version/window semantics. It is event-driven, though (`windowRevision` bumps on `MESSAGE_EDITED/DELETED/SWIPED/UPDATED`, `src/runtime/turnBridge.ts:54-57`). QIG's content signature also catches a message rewritten in place with no event, which QIG itself does (`index.js:21830-21875`).
- **Cancellation**: SO has an epoch `AbortSignal` (`src/runtime/runOwner.ts:47,76`) but wires it **only to the judge** (`src/runtime/judge.ts:130`). QIG cancels its Connection Manager calls.
- **Compare-and-set restore**: SO has it for host effects (`src/runtime/effectLedger.ts`) and not for `memoryQueue.commitDecision` (`src/runtime/memoryQueue.ts:102`, already v2.4 seed D). QIG's `restorePropertyIfUnchanged` is that shape.
- **Background**: both lock via `custom_background`. SO goes through `/bg` (`src/services/stHost/backgrounds.ts:11,50`).
- **Images**: SO has none (baseline §4).

**1. CMRS abort signal.** ST's `ConnectionManagerRequestService.sendRequest` takes `custom.signal` and hands it to `ChatCompletionService`/`TextCompletionService.processRequest` (ST `public/scripts/extensions/shared.js:415,424,458`; present since commit `a7d48b1ae`, 2025-03-26, and in our declared older host 1.18.0). QIG uses it (`lib/client-orchestration.js:200`). Our `src/judge/types.ts:66-68` says CMRS "takes no signal (shared.js:423), so extraction calls cannot be cancelled at the host at all". That is **false**. `sendConnectionProfileRequest` (`src/services/stHost/connectionProfiles.ts:43-50`) passes no signal, so on a chat switch or restart every in-flight shared read, scene/epistemic pass, director call and expansion keeps burning the (single, slow) backend, and the RunToken discards the result afterwards. Fix: add an optional `signal` to `sendConnectionProfileRequest`/`callExtractionModel` and supply `ownership.signal()`. Treat an abort as `lapsed`, not `error`, or it pauses extraction install-wide. Fits invariants 5/10; the reply path is unaffected.

**2. Settings-save evidence.** `saveSettings` catches everything and only toasts (ST `public/script.js:8096-8114`). `SETTINGS_UPDATED` fires **only on success**, with no payload. QIG arms a `SETTINGS_UPDATED` listener before saving, then confirms by reading `/api/settings/get` for a value it wrote (`lib/host-persistence.js:32-48,87-137`; `lib/settings-persistence.js:73+`). SO trusts `saveSettingsDebounced()` for the story library and wizard sessions, the exact store the S12 "library loss" incident hit. Proposal: a `stHost/settingsEvidence.ts` that writes a nonce (e.g. `extensionSettings["story-orchestrator"].saveNonce`), triggers the save, and reads it back. The Studio's `Saved "X" vN to the library.` line should then depend on that evidence, and the player-visible wording should follow the chat-save split (`unsaved` vs `unconfirmed`). This extends invariant 17 from chat metadata to install-wide settings. Caveat: the debounce means the nonce read must wait past `DEFAULT_SAVE_EDIT_TIMEOUT`, or call `saveSettings` directly.

**3. Generated-media messages in extraction windows.**
- `readMessage` keeps any non-system message with text (`src/extraction/chatWindow.ts:6-13`).
- ST's `/sd` posts a **visible assistant message whose `mes` is the templated image prompt** (tag soup), with `extra.media[].source = GENERATED` (ST `public/scripts/extensions/stable-diffusion/index.js:4970-4998`).
- QIG posts `"Generated image"` as the character, with no event (`index.js:10480-10507`).
- TurnBridge already refuses the `/sd` post as a boundary (`NON_TURN_MESSAGE_TYPES` has `extension`), but its text still enters the shared read, the evidence check and the scene/epistemic passes as a character line.

Filter a message whose `extra.media` is non-empty and all `source === "generated"`, when its text is empty, `"Generated image"`, or the SD template (QIG's predicate: `lib/client-orchestration.js:260-268`). Pure, S. Fits invariant 4 (it reduces the evidence a model can cite).

**4. Resilient bootstrap.** `src/services/stHost/modules.ts:9-16` + `context.ts:12-13` are ten **top-level awaited** host imports. If any one rejects (e.g. a future ST moves `logit-bias.js`), the whole bundle fails to evaluate. Then nothing mounts, the capability probes never run, and the user sees an extension that "isn't installed". QIG isolates optional imports (`index.js:22640-22680`) and renders the failure where the panel should be (`index.js:22736-22760`). For SO: `Promise.allSettled` over the non-core modules, feeding the capability probes (a missing module becomes `absent`, not a crash), plus a mount-time error card under `#extensions_settings`. Fits invariant 2 and the plan-06 "block, don't fail" rule.

**5. Silent in-place mutation.**
- QIG rewrites `mes`/swipes/`display_text` in place and saves, emitting no `MESSAGE_EDITED` (`index.js:21830-21862`). It then calls `reloadCurrentChat()` on a `setTimeout(0)` (`:21868-21873`). That goes through `getChat` → **`CHAT_CHANGED` for the same chat** (ST `public/script.js:1710-1720,7700`), which our `TurnBridge.onChatChanged` treats as a full switch: `reset()` drops pending turns, then rehydrate and bump the epoch (`src/runtime/turnBridge.ts:149-152`).
- Between the save and the reload, a read computed on the old text passes `tokenMatches` (no `windowRevision` bump). The reload then throws away in-flight reads for the reply that carried the tag.
- Other rewriting extensions (post-processors, regex-on-save) may never reload.

Proposal: (a) mint the token with a cheap hash of the window's `mes`+`swipe_id`, the way QIG's `getMessageContentSignature` does (`index.js:2066-2090`), and compare it before each write; (b) add a journey or interop scenario that runs `reloadCurrentChat()` mid-read and mid-pending-boundary, and record what is lost. Fits invariants 10/11. Cost: one hash per check over ≤ window size.

**6. Durable put-back.** `runDurableTransaction` (`lib/chat-transaction.js:49-77`): mutate, persist, validate, and on failure run rollback and **persist the rollback**, surfacing both errors (`AggregateError`). `restorePropertyIfUnchanged(target,key,expected,previous)` (`lib/client-orchestration.js:72-77`) only restores a field that still holds what we wrote. That is exactly seed D ("id-keyed restore in `memoryQueue.commitDecision` — compare-and-set like `effectLedger`"; ours `src/runtime/memoryQueue.ts:102`). Copy the shape, not the code. SO still decides failure from save evidence (`saveWasLost`), never from an exception (QIG's version relies on a thrown or `false` result, which `saveMetadata` never gives; see anti-patterns).

**7. Bundle boot smoke.** QIG boots its real entrypoint in jsdom by writing stub modules at ST's relative paths (`tests/helpers/qig-harness.js:13-80`), so any import-time failure is a unit-test failure. SO's jest cannot import anything touching `STAPI` (top-level await; gotcha "a module that imports the host seam cannot be unit-tested"). The only boot proof is a browser. Our imports are absolute (`"/script.js"`), so the harness would need a node loader hook or a tiny static server mapping `/scripts/*` to stubs. It would guard idea 4 and the `startRuntime` ordering. `npm run test:debug` (node:test) is the natural home. Value 2: clean-host + live runs already catch most of this, just late.

**8. Illustration effect.** QIG proves demand, and `/qig quiet=true` returns an image path to STscript (`index.js:22430-22463`). SO's addendum allows new stagecraft "only if a verified host seam exists", and ST core `/sd` is that seam; QIG is a third party, so it should be a probed option only. As a deterministic checkpoint effect (`effects.illustration: {prompt}`), it would post an `extension`-typed message, which TurnBridge already treats as non-turn. It would need a ledger row, rollback removal of the posted message (last-message-only, as QIG's undo refuses otherwise), and idea 3 so its prompt text does not pollute extraction. Low priority; it opens a whole new effect class.

## Patterns to copy / anti-patterns to avoid
Copy:
- **Undo only what is still last, else refuse** (`index.js:10513-10517`). Splicing mid-chat invalidates every later index. Relevant to any future SO message-posting effect (npc_replies rollback).
- **No automatic retry of a failed paid request** (`index.js:1889-1891`). Consistent with SO's single repair pass. Keep it that way for judge and extraction.
- **Bounded, redacted diagnostic ring**: the raw input is truncated *before* the redaction regexes run (hostile-payload CPU bound), and there are byte caps per entry and in total (`lib/privacy-log.js:72-91`). SO's journal/`so-journal follow` exports carry raw prompts. That is fine for authors, but the byte-cap-before-regex rule applies to any parser of model output.
- **Response size caps** on every host/provider read (`readResponseJson(response, maxBytes)`, `lib/host-persistence.js:24`). Relevant to v2.4 seed D, "no request-size bound on extraction path", in the response direction.
- **Owned-insertion checkpoint** (`lib/client-orchestration.js:229-257`): "the chat is unchanged except for the messages I added". A useful precise predicate for SO's `npc_replies` post-then-verify.

Avoid:
- **Reading group chat metadata from the group object.** `createChatSaveConfirmer` reads `/api/groups/all` → `group.chat_metadata` for group metadata-only saves (`lib/host-persistence.js:69-73`, comment "Group metadata lives in the group file"). Current ST **migrates that field out** of group files into the chat file header and deletes it (ST `src/endpoints/groups.js:22-94`; client reads the header, `public/scripts/group-chats.js:268,633`). So their check can only answer `false` on ST 1.19, and a correct save reads as failed. SO's `readServerBoundary` reads the header (`src/services/stHost/persistence.ts:108-133`), which is correct.
- **Whole-JSON equality as save evidence** (`lib/host-persistence.js:73,83`). Any concurrent metadata write by another extension (or by SO) turns a landed save into "failed". Compare only what you own (SO: the boundary).
- **Re-implementing CMRS's per-API request switch** to override a preset (`lib/client-orchestration.js:106-160`). It already drifts from ST (no `reverse_proxy`, `proxy_password`, `custom_prompt_post_processing`, `pollinations_endpoint`; cf. ST `shared.js:436-458`). SO's rule (host access through one seam, verified shapes) is right; use `overridePayload` instead.
- **In-band model tags + in-place message rewrite + `reloadCurrentChat`** (inject mode). The tags pollute the RP reply (and SO's extraction window), the rewrite emits no mutation event, and the reload masquerades as a chat switch.
- **Mutating the `CHAT_COMPLETION_PROMPT_READY` array** for injection (`index.js:21998-22051`). It works only for Chat Completion, ignores the event's `dryRun`, and needs a global "is this my own call" counter. SO's `setExtensionPrompt` + `INJECTION_REGISTRY` is the better shape.
- **Dry-run `checkWorldInfo` from an extension** (`lib/world-info-context.js:175`) runs `resetExternalEffects()` at its end (ST `public/scripts/world-info.js:5275`, `:417-419`). If QIG's scene-lore option is on and its scan lands between SO's `WORLDINFO_FORCE_ACTIVATE` (`src/services/stHost/worldInfoActivate.ts:18-25`) and ST's real scan, it **consumes SO's forced lore**, and QIG's image prompt gets it instead. The window is narrow (SO forces at `GENERATION_STARTED`; QIG runs after a reply plus a delay), but real in group rounds. Note for `loreSelect` interop; not fixable on our side beyond forcing as late as possible.
- A 23k-line `index.js`. The `lib/` split came late; SO's size budgets (`architecture.test.ts`) are the right answer.

## ST host facts learned
- `ConnectionManagerRequestService.sendRequest(profileId, prompt, maxTokens, {stream, signal, extractData, includePreset, includeInstruct, instructSettings}, overridePayload)` honours `signal` (their `lib/client-orchestration.js:200`; ST `public/scripts/extensions/shared.js:415,424,458`). **CONTRADICTS our `src/judge/types.ts:66-68`** ("takes no signal").
- `saveSettings` swallows failures (toast only); `SETTINGS_UPDATED` is emitted only after a 2xx, with no payload (their `lib/host-persistence.js:4,87-137`; ST `public/script.js:8096-8114`). Consistent with our `saveMetadata` gotcha; extends it to settings.
- `/api/settings/get` returns `{settings: <JSON string>}` containing `extension_settings` (their `lib/host-persistence.js:34-37`).
- Group chat metadata: QIG assumes `groups[].chat_metadata` (their `lib/host-persistence.js:69-73`). **Contradicted by ST 1.19** (`src/endpoints/groups.js:22-94` migrates it into the chat header). Agrees with our `persistence.ts` / gotchas; theirs is stale.
- `checkWorldInfo(chat /*strings, newest first*/, maxContext, isDryRun, globalScanData)` returns `worldInfoBefore/After`, `EMEntries`, `ANBeforeEntries/ANAfterEntries`, `WIDepthEntries[{depth,role,entries}]`, `outletEntries` (their `lib/world-info-context.js:16-66,175`; ST `public/scripts/world-info.js:4709`). A dry run still clears external force-activations (ST `:5275`). Consistent with our `worldInfoActivate.ts` comment; new consequence: third-party dry runs can eat our forced entries.
- `generateQuietPrompt({quietPrompt, skipWIAN, quietName, quietToLoud, signal})`, `generateRaw({prompt, quietToLoud, trimNames, prefill, signal})`, `generateRawData` (meta-returning) and `createRawPrompt`/`createGenerationParameters` are importable (their `index.js:1872-2010,22633-22655`).
- `ctx.addOneMessage` emits no event (ST `public/script.js:2551-2607`). An extension can append assistant messages that SO's TurnBridge never sees (their `index.js:10480-10507`). ST's `/sd` does emit `MESSAGE_RECEIVED`/`CHARACTER_MESSAGE_RENDERED` with type `extension` (ST `stable-diffusion/index.js:4995-4998`), consistent with our `NON_TURN_MESSAGE_TYPES`.
- `reloadCurrentChat` → `getChat`/`getGroupChat` emits `CHAT_CHANGED` for the **same** chat id (ST `public/script.js:1710-1720,7700`). Third parties call it after in-place edits (their `index.js:21868-21873`).
- A locked chat background is `chatMetadata.custom_background` (css url) plus the `chat_backgrounds` list (their `lib/chat-transaction.js:110-133`; ST `public/scripts/backgrounds.js:14-15`). Consistent with our gotcha; `chat_backgrounds` is new to us.
- `ctx.appendMediaToMessage(message, element, "adjust"|"replace")` and `extra.media[]` with `media_display:'gallery'` are the ST ≥1.14 media model (their `index.js:10175-10182,10349`).

## Verdict
Relevance **medium**. It is an image extension, but its `lib/` works through the same host-truth problems SO fights. The one thing worth taking is **idea 1**: pass the epoch signal into `CMRS.sendRequest`. It fixes a false host claim in our own code and stops dead reads from occupying the single backend after a chat switch, in about ten lines. Next best is idea 2 (settings/library save evidence, the unguarded twin of plan 06's chat-save evidence), then idea 3 (keep `/sd` prompt text out of extraction).
