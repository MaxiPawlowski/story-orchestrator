# Stat-us Maximus — v2.4 review

author Leandro (leandrojofre) · repo https://github.com/leandrojofre/SillyTavern-Stat-us-Maximus · commit `e9d83a6` 2026-09-01 (manifest 2.3.3, ST ≥1.17.0) · 25 upvotes / 486 msgs · source available: y (`source/`, ~5k lines plain JS + jQuery + Popper, no build, no tests)

## What it is
Hand-edited per-character "status blocks" (key/separator/value entries, with alt "swipe" values per entry) stored in `chat_metadata`, rendered as a collapsible table inside each character's last chat message, and injected as one extension prompt per present character. No LLM, no automation: the author says it is a prompt shortcut, and automation is left to user STscript via ~15 `/stum-*` slash commands. Status can also be "detached" (not tied to a character: world, car, etc.) and entries can be "private" (sent only when the owner is generating).

## How it works
- **Injection, per generation**: `eventSource.makeLast(GENERATION_AFTER_COMMANDS, …)` (`source/js/eventListeners.js:288`). The handler (`:110-215`) deletes every `extensionPrompts` key containing `stat_us_maximus` (`:127-129`, direct mutation of ST's object), recomputes present participants (`index.js:290` `getActiveParticipants`: group members minus `disabled_members`, plus the persona, drafted member always kept), then calls `setExtensionPrompt(uuid, prompt, IN_DEPTH, depth, true, role)` per status (`:204`). Prompt = `prefix + entries.join(separator) + suffix`, run through `substituteParams` with a `{{name}}` dynamic macro plus `/* */` and `//` comment stripping (`:138`, `index.js:648-659`).
- **Private entries** = our per-member epistemic idea in miniature: `charIsGenerating` is `context().characterId === status owner` (in groups ST sets `characterId` to the drafted member before `Generate`, `group-chats.js:1054-1063`), and private entries are filtered out for everyone else (`eventListeners.js:150-169`). Toggle per chat in `chat_metadata.stat_us_maximus_settings` (`source/classes/ChatSettings.js:14-56`).
- **Dynamic depth**: `Status.refreshDepth` (`source/classes/Status.js:311-328`) sets depth = distance from chat end to the owner's last visible (non-`is_system`) message, 0 if the owner is generating, -1 (skip) if the owner never spoke. Clamped by `minPromptDepth`; on `continue` a depth-1 block is shifted by -1 (`eventListeners.js:43-51,200`). ST itself already maps depth 0→1 on continue (`script.js:5665`).
- **Message attribution**: by avatar, parsing `file=` out of `mes.force_avatar` or `mes.original_avatar`, falling back to name (`index.js:436-483`).
- **In-chat UI**: `renderCharStatus` (`index.js:666-826`) inserts a drawer **before `.mes_text` of the owner's last message**; re-rendered (debounced 500 ms) on `MESSAGE_UPDATED/DELETED/MORE_MESSAGES_LOADED` and `*_MESSAGE_RENDERED` (`eventListeners.js:282-286`). Inline input widgets come from custom macros `{{text}} {{number}} {{boolean::v::T::F}} {{range::min::max::step::v}}` implemented as `dynamicMacros` handlers with `delayArgResolution` (`source/js/macros.js:60-440`); edits write straight back to metadata (`eventMethods.js:493-570`).
- **Persistence**: array of Status objects in `chat_metadata.stat_us_maximus` (+ `_files`, `_settings`), `dataVersion` + one migration (`Status.js:73-98`). Every setter calls `saveMetadataSafe` → debounced `saveChat` (`index.js:606-617`); with autosave off the save buttons turn red (CSS var) as a dirty indicator. Install settings in `extension_settings['SillyTavern-Stat-us-Maximus']`, defaults backfilled on `APP_INITIALIZED` (`index.js:1161-1175`).
- **Mutations**: none handled. No swipe/edit/delete logic — status is a single current value per chat, not anchored to messages (grep `swipe|MESSAGE_SWIPED|rollback` finds only the entry "alt value" feature). Rename: `CHARACTER_RENAMED_IN_PAST_CHAT` rewrites avatars in each past chat's metadata header (`eventListeners.js:222-240`).
- **Scripting surface**: `SlashCommandParser.addCommandObject` with named args, `returns`, raw-string returns for pipes (`slashCommands.js:567`), fuzzy lookup via `SillyTavern.libs.Fuse`, and **context-dependent `enumProvider`s** that read sibling args from `executor.namedArgumentList` to autocomplete entry uids for the chosen character (`slashCommands.js:196-235`). One new-engine macro `{{detachedStatusNames}}` via `context().macros.register` with typed `unnamedArgs` (`macros.js:441-470`). `SCRIPTS.md` ships QR recipes (LALib dependency).
- LLM calls: none.

## Overlap with Story Orchestrator
- Per-entity state → our ledger `[state:Entity:type] field=value` + blackboard-bound fields (`src/memory/ledger.ts:31`, `:164` `renderLedgerBlock`), extracted automatically, rollback-safe. Theirs is manual and unanchored; ours is better on correctness, theirs better on direct manual control.
- Private-to-owner entries → our per-member epistemic block swapped on `GROUP_MEMBER_DRAFTED` (`src/runtime/index.ts:188`, `onMemberDrafted`), with provenance/quarantine. Ours strictly richer. Same host mechanism (draft sets the drafted member before generation).
- Presence filtering (present, unmuted members only) → **we do not filter the ledger block by presence**: `renderLedgerBlock` renders every live row (`src/memory/ledger.ts:164`, applied at `memoryCoordinator.ts:455`). Memory tiers use `activeSpeakerId` only.
- Slash surface → `/cp` (author), `/so-mem`, `/story` (`src/runtime/slashCommands.ts:60,121,172`), all subcommand-in-one-string, output posted as a system message/toast (`dump`/`show`, `:17-25`), no enumProvider completion for quality keys or checkpoint ids, no quiet raw-value getter for pipes.
- Macros → we register ~16 `{{story_*}}` via `MacrosParser.registerMacro` (`src/services/stHost/context.ts:49`), zero-arg only; per-roster `story_role_<id>` is re-registered on every snapshot (`src/runtime/macros.ts:58` `syncRoleMacros`).
- Author state editing → Blackboard tab is a read-only table (`src/components/drawer/DrawerTabs.tsx:131-150`); the only write path is `/cp set` → `setQuality` (`src/runtime/runtimeManager.ts:294`, enqueue + commit boundary).
- In-message DOM widgets → deliberately absent in SO (baseline §4: never rewrites message DOM).

## Ideas for v2.4

| # | idea | kind | our area | our state | value | effort |
|---|---|---|---|---|---|---|
| 1 | Author-view typed inline editors on Blackboard rows | ux | player-ui (author view) | absent | 3 | S |
| 2 | Parametric macros on the new macro engine (`{{story_quality::key}}`, `{{story_role::id}}`, `{{story_ledger::entity}}`) | host-integration | host | partial | 3 | M |
| 3 | Script-friendly `/cp get` + enumProvider completions | host-integration | host | partial | 2 | S |
| 4 | Presence-filtered ledger injection | enhancement | memory | absent | 2 | S |
| 5 | Roster drift on character rename | host-integration | host | absent | 1 | M |
| 6 | Anti-pattern: unanchored state + saves on the generation path | anti-pattern | engine | present | 2 | S |

**1. Typed inline editors on the Blackboard tab.** What: in author view, render each quality by its declared type (enum → select, number → stepper/range with min/max, boolean → toggle), submitting through the existing `setQuality` (queue + boundary). Theirs: `{{number}}/{{boolean}}/{{range}}` macro widgets + arrow/range handlers (`source/js/macros.js:380-410`, `source/js/eventMethods.js:493-570`). Ours: read-only table `DrawerTabs.tsx:131-150`; typed parse already exists (`runtimeManager.ts:298` `parseQualityValue`). Fit: author-only (inv. 9); writes go through the apply queue at a boundary (inv. 3); `source: code` qualities should stay read-only in the editor, matching extractor rules (inv. 4). Also removes the `setQuality('location','shaded hollow')` silent-reject trap (gotchas) by offering only declared enum values.

**2. Parametric macros via `context().macros.register`.** What: register `{{story_quality::<key>}}`, `{{story_role::<id>}}`, `{{story_ledger::<entity>}}` with typed `unnamedArgs`, replacing the per-roster `story_role_<id>` re-registration loop, keeping `MacrosParser` as the fallback when `macros` is absent. Theirs: `macros.js:441-470` (category, `returnType`, `unnamedArgs` with type/default). Ours: `stHost/context.ts:49` zero-arg only; `macros.ts:58` resync per snapshot. Host: `st-context.js:245` exposes `macros`; `macro-system.js:58` `register`; `experimental_macro_engine` defaults `true` (`power-user.js:302`). Note: our own rule is "migrate the seam body when ST flips the flag default" — per current source the default has flipped, so the trigger is met; the legacy engine will not see new-engine-only registrations, so keep the dual path and a capability probe (inv. 2: new seam in `stHost/`). Parametric `story_quality` exposes blackboard values — author-intended for card/AN templates; not a player surface.

**3. `/cp get` + completions.** What: a quiet `/cp get <quality>` returning the raw typed value (no system message) so QR/STscript can branch on story state; `enumProvider`s listing quality keys (type + current value in the description) for `set/get` and checkpoint ids for `activate`. Theirs: raw-string returns (`slashCommands.js:567`), context-dependent `enumProvider(executor)` reading sibling args (`:196-235`). Ours: `slashCommands.ts:60-115`, only `/story` has a static `enumList` (`:167`). Fit: `/cp` stays author-only (inv. 9); read-only getter writes nothing. Our `/cp` packs subcommands in one unnamed arg, so completion for the second token needs either split named args (`/cp-get key=`) or an enumProvider that reads `executor.unnamedArgumentList` — verify in `SlashCommandArgument.js` before building.

**4. Presence-filtered ledger block.** What: at injection, drop (or demote to a one-line "absent: …") ledger rows whose entity resolves to a roster member who is disabled/not present; non-roster entities (objects, places) unchanged. Theirs: `index.js:290-340` (muted members discarded unless drafted), `eventListeners.js:139-141`. Ours: `ledger.ts:164`, `memoryCoordinator.ts:455` render all live rows; `roster.ts:49` `rosterIdForName` and enabled-member resolution exist. Fit: must refresh its own injection when cast changes (inv. 16 — cast_changes already runs through `EffectsApplier`, so hook the refresh there); rollback unaffected (render-time filter, no state). Token saving only matters on large casts — measure ledger block size on Adolion before building.

**5. Rename drift.** What: ST rewrites `mes.name` in past solo chats on rename and emits `CHARACTER_RENAMED(old,new)` / `CHARACTER_RENAMED_IN_PAST_CHAT(chat, old, new)` (`script.js:7246,7335`); our roster attribution is name-based (`roster.ts:36-38`), so a renamed cast member silently stops matching. Theirs: `eventListeners.js:222-240`. Cheapest fit: surface it in Repair (a roster member whose name no longer resolves) rather than rewriting the pinned story (inv. 12 — pinned copy must not change behind the author). Group chats are not covered by the past-chat event. Low value: rename during a campaign is rare.

**6. Anti-pattern (keep avoiding).** Their status is chat-level, not message-anchored, so a swiped/edited/deleted reply keeps whatever a script wrote during it; and `refreshDepth` persists a *derived* depth through `set()` → `saveMetadataSafe` on every generation (`Status.js:184,311-328`), i.e. a chat save racing the generation it is preparing. Ours: rollback ≡ replay (`src/runtime/rollback.ts:35`), boundary-only writes (`applyQueue.ts`). Worth a line in the v2.4 "why not a stat tracker" rationale, nothing to build.

## Patterns to copy / anti-patterns to avoid
Copy:
- Context-dependent `enumProvider` reading sibling args (`slashCommands.js:196-235`) — autocomplete that knows the story.
- Raw-value slash returns for pipes, with `returns:` metadata and example-rich `helpString` HTML (`slashCommands.js:1094-1150`).
- `makeLast` for listeners that must see everyone else's prompt changes (`eventListeners.js:276-288`).
- Recipes doc for automation users (`SCRIPTS.md`) — a `/cp`+QR recipe page would cost little once idea 3 lands.

Avoid:
- Comment stripping with `/\/\/.*$/gm` on prompt text (`index.js:655`, applied to every injected block via `eventListeners.js:138`) — eats everything after `http://`.
- Unescaped `.html(value)` of entry titles/values (`index.js:743-745`); values can come from `/stum-set-entry-field` fed by scripts or LLM output. Our rule (popups via DOM text nodes, `stHost/popup.ts:13`) stays.
- Deleting keys out of `context().extensionPrompts` by substring (`eventListeners.js:127-129`) instead of `setExtensionPrompt(key, '')` through a registry — a prefix collision with another extension would delete its prompts.
- DOM injection into `.mes_text` siblings, re-rendered on every message event (`index.js:822`) — fights themes, other extensions and ST re-renders; our HUD/drawer placement is the better choice.
- Persisting derived values on the reply path (idea 6).

## ST host facts learned
- `GENERATION_AFTER_COMMANDS(type, params, dryRun)` fires once per `Generate()` after slash-command processing (`script.js:4321`); in groups `setCharacterId(chId)` precedes it, so `getContext().characterId` is the drafted member (string) at that point (`group-chats.js:1054-1063`). Theirs: `eventListeners.js:110-153`. Consistent with our `GROUP_MEMBER_DRAFTED` approach.
- `doChatInject` places depth-0 in-chat prompts at depth 1 on `continue` (`script.js:5665`), so a depth-0 block never splits the continued message. Relevant to our `continuityNote` (depth 0): on a continue it lands above the message being continued. Not in our gotchas.
- `CHARACTER_RENAMED_IN_PAST_CHAT(currentChat, oldAvatar, newAvatar)` fires per past **solo** chat after names are rewritten and before ST re-saves it; `currentChat[0]` is the metadata header, so mutating it persists (`script.js:7300-7340`). Their use `eventListeners.js:222-240`.
- Group replies carry `original_avatar = character.avatar` and a `force_avatar` thumbnail URL with `file=<avatar>` (`group-chats.js:599-604`, `script.js:7548`) — a stabler attribution key than `mes.name`. Their use `index.js:436-483`.
- New macro engine: `getContext().macros.register(name, {category, description, returns, returnType, unnamedArgs:[{name,type,optional,defaultValue}], handler({args})})` (`st-context.js:245`, `macros/macro-system.js:58`); `substituteParams(content, {dynamicMacros})` supports per-call macros with `delayArgResolution` + `resolve()` (`script.js:2981`, `macros/engine/MacroEngine.js:178`). `MacrosParser.registerMacro` is deprecated but bridges into the new engine (`macros.js:183-205`). `experimental_macro_engine` defaults to `true` in source (`power-user.js:302`) — agrees with our gotcha; **contradicts the CLAUDE.md framing** that the seam migrates "when ST flips the flag default": the default has flipped (the flag still exists).
- `SlashCommandArgument` `enumProvider(executor, scope)` (`slash-commands/SlashCommandArgument.js:32-64`) can read `executor.namedArgumentList` for sibling values (their `slashCommands.js:196-235`).
- `SillyTavern.libs.Fuse` is exposed (`lib.js:86,114`).
- `eventSource.makeLast(event, listener)` exists (`lib/eventemitter.js:66`).

## Verdict
Relevance **low**. A manual prompt-shortcut/stat block with no LLM, no mutation handling and chat-level (not message-anchored) state; everything it does for state, SO does more safely. The one thing worth taking: **its scripting/host surface** — typed parametric macros on the new macro engine and pipe-friendly, autocompleted slash commands (ideas 2+3), plus the author-view typed inline editors (idea 1) for manual state correction.
