# Gotchas

Product and host traps, each with the symptom that identifies it and where the guard lives. Harness conventions (lanes, journeys, scenario vocabulary, cleanup) are in `debug-scripts.md`.

## Writing checks and fixtures

- **A wait that enumerates accepted states goes stale when a state is added** (J11.25): `validated` (critic passed, promoted to `inserted` by boundary work `expansion-commit`) was not in the list, so a successful pre-generation burned 480 s as "never finished". Wait on the property ("left queued/generating"), and when enumerating, enumerate what success looks like too.
- **Never assert a schema-version literal.** J10 checks demanded blob version 3 after a bump and failed before their structural asserts ran. Assert the property; in jest import `BLOB_VERSION` (`runtime/persistence.ts`, currently 7).
- **`wait: {checkpoint: "cpN"}` races a story that advances past cpN** (J6): the wait burns 300 s and reports a checkpoint already left. Use `wait: {checkpointIn: [...]}` / `expect: {activeCheckpointIn}` unless the check is about being parked there.
- **Clearing the global config makes the profile picker take the FIRST profile** (`select-profile` keeps `extraction.profileId` only if still offered). Symptom: `auditCount: 0`, `lastAudit: null` after several turns = no profile could answer, not "scheduler did not fire". Every offered profile must be live, or set `ST_DEBUG_PROFILE`.
- **Privacy assertions must name the block, and must not be circular** (J5.8). The shared transcript reaches every member, so scanning the whole request body flags a "secret" planted in chat; test inside `renderPrivateEpistemicBlock`'s header + bullets. And a draft's own extraction pass can create the knowledge being measured: assert only knowledge present before the trigger, record exclusions with reasons. `--only` with nothing seeded must fail, not pass vacuously.
- **When a gate and a probe disagree, check which question the probe answers.** `getEpistemicBlock()` re-renders for the active speaker (macro meaning); `getAppliedEpistemicBlock()` reads what ST's next prompt holds (`readInjectedPromptBlocks`). Prefer the applied artifact over a recomputation.
- **A fixture can lie three ways, all reading as product failures**: wrong value shape (the validator now checks verb value shapes), a global read but never written (`globalsReadButNeverWritten`), a vacuous negative (`getMemoryInjectionBlocks()?.facts?.value` on a string is `""`). `expect.payloadAbsent` refuses a missing block, so assert an emptied tier as "row in store AND no live rows".
- **A unit test of a CSS selector pins the string, not the DOM.** `:nth-of-type` counts same-tag siblings, so it matched the panel's first div and failed like an empty queue. Use Playwright `>> nth=N`. Drive any "not exercised live" probe once.
- **A live judge fixture's second run in the same page is a cache hit** (`cached: true`, `latencyMs: 0`). Vary the request per run or reload between arms. A check that writes judge settings must defer to the runner's arm marker `globalThis.__soJudgeMode` (`lib/judgeHarness.mts`).
- **A fixture expecting a seeded fact to win must LOCK it** (`rt.memoryActions.setMemoryLocked(id, true)`): a claim landing on an established fact (locked/author-decided/authored, `isEstablished`; a pin is retention, not truth) is held as a conflict, otherwise stored live.
- **Two findings sharing a verdict must not share a reason**: a nullable read and an inequality feeding one branch must state what was observed (read-back blind vs server older).
- **An acceptance claim whose citations live in the debug dir expires** (it rotates). Archive under `test/journeys/records/<gate>/` when writing the claim; `scripts/release/attestation.test.mjs` fails on a missing cited record.
- **Hash the thing that ran, not the file that describes it**: `so-run-header` hashes the served `dist/index.js` in-page and warns when it differs from `dist/manifest.json` `bundle.sha256`. A field that can only be `null` can never fail a diff.

## Async writes, saves, ownership

- **`saveMetadata` never rejects** (`saveChatConditional` catches everything, script.js:9412). A `catch { undo() }` around an awaited save is unreachable. Read the save evidence (`extras.saveHealth`): `saveWasLost()` = evidence of a lost write (`unsaved`); `unconfirmed` (blind read-back) is not; `hasUnsavedChanges()` is deliberately sticky for the player line. Author decisions share `commitDecision` (`runtime/memoryQueue.ts`); a put-back decision says so (`[data-so="decision-refused"]`). Read the mock before patching it: a mock with `readBackBoundary: () => null` is the blind case that must NOT refuse.
- **A write-ahead record nobody verifies is not write-ahead**: `EffectsApplier.withLedger` reads `unsaved` after the pending-row persist and refuses the effect (`PENDING_NOT_SAVED`). When a return value is not evidence, read the state that is.
- **ST binds a chat save to the chat open when the save RUNS**: `saveChatConditional` polls `waitUntilCondition` at least one interval (utils.js:1934) before reading `chat_id`, and `openGroupChat` repoints `chat_id` first. A save asked just before a switch can write an empty chat under the next chat's name. The save watcher (`runtime/chatSave.ts`) refuses an empty save for another chat and records it `lost`. Diagnose "a chat lost its messages" with a fetch recorder on `/api/chats/*/save` first. Switching chats with a save pending can also trip ST's integrity popup and wedge the page at "Initializing…": wait for `schedulerIdle` and `!isChatSaving` (+~2 s) before an in-page switch.
- **Every async writer takes a `RunOwnership`; a `checked` census row means "the body contains a token check", not "every write is preceded by one"** (`ownership.guard.test.ts`, `test/findings/ownership-sites.json`). Put the check before EACH host write, inside per-item loops; the per-write order is proven only by tests that reach each check. Arrows are named by location (`Class.deps.key`, `callback[cp]`, `Owner>withLedger`), so moving code into/out of an object literal changes its row key. A `delegate` row needs an `awaits <Class.method>` clause.
- **A `RunToken` cannot detect a stale CACHE entry**: only what the key names can. `LoreSelector` once cached by chat+message+scope without story, and discarded `force()`'s `WriteResult` (a refused force read as applied). A `WriteResult` nobody reads is indistinguishable from success. `ExpansionCoordinator.generate` had no token; `expansionOwnership.review.test.ts` keeps the unowned run as a negative control.
- **Fault-matrix cells are claims only with a citation** (`test/findings/faultMatrix.json`, `faultMatrix.guard.test.ts`): `covered`/`partial` must cite a test title that exists as a quoted string; `todo`/`na` cite nothing and say why.
- **A store write that changes injected state refreshes the injection itself** (`applyEpistemic`/`applyLedger` call `updateInjection()`); a caller-side refresh is a race. Symptom: a member drafted right after an epistemic pass gets an empty private block. Test: `coordinators/memoryInjectionRefresh.review.test.ts`.
- **A patch spread from a state computed BEFORE a side write erases that write** (`addSceneSummary` lost its `scene_summary` derived record: `sceneCount: 1`, `derived: []`). Patch the pure helper's whole-state result first, then auxiliary writes, or patch only changed fields.
- **A rollback that restores nothing still drops queued writes that read the mutation**: `quarantine()` calls `engine.discardPendingFrom(messageId)` on every path (`runtime/rollback.ts`). Writes read before the message and applied later legitimately stay, so assert replay invariance, not "state equals recording".
- **`Math.max(0, NaN)` is `NaN`, and a NaN message id rewinds the whole story** to boundary 0. Parse host ids with `hostMessageId` (turnBridge.ts), never `Number(value)` (`Number(null) === 0`). A probe needs a FIRED transition first or it cannot fail.
- **Swapping the played graph must keep the engine's queue and history**: use `engine.replaceGraph(story)`, never `loadStory` + `hydrate`. Symptom: write ok, boundary advances, `queue {applied:[],discarded:[]}`.
- **A staled chain is part of what a rollback undoes** (T6-1-2): rollback into a stale `gen_…` checkpoint left `activeCheckpoint` undefined and no boundary ever committed. `runRollback` calls `restoreStaledAfter`, then `engine.ensureActiveCheckpoint()`. Test: `runtime/t61Rollback.review.test.ts`.
- **Derived memory artifacts** (`memory/derived.ts`, `reverse.ts`): an artifact's own removals are never its inputs (judge orphanhood by the removal set); a restored row is passed through `stripLinksAfter`; lift an exclusion hash only if no kept record carries it. `rollbackReplay.property.test.ts` finds this class; a generator that mutates shared rows in place makes it lie.
- **`snapshot.scanGate` right after a reopen is ST's pre-cache scan** (`owner: no-story`; ST's `CHAT_CHANGED` runs `getSortedEntries()` before our hydrate). Make one scan after hydrate settles before diffing it. Test: `runtime/t7ReopenScanGate.review.test.ts`.

## Model, backend, generation

- **A backend outage looks like a product fault**: a send posts the player's line, no reply, no boundary, a pending delta looks dropped. `ctx.onlineStatus` is a cached label; probe a profile with a real `ConnectionManagerRequestService.sendRequest` (see debug-scripts.md). A page loaded while the backend was dead keeps `#send_but` hidden (`displayNone`) across reloads; re-select the profile (`MSYS_NO_PATHCONV=1 node scripts/debug/st-actions.mts slash "/profile <name>"`), also after repointing a profile.
- **llama-server `/v1/chat/completions` applies the thinking template**: a CC profile on Gemma 4 can spend all `max_tokens` in `reasoning_content` and post `""`. Fix on the profile: `custom_include_body` `chat_template_kwargs: {enable_thinking: false}`. Curl first.
- **A thought-only reply is not "Send shown mid-stream"** (F-B1b-1): `Generate` calls `deactivateSendButtons()` (script.js:4430) per member. A reply whose output stayed in the thought channel ends `mes === ""` with text in `extra.reasoning`. Compare pod `predictedMs` with the page's stream stats before calling it still streaming. Recovery: `runtime/emptyReply.ts`.
- **A chained voice and a player send could open two group wrappers** (`is_group_generating` is set after an await). A chain now yields to the player, and the next voice starts through `stHost/generation.ts` voiceStart (refuses while busy, sets `is_send_press` in the checking tick). Tests: `runtime/talkChainYield.review.test.ts`, `stHost/voiceStart.test.ts`.
- **No prompt-cache reuse on Artemis is server + ST structure**: Gemma 4 SWA restores only from a context checkpoint before the first differing token. First diffs: ST Vector Storage chat vectorization (per-turn block + spliced history, vectors/index.js), then the deepest depth injection, and the joined depth-4 block moving each turn. Per-turn story lore is moved late for this reason (`runtime/lorePlacement.ts`).
- **Never await model/network work in a `MESSAGE_SENT` handler**: ST awaits the emit before `addOneMessage`, delaying the player's own line. Start it there, await in the generate interceptor (`runtime/loreSelectTiming.ts`).
- **Inline reasoning is stripped centrally** by `stripReasoningBlocks` (`extraction/parse.ts`, applied in `extraction/reply.ts` `replyVia` and `harnessReply.ts`), because ST's Connection Manager reads only out-of-band reasoning. Only leading blocks, nested by depth; unterminated = `""`; orphan `</think>` strips before it; Gemma `<channel|>` has no orphan rule (stray per-line tokens, golden `extractor15`). `stripChannelNoise` runs the same block strip plus channel-token cleanup.
- **RunPod** (not used for the rest of Oct 2026; local 3090): the HTTPS proxy reaches llama-server only with `--host 0.0.0.0` in `LLM_EXTRA_ARGS` (a loopback bind gives 502). Otherwise read `get-pod` `ssh.direct` (only while RUNNING; port reassigned on every start/restart) and `ssh -i ~/.ssh/id_ed25519_runpod -N -L 18080:127.0.0.1:8080 -p <port> root@<ip>`; profiles point at `http://127.0.0.1:18080`, then re-select the profile. `pod-action restart` renews `MAX_UPTIME_HOURS`. An EXITED pod can hold its host GPU (`400 not enough free GPUs`); a new pod with the same volume in the same DC starts. Repointing a profile is install-wide: record and restore the old `api-url`.
- **A fixed timeout around a real generation is a hardware assumption**: suspect harness timeouts first when the backend moves.

## SillyTavern host

- **Turns**: `TurnBridge` drops `NON_TURN_MESSAGE_TYPES` (`first_message`, `extension`) before dedupe; everything else (normal, regenerate, swipe, continue, appendFinal, command incl. our `/sendas` NPC replies, untyped emitters) commits a boundary. Denylist on purpose. A fresh group posts greetings BEFORE `CHAT_CHANGED` (group-chats.js), which once committed into the previous chat's story. `MESSAGE_RECEIVED`/`CHARACTER_MESSAGE_RENDERED` carry `(messageId, type)`; `document.body.dataset.generating` is ST's own flag. Live gate: `scripts/debug/so-turn-types-check.mts`.
- **ST hides `#send_but` while generating, and when disconnected** (both buttons hidden); a stopped stream leaves `streamingProcessor.isFinished === false` forever. Generating = stop visible || (send hidden && stop not hidden).
- **Group saves are a 1 s debounce over the group OBJECT** (`saveGroupDebounced`, group-chats.js:140; `editGroup(id, false)` returns before the server has it, `_save` never reads the answer). `stHost/groups.ts` saves with `editGroup(id, true, false)` and reads `/api/groups/all` back. A pending save holding an old object can resurrect a deleted group chat after `getCharacters()` (provisioning reloads); verify a deletion no sooner than ~2.5 s after the last group write. Assert request ORDER, not state, for debounce bugs.
- **`openGroupChat(groupId, chatId)` returns silently unless `chatId` is in `group.chats`** (group-chats.js:2195); after reload no group is selected and `new-chat` acts on the current character (an empty solo chat). Open from outside (`st-navigation open-group <id>`) and assert `ctx.groupId` + truthy `ctx.chatId` after every switch. `open-chat <chatId>` leaves `ctx.groupId` null until ST re-resolves, which a run-header diff reads as drift.
- **`ctx.saveSettings` does not exist** (only `saveSettingsDebounced`), and `script.js` `saveSettings` (8051) swallows failure. Harness writes go through `scripts/debug/lib/settingsSave.mts` `saveSettingsNow(page)` (observes `POST /api/settings/save`).
- **Stored install-wide settings are a delta over defaults** (F15). Raw `extensionSettings["story-orchestrator"].settings` may lack any section; read `storyOrchestratorRuntime.getGlobalSettings()` for effective values, write null-safe (`root.settings ??= {}`), restore a captured `undefined` as absent. A value written equal to its default leaves the store.
- **World Info**: existence is `world_names`, never `loadWorldInfo` (answers a missing name with a cached dummy; `importWorldInfo` never evicts it). Names resolve to the listed file id (server strips `:`/`?`). `upsertWIEntry` never creates a book and always re-enables what it writes (callers re-disable). Constant entries skip all key checks; scan depth 0 matches nothing; entries without `position` insert nowhere; `role` 0 system/1 user/2 assistant; ↑AN/↓AN only on turns the AN is inserted; editing an entry resets sticky/cooldown. `createNewWorldInfo` writes no `globalSelect` (world-info.js:4448). `/getchatbook` creates and binds; `/world ""` disables every global book. `globalSelect` is a debounced mirror of `selected_world_info`.
- **Slash commands**: we pin `parserFlags {STRICT_ESCAPING on, REPLACE_GETVAR off}` and `handleParserErrors: false` (else a parse error returns `isError: false`); `quoteSlashArg` encodes for strict mode (inside quotes only `"` special; `{`/`}` escaped so macros resolve per prompt). `/sendas` and `/comment` are `rawQuotes`: pass `raw=false`. `/profile`, `/preset` await the switch; `/preset` fuzzy-matches; `/qr-update` without `automationId=` clears it; `/let x` after a pipe stays empty (`/let key=x`). Git Bash path-mangles a leading `/` (see debug-scripts.md). Regression: `test/scenarios/effects-slash-quoting.json`.
- **Author's Note**: `/note ""` is a no-op, so clearing goes through `clearNoteText()` (`stHost/authorNotes.ts`, empties `#extension_floating_prompt` + `input`). Role via `/note-role`, reset to system on clear. Regressions: `effects-author-note-role.json`, `live-effects-author-note-role.json`.
- **Backgrounds**: no context API. Read `background_settings`, write `/bg <name>` (fuzzy, clicks `.bg_example`); a locked background is `chatMetadata.custom_background` as a css url.
- **Macros**: this install runs the new macro engine (`experimental_macro_engine`; re-measure, `so-run-header` records `host.macroEngine`). `registerHostMacro` registers into the engine active at startup, so flipping it leaves `{{story_*}}` unresolved until reload. Event subscriptions use `eventTypes` constant KEYS, resolved in `stHost/events.ts`.
- **Cards/groups**: `/api/characters/create` coerces (`fav` `"true"`, talkativeness 0 → `"0"`, `extensions` JSON string); an embedded `character_book` raises a blocking import confirm on first open; group mention matching splits names into words (`SO-J9` makes every "so" a mention); stored names/avatars can differ from requested.
- **Every ST popup carries its own chrome**, including a hidden `<img class="popup-crop-image">`; scope popup content assertions to `.popup-content`.
- **`a11y.js` rewrites `role="button"` onto `.menu_button`**: drawer tabs read `role="button"` live; select `#drawer-manager [role="tablist"] button`. `aria-selected` survives.
- **ST's `<html>` has `translateZ(0)`**, the containing block for every `position:fixed`; in mobile mode it collapses. Modals must be native `<dialog>` + `showModal()` (`#so-studio-modal`). Storybook plays use retrying `find*`. `isMobile()` is UA-based, so a viewport emulation changes width only.
- **CSRF can go stale under a long-open page**: GETs work, every POST 403s. `ensureSTReady` refuses ("CSRF token is stale"); reload, re-open the pinned chat. A cold page has an empty token for ~1 s.
- **A plain reload can re-run the cached bundle** (ETag): the page works with the previous build. `node scripts/debug/st-session.mts reload` disables the CDP cache; "… is not a function" from a debug script usually means this.
- **An occluded browser starves `requestAnimationFrame`** (~1 fps, 0 on a locked desktop): Playwright click times out "element is not stable". Count rAF callbacks before hunting a moving element. `st-session start` passes the anti-throttling flags; an older browser needs stop + start.
- **A JS dialog on the shared CDP browser can kill a runner** (`No dialog is showing` uncaught, cleanup skipped). `lib/connection.mts` `settleDialogs(page)` handles it. After a lane-0 crash: `so-journey.mts restore-config`, then `so-run-header diff` and undo by hand.
- **Vectors**: `/api/vector/query` drops scores server-side (src/endpoints/vectors.js), so dedup bands are two threshold queries (0.82 dup / 0.55 same-topic); Jaccard when absent. Consolidation runs only for tier groups ≥ `CONSOLIDATION_MIN_GROUP` (8).
- **Third-party extensions here**: Presence hides most of the chat while a member is drafted (an extraction read then sees one member's view); Stepped Thinking "Separated" mode posts thoughts as real messages (boundaries). ST Summarize and Vector Storage copy the transcript and cannot be filtered (`transcript-copiers` check).

## Product traps

- **Speaker direction**: `globalThis.talkControlInterceptor` is set inside `startRuntime()`; never re-assign it after startup (a re-stub silently disabled the feature). Decision key is `chatId:checkpointId:lastMessageId`; without the chat id a new chat at the same index reused a cached decision. A `lead` outside `speakers` is still a candidate (weight 1).
- **Scene-break heuristic needs a prior location**: the first location is never a break. Seed with a value the enum declares and assert it landed (`setQuality` rejects out-of-enum values silently), then pin cadence so the scene read does not fold into a cadence read.
- **Curator writes land only at a boundary**: `applyCuratorProposals()` writes accepted ops only, called by the boundary, so a mid-turn proposal does nothing until the next commit.
- **Canon shown to a player is `getCanonProse()`** (WHAT HAS HAPPENED only); `getCanon()` falls back to canon-lite scaffolding. The canon input hash includes the active checkpoint.
- **Generated routes**: priority is declaration order DESCENDING (transitions sort priority desc, first match fires); `sanitizeExpansion` drops entries from another `EXPANSION_CONTRACT`.
- **Epistemic hygiene**: `applyEpistemic` runs `dropCommonKnowledge` (a `[knows]` given to ≥3 or everyone present, unless also marked unaware/hiding) and `capEpistemic` (12 newest per subject); the group resting block is empty by design and withheld for `impersonate`/`quiet`. Epistemic is never written to World Info.
- **`so-state` reads persisted `chat_metadata`**; live values between persists may differ.

## Build, types, tests

- **Run `npm run typecheck:test` for any change touching a test file**: jest runs ts-jest with `diagnostics: false` and `isolatedModules: true`, so a typed-wrong test passes; a `const enum` or a type re-exported without `export type` across files fails at runtime in jest. Jest runs in parallel workers; an order-dependent test is a defect.
- **tsconfig `include` enumerates src dirs**: a new top-level `src/` dir is type-checked only through imports until added.
- **tsconfig `"types": []` and explicit `"lib"`**: otherwise every ancestor `node_modules/@types` is included (an `@types/toastr` above the extension broke `stHost/slashCommands.ts`).
- **Babel targets are ST's browser floor** (`HOST_BROWSER_FLOOR` in `webpack.config.js`), not package `browserslist`; the old target inlined ~191 KB of helpers. Move it only when ST moves. Webpack fallbacks disable node builtins.
- **`npm run test:release` rewrites `dist/manifest.json`** (`builtAt`, source hash): don't run it during a live batch; `bundle.served.sha256` says whether code changed.
- **A module importing `@services/STAPI` cannot be unit-tested** (top-level await in `stHost/context.ts`). Split the default-deps factory into a `*Host.ts` (as `saveEvidence.ts` / `saveEvidenceHost.ts`), don't mock the seam.
- **Every `stHost` write answers `WriteResult`** (`utils/writeResult.ts`); `stHost/typedResults.test.ts` fails on a new boolean/void writer. Missing host features are `stHost/capabilities.ts` (`present|absent|error`, error not cached), so they block a feature instead of failing it. `settingsReady()` gates writes before `extension_settings_loaded`.
- **Host types are vendored** (`stHost/hostTypes.ts`); each member has a host file:line row in the v2 overview's "Verified ST host facts". Verify there before widening.
- **CSS is scoped to the mount roots** (`src/styles.css` `:is(#drawer-manager, #so-hud-root, #story-orchestrator-settings, #so-studio-root, #so-studio-modal)`, Tailwind 4 via `@tailwindcss/postcss`). Our panels stay 1rem regardless of ST Font Scale (user decision). A UI outside those roots gets no Tailwind: add its id to the scope list and to `mountRootFor` in `.storybook/preview.ts`. Root element styling goes in an id rule. Storybook's Lightning CSS drops unprefixed `backdrop-filter`.
- **Architecture guards** (`runtime/architecture.test.ts`): manager/coordinator effective-line budgets (every started 120 chars counts, so packing cannot meet them), components↔studio boundary, drawer reads snapshot, engine purity, stagecraft isolation. A failing guard is a failing build.
- **No raw NUL bytes in source**: ripgrep treats the file as binary and skips it silently. Write `"\u0000"`.
- **This repo is CRLF.** Python `newline="\n"` does no translation, so multi-line search strings never match; read with `newline=""`. Heredoc'd python here can split string literals: write the script to a file and run it. Check endings: `python -c "import io;print(chr(13)+chr(10) in io.open('src/x.ts',newline='').read())"`.

## In-page handles

- `globalThis.storyOrchestratorRuntime` is the `RuntimeManager`; its public methods are in `src/runtime/runtimeManager.ts` and `src/runtime/managerDelegates.ts` (grep there rather than trusting a list). Most used: `getSnapshot()`, `importStory(json)`, `runExtractionNow(response?, reason?)`, `getGlobalSettings()`, `restartStory(alreadyConfirmed?)`, `applyStoryUpdate(record?)`, `onMemberDrafted(chid)` (ST's numeric character index, never a roster id), `getAppliedEpistemicBlock()`, `getMemoryInjectionBlocks()` (returns strings), `capturePayload(reason?)`, `getTalkState()`.
- Debug-response globals (`storyOrchestratorDebug*Response`, read in `src/runtime/modelCallCore.ts`) outlive a run until reload; mocks are for unit determinism and plumbing only, never sign-off.
- Other globals: `storyOrchestratorJudge`, `storyOrchestratorStudioTabs`, `storyOrchestratorLiveSuite`, `storyOrchestratorSpikes`, `storyOrchestratorAsk`.
