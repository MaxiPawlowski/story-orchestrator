# Debug Scripts

For any live/E2E work, load the **`debug` skill** (`.claude/skills/debug/SKILL.md`) — full tool reference, recipes, error table. Also: `scripts/debug/README.md`.

Essentials:

- Scripts are `.mts`, run directly: `node scripts/debug/<tool>.mts`. Artifacts → `.debug/` (gitignored).
- Responsive testing: prefix EVERY command with `ST_DEBUG_VIEWPORT=<W>x<H>` (e.g. `390x844`) to hold an emulated viewport; unprefixed runs snap viewports narrower than 1280px back to 1920×1080.
- Browser is **headless by default** — the user sees nothing. `st-session.mts start --headed` opens a visible window (scripts + MCP then drive it live); use it whenever the user wants to watch.
- Scripts = deterministic reads/actions/assertions, anything a gate depends on, anything run twice. Playwright MCP `browser_*` = exploratory only; never chain MCP calls into a validation when a script exists.
- **Default gate for LLM-consuming paths = real-LLM validation** (profile selected, no `debugResponse`) — see "Real-LLM validation" in the debug skill. Can't run it → flag at handover, gate NOT green.
- Shared session first when mixing scripts + MCP: `node scripts/debug/st-session.mts start` (CDP `http://127.0.0.1:9222`). Repo `.mcp.json` points the playwright MCP at that endpoint — **an MCP server without `--cdp-endpoint` launches its own isolated Chromium** whose state scripts can't see. Verify sharing with a `globalThis.__x` marker round-trip (MCP `browser_evaluate` set → `st-eval.mts` read) before any shared-state MCP work.
- Chat/entity control: `st-navigation.mts list-entities | open-group <id|name> | open-character <name> | list-chats | open-chat <chatId> | new-chat`. Group draft: `st-actions.mts trigger <member>`. Ad-hoc in-page JS: `st-eval.mts "<js>"` (ctx + rt in scope) — no more throwaway .mts files.
- Test cleanup: `so-library.mts remove "<title>"` (v2Stories store — the LIVE one; `--legacy` for the dead v1 studio store) + `so-library.mts wipe-chat-meta` + `/delchat`.
- **The memory mirror leaves a lorebook per chat** (`Story Orchestrator - <title> - <chatId>`, recorded in `getSnapshot().memory.wiBook`), and deleting the chat does not delete it. `so-scenario --sandbox` and `so-journey` cleanup delete them. The guard records every story title and `wiBook` after each step. Once the chats are gone, cleanup deletes each listed book whose name is `<recorded title> × <owned chat id>`, via `deleteWorldInfo` after `updateWorldInfoList`. A name without an owned chat-id suffix is never touched. The report is `cleanup.mirrorBooks {deleted, failed, leaked}`. A scenario that reads its mirror book takes the name from `memory.wiBook`, never a fixed title: `loadWorldInfo` answers a missing name with an empty dummy. The old fixed-name `Story Orchestrator - <title>` books from before per-chat mirroring are out of scope, so they stay.
- **`storyOrchestratorDebug*` globals outlive a run** until the page reloads. The next run's first real pass got plan07-memory's leftover mock fact, and so would a real player in the shared browser. `so-scenario --sandbox` now clears them at start and at cleanup, as `so-journey` setup already did at start. A mocked plumbing scenario must also keep real extraction out: extraction is on install-wide since v2.1 plan 02, and real reads of the group greeting raced plan07-memory's exact memory counts. It pins `storyOrchestratorDebugExtractionResponse = 'SCENE_NONE'` before `import_story`, which parses clean and has no rejected line, so extraction does not pause.
- **Git Bash mangles leading-slash slash-command args**: `node scripts/debug/st-actions.mts slash "/delchat"` gets MSYS-path-converted to a Windows path (`C:/Program Files/Git/delchat`) and silently no-ops — the JSON result's `"command"` field shows the mangled path. Prefix with `MSYS_NO_PATHCONV=1` for any slash command starting with `/`.
- **`cast_changes`/`setGroupMembersDisabled` mutate the group's `disabled_members`, not the chat** — this persists across `/newchat` sandbox sessions and outlives `--sandbox` cleanup. A live scenario that disables a roster member leaves that member disabled in the real group afterward; restore it (e.g. another `cast_changes: {enable:[...]}` pass) before ending the session. **Restore after deleting the sandbox chat, not before** — `/member-enable` inside the sandbox chat reports success and is then undone when ST reloads the group behind `/delchat`; `so-journey` now enables members post-`/delchat` and reports the resulting `disabledMembers` in its cleanup record (v2.1 plan 04).

- **The wizard creates real ST assets** (v2.1 plan 06). Drive it as an author with `so-ui.mts open-wizard | new-story-wizard | wizard-run [stage] [message] | wizard-answer [a1|a2|a3] | wizard-apply [index] | wizard`. Clean up with `so-assets.mts remove --marker <prefix>`, and never delete an unmarked asset. The whole scope is the marker, plus the `applied` ledger of **test** wizard sessions only: keys starting with the slugged marker (`so-j9-wizard`), plus, in a journey, entries recorded since the run's `snapshotAssets` baseline. A real author's sessions, their resume state and the assets they created are never touched. With a baseline, any asset that existed before the run is spared (`protected`), and only the test sessions are dropped.
- **The World Info curator writes to a real lorebook** (v2.1 plan 07), so drive it the way an author does and clean up after it: `so-scenario` step `{stagecraft: {action: "curate"|"accept"|"reject"|"accept-op"|"reject-op"|"apply"|"state"}}`, review through the drawer with `so-ui.mts stagecraft | curator-accept [index|text-first] [text] | curator-reject [index]` (`ui: {action:"stagecraft", minOps}` waits for the cards; `pick:"text-first"` lets the model choose the op kind: never hard-code that a real curator proposes a text change), and assert with `expect: {background}` / `expect: {stagecraft: {...}}`. It is off by default (`#so-curator-enabled`), a journey that switches it on must snapshot the global config, and `so-assets.mts remove --marker` deletes the lorebook it wrote into.
- **Pin the sandbox group on a shared install**: `so-scenario run <file> --sandbox --group <id|name>`. Without `--group` the sandbox takes ST's *most recent* group, which may be another session's (2026-09-19: a run created and deleted its own chat inside another session's group). Journeys take `setup.group`, or the group already open.
- **A disconnected ST hides both `#send_but` and `#mes_stop`**, and `getGenerationState` used to read a hidden send button alone as "generating", so every `wait: {idle}` timed out while the backend was down. Generating is now `stop visible || (send hidden && stop not hidden)`. With the backend down the mocked scenario corpus runs; only steps that make a real model call fail (`plan08-hygiene`).
- **In a group the resting epistemic block is empty by design** (2026-09-19) and the private block is swapped in per drafted member, so a scenario asserting it must call `onMemberDrafted(chid)` first — **ST's numeric character index** (`ctx.characters.findIndex(...)`), never a roster id. `plan10-epistemic-ledger` asserts both halves.
- **A capability probe may be async, and must not read a global an earlier check set**: a check that reloads the page wipes it, and the probe is cached on first use, so everything after the reload blocks (2026-09-19: five J11 checks). `judge-plugin` now fetches the plugin's own status.
- **Every check imports the story it needs**: `--only` runs one check against a fresh chat, so a check that inherits a story from an earlier one seeds nothing (J11.9/J11.10 seeded 0 of 10). Run the no-backend subset with `--only` to catch the coupling the v2.1 J9 finding warned about.
- **Journeys are the composition gate** (v2.1): `so-journey.mts --list` / `run <id>`; catalog and check tables in `docs/plans/v2.1/test-plan.md`. Fresh-start by default; outcomes are `pass|fail|blocked|not-runnable|skipped`; `--strict` turns `blocked` into failure at acceptance. **Run a journey twice before believing it**: the plan-08 acceptance run found a stale-cache bug (J5) and a parser-tolerance gap (J8) that only a second consecutive run exposed. Archive the run that greened a gate under `test/journeys/records/<gate>/` — `.debug` rotates. Global-settings clearing is snapshotted to `.debug/so-journey-config-snapshot.json` first — `so-journey.mts restore-config` recovers a crashed run.
- **Nondeterministic journey steps** (2026-09-19, J8 on Artemis): assert whatever the real model chose, never a hard-coded op kind, and read the prompt ST actually sent from `GENERATE_AFTER_DATA` (main `Generate()` only). A fetch wrapper on `/api/backends/` also catches memory-model and curator calls. A check that measures "nothing else changed" starts after `wait: {schedulerIdle: true, quietMs}`, because a slow model is still reading the previous turn when the chat goes idle. `"log": true` next to a step verb prints its output, so an archived log shows which branch ran.
- **Session journal**: `so-journal.mts export|show` writes `.debug/journal-<chat>.md|json` — the artifact a human-eval session hands back. The drawer's ⚑ control files a flag (`#so-flag-moment`).
- **ST hides `#send_but` while generating** (it swaps in `#mes_stop`), and a stopped stream leaves `streamingProcessor.isFinished === false` behind forever — `getGenerationState` treats the button swap as truth and requires a continuous idle window, so group turns are not cut short between members.
- **ST nests our settings panel two drawers deep** (`#extensions-settings-button` → `#rm_extensions_block` → our `.inline-drawer`). Anything driving the panel must open by *visibility*, and must close the nav drawer afterwards — an open Extensions drawer hides `#options_button` and `#send_but`.

Standard snapshot:

node scripts/debug/st-navigation.mts recent-group
