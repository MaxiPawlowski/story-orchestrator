# Debug Scripts

For any live/E2E work, load the **`debug` skill** (`.claude/skills/debug/SKILL.md`): tool reference, recipes, error table. Also `scripts/debug/README.md`.

## Setup and build

- **Repo is outside ST** (`C:\dev\story-orchestrator`). ST's slot `public/scripts/extensions/third-party/story-orchestrator` holds only the staged allowlist. ST root = `ST_ROOT` or the gitignored `.st-root` (`scripts/lib/stRoot.mjs`), never derived.
- **One build**: `npm run build` writes the one bundle to `dist/` with every `storyOrchestrator*` handle and debug-response seam; harness/calibration/spike modules ride lazy chunks (`runtime/lazyHarness.guard.test.ts`); `runtime/oneBuild.guard.test.ts` fails if a build flag, `dist-dev`, `build:dev` or `serve:dev` comes back. `npm run dev` (watch) writes `dist/` too, with source maps.
- **After every build**: `npm run build && npm run stage`, then `node scripts/debug/st-session.mts reload` (lane: `st-lanes.mts run <n> -- scripts/debug/st-session.mts reload`). A plain reload can re-execute the cached bundle and measure the previous build. `so-journey`, `so-scenario`, `so-payload-golden`, `so-c2-save-race` refuse to start when the page has no `storyOrchestratorRuntime` and say stale page vs no build (`lib/servedBundle.mts`); `st-lanes.mts batch` refuses when no `dist/manifest.json` is staged.
- Scripts are `.mts`, run directly: `node scripts/debug/<tool>.mts`. Artifacts go to **the debug dir**: `SO_DEBUG_DIR`, default `<so-lanes>/0/debug` (outside `public/`, because logs, journals and payloads hold chat text). Never write into `.debug/` under the served tree; `scripts/debug/servedDebugDir.test.mts` fails a script that does.
- **Harness unit tests**: `npm run test:debug` (node:test over `scripts/debug/**/*.test.mts`, `scripts/local`, `scripts/lib`; jest covers `src/` only). Tests drive the shipped closures against a fake `page` (`{ evaluate: (fn, arg) => fn(arg) }`) with `SillyTavern` / `storyOrchestratorRuntime` stubbed on `globalThis`.

## Browser and session

- Browser is **headless by default**; `st-session.mts start --headed` opens a visible window. Use headed whenever the user wants to watch.
- Shared session when mixing scripts + MCP: `st-session.mts start` (CDP `http://127.0.0.1:9222`); repo `.mcp.json` points the playwright MCP there. An MCP without `--cdp-endpoint` launches its own isolated Chromium. Verify sharing with a `globalThis.__x` round-trip (MCP `browser_evaluate` set, `st-eval.mts` read).
- Scripts = deterministic reads/actions/assertions, anything a gate depends on, anything run twice. MCP `browser_*` = exploratory only.
- **Default gate for LLM-consuming paths = real-LLM validation** (profile selected, no `debugResponse`); see "Real-LLM validation" in the debug skill. Can't run it: flag at handover, gate NOT green.
- Responsive testing: prefix EVERY command with `ST_DEBUG_VIEWPORT=<W>x<H>` (e.g. `390x844`); unprefixed runs snap viewports under 1280px back to 1920x1080.
- Chat/entity control: `st-navigation.mts list-entities | recent-group | open-group <id|name> | open-character <name> | list-chats | open-chat <chatId> | new-chat`. Group draft: `st-actions.mts trigger <member>`. Ad-hoc in-page JS: `st-eval.mts "<js>"` (ctx + rt in scope).
- **Pin the group on every navigation.** `new-chat` acts on whatever is current (after a reload: possibly a solo character); a peer session can move the page mid-run. Treat an `open-group` timeout as a hard stop. Scenarios: `so-scenario run <file> --sandbox --group <id|name>` (without `--group` the sandbox takes ST's most recent group). Journeys: `setup.group`, `--group`, or the open group.
- **Git Bash mangles leading-slash args**: `st-actions.mts slash "/delchat"` becomes `C:/Program Files/Git/delchat` and no-ops. Prefix `MSYS_NO_PATHCONV=1`.
- **`/cp` and `/so-mem backlog` answer only in Author view.** `st-actions.mts slash`, the scenario `slash` verb and `sagaRecall` wrap the command in Author view and restore player mode (`lib/authorSlash.mts`); an in-page `executeSlashCommandsWithOptions('/cp …')` does not.
- `ensureSTReady` (`lib/st-ready.mts`) waits for the CSRF token, then refuses a stale one: reload the shared page and re-open the pinned chat.
- `lib/connection.mts` `settleDialogs(page)` handles JS dialogs on every attached page; without it a dialog settled by another CDP client crashes the runner uncaught and skips cleanup. After any runner crash on lane 0: `so-journey.mts restore-config`, then `so-run-header diff` against a pre-run capture.
- Test cleanup: `so-library.mts remove "<title>"` + `so-library.mts wipe-chat-meta` + `/delchat`.

## Fixtures and scenarios

- **Closed vocabulary**: `lib/scenarioSchema.mts` lists every verb, modifier (`log`, `attempts`, `retryBack`, `expectFail`, `adoptsNewChat`), `expect`/`expect_ui`/`wait` key and `ui`/`stagecraft`/`copilot` action, plus verb value shapes; both runners validate before running. Typos, empty assertion objects and two-verb steps are load errors. A new verb/key must be added there. `auditCount>=`, `reconciliationEvents>=`, `sceneBreaks>=` are real keys.
- **`eval` is one line of JS**: a `//` comment swallows the rest of the step (`SyntaxError: Unexpected end of input`). Use `/* … */` or the check's `goal`. Evals are not syntax-checked until they run: pre-check with `new Function('return (async () => { ' + step.eval + ' })()')`.
- **A step whose result has `ok:false` fails** (enforced in `runSteps`); a step meant to fail sets `expectFail: true`. So a step proving a refusal must return a wrapper (`{ refused: true, message }`), not the refusal object.
- **`send` is `/send compact`: posts the line, generates NOTHING**, and commits no boundary. A real turn is `send_generate`; it returns `replied`/`lastSpeaker`/`lastLength`, and `expectReply: true` fails a silent turn (silence is legitimate under talk control, so not fatal by default). With the backend down a send still appends an empty reply and commits a boundary.
- **One player send in a group is N loud generations** (one per drafted member). A check counting generations drafts one member per generation with `/trigger await=true "<name>"`. Member-filtered lore (`characterFilter`) fires only on that member's turn.
- **Top-level `requires`** (`lib/scenarioRequires.mts`): `lane` (`no-model`|`model`), `group` (wins over `--group`; Adolion groups by NAME), `members` (re-enabled before the sandbox chat), `authorView`, `judge: "off"`, `briefingDraft: "off"` / `innerBeat: "off"` (a sandbox run switches that install-wide use off, read back, and restores it in cleanup, reported as `cleanup.modelSettings`; payload cases need both because a no-model lane makes those calls), check-only `mainApi`/`roleProfiles`/`macroEngine`/`vectorsWorldInfo`, `prior`. Unmet = `not-runnable` (`NOT RUNNABLE` in batch logs), not red. `scripts/suite/decisions.mjs` derives the no-LLM list from it. No-model lane: `st-lanes.mts stop <n>; st-lanes.mts no-model <n>`, back with `restore-model <n>`.
- **`storyOrchestratorDebug*` globals outlive a run** until reload. `so-scenario --sandbox` and `so-journey` clear them. A mocked plumbing scenario keeps real extraction out by pinning `storyOrchestratorDebugExtractionResponse = 'SCENE_NONE'` before `import_story`.
- **A manual read straight after `send`**: `runNow` reads up to the newest chat message, since the engine's `lastMessageId` lags until a boundary.
- **Nondeterministic model steps**: assert whatever the model chose (curator `pick:"text-first"`, never a hard-coded op kind); read the prompt ST sent from `GENERATE_AFTER_DATA` (main `Generate()` only; a `/api/backends/` fetch wrapper also catches memory-model and curator calls). "Nothing else changed" checks start after `wait: {schedulerIdle: true, quietMs}`. Prefer monotonic waits (`wait: {checkpointIn: [...]}`, `expect: {activeCheckpointIn}`) over exact `checkpoint` when the story can advance past it.
- **Group epistemic**: the resting block is empty; call `onMemberDrafted(chid)` first, with ST's numeric character index (`ctx.characters.findIndex(...)`), never a roster id. Probe the applied block with `getAppliedEpistemicBlock()`.
- **Scene-break reads** need a seeded prior location (first location is never a break), seeded with a value the enum declares (`setQuality` drops out-of-enum values silently), and a cadence that does not already read every boundary.
- **Settings checkboxes**: click `box.closest('label')`, not `input.click()` (toggles twice); open the panel first (`ui: {action: "open-settings"}`), a click on a hidden panel is swallowed; decide by the stored setting, never `box.checked`. ST nests the panel two drawers deep and an open Extensions drawer hides `#options_button`/`#send_but`: close it afterwards.
- **`element.click()` is not a pointer click.** `ui: {action: "hit-test", selector}` names what is topmost at the target's centre: `disabled` (correct for a disabled control, e.g. `#so-self-test`), `overlay`, `ancestor`, `offscreen`, `no-box`, `missing`.
- **Generation state**: ST swaps `#send_but` for `#mes_stop` while generating; a disconnected ST hides both. Generating = `stop visible || (send hidden && stop not hidden)`, with a continuous idle window so group turns are not cut short. `sendUserMessage`'s pre-send idle wait is `preSendIdleTimeoutMs` (default at least 60 s). When the backend moves, suspect fixed harness timeouts first.
- **`ctx.onlineStatus` is a cached label.** Probe a profile: `ConnectionManagerRequestService.sendRequest(<id>, [{role:'user',content:'Reply with exactly: PONG'}], 16, {extractData:true,includePreset:true,includeInstruct:true,stream:false}, {})`; a dead backend fails in under 10 ms. A page loaded while the backend was dead keeps `#send_but` hidden across reloads: re-select the profile (`/profile <name>`).
- **Chat switches during a pending save** can post one chat's metadata under another's name and wedge the page on ST's integrity popup. Wait for `schedulerIdle` before `solo_chat`, and for `isChatSaving` false (+ about 2 s) before any in-page chat switch. `openGroupChat(groupId, chatId)` silently returns unless the chat is in `group.chats`; open groups from outside (`st-navigation open-group`) and assert `ctx.groupId` + `ctx.chatId`.
- **`cast_changes`/`setGroupMembersDisabled` mutate the group's `disabled_members`**, which outlives sandbox cleanup. Restore AFTER deleting the sandbox chat (ST reloads the group behind `/delchat` and undoes an earlier enable); `so-journey` does and reports `disabledMembers`.
- **A capability probe must not read a global an earlier check set** (a reload wipes it and the cached probe then blocks everything after).
- **so-scenario sweeps run residue** after cleanup (`lib/runResidue.mts`): new `SO-` lorebooks/cards, `SO-` books left globally selected, `SO-` wizard-ledger rows/sessions, `spikes` settings. A sweep names the leaking fixture; a sweep that cannot clean fails the run.

## Cleanup and real assets

- **Memory mirror = one lorebook per chat** (`Story Orchestrator - <title> - <chatId>`, `getSnapshot().memory.wiBook`); deleting the chat does not delete it. `so-scenario --sandbox` and `so-journey` delete each recorded book named `<recorded title> - <owned chat id>` via `deleteWorldInfo` after `updateWorldInfoList` (report `cleanup.mirrorBooks {deleted, failed, leaked}`); a name without an owned chat-id suffix is never touched. Read a mirror book's name from `memory.wiBook`, never a fixed title (`loadWorldInfo` answers a missing name with an empty dummy).
- **Reap popup**: deleting a chat whose mirror book carries the `so-owner` marker asks whether to delete the book too. Every script that deletes a chat must call `settleReapPrompts` after its chat and mirror cleanup (declines questions for chats the run owned, reports `cleanup.reapPrompts {dismissed, leaked}`); an open question is a leak and fails the run. `so-mutation-check` has no mirror cleanup, so its declined books remain as Repair rows.
- **The wizard creates real ST assets.** Drive it with `so-ui.mts open-wizard | new-story-wizard | wizard-run [stage] [message] | wizard-answer [a1|a2|a3] | wizard-apply [index] | wizard`; agent cards with `so-ui.mts agent-accept [n|all]` (edit cards, stops at provisioning) and `agent-apply [n]` (provisioning cards), waiting between cards (`lib/agentCards.mts`). Stage chips (`[data-so="wizard-stage"]`, `aria-pressed` = running stage) sit inside a closed `details`; `so-ui` opens it before clicking.
- **Asset cleanup**: `so-assets.mts list | remove | assert-clean --marker <prefix> [--baseline <file>]`. Never delete an unmarked asset. Scope = the marker plus the `applied` ledger of **test** wizard sessions (keys starting with the slugged marker) plus, in a journey, entries since the run's `snapshotAssets` baseline (written to the debug dir as `so-journey-asset-baseline.json`). Assets that existed before the run are `protected`; a real author's sessions are never touched. **An empty baseline is untrusted**: cleanup falls back to marker-only and reports `baselineUntrusted`. Books are deleted through ST's `deleteWorldInfo` (`lib/lorebookDelete.mts`); one still cached is `staleCache`.
- **The WI curator writes a real lorebook** (on by default): scenario step `{stagecraft: {action: "curate"|"accept"|"reject"|"accept-op"|"reject-op"|"apply"|"state"}}`, drawer review via `so-ui.mts stagecraft | curator-accept [index|text-first] [text] | curator-reject [index]` (`ui: {action:"stagecraft", minOps}` waits for cards), assert with `expect: {background}` / `expect: {stagecraft: {...}}` (`opsAtLeast` fails a 0-op proposal). `so-assets.mts remove --marker` deletes the book it wrote. `evictWorldInfoCache` reloads books page-wide, so it can fail a peer's in-flight curator pass.
- **Install-wide config**: journeys snapshot global settings to the debug dir (`so-journey-config-snapshot.json`) before clearing; `so-journey.mts restore-config` recovers a crashed run, and `emptySnapshotRefusal` (`lib/configRestore.mts`) refuses an untrusted empty snapshot over a populated config. **Extraction settings are install-wide; both runners capture and restore them** (`lib/extractionSettings.mts`, reported as `cleanup.extraction`), because a mocked corpus otherwise left extraction disabled and `stabilityLag` changed for the next real player. Persist harness settings writes with `lib/settingsSave.mts` `saveSettingsNow(page)`, never `saveSettingsDebounced`.

## Journeys

- `so-journey.mts --list | run <id> | restore-config`; catalog and checks in `docs/plans/v2.1/test-plan.md`. Fresh start by default; outcomes `pass|fail|blocked|not-runnable|skipped`.
- **Three gates**: automated / human / cleanup, counted separately. A cleanup failure or leaked asset fails the run with or without `--strict`; `--strict` also fails blocked, not-runnable and skipped. `--only` marks the record `partial` (never a gate) and runs against a fresh chat, so every check imports the story it needs. `--group <id>` pins the group; `--require-human-record <file>` fails on an unscored rubric row.
- A check can declare its expected outcome (`"expect": "blocked"`); J0 gates the runner itself this way.
- Each check reports first-attempt passes (`first try: N of M passing check(s) needed no retry`); `attempts`/`retryBack` make retries visible, not equivalent.
- **Run a journey twice before believing it**, and archive the greening run under `test/journeys/records/<gate>/` (the debug dir rotates).
- **A journey establishes its story's requirements**: a listed lorebook is scanned for its own story (`storyLore.ts`), so `setup.activateLorebooks` is only needed on a host without ordered scan listeners. Keep a guard step that fails on `!snapshot.requirements.ready` naming `missingLorebooks`.

## Evidence and tails

- **Run header**: `so-run-header.mts capture --label <name>` pins build (served bundle hash), host + macro engine, profiles (incl. `profiles.urls`), active sampler, judge uses, stagecraft, extraction settings, chat, story, cast, and `stories`/`wizardSessions`/lorebook-selection inventories. `diff <baseline.json> [--allow a,b] [--owned <chats>]` exits 1 on any undeclared difference; `--allow` takes paths or list items (`inventory.stories:+SO-J12`). A declared addition never excuses an undeclared removal in the same list. Unreadable fields land in `warnings`, not `null`. **Diff around every batch of runs**, not just one; `chat.authorView` differing is a per-chat override, not residue; `story.*` differing after a corpus can also mean a wiped chat (ST keeps per-save copies in `data/default-user/backups/`).
- **Session journal**: `so-journal.mts export|show` writes `journal-<chat>.md|json` to the debug dir; `follow --out <f.jsonl>` tails journal events plus full extraction audits. `st-payload.mts arm --persist --out <f.jsonl>` keeps every generation request with the drafted member; `watch` prints. Both tails survive reloads and closed stdout. Payload entries carry a monotonic `index` + `epoch`; `drainPayloads` reports `dropped` when the poller fell behind the ring (100).
- **Payload goldens**: `so-payload-golden.mts capture --label <name> --out <dir>` runs each `test/scenarios/payload/*.json` as a sandbox scenario and records ST's dry-run prompt (resting and per drafted member) plus every `story_*` block, no model call (an in-page tripwire fails on any `/generate` or judge request); `diff <baseline> <candidate> [--declared <file>]` exits 1 on an undeclared hunk or stale declaration (`lib/payloadGolden.mts` `NORMALISE_RULES`). These fixtures fail on purpose under plain `so-scenario`. Layout: `test/measurements/v2.7/payload/README.md`.
- **Live suite** (`so-live-suite.mts`): scores every tier a fixture states; per-tier floors `--min-tier facts=0.85,rejected=0.9`, `--expect-count <n>` refuses a shrunken denominator, errored fixtures are `incomplete` and fail, empty `mustContain` needles are `vacuous` and never count; headline `plotDeltaAccuracy`; `--record` writes `test/goldens/live/`. Needles are whole terms unless the fixture lists them under `modes` as `prefix` (`src/utils/termPresent.ts`, one matcher for the self-test and all scorers); `so-live-suite.mts inventory [--check]` classes every needle against the recorded answers and `rescore` writes a new versioned record under `test/goldens/live/rescore/` (offline, never overwrites).
- **Row evidence**: every `st-lanes batch` row writes `<lane>/debug/batch/<stamp>/<item>-run<k>/` (runner.log, record.json, page.jsonl + page-summary.json, the server.log slice, tunnel.json + pod.json on a pod lane) and evidence.json; a row missing a piece is INCOMPLETE, never green. `SO_ROW_DIR` turns page capture on in any `runCli` runner; scenario, journey, payload golden and `so-b1-*` capture outside rows too (`SO_PAGE_CAPTURE=off` disables).
- **Pods**: a pod lane needs `so-pod.mts target <k>` + `so-pod.mts up <k>` running (tunnel supervisor + health/metrics/slots, nvidia-smi and llama-server log every 15 s into `<so-lanes>/pods/<k>/`; the pod needs `LLM_DEBUG_LOG=1`). `so-pod.mts pull <k>` before any llama-server restart; `so-pod.mts release <k>` must exit 0 before the pod is stopped. Then `so-evidence.mts archive --label <x>` copies lanes + pods into the private so-sessions tree, and `npm run sessions:archive` commits it (alone it covers only `test/sessions`).
- **Phase C**: `test/phase-c/manifest.json` is the only list of rows a Phase C verdict counts (`scripts/release/phaseCManifest.test.mjs` in `test:release`); write each run's record path into the row's `evidence`. `SO_ACCEPTANCE=1 npm run test:release` fails on a missing `docs/release/<version>/attestation.json` or build and verifies commit, served and built hashes; ordinary runs skip attestation checks while the file is absent. `test:release` rewrites `dist/manifest.json` (`builtAt`): do not run it during a live batch.
- Shell: `$?` after a command substitution is the substitution's status. Capture `code=$?` on the line right after the command.

## Lanes

- `st-lanes.mts seed [--fresh] | start | stop | status | env | run <n> [--allow-load] -- <script> | batch | no-model | restore-model`. A lane is its own ST server (port 8100+n, `--dataRoot` seeded from `data/default-user` minus backups/vectors/thumbnails) over the SAME code tree (so the one staged `dist/`) and its own browser (CDP 9300+n, own `SO_DEBUG_DIR`). Install-wide state never crosses lanes.
- **Reserved ports** (`lib/laneRange.mts` `RESERVED_PORTS`, the one list): 8188 ComfyUI, 8000 owner ST, 18888/18889 local controller, 18079 offline closed port, 18080 pod tunnel, 8095/8096 local judge/landmarks, 8765 showcase, 6006 Storybook, 9222 shared CDP. Every lane command (`st-lanes`, `so-session`, `adolion-fresh`, the p41 `laneProblem`) refuses a lane whose ST or CDP port is on it, naming the service (`laneIssue`); today that is lane 88 (8188 = ComfyUI, blocked an image run 2026-10-18). A new local service adds its port there.
- **Same lane number, other lanes root** (`SO_LANES_ROOT`, e.g. `C:\dev\so-live-lanes`) = same ports. `status`/`stop` report `serverUp` only when the process listening on the port runs `--dataRoot` of THIS root (`lib/lanePortOwner.mts`; unreadable command line falls back to `server.pid`), else `serverUp: false` + `portHeldBy`; `start` refuses such a lane instead of attaching a browser to the other root's server.
- Lanes live OUTSIDE the ST tree (`C:\dev\so-lanes`, or `SO_LANES_ROOT`): a lane holds a copy of `secrets.json`. A lane result is evidence about the lane's copy; re-seed (`seed <n> --fresh`) when the real install's characters, groups or lorebooks change.
- `batch --lanes 1,2 --repeat 2 --strict <item...>` runs each item `--repeat` times back to back on ONE lane ("twice" = consecutive on one install).
- **Windows does not kill a dead shell's children.** Killing the wrapper shell (bash, cmd, a stopped background task) leaves its node driver and the driver's node children running. `st-lanes run|batch` guard their children (`lib/childTree.mts`): a stop signal, exit, or the parent shell gone (checked every 2 s) tree-kills them with `taskkill /T /F`. `SO_DETACHED_RUN=1` turns the parent check off for a deliberately detached run. Stop any other driver with `taskkill /T /F /PID <driver pid>`, never by killing only the shell.
- **At most `SO_MAX_LLM_LANES` (default 2) lanes with a model at once**: `batch` and an integration `play` through `run` refuse above it (no-model lanes do not count; `--allow-load` overrides). An integration run stops (`turns.jsonl` `kind: "stop"`) when a chat switch fails or the open chat is not the run's.
- **Adolion runs start from `adolion-fresh`**: `adolion-fresh.mts seed <lane>` (lane 1+, never 0) strips the campaign's assets from the copy, switches `image.enabled`/`sprites.enabled` off before the server starts, applies the preset overlay (`adolion-fresh.presets.json`, read back, fail closed; `--no-preset-overlay` for the old condition), installs the campaign at `adolion-fresh.pin.json`, creates the groups, deselects every globally selected lorebook, imports the stories, writes the asset baseline to `<lane>/debug/adolion-fresh-asset-baseline.json` and diffs the inventory against the lane's last one. `check <lane> [--drop-book <name>]` re-checks. A drifting seed exits 1; after a deliberate change, `accept-baseline <lane> --reason "<why>" [--by <who>] [--report <file>]`. Leased lanes (holding a continued chat) are refused without `--for`/`--break-lease`.
- **No ComfyUI from lanes**: `image.enabled` defaults on, and story imports alone can post `/prompt` to the shared ComfyUI. `adolion-fresh` fails a seed whose lane log shows a ComfyUI call; any other script that starts a lane and imports or plays must switch images and sprites off first, and never calls `/sd` or `/interrupt`.
- **Session tooling** (`so-session.mts`): `start <charterId> [--lane n] [--media on --allow-comfy] | stop | digest | cards --write | validate | index` runs one session per card of `test/sessions/charters.json` on an adolion-fresh lane, headed, evidence in `test/sessions/<tier>/<id>-<n>/`. Live verbs (`turn | swipe-new | regen | edit | delete | switch-chat-mid-gen | reload-mid-gen | delete-chat | flag | shot | age | adopt | goal | agent | score | plan | budget | runbook`) act only on the session's chat and append to `<dir>/turns.jsonl`. Fail closed: `start` exits 2 (`start-failed.json`) on any settings (`test/sessions/baseline-settings.json` + card overrides)/pin/page/header discrepancy, a tail without its ack, a missing `requires.features` or a leased lane; `stop` diffs the header with `--owned`, drains tails, verifies required artifacts and marks the session INVALID (exit 1) on a gap. `score` on an INVALID session needs `--provisional`; rating packs (`rating-pack`, `--arm`/`--gate`) pair only VALID sessions. `so-session lane archive|restore|lease`. Generated docs: `docs/plans/v2.6/14-cards.md`, `14-autonomous-runbook.md`. Detail: debug skill "Human sessions".

## Gates

- `npm run gates` runs every step as soon as its needs are done (`--jobs`, `--serial`, `--no-storybook`, `--resume`; `npm run gates -- --help`); each finished step is recorded in `.build/gates-last.json` against a hash of the working tree (HEAD + diff + untracked), the gitignored inputs (`.st-root`, the campaign story index, `node_modules/.package-lock.json`), the node version and the `SO_`/`ST_`/`NODE_`/`JEST_`/`CI` env; opt-in `--resume` reuses steps green on that exact state (flake or environment fix only; a rerun dependant reruns its `build`), and plan closes and merges cite a run without it; with `typecheck` in the run the builds skip their own type pass (`SO_BUILD_TYPECHECK=0`). Webpack/Storybook cache in `.build/webpack-cache`. `npm run test:replay` runs rows in parallel staged copies (`--workers`), `--cached` reuses rows no change can reach (`.build/defect-replay-cache.json`).
- **`npm run gates:quick`** is the per-change gate: typecheck (+ `typecheck:test` when a test changed), eslint and `jest --findRelatedTests` on changed src files, replay `--cached`; changed = since merge-base with `--base` (default `master`) plus uncommitted/untracked. Plans close and releases ship on `npm run gates`, never `gates:quick` or `--cached`.
